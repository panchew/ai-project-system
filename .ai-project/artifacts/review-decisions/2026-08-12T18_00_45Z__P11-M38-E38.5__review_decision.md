# Review Decision: P11-M38-E38.5 — Milestone-Context Evidence

## Decision: REJECT ✗ — scoped measurement rework

The submission has a useful result, but not yet the result the Epic defined. The 252,583-byte probe
shows that Ollama silently truncates an input far beyond the loaded window. The Delivery Notice then
applies a bytes-per-token estimate to a different, 147,626-byte session-start corpus and labels that
corpus a capacity FAIL. The spec explicitly says that estimate does not replace E38.5's measurement.

PR **#198**, `epic/P11-M38-E38.5` → `milestone/M38`, must not merge in its current state.

## Finding 1 — the measured probe is not the defined milestone context (blocking)

The Delivery Notice defines milestone context as a scoped session-start set totaling **147,626
bytes**. Its live probe instead uses **252,583 bytes** assembled from the milestone spec, phase spec,
PSG, and AOG **in full**.

Those are different corpora. The larger probe supports this narrower finding:

> A substantially oversized full-document prompt is silently truncated to the loaded window.

It does not establish that the defined session-start set itself truncates. That claim still comes
from `147,626 / 3.9 ≈ 37,853` estimated tokens. The Delivery Notice acknowledges roughly 20% ratio
variance; at its favourable end the estimate is about **31,544 tokens**, below 32,768. Therefore the
uncertainty crosses the exact boundary E38.5 is required to measure.

### Required rework

Run the marker probe against the **exact defined session-start corpus**, remeasured and commit-anchored
on the resubmission state. Put the unique marker at position 0 and place the retrieval instruction in
the retained tail so marker loss is distinguishable from instruction loss. Record the observed
`/api/ps` value after load and the structured response. Report PASS, FAIL, or an honestly bounded
result from that run; do not fit the definition to the outcome.

If a real model tokenizer is used instead, retain its exact identity and command. A tokenizer count
may establish whether the corpus fits, but the live marker probe is still needed to establish the
failure mode if it does not.

## Finding 2 — the submitted method is not reproducible enough (blocking with Finding 1)

The only probe command contains `"<252KB prompt>"`. The exact section ranges, separators, prompt
assembly, tail instruction, raw `/api/ps` output, and raw `/api/generate` response are not retained.
A reader cannot reconstruct the tested bytes or distinguish truncation from a prompt-instruction
effect from the committed record alone.

### Required rework

Commit a deterministic, non-secret probe script or equivalent exact construction manifest plus raw
structured results under `.ai-project/artifacts/agentic-runs/P11-M38-E38.5/`. It must identify:

1. every source path and commit;
2. exact section boundaries and concatenation order;
3. inserted marker and tail instruction;
4. corpus byte count and whether every token figure is measured or estimated;
5. `/api/ps` after load; and
6. the probe response fields used for the conclusion.

The artifact need not commit model weights or an unnecessarily large duplicate corpus; deterministic
construction from commit-anchored sources is sufficient.

## Finding 3 — suite and model-route report is factually false (blocking)

The Delivery Notice says `.ai-project.yml` declares `epic_manual: remote:deepseek-v4-flash`, excludes
two allegedly pre-existing failures, and reports `484 passed, 5 deselected`. None describes the
delivered tree. The config declares **`remote:claude-opus-5`**, and the exact required command passes
all **489** tests without exclusions.

### Required rework

Replace §11 with the unfiltered required command and result. Remove the nonexistent route divergence,
the two nonexistent failures, and the claim that exclusions were needed. Reconfirm the manual model
identity explicitly from the actual execution environment; if a harness identity and configured route
are both present and disagree, obey the starter's STOP condition rather than continuing.
