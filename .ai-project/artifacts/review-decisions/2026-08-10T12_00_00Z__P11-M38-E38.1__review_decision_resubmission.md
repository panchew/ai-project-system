## ⚠ Annotation to fix before merge — two stale reproduction commands

**`drivr/.ai-project.yml:33-34`** still name the old path:

```
  #   git -C governance describe --tags  ->  v7.1.0
  #   git -C governance rev-parse HEAD   ->  bb727a52678b86df3bf5eac1a56eead5fec7bd9c
```

**Both now error.** Measured:

```
$ git -C governance describe --tags
fatal: cannot change to 'governance': No such file or directory

$ git -C .governance describe --tags
v7.1.0
```

**Why this is worth fixing rather than noting.** These are not decorative comments — they are
**recorded reproduction commands**, and their entire purpose is to let a reader re-derive the pin
instead of trusting the record. **A reproduction command that errors makes a verifiable claim
unverifiable, and reads as though the pin itself were wrong.** In a milestone whose lineage is about
citations that resolve, a broken verification command is the wrong thing to ship.

**The fix:** `governance` → `.governance` on both lines. **Two characters twice, in a file the rework
already edited.**

> **And a small `G2` instance for the record, stated without weight.** The Delivery Notice's step
> table (`:605`) lists step 2 as *"done"* including *"comments."* **The substantive parts are done and
> the `# Spec:` line specifically named in the instruction was updated** — but the blanket claim is
> broader than the file supports. **This is why the reviewer re-measures**, and it cost one grep to
> catch.

**This annotation does not require a further Review Decision.** Fix it on the same branch, in the same
PR, and report the corrected lines.
