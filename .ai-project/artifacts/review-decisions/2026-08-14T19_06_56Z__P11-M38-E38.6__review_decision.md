# Review Decision: P11-M38-E38.6 — Local/Paid Controlled Comparison

## Decision: REJECT ✗ — scoped protocol rework

The submission correctly refuses to turn a contaminated run into a tier conclusion. That honesty is
accepted. It does not, however, satisfy the Epic by itself. The binding spec says an unblinded
comparison over committed material is a retrieval test, requires both arms on comparable material,
and closes with: an unblinded, asymmetrically constrained comparison **is not a result**.

PR **#199**, `epic/P11-M38-E38.6` → `milestone/M38`, must not merge in its current state.

## Finding 1 — there is no valid comparable local/paid pair (blocking)

The local arm ran in a git-free workspace and had to derive its answer. The paid arm had the full
repository, found the committed answer, and returned it. The Delivery Notice correctly labels the
paid result invalid and the arms non-comparable. Those facts mean the explicit deliverable — both
arms run on comparable material — and the Definition of Done — the same work run both ways — remain
open.

The contamination report is a useful protocol-failure record. It is not a substitute for the
controlled comparison E38.6 exists to produce.

### Required rework

Preserve paid run 1 and its INVALID classification. First resolve Finding 2 below, because it decides
whether only paid or both arms require replacement. Before any replacement run, commit a short,
explicit protocol-correction addendum that:

1. identifies paid run 1 as a protocol-invalid trial, not a scored arm and not a candidate result;
2. identifies every invalid arm and authorizes exactly one replacement for each, solely because the
   original violated or cannot be shown to have followed a frozen execution condition; and
3. freezes the replacement paid conditions: a fresh manual session at `models.epic_manual`, the
   original blinded packet content only, no repository/git/search access, no post-fix artifacts, no
   evaluator follow-up, and the original rubric unchanged.

Then run the replacement paid arm and report it whatever its quality result is. If Finding 2 requires
a local replacement, run it under the original registered adapter/container conditions and preserve
the original local output as an invalid protocol trial. Keep every run in the record. Do not choose
between outputs, tune the prompt, or suppress an invalid trial. If the frozen conditions cannot be
provided, stop and escalate that inability; do not call a divergent run completion.

Score the valid paid output from its produced artifact or exact proposed patch, not from its prose.
Record G1 and G2 for it. Recompute the comparison judgment using the valid local/paid pair and retain
the narrow sample-size limits. A CATCH is not required by this review — an honestly measured MISS is
still evidence — but both arms must be valid and scorable under the registered conditions.

## Finding 2 — the local execution record conflicts with the frozen environment (blocking)

The rubric registers `ContainerEnvironment (debian:12-slim)`. The Delivery Notice says the local arm
ran on the host in `/tmp/opencode/e38.6-comparison`. Its raw file is an OpenCode event stream; it
shows work in that path but not the adapter call or an enclosing container. The record therefore does
not establish that the arm ran through the registered dispatch/environment path.

### Required rework

If the original run did use Drivr's OpenCodeAdapter and the registered ContainerEnvironment, commit
the exact invocation plus adapter/run metadata that proves it and correct the Delivery Notice's
`host` statement. In that case the original local arm remains valid and need not be rerun.

If it ran directly on the host, through a process environment, or the required boundary cannot be
verified, classify local run 1 as protocol-invalid and include one replacement local run under the
original frozen adapter/container conditions in the protocol-correction addendum. Retain and report
both local runs; do not score-select between them.

## Finding 3 — paid-arm wall-clock timing is missing (blocking with Finding 1)

The spec requires wall-clock timing for both arms. The Delivery Notice records approximately 192
seconds for local and says paid timing was not captured. Manual execution does not waive the item.

### Required rework

Capture start and end timestamps, elapsed wall-clock duration, and the timing basis for the valid
replacement paid run. Retain the existing local timing and its first-to-last-event basis.

## Finding 4 — the Delivery Notice does not state an actual suite result (record correction)

The suite section gives the command and a 489-test baseline, then says the suite is *expected* to
remain there and refers to a remeasurement in the PR. A commit message is not the Delivery Notice's
test result. Its `P10-GH-10` sentence is also conditional rather than reporting what happened.

### Required rework

Run the exact command on the final resubmission commit and record its actual counts in the Delivery
Notice. State whether `P10-GH-10` occurred; if it does, retain both the first result and the isolated
rerun as required. The independent review baseline is 489 passed, but the resubmission must report
its own final-state measurement.
