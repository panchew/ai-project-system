**No surface on this host offers this model under any name.** `opencode models` returns 97 entries
across four providers (`openai`, `google`, `opencode`, `ollama`) and contains **no `deepseek/*`

## Item 2 — `phase` → **GPT-5.6 Sol** is ambiguous, and does not answer [BLOCKING]

**Two independent problems, either of which alone would block the row.**

**(a) The product name matches three roster entries, not one:**

```
openai/gpt-5.6-sol
openai/gpt-5.6-sol-fast
openai/gpt-5.6-sol-pro
```

The unsuffixed entry is the natural reading. **That is an argument from which suffix looks default,
which is precisely the reasoning Binding Constraint 3 forbids** — *never infer an identifier from a
product name.* The row is not narrowed to the base string on this Epic Chat's judgment.

**(b) It does not answer, and a control proves why.** `opencode run --model openai/gpt-5.6-sol`

**byte-identical** error. **So the failure is the credential, not the model**, and nothing was
learned about whether `gpt-5.6-sol` itself works.

**(c) And even a working key would not settle the config value.** Per R5, a manual verification
target's `.ai-project.yml` string is *what a chat compares against a self-report* — a **third
namespace**, distinct from the API id. **No self-report string for this model has ever been
observed.** Writing `remote:gpt-5.6-sol` would assert an identity between two namespaces this epic
has not measured, and would arm a fail-closed check against a string that may never match.

**Consequence:** `phase`'s value is **UNDETERMINED**. **E41.5 cannot land this row on current
