# Escalation Notice: E48.3 planning budget exhausted — seven findings, incl. a framework-level Notice lifecycle conflict (E48.3)

## Trigger

**All authorized E48.3 rework is exhausted** — the original three-attempt budget, with no `+1`
granted. The rework-3-of-3 delivery received a Reject decision, so PSG §11.6 provides no further
route; this notice asks for Phase disposition. The reviewing party is **P13 Phase Chat, OpenCode
session (`remote:gpt-5.6-sol`)**.

## The seven remaining findings (as received, verbatim by substance)

1. **High — local-only artifact lifecycle is not Git-feasible.** Enrollment runs after the
   initializer's final commit, but `.ai-project/enrollment.yml` is never committed; transitions
   between local-only and remote enrollment do not define removal/commit ordering, so stale
   coexistence can immediately produce `verification-failure` or invalidate a verified `HEAD`.
   (`spec:148-155,163-186`)
2. **High — evidence booleans cannot represent unavailable observations.** `tracking`, `pushed`,
   `ref_equal` are mandatory booleans, but authentication/transport/`undetermined` states may prevent
   observation; they must be nullable / explicit-unavailable rather than conflating unknown with
   `false`. (`spec:121-133,180-184`)
3. **High — the Delivery Notice still has no valid lifecycle.** The template's
   `completion_notice_timestamp` and `review_decision_timestamp` remain unresolved; a clean delivery
   produces no Review Decision; and updating merge fields after merge conflicts with the Notice being
   **created once / append-only** (PSG §12) and with the child stopping after merge.
   (`starter:225-241`; PSG:698-714)
4. **Medium — an existing credential-bearing `origin` has no status/detail/exit mapping.**
   `invalid-url` describes *supplied input* rejected before writing, not an *already-stored* URL; the
   visual routes query directly to `absent`, bypassing credential inspection. (`spec:112-135`;
   `.mmd:15-19`)
5. **Medium — usage exits remain non-exact.** The `--skip-git` exit is only "e.g. `2`", both
   enrollment flags have an unspecified non-zero exit, and precedence when all three flags occur is
   undefined. (`spec:167-175`)
6. **Medium — classifier rules contradict themselves.** Refusal-first ordering classifies
   mixed-token stderr as refusal, while the next rule says ambiguous stderr becomes `undetermined`;
   `repository not found` must not be classified `authenticated-refusal` without stronger evidence.
   (`spec:196-205`)
7. **Low — query exit semantics undefined.** Exit `0` is defined only when a disposition "was
   recorded," but query records nothing. (`spec:102-107,137-139`)

## What the review verified as correct (not re-raised)

Total command modes, the exclusive delivery-ready predicate, initializer placement, prerequisite

## Why this is escalated rather than reworked

- **The budget is exhausted and no fourth attempt is authorized.**
- Two of the seven are **not fixable at the Epic-planning layer without parent/framework input**:
  - **Finding 3** is a framework-level conflict: PSG §12 makes the Delivery Notice *append-only,
    created once at completion*, and a clean delivery produces no Review Decision — so the template's
    `completion_notice_timestamp` / `review_decision_timestamp` / post-merge `merge_details` cannot be
    truthfully filled by a single pre-review artifact. This is a template/PSG lifecycle question, not
    an E48.3 contract detail.
  - **Finding 1** (committing `.ai-project/enrollment.yml` after the initializer's final commit) and
    **Finding 3** both touch how the enrollment artifact participates in the repository's commit
    lifecycle, which E48.3's own "no write through another repo's chain" boundaries must respect.
- The remaining findings (2, 4, 5, 6, 7) are bounded contract-completeness gaps this chat can
  describe but may no longer apply.

## Resolution

**Resolved 2026-09-09 by P13 Phase Chat, OpenCode session (`remote:gpt-5.6-sol`).**

`f7624f5` on `phase/P13`, synchronized into `milestone/M48` by merge `e10fdfb`. It fixes, rather

- exact initializer usage exits and precedence;

- query credential inspection plus artifact/nullability flow in the proposed visual.

append-only Notice uses the bounded null/pending convention in the ruling and is not rewritten after
merge; parent merge plus named acknowledgment remains the separate acceptance record.

This is exactly one final planning attempt, not a reset to three. It is limited to synchronizing the
E48.3 spec, Starter, and proposed Mermaid visual with the ruling. No execution or merge is
authorized. If the `+1` delivery is not acceptable, no further rework is available and M48 must
