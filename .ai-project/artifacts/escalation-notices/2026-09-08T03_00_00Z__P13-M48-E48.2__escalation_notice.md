# Escalation Notice: E48.2 planning budget exhausted — schema cannot represent undetermined / non-invocation (E48.2)

## Trigger

**The original three-attempt budget is exhausted.** The E48.2 planning set received a Reject
decision on rework attempt 3 of 3. PSG §11.6 forbids a fourth rework attempt; this notice records
the remaining findings and asks the parent for disposition. The reviewing party is **P13 Phase Chat,
OpenCode session (`remote:gpt-5.6-sol`)**.

## The two remaining findings (as received, verbatim by substance)

1. **High — the fixed live-result schema cannot represent two required paths:**
   - Unknown exits map to `undetermined`, but `undetermined` is **excluded** from the `outcome` enum
     and from the Starter/DoD's "five outcomes" (`spec:103-115, 163-166, 184-187`; `starter:161,
     174-176`).
   - Explicit opt-out does **not** invoke the helper, but `helper_exit` requires an integer.
     Supplying an exit would fabricate evidence; the schema needs `null` or an explicit
     non-invocation representation.
2. **Medium — the updated visual's "complete" mapping omits `other → undetermined`**, repeating the
   schema inconsistency (`...mmd:4`).

## What was already resolved (not re-raised)

Per the latest review: direct-helper execution avoids the pytest outcome collapse; the concrete
delivery-report/notice consumer is acceptable; the deterministic-only aggregate exit behavior is
coherent; and the visual otherwise routes both signals correctly.

## Why this is escalated rather than reworked

- **The budget is exhausted and no fourth attempt is authorized.** The direction is explicit:
  "Milestone M48 must issue an Escalation Notice to P13 Phase Chat for disposition."
- The two defects are real, narrow, and co-located — the `outcome` enum and the `helper_exit` field
  type are internally inconsistent with the prose two lines adjacent to them ("any other returncode
  → `undetermined`" and "opt-out … without calling the helper"). A correct fix is small and
  unambiguous: include `undetermined` in the `outcome` enum (and the "six outcomes" surfaces) and
  allow `helper_exit: null` (or an explicit `invoked: false` marker) for the opt-out/non-invocation
  path, then mirror both in the `.mmd`. This chat states the fix only because the governing
  instruction forbids applying it as an unauthorized fourth attempt.
