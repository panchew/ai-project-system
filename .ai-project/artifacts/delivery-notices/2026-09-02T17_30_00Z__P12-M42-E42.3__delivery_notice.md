# Delivery Notice: P12-M42-E42.3 — The Merge Ladder Aborts

## Summary

**Approval failure is no longer a warning that proceeds; it aborts. The privilege-escalating merge
ladder is gone, and the suite now asserts the guard instead of recording the defect.**

In `bin/ai-project-git-merge`, `promote_branch` previously approved its own PR and, on approval
failure, printed *"Proceeding to merge"* and fell into a ladder — standard → `--admin` (bypasses
branch protection) → `--auto` — escalating privilege in answer to refusal. A branch protection that
said no was answered by trying harder, and `test_promote_branch_fallback_merge` asserted that
override succeeded as correct.

**What it does now:** approval failure **aborts** `promote_branch` (`return False`, no
warning-and-continue, `merge_cmd` never constructed from that branch). The `--admin` rung is
**removed** — the conforming answer, because gating it behind a recorded authorization would build a
**shadow authorization model**: `governance/templates/merge-authorization.md` is M43's (SN-31
Decision 4, verified unchanged at this branch's point and against M43's tip) and M43 would have to
reconcile any parallel record. The `--auto` rung is **dropped deliberately** — it is tempo, not
privilege, but as a retry-after-refusal rung it is the same fail-open shape this milestone closes;
auto-merge remains available to a human directly via `gh`. The standard merge is the single, honest
attempt; a refusal is a finding to report, not a reason to try harder.

**Two tests, because G2:** `test_promote_branch_fallback_merge` is **inverted** — it now asserts
`res is False` and that no subprocess call carries `--admin` (the suite fails if the override is
reachable unrecorded). A **new** `test_promote_branch_approval_failure_aborts` guards the `:269`
path that G2 showed had no coverage at all: approval non-zero → abort, no `gh pr merge` call. Both
guards were **falsified** — with each guard removed the suite went red
(`AssertionError: True is not false`), and restored after.
