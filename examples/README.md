# Examples Directory

This directory contains complete, worked examples demonstrating the AI Project System in action.

## Purpose

These examples serve as:
- **Learning references** for new users understanding the system
- **Copy-pasteable templates** for starting new projects
- **Validation** that the system works as documented
- **Best practice demonstrations** showing proper artifact structure

## Available Examples

### 1. Personal Task Tracker CLI

**Location:** [task-tracker-project/](task-tracker-project/)  
**Status:** Complete  
**Problem Domain:** Command-line tool for managing personal tasks

**What it demonstrates:**
- Complete Phase → Milestone → Epic hierarchy
- All major artifact types (spec, completion report, delivery notice, review seal, chat starter)
- Realistic problem statement and solution design
- Proper repository structure and file naming
- Full Epic 1.1 walkthrough (from spec to acceptance)

**Time to review:** ~30 minutes

**Best for:**
- New users learning the system
- Understanding the complete Epic lifecycle
- Seeing all artifact types in context
- Copy-pasting structure for your own project

[**Start here →**](task-tracker-project/README.md)

## How to Use These Examples

### For Learning

1. **Pick an example** (start with Task Tracker CLI)
2. **Read the example README** to understand what's demonstrated
3. **Walk through the artifacts** in the suggested order
4. **See the full lifecycle** from planning to acceptance

### For Starting Your Own Project

1. **Review an example** to understand structure
2. **Copy the directory structure** for your own project
3. **Adapt the artifacts** to your problem domain
4. **Reference templates** in [../governance/templates/](../governance/templates/) for blank starting points
5. **Follow governance** from [../governance/PROJECT-SYSTEM-GUIDELINES.md](../governance/PROJECT-SYSTEM-GUIDELINES.md)

### For Validation

1. **Compare your artifacts** to example artifacts
2. **Verify structure and naming** match conventions
3. **Check Definition of Done** completeness
4. **Review acceptance criteria** patterns

## What Examples Are NOT

- ❌ **Not production code** — Examples focus on process, not implementation
- ❌ **Not comprehensive** — Examples are pedagogical, not exhaustive
- ❌ **Not prescriptive** — Your project can vary based on domain and needs
- ❌ **Not dependencies** — Don't import or reference examples in real projects

## Contributing Examples

Want to add an example? Examples should:

1. **Use a universally understandable problem domain**
   - Everyone should be able to understand the problem
   - Problem should be simple but not trivial

2. **Demonstrate something specific**
   - Full Epic lifecycle (like Task Tracker CLI)
   - Complex multi-Milestone project
   - Specific governance pattern

3. **Be pedagogically sound**
   - Reviewable in ~30 minutes
   - Clear learning objectives
   - Realistic but simple

4. **Follow governance exactly**
   - Current PROJECT-SYSTEM-GUIDELINES.md
   - Current AI-OPERATING-GUIDELINES.md
   - Proper file naming and structure

5. **Include a README explaining what's demonstrated**
