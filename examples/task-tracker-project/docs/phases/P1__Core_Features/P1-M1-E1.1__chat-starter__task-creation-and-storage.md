## Epic Specification

**Full spec:** [P1-M1-E1.1__spec__task-creation-and-storage.md](https://github.com/task-tracker/task-tracker-cli/blob/master/docs/phases/P1__Core_Features/P1-M1-E1.1__spec__task-creation-and-storage.md)

**Commit:** `7f3a2e9`

### Summary

Implement foundational task creation functionality, enabling users to create tasks via CLI command (`task add "description"`) with proper data model, validation, and in-memory storage.

### Problem Statement

Users cannot create tasks, which is the most basic requirement for any task management tool. No task data model, creation command, or storage mechanism exists. This Epic establishes the foundation that all future task management features (listing, completion, persistence) will build upon.

### Goals

1. Define Task data model with proper structure (ID, description, status, timestamps)
2. Implement task creation CLI command: `task add "description"`
3. Implement in-memory storage for tasks (file persistence deferred to M3)
4. Implement input validation with clear error messages
5. Achieve >90% test coverage for core functionality

## Open Questions

**Q: Should task IDs be short (e.g., `a3f2c1d4`) or full UUIDs?**  
**A:** Use full UUIDs internally, display short prefix (first 8 chars) to users for readability.

**Q: Should empty descriptions be trimmed before validation?**  
**A:** Yes, strip whitespace before validation to catch whitespace-only input.

**Q: What happens if user provides description with quotes?**  
**A:** Handle gracefully — quotes are part of description if inside the string.
