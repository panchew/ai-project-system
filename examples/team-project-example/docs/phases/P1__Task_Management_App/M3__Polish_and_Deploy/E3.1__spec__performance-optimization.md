# Epic E3.1 — Performance Optimization

## Context

With M1 and M2 delivering a working Taskflow application, M3 focuses on production readiness. E3.1 addresses performance: the API and frontend must meet the SLAs agreed with the product stakeholder (Morgan Chen, CFO) before a public launch can be authorized.

Initial staging measurements show the task list API at 320ms p95 (target: ≤ 200ms) and the dashboard Lighthouse score at 72 (target: ≥ 90).

---

## Problem Statement

The application works correctly but does not meet its performance SLAs. Shipping with these metrics would result in a poor user experience and potential CFO refusal to authorize production deployment.

---

## Goals

By the end of this Epic, the system must:

1. Reduce `GET /tasks` API p95 response time from 320ms to ≤ 200ms (50 concurrent users)
2. Increase dashboard Lighthouse performance score from 72 to ≥ 90
3. Document all optimization changes with before/after measurements
4. Ensure no regressions in test suite after optimizations

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Implement database read replicas or horizontal scaling
- Optimize endpoints beyond task list (auth endpoints are already within SLA)
- Add new features or change UI behavior

---

## Scope of Work

### 1. API Performance

Profile and optimize `GET /tasks`:

**Must include:**
- Add composite index on `(owner_id, archived_at, due_date)` via Alembic migration
- Enable SQLAlchemy connection pooling (pool_size=10, max_overflow=5)
- Add Redis cache for task list responses (TTL: 30s, invalidate on task write)
- Load test with Locust: 50 concurrent users, confirm p95 ≤ 200ms
- Document load test results in `docs/performance/api-load-test-results.md`

### 2. Frontend Bundle Optimization

Profile and optimize the React frontend:

**Must include:**
- Enable code splitting: dashboard page, login page, and vendor bundle separate
- Lazy-load `FilterSidebar` (only rendered when user clicks "Filters")
- Convert PNG icons to WebP format
- Enable gzip compression in the Vite production build config
- Run Lighthouse against the optimized build; confirm score ≥ 90

### 3. Optimization Report

Produce `docs/performance/optimization-report.md`:

**Must include:**
- Before/after metrics table (API p95, Lighthouse score, bundle size)
- Description of each optimization applied
- Outstanding risks or areas not yet optimized
