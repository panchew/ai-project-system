# Bugfix Epic B1.1 — Auth Session Expires on Concurrent Requests

## Problem

Users making simultaneous API requests receive 401 errors intermittently. Investigation shows that two concurrent requests both trigger a token refresh race condition: both receive a new access token, but the first call's refresh token is revoked by the second call, causing the first call to fail on retry.

Affected in staging since 2026-06-18. Reproduced consistently with 5+ concurrent tab sessions.

## Impact

- **Severity:** Critical
- **Affected Component:** `src/auth/routes.py` — `POST /auth/refresh` endpoint
- **Affected Users:** All users with multiple browser tabs open simultaneously
- **Business Impact:** Users randomly logged out mid-session; significant negative UX impact; blocks production launch

## Root Cause

`POST /auth/refresh` performs a non-atomic read-check-delete of the refresh token. When two requests race:
1. Both requests read the token as valid
2. Request A deletes (revokes) the token and issues a new one
3. Request B also deletes the same token (now already revoked) and tries to issue a new one, which fails because the row is already marked revoked

Fix: wrap the refresh operation in a `SELECT FOR UPDATE` lock, or use an optimistic lock with a version field on the `refresh_tokens` row.

## Fix

Add `SELECT FOR UPDATE` to the `refresh_tokens` lookup in the refresh endpoint:

```python
# In src/auth/routes.py, refresh_token() handler
token_row = db.query(RefreshToken).filter(
    RefreshToken.token_hash == token_hash,
    RefreshToken.revoked_at.is_(None)
).with_for_update().first()
```

Also add a test for concurrent refresh requests to `tests/auth/test_auth_endpoints.py`.
