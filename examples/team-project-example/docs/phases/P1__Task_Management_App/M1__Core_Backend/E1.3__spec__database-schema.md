# Epic E1.3 — Database Schema

## Context

The Taskflow backend runs on PostgreSQL. Before any API endpoints can be implemented, the relational schema must be defined and the migration tooling must be wired up. E1.3 is the first Epic in M1 and unblocks both E1.1 and E1.2.

---

## Problem Statement

Without a schema, no data can be persisted. E1.1 cannot hash and store passwords, and E1.2 cannot store tasks. E1.3 is the critical-path dependency for the entire M1 milestone.

---

## Goals

By the end of this Epic, the system must:

1. Define the `users` table with required fields for authentication
2. Define the `tasks` table with all fields required for CRUD operations in E1.2
3. Define the `refresh_tokens` table for JWT refresh token storage
4. Provide Alembic migration scripts that apply the schema idempotently
5. Provide a local development seed script with sample data

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Design tables for Phase P2 features (comments, organizations, integrations)
- Implement database replication or read replicas
- Configure production database provisioning (infrastructure team handles this)

---

## Scope of Work

### 1. Schema Design

Define all tables in `src/db/models.py` using SQLAlchemy ORM:

**Must include:**
- `users` — id (UUID), email (unique), password_hash, created_at, updated_at
- `tasks` — id (UUID), owner_id (FK → users), title, description, priority (enum), assignee_id (nullable FK → users), due_date (nullable), archived_at (nullable), created_at, updated_at
- `refresh_tokens` — id (UUID), user_id (FK → users), token_hash, expires_at, revoked_at (nullable), created_at

### 2. Alembic Migrations

Set up Alembic in `alembic/` and create the initial migration:

**Must include:**
- `alembic/versions/0001_initial_schema.py` — creates all three tables
- Indexes: `tasks.owner_id`, `tasks.due_date`, `refresh_tokens.token_hash`
- Migration is reversible (downgrade drops all tables)

### 3. Seed Script

Create `scripts/seed.py` for local development:

**Must include:**
- Creates 3 sample users
- Creates 10 sample tasks distributed across users
- Idempotent (safe to run multiple times)

---

## Definition of Done

Epic E1.3 is complete when:

- [ ] All three tables defined in `src/db/models.py`
- [ ] Migration applies cleanly on a fresh PostgreSQL 15 instance
- [ ] Migration reverses cleanly (downgrade tested)
- [ ] Seed script creates data without errors
- [ ] Schema documented in `docs/db/schema.md`
- [ ] Epic Completion Notice produced and committed
- [ ] Pull request opened to `milestone/M1`

---

## Acceptance Criteria

- [ ] Running `alembic upgrade head` on a blank DB creates all tables and indexes
- [ ] Running `alembic downgrade base` cleanly drops all tables
- [ ] The `tasks.priority` column rejects values outside the defined enum
- [ ] Schema documentation is accurate and matches the implemented models

---

## Technical Constraints

**Format:** Python, SQLAlchemy 2.0, Alembic 1.13
**Technology:** PostgreSQL 15+
**Performance:** All indexed columns match the query patterns used by E1.1 and E1.2
**Compatibility:** Column names must match the Pydantic schemas defined in E1.1 and E1.2
