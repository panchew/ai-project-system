# Epic E2.1 — Login UI

## Context

Milestone M2 builds the React frontend for Taskflow. E2.1 is the first M2 Epic, implementing the authentication screens. Without a login page, users cannot access the application and other M2 Epics cannot test their authenticated flows.

E2.1 consumes the `POST /auth/login` and `POST /auth/register` endpoints delivered in M1-E1.1.

---

## Problem Statement

There is no way for a user to authenticate in a browser. The M1 API works but requires tools like `curl` or Postman. E2.1 bridges this gap by providing a polished, accessible login and registration experience.

---

## Goals

By the end of this Epic, the system must:

1. Display a login form (email + password) that calls `POST /auth/login` and stores the JWT
2. Display a registration form (email + password + confirm password) that calls `POST /auth/register`
3. Redirect authenticated users to the task dashboard after login
4. Display field-level validation errors inline (not in a toast or modal)
5. Pass accessibility checks (WCAG 2.1 AA) for all form elements

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Implement OAuth2 / social login
- Build a password reset flow
- Build the task dashboard (deferred to E2.2)
- Implement persistent sessions beyond JWT storage in memory/sessionStorage

---

## Scope of Work

### 1. Login Page Component

Implement `src/pages/LoginPage.tsx`:

**Must include:**
- Email and password fields with aria-labels
- Submit button with loading state during API call
- Inline error message for invalid credentials (401 response)
- Link to registration page

### 2. Registration Page Component

Implement `src/pages/RegisterPage.tsx`:

**Must include:**
- Email, password, and confirm-password fields
- Client-side validation: email format, password match, minimum 8 characters
- API call to `POST /auth/register` on submit
- Success redirect to login page with a confirmation message

### 3. Auth Context

Implement `src/context/AuthContext.tsx`:

**Must include:**
- React context storing current JWT and `user_id`
- `login(email, password)` and `logout()` functions
- `isAuthenticated` boolean derived from presence of valid JWT
- Used by all protected routes in E2.2 and E2.3

### 4. Component Tests

Write tests in `tests/pages/test_login_register.tsx`:

**Must include:**
- Form submission tests (mock API calls)
- Validation error display tests
- Redirect behavior tests (post-login, post-register)

Epic E2.1 is complete when:

- [ ] Login form calls `POST /auth/login` and stores the returned JWT
- [ ] Registration form calls `POST /auth/register` and redirects on success
- [ ] Field-level validation errors display inline for all validation failures
- [ ] `AuthContext` exported and usable by downstream Epics
- [ ] All component tests pass
- [ ] Epic Completion Notice produced and committed

---

## Acceptance Criteria

- [ ] A user can register and log in without reloading the page
- [ ] An incorrect password shows an error message on the login form, not a browser alert
- [ ] All form inputs have associated labels (accessible to screen readers)
- [ ] The login page renders correctly at 375px width (mobile viewport)

**Compatibility:** `AuthContext` API must be stable for E2.2 and E2.3 to consume
