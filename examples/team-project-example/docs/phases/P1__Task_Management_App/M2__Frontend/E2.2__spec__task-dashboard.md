# Epic E2.2 — Task Dashboard

## Context

With login working (E2.1) and the task API available (M1-E1.2), E2.2 delivers the main screen of the application: the task dashboard. This is where users spend the majority of their time in Taskflow.

---

## Problem Statement

There is no user-facing task management screen. Users with valid JWTs have no way to view, create, edit, or delete tasks in a browser. E2.2 is the highest-value deliverable in M2 — without it, the product has no usable interface.

---

## Goals

By the end of this Epic, the system must:

1. Display all tasks for the authenticated user in a paginated list
2. Allow creating a new task via an inline form or modal
3. Allow editing task title, description, priority, and due date inline
4. Allow deleting (archiving) a task with a confirmation prompt
5. Show task priority with visual differentiation (color-coded badge)
6. Update the task list in real-time after create/edit/delete without a full page reload

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Implement search or filtering (deferred to E2.3)
- Implement drag-and-drop task reordering
- Display tasks assigned to other users
- Build a Kanban board view

---

## Scope of Work

### 1. Task List Component

Implement `src/components/TaskList.tsx`:

**Must include:**
- Renders tasks from `GET /tasks` API response
- Paginator component (prev/next, current page indicator)
- Loading skeleton while API call is in flight
- Empty state when user has no tasks

### 2. Task Form Component

Implement `src/components/TaskForm.tsx`:

**Must include:**
- Title (required), description (optional), priority (dropdown), due date (date picker)
- Submit calls `POST /tasks` or `PUT /tasks/{id}` depending on context
- Inline validation errors for required fields

### 3. Task Card Component

Implement `src/components/TaskCard.tsx`:

**Must include:**
- Displays task title, priority badge (color-coded), due date (relative: "due in 3 days")
- Edit button opens `TaskForm` pre-filled with existing values
- Delete button shows confirmation dialog before archiving

### 4. Dashboard Page

Implement `src/pages/DashboardPage.tsx`:

**Must include:**
- Renders `TaskList` with "New Task" button at top
- Protected route — redirects to login if not authenticated
- Passes `AuthContext` JWT to all API calls

### 5. Component Tests

**Must include:**
- Task list renders correct number of items from mock API response
- Create task form submits correct payload
- Delete confirmation dialog prevents accidental deletion

## Definition of Done

Epic E2.2 is complete when:

- [ ] Dashboard page displays tasks from the API with pagination working
- [ ] Create, edit, and delete operations update the task list without page reload
- [ ] Priority badges are color-coded (urgent=red, high=orange, medium=yellow, low=grey)
- [ ] Protected route redirects to login when JWT is absent
- [ ] All component tests pass
- [ ] Epic Completion Notice produced and committed
- [ ] Pull request opened to `milestone/M2`

---

## Acceptance Criteria

- [ ] A user can create a task and see it appear in the list within 1 second
- [ ] Editing a task's priority updates the color badge immediately on save
- [ ] Attempting to delete a task shows a "Are you sure?" dialog
- [ ] The dashboard renders correctly with 100 tasks (no performance degradation)

---

## Technical Constraints

**Format:** React 18 (TypeScript), Tailwind CSS
**Technology:** Vite 5, React Query for server state management
**Performance:** Dashboard initial load ≤ 2 seconds (50 tasks, staging network)
**Compatibility:** Uses `AuthContext` from E2.1; uses task API schema from M1-E1.2

**External Dependencies:**
