# Epic E2.3 — Search and Filter

## Context

With the task dashboard available (E2.2), users can view and manage their tasks. However, as the number of tasks grows, finding specific tasks requires scrolling through pages. E2.3 adds search and filter capabilities directly in the frontend, using query parameters to the existing `GET /tasks` API.

---

## Problem Statement

Users with more than 20 tasks cannot efficiently find specific items. Scrolling through paginated pages is too slow for a task management tool. Without search and filter, power users will find Taskflow frustrating and may abandon it.

---

## Goals

By the end of this Epic, the system must:

1. Provide a search bar that filters tasks by title or description (client-side debounced query)
2. Provide a filter sidebar with controls for: status (open/closed), priority, due date range
3. Combine search and filter (both can be active simultaneously)
4. Persist the active search/filter state in the URL query string
5. Show a "No results" state when the combination returns zero tasks

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Implement full-text search at the database level (frontend filtering via API query params)
- Add server-side full-text index or dedicated search service
- Build saved filter presets or custom views

---

## Scope of Work

### 1. Search Bar Component

Implement `src/components/SearchBar.tsx`:

**Must include:**
- Text input with 300ms debounce
- Calls `GET /tasks?search=<term>` with debounced value
- Clear button that resets the search

### 2. Filter Sidebar Component

Implement `src/components/FilterSidebar.tsx`:

**Must include:**
- Status filter: All / Open / Closed (radio buttons)
- Priority filter: multi-select checkboxes (urgent, high, medium, low)
- Due date range: start date picker + end date picker
- "Clear All" button that resets all filter controls
- Calls `GET /tasks` with appropriate query params on change

### 3. URL State Management

Implement URL persistence in `src/hooks/useTaskFilters.ts`:

**Must include:**
- Reads initial filter state from URL query string on mount
- Updates URL on every filter or search change (no page reload)
- State is shareable: copying the URL reproduces the same filter view

### 4. Component Tests

**Must include:**
- Search bar triggers API call with debounced value
- Filter combination sends correct query params
- URL updates on filter change (history.pushState called with correct params)
- "No results" state displays when API returns empty array
