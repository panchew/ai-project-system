### Summary

Close carry-forward P7-GH-21: the `.ai-project.yml` schema's `visual_artifacts.types` value
`diagrams` is documented across four surfaces as producing "Mermaid/PlantUML structural" output,
but `bin/ai-project-visual`'s implementation makes every call — `diagrams` included —
unconditionally a ComfyUI generative call. Reconcile all four named surfaces to one coherent
naming/documentation scheme with no Structural/Generative collision.

### Binding constraints (carry into every decision — verbatim from the Milestone spec)

- **All four named surfaces MUST be touched and MUST agree** — `governance/ai-project-yml-spec.md`
  §3.5, `bin/ai-project-visual`'s docstring, this repo's `.ai-project.yml` comment,
  `VISUAL-ARTIFACTS.md`'s config example. A partial fix leaving one surface still wrong does not
  close P7-GH-21.
- **Do not touch `visual_artifacts.enabled`** — E29.2's surface, not yours.
- **Do not perform precision validation or generate any artifact** — E29.3's surface.
- **AOG §16.3 is already correct and is not an edit target** — reconcile other surfaces to match
  AOG, not the reverse.

### Design Decision (yours to resolve — decide, document, move; do not escalate to ask which
direction to take)

Choose between:
- **(A) Rename** the schema's generative `diagrams` value to something that cannot be read as
  Structural.
- **(B) Reframe** `types` as generative-only categories, documenting that Structural mode needs no
  `visual_artifacts` config at all — the value `diagrams` stays, but every surface makes
  unmistakably clear it names a ComfyUI-generative call.

**Read the Epic spec's "Additional grounding — blast-radius asymmetry" section before choosing.**
In short: Direction (B) is fully contained in the four named surfaces (zero code/test changes).
Direction (A) is a true rename whose real footprint also includes
`bin/ai-project-orchestrator`'s `VALID_VISUAL_ARTIFACT_TYPES` enum (line 28) and its own inline
assertions (lines 554-579), plus six hardcoded `"diagrams"` references in
`tests/integration/test_visual_artifacts_helper.py` and several in
`tests/test_visual_artifacts_config.py` (lines 45-70, 163-166) — none of which are in the
Milestone spec's named Deliverables list. If you choose (A), pull all of those surfaces into this
Epic's own scope and deliverables in the same commit set — do not land a rename only the
documentation surfaces know about.
