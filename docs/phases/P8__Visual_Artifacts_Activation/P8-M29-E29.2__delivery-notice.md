## Execution Summary

Endpoint reachability was re-verified live at execution time (`curl -m 5
http://localhost:8188/system_stats` returned valid JSON, ComfyUI 0.26.0) before flipping the
flag, per GH-2 discipline and the spec's explicit instruction not to rely on stale
phase/spec-time grounding.

`.ai-project.yml`'s `visual_artifacts.enabled` was flipped `false` → `true`, and the stale
opt-out comment (lines 29-40) was rewritten to state the current (enabled) reality — the
capability is on, Structural mode remains independent of it (AOG §16.3/§16.8), and
contributors without a reachable endpoint have an explicit opt-out.

Proving the real endpoint call surfaced two genuine bugs in `bin/ai-project-visual` that no
prior milestone had ever exercised, because `enabled` had always been `false`:

1. **Stale default checkpoint.** The helper's `--checkpoint` default
   (`v1-5-pruned-emaonly.safetensors`) does not exist on the live ComfyUI server (confirmed
   via `/object_info/CheckpointLoaderSimple`: only `DreamShaper_8_pruned.safetensors`,
   `Juggernaut-XL_v9_RunDiffusionPhoto_v2.safetensors`, `cyberrealisticPony_v125.safetensors`,
   and `ltx-video-2b-v0.9.5.safetensors` are installed). ComfyUI rejected the workflow
   submission with `HTTP 400: Bad Request`. Fixed by changing the default to
   `DreamShaper_8_pruned.safetensors`, a checkpoint actually present on the server.
2. **Full-graph-cache timeout on repeated identical calls.** The default sampler `--seed` was
   a fixed `0`. A second call with the same prompt, checkpoint, and seed produced a ComfyUI
   history entry with `status: success` but an **empty** `outputs` field, because every node
   in the graph — including `SaveImage` — was a full cache hit and ComfyUI does not
   re-populate `outputs` for nodes it didn't re-execute. `wait_for_outputs` polled `/history`
   for 180s, never saw a non-empty `outputs`, and raised `TimeoutError`. Confirmed by
   inspecting `/history/<prompt_id>` directly: `execution_cached` listed all seven nodes.
   Fixed by randomizing the default seed per invocation (`random.randint(0, 2**31 - 1)` when
   `--seed` is not explicitly passed); explicit `--seed` is still honored for reproducible
   generations. Verified stable across 3 consecutive real-endpoint test runs after the fix.

Both fixes are minimal, scoped to `bin/ai-project-visual`, and fall squarely within the
spec's named carve-out ("a real bug in the helper surfaces while proving the endpoint call" —
Technical Constraints; "timeout, model-name mismatch, checkpoint not found" are the spec's own
named examples of failures to root-cause, not route around).

**No-live-endpoint mechanism chosen:** an opt-out environment variable,
`AI_PROJECT_SKIP_LIVE_ENDPOINT_TESTS`. Unset (the default) still runs and requires the real
endpoint call — preserving the Hard Constraint for anyone who hasn't explicitly opted out.
Setting it to any value other than `""`/`"0"` skips only
`test_helper_generates_against_endpoint`; verified both branches directly (unset → runs and
passes; set to `1` → skipped, other 5 tests unaffected). Documented in the test module's
docstring and inline above the skip marker. This mirrors the existing precedent of
`models.epic_dev`/`epic_qa` already requiring local Ollama infrastructure — a documented
dev-environment requirement, not a silent default-skip.

`test_helper_generates_against_endpoint` now passes for real against the live endpoint (no
`xfail`, no re-skip, no re-disable). The five isolated-fixture tests
(`test_helper_exits_clearly_when_disabled`, `test_helper_rejects_unconfigured_type`, and the
three execution-lock guardrail tests) were run and confirmed green and unaffected — each
constructs its own isolated `.ai-project.yml` in `tmp_path`, independent of this repo's
config, as the spec's Grounding stated; this was confirmed by execution, not assumed.

**Structural-mode independence confirmed:** grepped for every file referencing
`visual_artifacts` (`bin/ai-project-visual`, `bin/ai-project-orchestrator`,
`governance/ai-project-yml-spec.md`); no code path outside `bin/ai-project-visual` reads
`visual_artifacts.enabled`, and Structural mode (Mermaid/PlantUML) never calls that helper.
AOG §16.3/§16.4/§16.8 gate Structural mode solely by tool-capability, never by this flag.
Flipping `enabled: true` has zero effect on Structural-mode availability — confirmed on the
record here per the spec's Deliverable 5.

One pre-existing test, `tests/test_ongoing_artifacts.py::TestVisualArtifactsRepoConfig`,
hard-asserted `visual_artifacts.enabled is False` — that assertion encoded exactly the
invariant this Epic exists to overturn (Goal 1: "This repo dogfoods its own default-on
flip"), and leaving it as-is would make the suite-green Hard Constraint structurally
impossible to satisfy alongside `enabled: true`. Renamed the test and flipped its assertion
to `is True`, with an updated comment; this is outside the spec's named two-file scope list
but is a direct, unavoidable consequence of the Epic's own stated goal, not a scope
expansion — flagged here rather than silently done.

## Notes

**No-live-endpoint mechanism and reasoning:** an environment-variable opt-out
(`AI_PROJECT_SKIP_LIVE_ENDPOINT_TESTS`) was chosen over a bare "document the endpoint as a
dev-environment requirement, no code change" approach because it gives a contributor an
explicit, auditable, single-test-scoped way to run the rest of the suite on a machine without
ComfyUI, without weakening the default (unset ⇒ endpoint required, matching the Hard
Constraint). Both candidate directions were compliant with the spec; this one is more
usable for a contributor who legitimately lacks the endpoint while keeping the default
strict.
