# Epic E29.2 — Enable + real endpoint test

## Context

M29's second epic. E29.1 (merged to `milestone/M29`, PR #128) closed the naming collision via
Direction (B) — reframing, not renaming `visual_artifacts.types` values. **No `--type` naming
changed**, so E29.2 inherits `diagrams`/`infographics`/`video` unchanged; nothing about this
Epic's test assertions needs adjusting on E29.1's account. E29.2 is the epic that finally flips
this repo's own `visual_artifacts.enabled` and proves the capability for real against the live
local ComfyUI endpoint — every prior milestone (P5-M22, P7-M27) preserved suite-green by leaving
`enabled: false`; this is the one that stops deferring that trade.

> **Provenance:** Authored by the Milestone Chat (P8-M29) on 2026-07-15 per GH-8 adjacency. The
> Coding Agent implements it. E29.3 depends on this Epic's completion (cannot generate before the
> capability is on and the endpoint call is proven).

> **Source:** M29 Milestone spec (Epic Detail → E29.2); P8 phase spec P8.1; SN-20 ratified
> decision 1 (P8 spine).

## Problem Statement

`.ai-project.yml:42` carries `enabled: false` with a comment (now updated by E29.1, but still
opting out) explaining exactly why: enabling un-skips
`test_helper_generates_against_endpoint`, which then fails with connection-refused because no
live endpoint was reachable when that comment was first written (P7/M27). That premise has since
changed — the endpoint is confirmed live and reachable, re-verified at this spec's own
authoring time — but the repo config and the test's skip-when-disabled behavior have not been
revisited since. Every prior milestone that touched this file chose suite-green-via-disabled over
proving the capability; M29 is explicitly the milestone that stops making that trade.

---

## Goals

By the end of this Epic:

1. **This repo dogfoods its own default-on flip.** `visual_artifacts.enabled: true` in
   `.ai-project.yml`, with the stale opt-out comment (lines 29-40) rewritten to reflect the new
   state.
2. **The suite is green with a real test, not a skip.**
   `test_helper_generates_against_endpoint` passes for real against
   `http://localhost:8188` — not re-disabled, not re-skipped to get there.
3. **A no-live-endpoint contributor path is decided and documented** — not left implicit.
4. **The three isolated-fixture test groups are confirmed unaffected** by the flip (they already
   are, per Grounding — confirm explicitly, don't just assume).
5. **Structural-mode (Mermaid/PlantUML) availability is confirmed unaffected** by the flip — it
   was never gated by `enabled` in the first place; record that confirmation rather than leaving
   it implicit, since this was raised as a standing concern for the milestone.

## Non-Goals

This Epic explicitly does **not**:

- **Touch the naming-collision surfaces** — E29.1's job, already merged.
- **Perform precision validation or generate any diagram/clip case for judgment** — E29.3's
  surface; this Epic proves the endpoint call succeeds and produces *a* non-empty artifact, not
  that the artifact is precise enough for technical explanation.
- **Touch `governance/ai-project-yml-spec.md` or AOG** — no schema or policy change; this is a
  repo-config + test change only. (No version bump expected — confirm no schema field, default,
  or validation rule changes; if execution surfaces one, escalate before bumping.)
- **Build a CI pipeline.** No `.github/workflows/` exists and none is created here — the
  no-live-endpoint decision (Goal 3) is scoped to "what happens when `pytest` runs without
  ComfyUI," not to designing CI infrastructure that doesn't exist in this repo.
- **Weaken or remove Structural mode's independence from `visual_artifacts.enabled`.** Flipping
  `enabled: true` must not be accompanied by any change that makes Structural-mode diagrams
  (Mermaid/PlantUML, AOG §17.3) depend on this flag, the ComfyUI endpoint, or `bin/ai-project-visual`
  in any way — they were, and must remain, entirely orthogonal.

## Scope of Work

### 1. `.ai-project.yml` flip

Set `visual_artifacts.enabled: true` (line 42). Rewrite the comment block (lines 29-40) — it
currently opens "This repo opts OUT" and closes with "kept to preserve the suite-green
requirement," both now false. Replace with a short comment stating the repo is enabled per
E29.2 (P8-M29), pointing to `governance/ai-project-yml-spec.md` §3.5 for the field contract and
to `VISUAL-ARTIFACTS.md` for the Structural/Generative split — do not restate that split at
length here; E29.1 already put it in the canonical places.

**Must include:**
- `enabled: false` → `enabled: true`
- Comment rewritten to state the current (enabled) reality, not the historical opt-out reasoning

### 2. Real endpoint test

Confirm `test_helper_generates_against_endpoint` passes for real once `enabled: true` un-skips
it — no code change to the test itself is expected (it already resolves `vtype` dynamically), but
run it and verify. If it fails against the live endpoint for any reason (timeout, model-name
mismatch, checkpoint not found), fix the actual cause — do **not** paper over failure by
re-skipping, re-disabling, marking `xfail`, or narrowing the assertion.

**Must include:**
- `test_helper_generates_against_endpoint` runs (not skipped) and passes for real
- If a real failure surfaces, root-cause and fix it (e.g., correct `--checkpoint` default,
  confirm model availability) rather than working around the assertion

### 3. No-live-endpoint contributor path (design decision — yours to resolve)

Decide and implement how a contributor/agent running `pytest` on a machine without ComfyUI
reachable at `http://localhost:8188` is handled. No CI workflow exists to special-case (Grounding
above) — this is purely "what happens locally without the endpoint." Candidate directions
(non-exhaustive, pick one and document why):

- An environment-variable-gated marker (e.g., `AI_PROJECT_SKIP_LIVE_ENDPOINT_TESTS=1` opts a
  contributor **out** explicitly — the default, unset, still runs and requires the endpoint,
  preserving this repo's own suite-green-with-real-call bar for anyone who hasn't opted out).
- Accept that this test requires a local ComfyUI endpoint as a documented dev-environment
  requirement (consistent with `models.epic_dev`/`epic_qa` already requiring local Ollama
  infrastructure per `.ai-project.yml`'s own `models` block) — document it in the test's
  docstring and/or a CONTRIBUTING-style note, no code change needed.
- Any other mechanism, provided it does not reintroduce an unconditional skip-by-default (the
  Hard Constraint forbids that outright).

**Must include:**
- A documented decision (Delivery Notice, and inline in the test module if the mechanism is
  code-level) with stated reasoning
- Whatever mechanism is chosen must default to **not** skipping — an opt-out a contributor must
  actively invoke, never an opt-in silently defaulting to skip

### 4. Guardrail-test confirmation

Run and confirm `test_helper_exits_clearly_when_disabled`, `test_helper_rejects_unconfigured_type`,
`test_helper_refused_when_execution_lock_live`, `test_helper_proceeds_when_execution_lock_stale`,
and `test_helper_proceeds_when_execution_lock_absent` remain green and unaffected — they
construct isolated `tmp_path` fixtures independent of this repo's config (confirmed in Grounding),
but confirm explicitly by running them, don't assume from reading the code alone.

**Must include:**
- All five tests confirmed passing, unaffected by the repo-level flip
- The confirmation recorded in the Delivery Notice (not silently skipped as "obviously fine")

### 5. Structural-mode independence confirmation

Record, in the Delivery Notice, an explicit confirmation that flipping
`visual_artifacts.enabled: true` has no effect on Structural-mode (Mermaid/PlantUML) availability
— it was never gated by this flag (AOG §17.3/§17.8), and this Epic does not change that. This was
raised as a standing concern for the milestone and should be confirmed on the record here, not
left to inference.

**Must include:**
- A one- or two-line confirmation in the Delivery Notice, citing AOG §17.3/§17.8

## Hard Constraint (binding — carried verbatim from the Milestone spec)

**The suite MUST be green at delivery with `test_helper_generates_against_endpoint` passing for
real against the live ComfyUI endpoint.** Re-disabling `visual_artifacts.enabled` or re-skipping
the test to keep the suite green is **not** an acceptable resolution under any circumstance —
this is the single most load-bearing rule in this milestone (every prior attempt at this repo's
own visual-artifacts capability preserved suite-green by leaving `enabled: false`; this Epic is
explicitly the one that stops deferring that trade). If the live endpoint becomes unreachable
during execution, escalate to the Phase Chat rather than routing around the constraint —
endpoint availability is the CFO's responsibility (AOG §17.5), not something this Epic resolves
by disabling the capability.
