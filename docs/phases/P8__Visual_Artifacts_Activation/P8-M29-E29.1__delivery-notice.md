# Epic Delivery Notice — E29.1

**Epic:** E29.1 — Naming-collision resolution (P7-GH-21)
**Status:** Execution Complete, Delivered for Review
**Delivery Date:** 2026-07-15

## Execution Summary

**Direction chosen: (B) Reframe.** The Epic spec's blast-radius grounding was decisive: Direction
(A) (rename the schema's generative `diagrams` value) is not containable within the four named
deliverable surfaces — its true footprint spans `bin/ai-project-orchestrator`'s
`VALID_VISUAL_ARTIFACT_TYPES` enum and inline assertions, plus the majority of
`tests/test_visual_artifacts_config.py` and `tests/integration/test_visual_artifacts_helper.py`,
none of which the Milestone spec's Deliverables list names. Adopting (A) would have meant either
expanding this Epic's scope beyond what was assigned or landing a half-finished rename for E29.2
to discover — exactly the "partial fix" the Milestone spec's Deliverable 1 forbids. Direction (B)
is fully contained in the four named surfaces with zero code or test changes, so it was chosen.

Direction (B) does not rename the schema value. It reframes `visual_artifacts.types` as
exclusively Generative (ComfyUI) categories and states explicitly that Structural mode (AOG
§16.3 — Mermaid/PlantUML diagrams written as text by the agent) needs no `visual_artifacts`
config at all, since it never calls `bin/ai-project-visual`. `diagrams` stays the schema value,
but every surface now describes it unambiguously as a ComfyUI txt2img call.

Changes made on each of the four named surfaces:

1. **`governance/ai-project-yml-spec.md`** — §3.5 field table's `types` row no longer says
   "Mermaid/PlantUML structural" for `diagrams`; the `types` Field Details block gained a
   clarifying note that all entries (including `diagrams`) are Generative and that Structural
   mode is a separate, config-free path; the Worked Example's inline comments were corrected.
   Version bumped `2.3.0` → `2.3.1` with a changelog row (documentation-only change; no field,
   default, or validation rule changed).
2. **`bin/ai-project-visual`** — module docstring gained an explicit statement that every
   `--type`, including `diagrams`, is a Generative/ComfyUI call with no Structural mode in this
   helper; the `Usage:` and `Configuration` examples got clarifying comments.
3. **`.ai-project.yml`** — the `visual_artifacts` comment (which previously narrated the
   collision at length and deferred the fix) was rewritten to state the resolution: all `types`
   entries are Generative, Structural needs no config, collision resolved in E29.1. The `enabled`
   flag itself (`false`) was left untouched, per the Milestone spec's constraint (E29.2's surface).
4. **`VISUAL-ARTIFACTS.md`** — the config example (prose above it was already correct and
   untouched) got an inline comment clarifying all `types` entries are Generative and Structural
   needs no config.

Direction A's expanded footprint (orchestrator enum, inline assertions, both test modules) was
**not** pulled in — it is inapplicable under Direction B, since no schema value changed.
