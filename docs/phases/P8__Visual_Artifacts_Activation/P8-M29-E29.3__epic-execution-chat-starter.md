### Binding constraints (carry into every decision — verbatim from the Milestone spec)

- **The diagram case should be Generative**, not Structural — the Milestone spec's own Visual
  Bindings Description already commits this deliverable to "a Generative diagram-style case...
  distinct from this planning-stage Structural flow diagram." A Structural diagram would
  trivially pass the precision bar by construction and produce no evidence toward the actual
  open question.
- **Never commit generated binaries** — by-link only, no exceptions.
- **The finding is evidence, not a decision** — SN-20 Carry-Over item 3 belongs to the CFO. State
  pass/partial/fail per case with justification; do not recommend a resolution.
- **Judge honestly** — a favorable-by-default judgment defeats this Epic's purpose as surely as
  E29.2 re-skipping its test would have defeated that one.
- **Do not edit the Milestone spec** — the Milestone-level "implemented" binding pairing belongs
  to the Milestone Chat's own Milestone Closure Declaration, not this Epic. Record your own
  bindings at `Level: Epic` in this Epic's spec/Delivery Notice.

### Design points (yours to resolve — decide, document, move; escalate only the hosting question
if it is genuinely blocking)

1. **Hosting mechanism** — **likely genuine escalation, not a resolve-and-proceed point.** No
   storage backend has ever actually been used by this project; every "adopter owns the storage
   backend" reference in its history is policy prose, not a real host. Check whether the Phase
   Chat / CFO already has a preferred or provisioned mechanism before assuming you must pick one
   yourself. If none exists and none is readily available, **escalate to the Phase Chat with the
   concrete choice needed** rather than defaulting to an arbitrary public third-party host on
   your own authority, and rather than substituting a committed/local path (which would violate
   by-link outright).
2. **Clip subject** — exactly one governance node's proposed→implemented arc (AOG §16.7
   single-parent). Candidates: M29 itself, E29.1 (naming collision: confused → reconciled), or
   E29.2 (disabled/never-run → enabled/proven). Resolve non-blocking; document the choice.
3. **Diagram subject** — a real governance/code flow from this project (e.g. M29's own epic
   sequence, or the visual-artifacts Structural/Generative split). Resolve non-blocking; document
   the choice.
