## Design Decisions Made During Execution

The following non-blocking design decisions were made during execution and are recorded here per the Question Policy.

### Decision 1: Added `guides/` subdirectory

**Context:** `docs/FAQ.md` and `docs/QUICK-START.md` are governance-portable but are informational guides, not system references or templates.

**Decision:** Added `guides/` subdirectory to house them. This keeps informational content separate from operational references (`systems/`) and fillable templates (`templates/`).

**Rationale:** Clean separation of concerns; consistent with the principle that `systems/` = "how it works" and `templates/` = "blank forms to fill." Guides = "how to get started."

### Decision 2: Added `diagrams/` subdirectory

**Context:** `docs/diagrams/` contains three Mermaid diagram files that document the governance system (authority hierarchy, epic lifecycle, repository structure). These are governance-portable.

**Decision:** Migrated as `governance/diagrams/` rather than absorbing into another subdirectory.

**Rationale:** Visual documentation is distinct from written documentation. A dedicated folder makes it easy for the M7 CLI and M8 HQ agent to locate and reference diagrams consistently.

### Decision 3: `docs/EPIC-EXECUTION-CHAT-STARTER.md` migrates to `/governance/` root

**Context:** This file uses ALL-CAPS naming matching the two canonical governance docs. It's a canonical format reference for how Epic Execution Chat Starters are structured. `docs/systems/` and `docs/templates/` both contain lowercase `epic-execution-chat-starter.md` files that cover the system reference and template aspects.

**Decision:** The ALL-CAPS version belongs at the `/governance/` root alongside the two canonical governance documents (Authority Level 3). The lowercase versions in `systems/` and `templates/` remain in their respective subdirectories.

**Rationale:** The ALL-CAPS naming convention is reserved for top-level canonical governance documents. Having it at the root is consistent and visually distinctive. The three files serve different roles: canonical reference (root), system reference (`systems/`), fillable template (`templates/`).

### Decision 4: `governance-source.md` moves to `governance/templates/`

**Context:** `docs/governance-source.md` is a template for external projects to declare their governance adoption. It's a governance file but is a fillable form.

**Decision:** Placed in `governance/templates/governance-source.md`.

**Rationale:** It is a template by nature — a blank form other projects fill out. `templates/` is the correct home.
