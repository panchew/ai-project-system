# Epic E6.2 — Move Governance Files to `/governance`

## Context

With the `/governance` folder structure defined in E6.1, this Epic executes the migration: physically moving governance files out of `docs/` and into `/governance`, updating all internal references, and incrementing the governance version to v2.0.0.

This is a **breaking change** to the repository structure. All internal cross-references must be updated.

---

## Problem Statement

Governance files (`PROJECT-SYSTEM-GUIDELINES.md`, `AI-OPERATING-GUIDELINES.md`, `docs/templates/`, `docs/systems/`) currently live inside `docs/` alongside project history artifacts. This makes it impossible to:

- Reference governance files independently via submodule
- Distinguish system rules from project artifacts
- Ship governance to adopting projects without shipping project history

---

## Goals

By the end of this Epic:

1. All governance files are in `/governance` per the E6.1 spec
2. `docs/` contains only project history (phases, context, roadmap, admin, diagrams)
3. All internal references to moved files are updated
4. `PROJECT-SYSTEM-GUIDELINES.md` and `AI-OPERATING-GUIDELINES.md` versions incremented to v2.0.0
5. `/governance/README.md` created
6. `docs/README.md` updated to reflect new structure

---

## Non-Goals

- Defining `.ai-project.yml` format (E6.3)
- Writing submodule setup guide (E6.4)
- Writing migration guide for external projects (E6.5)
- Creating the HQ agent file (M8)

---

## Scope of Work

### 1. Execute file migrations

Move the following to `/governance` per E6.1 structure:

**Root governance documents:**
- `docs/PROJECT-SYSTEM-GUIDELINES.md` → `/governance/PROJECT-SYSTEM-GUIDELINES.md`
- `docs/AI-OPERATING-GUIDELINES.md` → `/governance/AI-OPERATING-GUIDELINES.md`

**Templates:**
- All files under `docs/templates/` → `/governance/templates/`

**System references:**
- All files under `docs/systems/` → `/governance/systems/`

### 2. Create `/governance/agents/` placeholder

Create `/governance/agents/.gitkeep` as the future home for `hq.agent.md` (M8 deliverable).

### 3. Update all internal references

Audit and update every cross-reference in:
- Remaining `docs/` files that link to moved files
- The moved files themselves (internal cross-links)
- `README.md` at repository root
- `docs/README.md`

### 4. Increment governance versions to v2.0.0

In both `PROJECT-SYSTEM-GUIDELINES.md` and `AI-OPERATING-GUIDELINES.md`:
- Bump version to `2.0.0`
- Update effective date
- Add changelog entry noting the structural change

### 5. Create `/governance/README.md`

Based on the draft from E6.1: overview of the folder, its contents, authority hierarchy, and how external projects reference it.

### 6. Update `docs/README.md`

Reflect the new split: governance lives in `/governance`, project artifacts stay in `docs/`.
