# Onboarding Validation Test Plan — P2-M8-E8.4

## Objective
Validate onboarding of a legacy or ungoverned project into the current P2 governance with preservation of existing docs.

## Environment
- Platform: Linux (required), macOS/WSL2 (optional)
- Tools: `git`, `bash`, VS Code

## Test Inputs
- A representative legacy project folder (no `.ai-project.yml`, minimal or missing `governance/`)

## Procedure (Linux)
1. Prepare a sample legacy project (example):
   ```bash
   rm -rf /tmp/legacy-onboard && mkdir -p /tmp/legacy-onboard/docs && cd /tmp/legacy-onboard
   echo "# Legacy Project\n\nSome existing docs." > docs/README.md
   git init && git add . && git commit -m "legacy baseline" > /dev/null 2>&1
   ```
2. Run onboarding (proposed baseline procedure):
   - Create `.ai-project.yml` with governance source/version
   - Add governance submodule and initialize
   - Add `.github/agents/hq.agent.md` (from governance if present, else stub)
   - Ensure no existing docs are overwritten
   Example commands:
   ```bash
   cat > .ai-project.yml << 'YML'
project:
  name: legacy-onboard
  created_at: $(date -u +"%Y-%m-%dT%H:%M:%SZ")

governance:
  source: https://github.com/panchew/ai-project-system
  version: v2.0.0
  submodule_path: governance/
YML
   git submodule add --branch v2.0.0 https://github.com/panchew/ai-project-system governance || true
   git submodule update --init --recursive
   mkdir -p .github/agents
   if [ -f governance/agents/hq.agent.md ]; then cp governance/agents/hq.agent.md .github/agents/hq.agent.md; else
     printf "# HQ Chat Agent\n\nStub for onboarding.\n" > .github/agents/hq.agent.md; fi
   git add . && git commit -m "Onboard to AI Project System governance" || true
   ```
3. Verify:
   ```bash
   test -f .ai-project.yml && echo OK:.ai-project.yml
   test -d governance && echo OK:governance
   test -f .github/agents/hq.agent.md && echo OK:hq.agent.md
   test -f docs/README.md && echo OK:docs preserved
   git status --porcelain=v1
   ```

## Expected Results
- `.ai-project.yml` created with valid fields
- `governance/` submodule initialized at desired version
- `.github/agents/hq.agent.md` present and readable
- Existing docs retained with no destructive changes
- Repo remains usable in VS Code; HQ agent available

## Pass/Fail Criteria
- PASS if all expected artifacts present and docs preserved
- FAIL if onboarding overwrites or deletes legacy content, or leaves invalid state
