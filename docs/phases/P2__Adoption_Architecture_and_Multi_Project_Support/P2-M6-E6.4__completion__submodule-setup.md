## Design Decisions

The following non-blocking design decisions were made during execution:

1. **Validation used `milestone/M6` as pinned ref (not a tag):** No version tags exist on the repository yet (the `.ai-project.yml` references `ref: v2.0.0` but the tag was never created). The guide documents the tag-based workflow as the canonical production pattern, with a gotcha (Section 9) noting how to handle pre-tag development. Validation was run against `milestone/M6` branch as a functional equivalent.

2. **`git submodule update --init` without `--recursive` is sufficient:** The governance repo has no nested submodules. `--recursive` is included in all documented commands for forward-compatibility, as a future governance source repo could theoretically include submodules.

3. **Copy vs. symlink for VS Code agent file:** Both options are documented (Section 8). Copy is simpler; symlink keeps governance agent updates transparent. The guide does not prescribe one — the choice depends on the team's workflow.

4. **Section 14B (not a standalone section number):** The additive lettered-section pattern (8A, 11.5, 12A, 14A) is already established. Adding 14B maintains structural consistency and avoids renumbering sections 15-17.
