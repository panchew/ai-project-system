# Epic E6.5 — Migration Guide & Source Repo Validation

## Context

With governance separated, `.ai-project.yml` defined, and the submodule pattern documented, the final M6 epic ensures two things: existing P1 projects have a clear path to adopt P2 structure, and the `ai-project-system` source repository is itself fully valid and conformant with the new layout.

This epic closes the books on M6.

---

## Problem Statement

Without a migration guide:

- Existing projects using P1 structure (flat `docs/`, governance in `docs/`) have no path forward
- Adopters face a breaking change with no instructions
- The `ai-project-system` repo itself may have stale paths or references after E6.2

Without source repo validation:

- M6 completion cannot be declared — the reference implementation may be broken
- M7 cannot safely begin (CLI tool scaffolds based on the source repo structure)

---

## Goals

By the end of this Epic:

1. A migration guide exists that walks a P1 project through adopting P2 structure
2. The `ai-project-system` source repository is fully valid: no stale paths, no broken references, no governance files remaining in `docs/`
3. The repository conforms to the P2 architecture end-to-end
4. M6 exit criteria are confirmed met

---

## Non-Goals

- Migrating any external projects (M10)
- Building automated migration tooling (future phase)
- Writing the `ai-project init` CLI (M7)

---

## Scope of Work

### 1. Write the migration guide

Create `/governance/migration-p1-to-p2.md` covering:

**Pre-migration checklist:**
- All P1 epics/milestones closed
- Working tree clean

**Step-by-step migration:**
1. Add `.governance/` submodule pointing to `ai-project-system` at v2.0.0
2. Create `.ai-project.yml` at repo root
3. Update `docs/README.md` to reflect new structure (governance is in `.governance/`, project artifacts stay in `docs/`)
4. Remove local copies of governance files from `docs/` (now provided by submodule)
5. Update any internal references that pointed to `docs/PROJECT-SYSTEM-GUIDELINES.md` etc.
6. Commit and push

**Post-migration validation checklist:**
- `.ai-project.yml` exists and is valid
- `.governance/` submodule is initialized and pinned
- No governance files in `docs/`
- Internal links resolve correctly

### 2. Validate the `ai-project-system` source repo

Perform a full conformance check:

- [ ] `/governance/` folder exists with correct contents (per E6.1 spec)
- [ ] `docs/` contains only project history — no governance files
- [ ] All links in `docs/` that reference governance files now point to `/governance/` paths
- [ ] `.ai-project.yml` at repo root is valid per E6.3 spec
- [ ] `/governance/README.md` exists
- [ ] `/governance/agents/` directory exists
- [ ] `/governance/templates/` contains all templates
- [ ] `/governance/systems/` contains all system reference docs
- [ ] `PROJECT-SYSTEM-GUIDELINES.md` and `AI-OPERATING-GUIDELINES.md` both at v2.0.0
- [ ] Repository root `README.md` reflects new structure

### 3. Fix any issues found during validation

If any conformance issues are discovered during the validation step, fix them in this epic before declaring completion.

### 4. Confirm M6 exit criteria

Document in the delivery notice that all M6 exit criteria are met.
