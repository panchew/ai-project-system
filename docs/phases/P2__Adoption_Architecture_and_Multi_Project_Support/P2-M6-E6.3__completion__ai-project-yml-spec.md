## Design Decisions

The following non-blocking design decisions were made during execution:

1. **`governance.ref` field made required (not optional):** The epic spec's schema draft showed `ref` as a field but did not explicitly mark it required or optional. Made required because: the HQ agent needs a deterministic ref to fetch governance files; a missing ref would require fallback logic that is not yet specified. This is the most conservative and unambiguous choice for M7/M8.

2. **SSH URLs explicitly excluded from `governance.source`:** HTTPS URLs and local paths are permitted; SSH URLs (`git@...`) are excluded. Rationale: SSH auth in CI and HQ agent contexts is not defined yet. The CLI and HQ agent can trivially handle HTTPS; SSH support can be added in a future milestone without breaking the contract.

3. **`governance.version` must be quoted in YAML:** Documented as a constraint because unquoted semver (e.g., `2.0.0`) parses as a valid YAML string but `2.0` would parse as a float. Quoting ensures consistent parsing across YAML libraries.

4. **Unknown `overrides` keys ignored in M6/M7/M8:** Rather than failing on unknown keys, tooling should ignore them. This makes the stub override block forwards-compatible with M9 additions.
