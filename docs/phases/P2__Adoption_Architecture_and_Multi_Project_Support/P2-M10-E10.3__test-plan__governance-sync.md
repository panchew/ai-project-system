## Scenario 1: Patch Version Update (Happy Path)

**Type:** Happy Path  
**Description:** Simulate a patch governance update (2.0.0 → 2.0.1) by creating a minor change in the source, tagging it, then pulling it in the consumer project.

### Preconditions

1. Consumer project exists at `/tmp/governance-consumer` with governance submodule pinned to `v2.0.0`
2. Governance source has a `v2.0.0` tag
3. Consumer `.ai-project.yml` references `version: "2.0.0"` and `ref: v2.0.0`

### Steps

1. In governance source, create a patch change (update FAQ date), commit, and tag `v2.0.1`:
   ```bash
   cd /home/fguzman3/software/ai-project-system
   # Edit a governance file with a patch-level change
   git add -A
   git commit -m "chore: patch governance update for testing"
   git tag -a v2.0.1 HEAD -m "Governance v2.0.1 — patch update"
   ```

2. In consumer project, update submodule to `v2.0.1`:
   ```bash
   cd /tmp/governance-consumer/.governance
   git fetch
   git checkout v2.0.1
   cd ..
   ```

3. Update `.ai-project.yml` with new version:
   ```yaml
   governance:
     version: "2.0.1"
     ref: v2.0.1
   ```

4. Commit changes:
   ```bash
   git add .governance .ai-project.yml
   git commit -m "chore: update governance to v2.0.1"
   ```

### Expected Outcome

- Submodule checkout succeeds
- `.ai-project.yml` validates against schema
- Governance files are accessible at `.governance/governance/`
- HQ agent references resolve correctly

**Verdict:** ⬜ (Pass / Fail)

## Scenario 4: Edge Case — Merge Conflict in Submodule Pointer

**Type:** Edge Case  
**Description:** Local submodule pointer diverges from remote, causing a merge conflict during `git pull`.

### Preconditions

1. Consumer project has governance submodule at `v2.0.0`
2. Consumer has a local commit that advances the submodule to a different ref

### Steps

1. In consumer, simulate divergence by updating submodule to an intermediate state:
   ```bash
   cd /tmp/governance-consumer/.governance
   git checkout v2.0.0
   cd ..
   git add .governance
   git commit -m "chore: local submodule move (simulated divergence)"
   ```

2. From the consumer, attempt to update to `v2.0.1` using `git pull` from a hypothetical remote:
   - Since this consumer has no remote, simulate by applying the update as a conflicting commit:
   ```bash
   cd .governance
   git checkout v2.0.1
   cd ..
   git add .governance
   git commit -m "chore: simulated remote update to v2.0.1"
   ```

3. Resolve the conflict using documented procedure:
   ```bash
   # Accept incoming (remote) version of submodule pointer
   git checkout --theirs .governance
   git add .governance
   git commit -m "chore: resolve governance submodule conflict"
   ```

### Expected Outcome

- Conflict resolution succeeds
- Submodule pointer matches the intended target ref
- Consumer can proceed with normal workflow

**Verdict:** ⬜ (Pass / Fail)
