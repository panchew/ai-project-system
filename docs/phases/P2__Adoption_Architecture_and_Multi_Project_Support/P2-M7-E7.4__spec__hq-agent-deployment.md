# Epic E7.4 — Ship HQ Chat Agent Files & End-to-End Validation

> Governance approvals
> - Phase Chat acceptance: 2026-04-28
> - Milestone Chat delivery authorization: 2026-04-28 (see Authorization section)

## Context

E7.1–E7.3 have built the CLI scaffolding, governance integration, and configuration. This Epic completes the CLI by installing HQ Chat agent files into generated projects and performing end-to-end validation that the entire initialization pipeline works. A developer should be able to run `ai-project init my-project`, open the project in VS Code, and immediately use the HQ Chat agent for governance-driven planning.

---

## Problem Statement

E7.3 creates the project structure and governance submodule, but does NOT:
- Install HQ Chat agent files (`.github/agents/hq.agent.md`)
- Verify that developers can use the HQ agent immediately
- Perform end-to-end testing of the entire `ai-project init` pipeline
- Provide guidance on how to activate the HQ agent after initialization

Without agent file installation and end-to-end validation, the CLI is incomplete. The generated project will have structure and governance, but no executable agent to drive planning.

---

## Goals

By the end of this Epic:

1. HQ Chat agent files are copied from governance source to generated projects
2. Agent file is placed at `.github/agents/hq.agent.md` in the generated project
3. End-to-end test confirms: `ai-project init my-project` → open in VS Code → HQ agent is usable
4. CLI provides post-init guidance (next steps, how to use HQ agent)
5. Canonical "start a project" prompt is documented for HQ agent use
6. All four E7.1–E7.4 features work together seamlessly
7. CLI is production-ready and documented

---

## Non-Goals

- Building the full HQ agent implementation (M8 deliverable)
- Integrating HQ agent with `.ai-project.yml` overrides (M9 deliverable)
- Creating a web UI or interactive setup wizard
- Supporting agent versioning or updates

---

## Scope of Work

### 1. Copy HQ Agent File to Generated Project

Extend the `ai-project init` CLI to copy `hq.agent.md` from the governance source to the generated project:

```bash
# After governance submodule is initialized:
cp governance/agents/hq.agent.md .github/agents/hq.agent.md
```

Or, if the agent file doesn't exist yet (M8 in progress), create a stub:

```markdown
# HQ Chat Agent

This agent is under development in Milestone M8.

For now, use this as a placeholder for the governance-aware HQ Chat agent.

When M8 is complete, this file will be replaced with the full HQ agent implementation.
```

The agent file should be committed in the initial git commit.

### 2. Validate Agent File Placement

After copying the agent file, verify:

- File exists at `.github/agents/hq.agent.md`
- File is readable
- File is committed in git
- File contains valid agent markup (basic syntax check)

If validation fails, print a warning (not an error) and continue. This allows the CLI to work even if the agent file is unavailable.

### 3. Provide Post-Init Guidance

After successful initialization, the CLI should print next steps:

```
✓ Project created successfully!

Next steps:
  1. Navigate to the project:
     cd my-project

  2. View the initial git commit:
     git log

  3. Open in VS Code:
     code .

  4. Start planning with HQ Chat:
     - Open GitHub Copilot Chat in VS Code
     - Select the "hq" custom agent
     - Send this prompt:
       "I'm starting a new project using the AI Project System governance framework. Initialize HQ Chat and help me create a Phase 0 project formalization."

  5. Read more:
     - Project documentation: docs/README.md
     - Governance: governance/PROJECT-SYSTEM-GUIDELINES.md
     - AI System Guidelines: governance/AI-OPERATING-GUIDELINES.md
```

Document the canonical "start a project" prompt in both the CLI output and in M7 documentation.

### 4. Document Canonical "Start a Project" Prompt

Create a reference document that developers can use when opening HQ Chat for the first time:

**File:** `docs/systems/hq-startup-prompt.md`

**Content:**
```markdown
# HQ Chat Startup Prompt

When you first open the HQ Chat agent in your project, use this prompt to initialize governance-driven planning:

"I'm starting a new project using the AI Project System governance framework. 
Initialize HQ Chat for [project-name] and help me create a Phase 0 project formalization."

This prompt will:
1. Activate the HQ Chat role (governance mode)
2. Read .ai-project.yml for project configuration
3. Load governance rules from the submodule
4. Begin the Phase 0 planning process

The HQ Chat will then guide you through Phase 0 formalization, which includes:
- Project purpose and scope
- Initial Phase structure
- Milestone planning
- Chat hierarchy setup
```

Include this document in the generated project's `docs/` folder.

### 5. Perform End-to-End Validation

Create a comprehensive test that validates the entire `ai-project init` pipeline:

**Test Steps:**

1. Run `ai-project init test-project` from a clean directory
2. Verify folder structure: `docs/`, `.github/agents/`, `governance/`, etc.
3. Verify `.ai-project.yml` is valid YAML with correct governance reference
4. Verify `.gitmodules` file is correct
5. Verify `governance/` submodule is initialized and contains governance files
6. Verify `.github/agents/hq.agent.md` exists and is readable
7. Verify initial git commit contains all expected files
8. Verify `git status` shows a clean repo (all committed)
9. Simulate opening in VS Code: verify `.vscode/` extensions configuration (if needed)
10. Verify all startup guidance is printed and helpful

**Success Criteria:**
- All folders exist and are correct
- All files are committed
- Governance is accessible via submodule
- HQ agent file is present
- CLI output provides clear next steps
- No errors or warnings in the final state

### 6. Test on Multiple Platforms

Verify the CLI works on:

- **macOS:** 10.14+ (bash 4+)

Document any platform-specific issues or workarounds.
