# Epic E6.3 — Define `.ai-project.yml` Specification

## Context

`.ai-project.yml` is the project configuration contract introduced in Phase P2. Every project using the AI Project System declares its governance source and version in this file. It is the foundation for governance sync, the HQ agent's self-configuration, and the override system.

This Epic defines the format, required fields, optional fields, and validation rules — and writes a reference `.ai-project.yml` for the `ai-project-system` source repository itself.

---

## Problem Statement

Without `.ai-project.yml`:

- The HQ Chat agent (M8) has no way to discover where governance lives or what version is active
- The `ai-project init` CLI (M7) has no configuration contract to scaffold
- There is no way to declare project-specific overrides
- External projects have no standard way to pin a governance version

---

## Goals

By the end of this Epic:

1. `.ai-project.yml` format is fully specified in a governance doc
2. All required fields are defined with types, constraints, and examples
3. All optional override fields are defined with precedence rules
4. The spec is in `/governance` and cross-referenced from `PROJECT-SYSTEM-GUIDELINES.md`
5. A valid `.ai-project.yml` exists at the root of `ai-project-system` (self-referential)

---

## Non-Goals

- Implementing override resolution in the HQ agent (M8/M9)
- Writing the submodule setup guide (E6.4)
- Building validation tooling (future phase)

---

## Scope of Work

### 1. Design the `.ai-project.yml` schema

Minimum required fields:

```yaml
# .ai-project.yml
governance:
  source: https://github.com/panchew/ai-project-system  # or path for submodule
  version: "2.0.0"                                        # pinned governance version
  ref: main                                               # git ref (tag, branch, SHA)

project:
  name: my-project
  description: "Short project description"
```

Optional override fields (stub — full spec in M9):

```yaml
overrides:
  branch_strategy: gitflow       # default: trunk-based
  merge_strategy: squash         # default: merge
  epic_prefix: feature/          # default: epic/
```

### 2. Write the `.ai-project.yml` specification document

Create `/governance/ai-project-yml-spec.md` covering:
- Purpose and role of the file
- Required fields with types, constraints, and examples
- Optional fields (with note that full override spec is M9)
- How the HQ agent reads and uses it
- How `ai-project init` generates it
- Validation rules (what makes a file valid vs. invalid)
- How to update governance version (sync process)

### 3. Update `PROJECT-SYSTEM-GUIDELINES.md`

Add a section referencing `.ai-project.yml` as a required project artifact and linking to the spec document.

### 4. Write reference `.ai-project.yml` for `ai-project-system`

Create `.ai-project.yml` at the repository root declaring this repo as the governance source (self-referential), with version `2.0.0`.
