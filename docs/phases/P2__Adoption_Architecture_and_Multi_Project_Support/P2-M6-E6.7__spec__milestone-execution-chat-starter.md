# Epic E6.7 — Milestone Execution Chat Starter

## Context

With E6.6 delivering the Phase Execution Chat Starter, this Epic completes the middle rung of the hierarchy by defining the Milestone Execution Chat Starter. A Milestone Chat is launched by a Phase Chat (or HQ Chat) and is responsible for producing Epic specs and Epic Execution Chat Starters for all Epics within the Milestone.

The full hierarchy becomes:

```
HQ Chat
 └─ produces → Phase Execution Chat Starter
                └─ Phase Chat
                    └─ produces → Milestone Execution Chat Starter
                                   └─ Milestone Chat
                                       └─ produces → Epic Execution Chat Starter
                                                      └─ Coding Agent (executes)
```

---

## Problem Statement

Without a Milestone Execution Chat Starter:

- No standard way to launch a Milestone-scoped planning session
- Epic specs must always be written at the Phase Chat or HQ Chat level
- Context accumulates across the full chain instead of being scoped per Milestone
- The handoff from Phase planning to Epic execution has no defined artifact

---

## Goals

By the end of this Epic:

1. The role and responsibilities of a Milestone Chat are defined in a system document
2. A fillable Milestone Execution Chat Starter template exists in `/governance/templates/`
3. Both documents are cross-referenced in `PROJECT-SYSTEM-GUIDELINES.md`
4. The full chat hierarchy (HQ → Phase → Milestone → Epic → Coding Agent) is documented end-to-end

---

## Non-Goals

- Creating the Milestone Chat as a VS Code agent (P3)
- Implementing any runtime behavior
- Writing any specific milestone's Epic specs (those happen during execution)

---

## Scope of Work

### 1. Write `milestone-execution-chat-starter.md` system doc

Create `/governance/systems/milestone-execution-chat-starter.md` defining:

**Role of a Milestone Chat:**
- A Milestone Chat is a planning session scoped to a single Milestone
- It is launched from a Phase Chat (or HQ Chat) with the Milestone Execution Chat Starter
- It does NOT execute work — it plans and produces artifacts
- It has read access to the Milestone spec and all Epic stubs within the Milestone

**Responsibilities:**
- Review the Milestone spec and confirm it is complete
- Produce Epic specs for all Epics in the Milestone
- Produce an Epic Execution Chat Starter for each Epic
- Hand off Epic Execution Chat Starters to the Coding Agent (or Phase Chat)

**What it is NOT:**
- A coding agent
- A place where branches are created or files are modified directly
- A substitute for Phase Chat or HQ Chat authority

**Governance authority chain:**
1. PROJECT-SYSTEM-GUIDELINES.md
2. AI-OPERATING-GUIDELINES.md
3. Milestone Execution Chat Starter (this document type)
4. Milestone Spec
5. Decisions made during the session

### 2. Write the Milestone Execution Chat Starter template

Create `/governance/templates/milestone-execution-chat-starter.md` — a fillable template modeled on the Phase Execution Chat Starter:

**Required fields:**
- Project name and repository
- Phase number and name
- Milestone number and name
- Milestone spec path
- Governance document versions
- Current Epic stubs (list)
- Session objective (what this Milestone Chat must produce)

**Sections:**
- Governance References
- Milestone Context
- Spec Existence Requirement
- Output Requirements (Epic specs + Epic Execution Chat Starters)
- Execution Instructions
- Completion Requirements
- Question Policy

### 3. Update `PROJECT-SYSTEM-GUIDELINES.md`

Add a reference to the Milestone Execution Chat Starter alongside the Phase Execution Chat Starter reference added in E6.6.

### 4. Document the full hierarchy end-to-end

In `PROJECT-SYSTEM-GUIDELINES.md` (or a new `governance/systems/chat-hierarchy.md`), include a single diagram or summary of the full chain:

```
HQ Chat → Phase Chat → Milestone Chat → Coding Agent
```

With each transition clearly named (Phase Execution Chat Starter, Milestone Execution Chat Starter, Epic Execution Chat Starter) and their artifact responsibilities listed.
