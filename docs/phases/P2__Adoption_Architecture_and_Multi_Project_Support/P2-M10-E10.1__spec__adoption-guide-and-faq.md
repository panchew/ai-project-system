# Epic E10.1 — Adoption Guide & FAQ

## Context

Phases P2 M6–M9 delivered the complete governance infrastructure: externalized governance files, `.ai-project.yml` specification, CLI initialization, the HQ agent, and the override system. The architecture is now feature-complete from a governance perspective.

However, no step-by-step documentation exists that walks a developer from zero to an active HQ Chat session. New adopters must reverse-engineer the process from scattered spec files, creating high onboarding friction. Similarly, common issues have no single troubleshooting reference — users must search through multiple documents or ask for help.

This Epic produces the two documentation artifacts that close the adoption gap: a structured adoption guide and a comprehensive troubleshooting FAQ.

---

## Problem Statement

Without an adoption guide and FAQ:

- A new developer unfamiliar with the system must spend 60+ minutes figuring out the setup sequence by reading disparate spec files
- The "under 30 minutes" adoption requirement (Milestone acceptance criterion) cannot be met
- Common issues (submodule misconfiguration, init failures, HQ agent not appearing) have no documented resolutions, forcing reliance on human support
- The Phase P2 exit criteria for "usable adoption documentation" remains unsatisfied
- There is no single source of truth for the complete adoption path

---

## Goals

By the end of this Epic:

1. A step-by-step adoption guide exists that walks a developer from zero to HQ Chat live in under 30 minutes
2. A troubleshooting FAQ covers at least 8 common issues with clear resolution steps
3. Both documents are published in the governance documentation structure
4. A developer unfamiliar with the system can independently complete adoption using only the guide

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Modify or extend the CLI tooling (M7 scope)
- Modify governance documents or specs
- Create automation or tooling for the adoption process
- Onboard real projects (E10.2 scope)
- Validate governance sync (E10.3 scope)
- Produce the Phase P2 completion report (E10.4 scope)

## Scope of Work

### 1. Create Adoption Guide

Create `governance/guides/ADOPTION-GUIDE.md` — a structured, step-by-step guide following the structure defined in the Milestone spec.

**Must include:**

| Section | Content |
|---------|---------|
| Prerequisites | git, GitHub account, VS Code, GitHub Copilot, `ai-project` CLI installed |
| Step 1 | `ai-project init my-project` — run the CLI to scaffold a new project |
| Step 2 | Verify governance submodule is correctly initialized and on the correct version |
| Step 3 | Open VS Code, configure the HQ agent in `.cursorrules` or `.github/copilot-instructions.md` |
| Step 4 | Send the canonical startup prompt to the HQ agent |
| Step 5 | Create a Phase 0 spec for the new project |
| Step 6 | Plan the first milestone using the HQ agent |

Each step must include:
- Exact commands to run (with expected output)
- Verification check (how to know the step succeeded)
- Troubleshooting callout (short inline tip for common pitfalls)
- Screenshot placeholder markers (labeled `[SCREENSHOT: description]` for future capture)

The guide must also include:
- A **time-budget callout** at the top estimating 25–30 minutes total
- An **overview flowchart** (ASCII or Mermaid diagram) showing the adoption sequence
- A **what's next** section pointing to FAQ and governance documents

### 2. Create Troubleshooting FAQ

Create `governance/guides/ADOPTION-FAQ.md` — a troubleshooting FAQ covering the following areas (minimum 8 topics):

| # | Topic Area | Typical Symptoms |
|---|-----------|------------------|
| 1 | Governance submodule issues | Submodule not found, wrong version, detached HEAD |
| 2 | `.ai-project.yml` validation errors | Invalid YAML, unknown keys, missing required fields |
| 3 | HQ agent not appearing in VS Code | No agent selector, wrong model selected |
| 4 | Branch naming conflicts | Wrong prefix, epic/milestone/phase confusion |
| 5 | Override configuration problems | Override not taking effect, validation errors |
| 6 | Governance sync/update failures | `git submodule update` fails, merge conflicts |
| 7 | CLI init failures | Permission errors, missing dependencies, network issues |
| 8 | General governance questions | Architecture questions, authority hierarchy, process flow |

Each FAQ entry must include:
- **Problem**: Clear symptom description
- **Cause**: Likely root cause(s)
- **Solution**: Step-by-step resolution (numbered steps, exact commands)
- **Prevention**: How to avoid the issue in the future
- **See also**: Links to relevant documentation sections

### 3. Publish and Link from Governance

- Ensure both guides are linked from `governance/PROJECT-SYSTEM-GUIDELINES.md` (add a "Getting Started" section reference if one does not exist)
- Add a reference in the repository `README.md` if appropriate
- Ensure the guide directory `governance/guides/` exists with a `README.md` index
