# New Project Validation Test Plan — P2-M8-E8.4

## Objective
Validate `ai-project init` on a fresh project and confirm the HQ agent is immediately usable with the canonical startup prompt.

## Environment
- Platform: Linux (required), macOS/WSL2 (optional)
- Tools: `git`, `bash`, VS Code with GitHub Copilot Chat

## Preconditions
- Internet access for governance submodule (unless using `--skip-submodule` for dry runs)
- Writable temp directory (e.g., `/tmp`)

## Procedure (Linux)
1. Create project:
   ```bash
   ./bin/ai-project-init e84-new --dir /tmp --governance-version milestone/M8
   cd /tmp/e84-new
   ```
2. Verify structure and files:
   ```bash
   ls -la
   test -f .ai-project.yml && echo OK:.ai-project.yml
   test -d governance && echo OK:governance
   test -f .github/agents/hq.agent.md && echo OK:hq.agent.md
   ```
3. Verify submodule and YAML:
   ```bash
   git submodule status
   sed -n '1,80p' .ai-project.yml
   ```
4. Verify git state:
   ```bash
   git status --porcelain=v1
   git log --oneline -n 1
   ```
5. Open in VS Code and start HQ planning:
   - Open folder in VS Code
   - In Copilot Chat, select the `hq` agent
   - Send canonical prompt from `docs/systems/hq-startup-prompt.md`

## Expected Results
- `.ai-project.yml` is syntactically valid with governance `source` and `version`
- `governance/` submodule is initialized at requested ref (e.g., `milestone/M8`)
- `.github/agents/hq.agent.md` exists and is readable (governance copy or stub)
- Initial commit present; `git status` clean
- HQ agent responds with governance-aware planning guidance

## Evidence to Capture
- Command outputs for structure, submodule status, YAML, git status/log
- Screenshot or transcript snippet of HQ agent responding to canonical prompt

## Pass/Fail Criteria
- PASS if all expected results are met without critical errors
- FAIL if governance is not initialized, agent file missing/unreadable, or HQ prompt unusable
