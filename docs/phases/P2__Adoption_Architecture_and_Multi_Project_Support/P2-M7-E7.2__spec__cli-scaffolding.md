# Epic E7.2 — Implement `ai-project init` Command (Scaffolding)

## Context

E7.1 has locked the CLI architecture design. This Epic implements the `ai-project init` command that scaffolds a P2-conformant project with the correct folder structure, git initialization, and configuration file. The implementation will be tested end-to-end by running the CLI and verifying all outputs.

---

## Problem Statement

The design (E7.1) is complete, but the CLI command does not exist. Developers currently cannot run `ai-project init my-project` to scaffold a new project. E7.2 builds this command and verifies it produces the correct output structure.

---

## Goals

By the end of this Epic:

1. The `ai-project init` command is implemented and executable
2. The command accepts the documented flags, options, and arguments from E7.1
3. Running the command creates all required folders (docs/, .github/agents/, etc.)
4. The CLI initializes a git repository
5. Project name validation works correctly (rejects invalid names, suggests corrections)
6. Error handling works for documented error cases (directory exists, git missing, invalid input)
7. User feedback is clear and matches the spec from E7.1
8. The implementation is tested end-to-end on a clean directory
9. The command is deployed to the repository (in `/bin/` or equivalent) and is usable

---

## Non-Goals

- Creating the governance submodule integration (E7.3)
- Installing HQ agent files in the generated project (E7.4)
- Building a published npm package
- Supporting monorepo projects
- Creating a GUI or web interface

---

## Scope of Work

### 1. Implement the Core CLI Command

Create an executable script (bash or Node.js) named `ai-project` or placed in a location like `/bin/ai-project-init` that:

- Accepts the command signature: `ai-project init <project-name> [options]`
- Parses all documented flags: `--dir`, `--governance-source`, `--governance-version`, `--skip-git`, `--skip-submodule`, `--help`, `--version`
- Validates the project name (no special characters, not reserved)
- Checks if the target directory is empty (or will be created)
- Exits with appropriate error codes (0 for success, non-zero for failure)

### 2. Implement Folder Structure Creation

The command must create this folder hierarchy:

```
<project-name>/
├── docs/
│   ├── README.md                    (Project documentation home)
│   ├── phases/                      (Phase artifacts folder)
│   ├── context/
│   │   └── project-tracker.md       (Baseline context stub)
│   ├── roadmap/
│   │   └── overview.md              (Empty roadmap stub)
│   ├── decisions/                   (ADR folder - empty)
│   ├── _legacy/                     (Historical artifacts - empty)
│   └── admin/                       (Admin notes - empty)
├── .github/
│   └── agents/                      (Chat agents folder)
├── .gitignore                       (Standard project ignores)
├── README.md                        (Project root readme stub)
└── [other files created in E7.3/E7.4]
```

Create appropriate stub content for markdown files (templates, headings, guidance).

### 3. Implement Git Repository Initialization

When `--skip-git` is NOT set (default), the command must:

- Initialize a git repository: `git init`
- Stage all created files: `git add .`
- Create an initial commit with message like `Initial project scaffold by ai-project init`
- (Note: Do NOT push to remote—that's out of scope)

If `--skip-git` is set, skip all git operations.

### 4. Implement Error Handling

Handle all documented error cases:

| Error Case | Example | Response |
|-----------|---------|----------|
| Invalid project name | `my project` (space), `my@project` (special char) | Error message + suggestion: "Use lowercase letters, dashes, numbers: my-project" |
| Directory already exists | Target path has files | Error: "Directory exists. Use `--dir` to specify different location." |
| Git not installed | `git --version` fails | Error: "git not found. Please install git 2.20+." |
| Invalid flag | `--invalid-flag` | Error: "Unknown option: --invalid-flag. Use `--help` for available options." |
| Network error (will be relevant in E7.3) | Governance submodule fetch fails | Error: "Network error fetching governance. Check internet connection." |

### 5. Implement User Feedback

Print clear status messages as the command runs:

```
✓ Validating project name: my-project
✓ Creating folder structure
✓ Initializing git repository
✓ Creating .ai-project.yml
✓ Project created successfully!

Next steps:
  cd my-project
  git log           # View initial commit
  cat README.md     # See project overview
```

On error:

```
✗ Error: Directory already exists at /path/to/my-project

Use --dir to specify a different location:
  ai-project init my-project --dir /path/to/other/location
```

### 6. Implement `.ai-project.yml` Creation

When the command runs, it must write `.ai-project.yml` to the project root:

```yaml
project:
  name: <project-name>
  created_at: <ISO-8601-timestamp>

governance:
  source: <governance-url>  # e.g., https://github.com/panchew/ai-project-system
  version: <governance-tag>  # e.g., v2.0.0
  submodule_path: governance/
```

Validate that the YAML is syntactically correct before writing.

### 7. Implementation Language Choice

**Decision:** Use **bash** for the initial implementation (simpler, no Node.js dependency, runs everywhere). If bash becomes too complex, document why and switch to Node.js in a later phase.

Requirements for bash implementation:
- Bash 4+ (macOS 10.14+ has bash 3.2, so need to handle or document requirement)
- No external dependencies except standard Unix tools (mkdir, touch, git, etc.)
- Portable across macOS, Linux, Windows WSL2

**If Node.js is chosen instead:**
- Node.js 14+
- Minimal dependencies (prefer no npm packages if possible)
- Distribute as executable script or shell wrapper

### 8. Testing & Verification

The implementation must pass these tests (run manually or script-based):

**Test 1: Happy Path**
```bash
$ ai-project init test-project
$ ls -la test-project/
# Verify all folders exist: docs/, .github/agents/, .gitignore, README.md, .ai-project.yml
# Verify git repo is initialized: cd test-project && git log
# Verify .ai-project.yml is valid YAML
```

**Test 2: Invalid Project Name**
```bash
$ ai-project init "invalid name"  # Space in name
# Expect error message + suggestion
```

**Test 3: Directory Already Exists**
```bash
$ mkdir my-project
$ ai-project init my-project
# Expect error: directory already exists
```

**Test 4: Help and Version**
```bash
$ ai-project init --help   # Show all options
$ ai-project init --version  # Show CLI version
```

**Test 5: Skip Git**
```bash
$ ai-project init test-project --skip-git
$ cd test-project
$ git status
# Expect: not a git repository
```

### 9. Deployment

The CLI must be placed in a location where it can be executed:

- Option A: `/bin/ai-project` (requires adding to PATH, documented in M10)
- Option B: `/bin/ai-project-init` (explicit name)
- Option C: Shell wrapper in repository root (simpler for development)

Document how to install the CLI so developers can use it.

### 10. Documentation

Create inline help for the command:

```bash
$ ai-project init --help

Usage: ai-project init <project-name> [options]

Create a new AI Project System project with governance and agent files pre-installed.

Arguments:
  project-name              Name of the project (lowercase, dashes, numbers only)

Options:
  --dir <path>              Directory where project will be created (default: current directory)
  --governance-source <url> Git repository URL for governance (default: https://github.com/panchew/ai-project-system)
  --governance-version <tag> Git tag/branch for governance (default: v2.0.0)
  --skip-git                Initialize directory without creating git repository
  --help                    Show this help text
  --version                 Show CLI version

Examples:
  ai-project init my-new-project
  ai-project init my-project --dir ~/projects
  ai-project init my-project --governance-source https://github.com/myorg/governance --governance-version v1.0.0

For more information, see: https://github.com/panchew/ai-project-system/docs/systems/cli-guide.md
```

## Execution Notes

**For the Coding Agent:**

1. **Start with E7.1 Design:** Read [P2-M7-E7.1__spec__cli-architecture.md](https://github.com/panchew/ai-project-system/blob/master/docs/phases/P2__Adoption_Architecture_and_Multi_Project_Support/P2-M7-E7.1__spec__cli-architecture.md) to understand the locked interface. Do NOT deviate from the design.

2. **Implementation Approach:**
   - Choose bash for simplicity (preferred) or Node.js if bash becomes unwieldy
   - Start with the happy path: project name validation → folder creation → `.ai-project.yml` → git init
   - Add error handling incrementally
   - Test after each major component

3. **Bash Recommendation:**
   - Use `bash -u` to catch undefined variables
   - Use `set -e` to exit on errors (or check exit codes)
   - Use clear variable names and comments
   - Test on macOS, Linux, and WSL2 if possible

4. **Node.js Alternative:**
   - Use `fs` and `child_process` modules
   - Minimize external npm dependencies
   - Create executable with shebang: `#!/usr/bin/env node`

5. **Testing Protocol:**
   - Create a temporary test directory
   - Run the CLI on a clean slate
   - Verify all folders and files exist
   - Check `.ai-project.yml` is valid YAML
   - Verify git history shows initial commit
   - Test error cases (invalid name, existing directory, etc.)

6. **Deployment:**
   - Place executable in `/bin/ai-project-init` or `/bin/ai-project`
   - Ensure executable permission: `chmod +x /bin/ai-project-init`
   - Document installation path in the Epic Completion Report

7. **Edge Cases to Handle:**
   - Project name with spaces: `my project` → error
   - Project name with special chars: `my@project` → error
   - Reserved names: `test`, `lib`, `node_modules` (possibly) → error
   - Existing directory: should fail gracefully
   - Missing git: should fail with clear message
   - Permission denied on target directory: should fail with clear message
