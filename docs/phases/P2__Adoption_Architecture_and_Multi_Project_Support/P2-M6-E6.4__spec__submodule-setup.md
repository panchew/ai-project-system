# Epic E6.4 — Document Git Submodule Setup

## Context

External projects reference the governance package via git submodule. This allows them to pin a governance version, receive updates on their own schedule, and maintain a clean boundary between their project artifacts and system rules.

This Epic documents the canonical submodule setup process and validates it works against the restructured `ai-project-system` source repo.

---

## Problem Statement

Without documented submodule setup:

- External projects don't know how to reference governance
- No canonical guidance on version pinning or update process
- `ai-project init` CLI (M7) cannot automate the step
- `.ai-project.yml` `governance.source` field has no documented corresponding setup procedure

---

## Goals

By the end of this Epic:

1. The canonical git submodule setup procedure is documented in `/governance`
2. Version pinning and update workflow are documented
3. The procedure is validated by adding `ai-project-system` as a submodule of itself (test case) or against a test external repository
4. `PROJECT-SYSTEM-GUIDELINES.md` references the submodule guide
5. The guide is ready to be consumed by the `ai-project init` CLI (M7)

---

## Non-Goals

- Building the CLI tool that automates this (M7)
- Writing the full adoption guide (E6.5)
- Supporting non-git reference mechanisms (HTTP download, npm package)

## Scope of Work

### 1. Write the submodule setup guide

Create `/governance/submodule-setup.md` covering:

**Initial setup (new project):**
```bash
# Add governance as submodule
git submodule add https://github.com/panchew/ai-project-system .governance
git submodule update --init --recursive

# Pin to a specific version
cd .governance && git checkout v2.0.0 && cd ..
git add .governance && git commit -m "chore: Pin governance to v2.0.0"
```

**Updating governance version:**
```bash
cd .governance
git fetch && git checkout v2.1.0
cd ..
git add .governance
git commit -m "chore: Update governance to v2.1.0"
```

**Team setup (clone with submodules):**
```bash
git clone --recurse-submodules <repo-url>
# or for existing clones:
git submodule update --init --recursive
```

**Referencing governance files:**
- Paths from project root: `.governance/PROJECT-SYSTEM-GUIDELINES.md`
- VS Code agent files: copy or symlink `.governance/agents/hq.agent.md` → `.github/agents/hq.agent.md`

### 2. Document the submodule folder convention

Define that governance submodules are conventionally installed at `.governance/` (hidden folder, signals "system dependency not project content").

### 3. Document the `.ai-project.yml` connection

Show how `governance.source` and `governance.version` in `.ai-project.yml` correspond to the submodule remote and pinned ref.

### 4. Validate the procedure

Test the documented steps against the `ai-project-system` repository to confirm they work correctly. Document any edge cases or gotchas discovered.

### 5. Cross-reference in `PROJECT-SYSTEM-GUIDELINES.md`

Add a reference to the submodule guide in the governance document.
