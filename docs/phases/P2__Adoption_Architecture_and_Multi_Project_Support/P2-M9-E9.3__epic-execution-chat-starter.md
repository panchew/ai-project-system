## Epic Specification

**Full spec:** [P2-M9-E9.3__spec__hq-agent-override-support.md](https://github.com/panchew/ai-project-system/blob/master/docs/phases/P2__Adoption_Architecture_and_Multi_Project_Support/P2-M9-E9.3__spec__hq-agent-override-support.md)

**Commit:** `<commit-hash>`

### Summary

Update `governance/agents/hq.agent.md` to read, validate, cache, and apply `.ai-project.yml` overrides during artifact generation, replacing E9.2 TODO placeholders with concrete implementation guidance.

### Problem Statement

The HQ agent reads `.ai-project.yml` for governance metadata but ignores the `overrides` block. All artifacts are generated with hardcoded defaults. A project that sets `overrides.epic_prefix: "feature/"` still sees `epic/` in generated artifacts. The override system is documented but non-functional.

### Goals

1. HQ agent reads and validates overrides on startup
2. Resolved override values cached in session context
3. Generated artifacts use overridden values
4. E9.2 TODO placeholders replaced with concrete implementation
5. Validation errors/warnings reported during startup

## Reference Materials

### Implementation Guidance

The HQ agent is a **documentation-based custom agent** — not executable code. "Implementation" means writing clear, actionable instructions in the agent definition file.

**Override validation rules to encode:**
- `epic_prefix` — must end with `/`, non-empty. Default: `epic/`
- `merge_strategy` — must be one of `merge`, `squash`, `rebase`. Default: `merge`
- `branch_strategy` — must be one of `trunk-based`, `gitflow`. Default: `trunk-based`

**Override resolution pseudocode to document:**
```
For each override field:
  If present and valid in .ai-project.yml → use the value
  If absent → use governance default
  If present but invalid → raise error, block startup
Cache resolved values in session.overrides
Report validation results to user
```
