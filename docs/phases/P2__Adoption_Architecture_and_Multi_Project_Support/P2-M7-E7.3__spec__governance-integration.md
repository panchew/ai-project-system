# Epic E7.3 — Integrate Governance Submodule & `.ai-project.yml` Creation

> Governance approvals
> - Phase Chat acceptance: 2026-04-28
> - Milestone Chat delivery authorization: 2026-04-28 (see Authorization section)

## Context

E7.2 has implemented the basic `ai-project init` scaffolding. This Epic extends the CLI to integrate governance as a git submodule and ensure `.ai-project.yml` is created with correct values. The generated project will have governance pinned at a specific version and accessible via submodule.

---

## Problem Statement

E7.2 creates the project structure and `.ai-project.yml` stub, but does not:
- Add governance as a git submodule
- Validate the `.ai-project.yml` file
- Test that the governance submodule is correctly initialized
- Verify that the generated project can reference governance via submodule

Without submodule integration, generated projects cannot access governance files, and the core benefit of the CLI (one-command initialization with governance ready) is incomplete.

---

## Goals

By the end of this Epic:

1. The `ai-project init` CLI adds governance as a git submodule in the generated project
2. The `.ai-project.yml` file is validated before being written
3. The governance version can be customized via `--governance-version` flag
4. The governance source can be customized via `--governance-source` flag
5. Running `git submodule update --init` in the generated project fetches governance
6. The generated project's `.ai-project.yml` correctly references the governance version used
7. End-to-end test confirms: generated project → governance submodule is initialized → files are accessible

---

## Non-Goals

- Building a full governance sync/update mechanism (future phase)
- Supporting non-git governance sources
- Monorepo governance patterns
- Automatic governance updates (versioning is manual)

---

## Scope of Work

### 1. Extend CLI to Add Governance Submodule

Modify the `ai-project init` command to (when `--skip-submodule` is NOT set):

- After project structure is created, run: `git submodule add <governance-source> governance/`
- Pin to the specified tag/version: `git submodule set-branch --branch <governance-version> governance`
- Or use: `git submodule add --branch <governance-version> <governance-source> governance/`
- Update `.gitmodules` to be correct and committed in the initial commit

The `.gitmodules` file should look like:
```ini
[submodule "governance"]
    path = governance
    url = https://github.com/panchew/ai-project-system
    branch = v2.0.0
```

### 2. Validate `.ai-project.yml` Before Writing

Before writing `.ai-project.yml` to disk, validate:

- **Project name:** matches the pattern (lowercase, dashes, numbers, no spaces or special chars)
- **Created timestamp:** is valid ISO-8601 format
- **Governance source:** is a valid URL
- **Governance version:** is a git tag or branch name (basic validation: alphanumeric, dashes, dots)
- **YAML syntax:** the file is valid YAML before writing

If validation fails, print an error and exit with code 1.

### 3. Handle `--skip-submodule` Flag

If `--skip-submodule` is set:

- Do NOT add governance submodule
- Still create `.ai-project.yml` with governance reference (so E7.4 can use it)
- Document that the submodule must be added manually
- This allows testing E7.2 without requiring submodule functionality

### 4. Verify Submodule Initialization

After adding the submodule:

- Run: `git submodule update --init --recursive` to fetch the submodule
- Verify that files are present in the `governance/` folder
- Confirm that governance files are readable
- Exit with error if submodule initialization fails

**Error handling:** If the governance source is unreachable or the tag doesn't exist:
- Print clear error: "Failed to fetch governance from <url> at version <tag>. Check internet connection and version tag."
- Suggest recovery: "Run `git submodule update --init` manually after fixing the URL/tag."
- Exit with code 1

### 5. Test Governance Submodule Integration

Create a test that:

1. Runs `ai-project init test-project`
2. Changes to `test-project` directory
3. Runs `git submodule status` and confirms `governance/` is present
4. Lists `governance/` contents and confirms key files exist (e.g., `governance/PROJECT-SYSTEM-GUIDELINES.md`)
5. Validates `.ai-project.yml` is correct YAML and has governance reference
6. Confirms `.gitmodules` file is correct

### 6. Document Submodule Behavior

In the CLI help and generated project documentation:

- Explain that governance is installed as a git submodule
- Document how to update governance: `git submodule update --remote` (future feature)
- Document the governance version pinning: "Each project pins governance to a specific version to ensure stability"
- Provide a troubleshooting section for common submodule issues

### 7. Handle Custom Governance Source

Allow developers to use alternative governance sources (for testing or custom governance):

```bash
ai-project init my-project --governance-source https://github.com/myorg/governance --governance-version main
```

The CLI must:
- Accept any valid git URL as `--governance-source`
- Accept any valid git ref as `--governance-version`
- Validate the URL is reachable before attempting submodule add
- Print warning if using non-canonical governance source

## Execution Notes

**For the Coding Agent:**

1. **Start with E7.2:** Ensure the basic scaffolding CLI works before extending with submodule logic.

2. **Submodule Implementation:**
   - Use `git submodule add --branch <version> <source> governance/`
   - Call `git submodule update --init --recursive` to initialize immediately
   - Verify files exist in `governance/` before success

3. **Validation Logic:**
   - Project name: `^[a-z0-9][a-z0-9-]*[a-z0-9]$` (no spaces, no special chars except dash, not starting/ending with dash)
   - Timestamp: Valid ISO-8601 (e.g., `2026-04-27T14:30:00Z`)
   - URL: Basic check for `http://` or `https://` prefix
   - Git ref: Alphanumeric, dashes, dots (e.g., `v2.0.0`, `main`, `release/2.0`)
   - YAML: Use a bash YAML parser or simple check (key: value format)

4. **Error Recovery:**
   - If submodule fetch fails, provide clear next steps: "Run `git submodule update --init` manually after fixing the URL."
   - Document that private governance repositories require SSH configuration

5. **Testing Protocol:**
   - Create a test project with default governance source
   - Create a test project with custom governance source (use public repo for testing)
   - Test `--skip-submodule` flag (submodule should not be added)
   - Test invalid governance version (should fail with clear error)
   - Verify `.gitmodules` content
   - Verify `.ai-project.yml` content

6. **Edge Cases:**
   - Network error during submodule fetch → clear error message + recovery steps
   - Invalid governance tag → error with suggestion to check tag exists
   - Governance source is unreachable → error with suggestion to check URL
   - User has no SSH key for private repo → error with suggestion to use HTTPS or add SSH key
