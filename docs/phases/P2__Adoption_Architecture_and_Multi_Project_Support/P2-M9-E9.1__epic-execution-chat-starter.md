**Commit:** `<commit-hash>`

### Summary

Define the complete override field specification for `.ai-project.yml` (types, defaults, allowed values, constraints) and document the override precedence hierarchy so that governance consumers can unambiguously determine which value applies in any conflict.

### Problem Statement

The `.ai-project.yml` overrides block is a stub with three fields listed but no formal constraints, validation rules, or precedence documentation. Projects cannot confidently customize governance, validation tooling has no schema, and the HQ agent (E9.3) has no specification to implement against.

### Goals

1. All 3 override fields fully specified (type, default, allowed values, constraints)
2. Override precedence hierarchy documented and unambiguous
3. Core (non-overridable) governance dimensions enumerated
4. `governance/ai-project-yml-spec.md` updated with complete override schema
5. `PROJECT-SYSTEM-GUIDELINES.md` updated with override system reference
