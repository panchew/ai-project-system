# Epic E6.1 — Define `/governance` Folder Structure

## Context

Phase P2 separates governance files from project documentation. Before any files are moved, the target structure must be designed, agreed upon, and documented. This Epic establishes the canonical `/governance` folder layout that all subsequent M6 epics will implement.

---

## Problem Statement

There is no defined structure for `/governance`. Without a spec:

- E6.2 (file migration) has no authoritative target layout
- E6.3 (`.ai-project.yml`) cannot reference a stable path
- The `ai-project init` CLI (M7) cannot scaffold the right structure
- The HQ agent (M8) cannot know where to find governance files

**This Epic unblocks all other M6 epics.**

---

## Goals

By the end of this Epic:

1. The canonical `/governance` folder structure is documented in a spec file
2. All subdirectories are defined with their purpose and contents
3. Naming conventions within `/governance` are established
4. The authority hierarchy within `/governance` is documented
5. The spec is committed so E6.2 can reference it as the migration target

---

## Non-Goals

- Moving any files (E6.2)
- Defining `.ai-project.yml` format (E6.3)
- Writing the submodule setup guide (E6.4)
- Writing the migration guide (E6.5)

---

## Scope of Work

### 1. Design the `/governance` folder layout

Propose and document the following structure (or a variation confirmed during execution):

```
/governance/
  PROJECT-SYSTEM-GUIDELINES.md     # Execution rules (moved from docs/)
  AI-OPERATING-GUIDELINES.md       # AI behavior rules (moved from docs/)
  agents/
    hq.agent.md                    # HQ Chat agent (M8 deliverable, placeholder here)
  templates/
    epic-spec.md
    epic-completion-report.md
    epic-execution-chat-starter.md
    epic-review-seal.md
    milestone-spec.md
    milestone-closure-declaration.md
    phase-spec.md
    README.md
  systems/
    hq-chat.md
    epic-execution-chat-starter.md
    governance-propagation.md
    PROJECT-TRACKER-INTEGRATION-SYSTEM.md
    (other system reference docs)
  README.md                        # Overview of governance folder and contents
```

### 2. Document the authority hierarchy within `/governance`

Define which files are authoritative, which are templates, and which are reference docs. Establish that `PROJECT-SYSTEM-GUIDELINES.md` and `AI-OPERATING-GUIDELINES.md` are the two canonical governance documents.

### 3. Write the `/governance/README.md`

A brief guide to the folder: what it contains, how it's used, how to reference it via submodule.

### 4. Commit the structure spec

The output of this Epic is a governance spec document (`docs/governance/governance-folder-structure.md` or equivalent) that E6.2 uses as the migration target. The actual folder and files are created in E6.2.
