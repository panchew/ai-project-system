## Key Decisions

1. **HTML comment syntax for inline guidance:** Chose HTML comment blocks (`<!-- comment -->`) instead of Markdown comments to ensure comments are visible in raw Markdown but hidden when rendered. This makes templates self-documenting without cluttering rendered views.

2. **Placeholder format:** Used `<angle-brackets>` for required replacements and `[square-brackets]` for example content to clearly distinguish between template structure and example content.

3. **Front-matter schemas:** Maintained strict consistency with existing specs (P1 Phase, M1/M2 Milestones, E2.1 Epic) to ensure templates reflect actual usage patterns.

4. **README structure:** Organized README by audience need (Quick Start → Field Reference → Usage Guidelines → Related Docs) to optimize for both new users and experienced users.

5. **Epic Review Seal enhancements:** Added governance alignment comments and Related Documentation section to epic-review-seal.md to strengthen connection with E2.1 and AI-OPERATING-GUIDELINES.md Section 11.

6. **Template completeness:** Included all sections (required and optional) in templates to demonstrate full spec structure, allowing users to delete optional sections rather than guessing what's available.
