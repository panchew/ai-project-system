# Epic E4.1 — Templates & Scaffolding

## Context

The AI Project System has proven effective through dogfooding (M1, M2, M3 execution), but new projects must reverse-engineer spec structure from existing files.

This creates adoption friction:
- No standardized starting point for Phase/Milestone/Epic specs
- Inconsistent front-matter across specs
- Users must infer required sections from examples
- Copy-paste from existing specs risks propagating project-specific content

Epic E4.1 solves this by providing complete, ready-to-use templates for all system artifacts.

---

## Problem Statement

Currently, to start a new project using the AI Project System:

1. Users must read governance documents to understand required spec structure
2. Users must examine existing specs to reverse-engineer format
3. Users must manually create front-matter and section structure
4. Risk of missing required fields or sections
5. No inline guidance for what each section should contain

This creates a **20-30 minute setup overhead** and increases error rates.

The system should provide **copy-paste-ready templates** that reduce setup time to under 5 minutes.

---

## Goals

By the end of this Epic, the system must:

1. Provide templates for all major spec types (Phase, Milestone, Epic, Completion Report)
2. Include inline guidance and examples within templates
3. Ensure templates align with current governance (v1.3.0)
4. Make front-matter self-documenting
5. Enable new projects to scaffold complete documentation structure in under 5 minutes

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Build automation or CLI tooling to generate templates
- Create project-type-specific templates (e.g., web app vs CLI)
- Modify existing governance documents
- Create templates for non-core artifacts (ADRs, context docs, etc.)
- Implement validation or linting for templates

## Acceptance Criteria

- A new project can copy templates and have complete spec scaffolding in under 5 minutes
- Templates are self-documenting (no need to reference governance for basic usage)
- All required front-matter fields are present in templates
- Templates demonstrate best practices through examples
- No template contains project-specific content (all examples are generic/placeholder)

---

## Technical Constraints

- **Tech stack:** Markdown only (no tooling)
- **Governance:** Must align with PROJECT-SYSTEM-GUIDELINES.md v1.3.0 and AI-OPERATING-GUIDELINES.md v1.2.0
- **Format:** Use YAML front-matter, Markdown sections, inline comments
- **Examples:** Must use placeholder/generic content, not real project data
- **Comments:** Use HTML comment syntax `<!-- comment -->` for inline guidance
