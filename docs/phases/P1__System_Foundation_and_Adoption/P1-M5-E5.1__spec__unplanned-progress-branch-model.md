# Epic E5.1 — Unplanned Progress Branch Model

## Context

During real-world usage of the AI Project System (specifically during M4 execution), a critical workflow gap was identified:

**The Gap:**
- During execution, humans encounter ideas, improvements, and creative insights
- These don't fit current Epic scope (correctly — scope discipline must be preserved)
- Current system has no canonical way to capture this work
- Result: Users work outside governance, creating drift and losing insights

**User observation (from E4.4 closure):**
> "I tend to see opportunity areas that are not necessarily tied to the current work, but adds value to the project... It's tempting to get into that hole and do things in an unstructured manner... I am already doing things out of governance, so I am looking to reconcile."

This Epic formalizes a Git-native solution: **Unplanned Progress Branches**.

---

## Problem Statement

Currently, the AI Project System does not provide a canonical mechanism for:

1. **Capturing exploratory work** that emerges during execution but is out of current Epic scope
2. **Preserving creative insights** without breaking execution discipline
3. **Creating feedback loops** from execution → planning
4. **Working within governance** for unplanned work

**Impact:**
- Users work outside governance (ungoverned commits, branches, files)
- Valuable insights are lost or forgotten
- System feels rigid when creativity emerges
- No process for HQ to review and integrate exploratory work

**Solution:** Define "Unplanned Progress Branches" as a canonical mechanism for capturing work that needs planning integration.

---

## Goals

By the end of this Epic, the system must:

1. Define "Unplanned Progress Branches" in governance (what they are, when to use them)
2. Establish branch naming convention (`unplanned/*`)
3. Define lifecycle (creation, work, integration, closure)
4. Specify HQ planning behavior (review unplanned branches during planning)
5. Define integration process (Epic spec decides strategy)
6. Enable users to capture exploratory work within governance

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Create document-based registries or tracking artifacts (Git branches ARE the artifact)
- Add automation tooling (branch listing, automatic integration)
- Change existing Epic execution discipline
- Retroactively apply to past work
- Define every edge case (start with core model, refine later if needed)

## Scope of Work

### **1. PROJECT-SYSTEM-GUIDELINES.md Update**

Add new section: **"Unplanned Progress Branches"**

**Must define:**
- **Purpose:** Capture exploratory work without breaking execution discipline
- **Branch naming:** `unplanned/<topic-slug>`
- **Authority:** Unplanned branches are proposals, not accepted work
- **Lifecycle:**
  1. Creation (from stable branch when insight emerges)
  2. Work (commits capturing ideas/improvements)
  3. Reference (stays open during planning)
  4. Integration (via Epic execution, strategy in Epic spec)
  5. Closure (after full integration or explicit discard)
- **Rules:**
  - Must NOT merge directly to milestone/phase/develop
  - Must be scoped to topic (not dumping ground)
  - HQ must review during planning
  - Integration via Epic execution only
  - Stays open until integrated or discarded (no auto-expiration)
- **Distinction from Epic branches:** Epic = spec-driven execution, Unplanned = exploratory work awaiting planning

**Include example workflow:**
- During Epic execution, idea emerges
- Create `unplanned/<topic>` from stable branch
- Make commits
- During planning, HQ reviews branch
- HQ creates Epic to integrate
- Epic spec defines integration strategy (cherry-pick, merge, partial)
- After Epic closes, unplanned branch deleted

---

### **2. AI-OPERATING-GUIDELINES.md Update**

Add new section: **"HQ Planning and Unplanned Progress Branches"**

**Must define:**

**HQ Chat planning behavior:**
1. During milestone/phase planning, ask: "Are there any unplanned progress branches to review?"
2. List branches (request from human)
3. Review contents (ask human to describe intent/commits)
4. Propose integration approach:
   - Create Epic to integrate
   - Defer (branch stays open)
   - Discard (branch closed)

**Epic specification requirements when integrating unplanned work:**
- Epic spec MUST reference unplanned branch by name
- Epic spec MUST define integration strategy:
  - Cherry-pick (list commits/ranges)
  - Full merge
  - Partial integration
- Epic spec MUST clarify branch closure behavior

**Coding Agent integration behavior:**
- Read unplanned branch commits/contents
- Follow integration strategy from Epic spec exactly
- Do NOT modify unplanned branch (work happens in Epic branch)
- After Epic closes, unplanned branch may be deleted per spec

**Branch lifecycle:**
- Stays open until fully integrated OR explicitly discarded
- No automatic expiration
