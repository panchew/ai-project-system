## CONTEXT

This Epic formalizes the Epic Execution Chat Starter format requirement in governance to address a usability issue identified during E5.1 planning (2026-02-17).

**The Issue:** Epic Execution Chat Starters were produced by HQ Chat as plain text in chat responses, requiring users to manually select and copy the entire text with risk of partial selection and poor user experience.

**User observation (from E5.1 planning):**
> "Epic Execution Chat Starter should be in a code block in markdown format for me to copy. If that is not in the governance, it should be."

**This Epic:** Defines format requirements for Epic Execution Chat Starters to ensure they are presented in markdown code blocks with proper formatting for easy one-click copying.

### Deliverable 1: AI-OPERATING-GUIDELINES.md Section 3.1.1 — Epic Execution Chat Starter Format

**File:** [docs/AI-OPERATING-GUIDELINES.md](docs/AI-OPERATING-GUIDELINES.md)  
**Status:** ✅ Complete  
**Version:** 1.4.0 → 1.4.1 (patch increment)

**Content Added:**
- Section 3.1.1 "Epic Execution Chat Starter Format" inserted under section 3.1 "HQ Chats"
- 4 format requirements clearly specified:
  1. Present in markdown code block (four backticks for fencing)
  2. Include filename in header (format: `name=<epic-id>-epic-execution-chat-starter.md`)
  3. Use markdown language identifier
  4. Provide brief instruction after code block
- Rationale provided: Code blocks provide clear visual boundaries, enable one-click copying, and prevent incomplete content selection
- Example included showing proper formatting with nested code blocks
- Scope clarified: Applies to Epic Execution Chat Starters only, not normal HQ responses or other outputs

**Key Concepts:**
- User experience first: Chat starters must be easy to copy with one action
- Four backticks ensure proper escaping of triple-backtick code blocks inside chat starters
- Filename header helps users identify and save the file
- Clear call-to-action instruction guides users on what to do next
