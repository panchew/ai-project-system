# Epic E4.3 — Example Project & Walkthrough

## Context

Epics E4.1 and E4.2 provided templates and documentation for the AI Project System, but new users still benefit from seeing a **complete, worked example** that demonstrates the full lifecycle.

Current state:
- ✅ Templates exist (E4.1) for all major artifacts
- ✅ Quick Start Guide (E4.2) provides step-by-step instructions
- ✅ Visual diagrams (E4.2) clarify key concepts
- ❌ No concrete reference implementation exists
- ❌ Users must still "figure it out" from documentation alone

This Epic provides a **fully worked example project** that demonstrates:
- Complete Phase → Milestone → Epic hierarchy
- Real Epic execution artifacts (specs, completion reports, delivery notices, review seals)
- Proper repository structure
- Realistic problem statement and solution

The example serves as a **learning reference** and **validation** that the system works as documented.

---

## Problem Statement

Currently, to learn the AI Project System:

1. Users read governance documents (comprehensive but abstract)
2. Users read Quick Start Guide (prescriptive but still conceptual)
3. Users examine `ai-project-system` repository (real but complex, not pedagogical)
4. Users must create their first project without a simple reference

**Gap:** No simple, pedagogical example that demonstrates "here's what a complete project looks like"

**Impact:**
- Users face trial-and-error when creating first project
- Uncertainty about "am I doing this right?"
- Governance and Quick Start are necessary but not sufficient for confident adoption

**Solution:** Provide a complete, small, pedagogical example project that users can:
- Walk through to understand the full lifecycle
- Copy/reference when creating their own projects
- Use to validate their understanding

---

## Goals

By the end of this Epic, the system must:

1. Provide a complete example project demonstrating Phase → Milestone → Epic hierarchy
2. Include all major artifacts (specs, completion reports, delivery notices, review seals, chat starters)
3. Use a realistic but simple problem domain (not "hello world" trivial, not complex)
4. Demonstrate proper repository structure and file naming
5. Be small enough to understand in under 30 minutes
6. Serve as a reference for new users creating their first project

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Create multiple examples (one comprehensive example is sufficient)
- Implement actual working code (example is documentation-focused)
- Create project-type-specific examples (web app, CLI, etc.)
- Replace the Quick Start Guide (example complements, not replaces)
- Create interactive tutorials or videos
- Demonstrate every possible edge case or variation

## Execution Notes

This Epic requires:
- Strong understanding of the full Epic lifecycle
- Ability to create realistic, pedagogical content (not just templates)
- Understanding of proper file naming and folder structure
- Ability to write from a learner's perspective (what would help someone understand?)

**Key principle:** The example should be **realistic but simple**:
- Realistic: Real problem domain, complete artifacts, proper structure
- Simple: Small scope, understandable in 30 minutes, focused on one Epic walkthrough

**Recommended approach:**
1. Start with Phase 1 Epic 1.1 (the main walkthrough)
2. Create all E1.1 artifacts (spec, completion, delivery, review, chat starter)
3. Work backward to create Phase 1 and Milestone 1 specs
4. Add minimal Phase 0 for completeness
5. Create roadmap showing context
6. Create READMEs explaining the example
7. Integrate with Quick Start

**Content quality:**
- Use realistic content, not placeholder text
- Epic spec should demonstrate good problem statements, clear goals, proper DoD
- Completion report should demonstrate proper DoD verification
- Review seal should demonstrate realistic human feedback
- Chat starter should be copy-pasteable (if someone wanted to actually execute it)
