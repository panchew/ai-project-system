# Epic E2.2 — Human-Language Review Capture & Structured Artifact Generation

## Context

Epic E2.1 successfully formalized:
- Human Review as a first-class lifecycle step
- Explicit separation between execution and acceptance
- The Epic Review Seal as a structured judgment artifact
- Clear Coding Agent stop conditions

However, real usage revealed an ergonomic gap:

While the **structure** for review and acceptance exists, humans are still required to manually translate natural-language judgment into structured artifacts.

This creates unnecessary Layer 8 friction and undermines the goal of making the system comfortable for sustained use.

Epic E2.2 addresses this interactional gap without reopening or modifying E2.1.

---

## Problem Statement

Currently:

- Humans naturally express review findings in plain language
- The system expects structured artifacts (e.g. Epic Review Seals)
- Humans must manually author or edit markdown to bridge this gap

This results in:
- Cognitive overhead
- Workflow interruption
- A feeling of “ceremony” rather than support

The system should instead allow:

> **Humans to speak naturally, and AI to perform the structuring.**

---

## Goals

By the end of this Epic, the system must:

1. Allow human review input to be provided in natural language
2. Enable HQ Chat or Coding Agents to generate structured artifacts from that input
3. Eliminate the requirement for humans to manually author review-related markdown
4. Preserve explicit HQ decision authority
5. Maintain a clear separation between judgment, structuring, and execution

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Automate acceptance decisions
- Introduce CLI tooling or bots
- Modify execution or delivery mechanics
- Replace existing templates (e.g. Review Seal)
- Introduce new lifecycle stages

---

## Scope of Work

### 1. Human-Language Review Capture
- Define how humans provide review feedback:
  - Plain language
  - Free-form
  - No required structure
- Clarify that this input is authoritative for judgment, not formatting

### 2. Structured Artifact Generation
- Define that:
  - HQ Chat or a Coding Agent may generate structured artifacts
  - Generated artifacts are based on human input
  - Humans approve or correct generated artifacts, but do not author them

### 3. Review Seal Generation Flow
- Document the canonical flow:
  - Human review → AI-generated Review Seal → HQ decision
- Clarify that Review Seals:
  - Are generated, not manually written
  - Serve as decision inputs, not execution triggers

### 4. Governance Clarifications (Minimal)
- Update governance docs only as needed to:
  - Clarify roles in review capture vs structuring
  - Reinforce that humans are not required to write markdown during review

---

## Deliverables

This Epic must produce:

- Documentation describing the human-language → structured-artifact flow
- Clarified guidance for HQ Chat behavior during review
- Clarified guidance for Coding Agents when asked to generate artifacts
- No changes to existing completed Epics or Milestones

---

## Definition of Done

Epic E2.2 is complete when:

- A human can provide review feedback in plain language only
- The system can generate an Epic Review Seal from that input
- Humans are not required to manually edit or author markdown for review
- HQ decision flow remains explicit and authoritative
- No execution loops are introduced

---

## Acceptance Criteria

- Layer 8 review feels natural and low-friction
- Structured artifacts are generated, not hand-written
- Review → decision → next-step flow is intuitive
- The system scales without increasing cognitive load

---

## Notes

Epic E2.2 is intentionally interaction-focused.

It completes the ergonomics work started in E2.1 and ensures the system supports humans rather than demanding ceremony from them.
