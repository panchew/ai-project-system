# Epic E5.3 — Milestone Closure Process

## Context

During Milestone M4 closure (2026-02-17), a critical governance gap was identified:

**The Gap:**
- Epic closure process is well-defined in governance (delivery notice → review → merge → stop)
- **Milestone closure process is NOT defined** (no documented merge requirement, no consolidation step)
- Result: M4 closure had to be figured out manually

**What happened with M4:**
- All 4 Epics (E4.1-E4.4) completed and merged to `milestone/M4` branch
- HQ declared M4 complete
- But `milestone/M4` branch was NOT merged to parent branch (`phase/P1`)
- When planning M5, we realized M4 needed consolidation before M5 could branch from clean baseline
- Had to manually create PR: `milestone/M4` → `phase/P1` and merge (commit `1784fe0`)
- Only then could `milestone/M5` be created properly

**User observation (from M4 closure):**
> "I just realized that if we are closing Milestone 4, then we should have a PR from Milestone 4 branch into Phase 1 branch, so I can proceed to create Milestone 5 branch."

This Epic formalizes the milestone closure process to prevent this manual discovery in the future.

---

## Problem Statement

Current governance does not define what happens when a milestone completes:

**Missing process steps:**
1. How to consolidate milestone work into parent branch
2. When to create PR from milestone → parent
3. Who reviews milestone consolidation
4. When milestone is "fully closed" vs. "Epics complete"
5. How next milestone branch is created

**Impact:**
- Users must figure out milestone closure manually
- Risk of forgetting consolidation step (milestone branches never merge)
- Branch hierarchy breaks down (next milestone branches from wrong baseline)
- Inconsistent milestone closure across projects

**Current state:**
- Epic branches merge to milestone branches (✅ defined)
- **Milestone branches merge to parent branches** (❌ not defined)
- Phase branches merge to ??? (❌ not defined)

**Solution:** Define milestone closure process parallel to Epic closure process.

---

## Goals

By the end of this Epic, governance must:

1. Define milestone closure process (steps from "all Epics complete" to "milestone fully closed")
2. Specify milestone → parent branch merge requirement
3. Clarify branch hierarchy consolidation at each level
4. Define HQ behavior during milestone closure
5. Provide template/guidance for milestone closure (parallel to Epic closure)

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Define phase closure process (defer until phases are used more)
- Change Epic closure process (already well-defined)
- Automate milestone closure (manual process is fine for now)
- Retroactively close past milestones (M1-M4 are already closed, this is forward-looking)
- Define milestone completion criteria (already in milestone specs)

## Scope of Work

### **1. PROJECT-SYSTEM-GUIDELINES.md Update**

**File:** `docs/PROJECT-SYSTEM-GUIDELINES.md` (currently v1.4.0 or v1.4.1 after E5.2)

**Add new section:** "5B. Milestone Closure" (after section 5 or 5A if it exists)

**Must define:**

**A. Milestone Closure Process (step-by-step):**
1. **All Epics complete:** All planned Epics for milestone are executed, reviewed, and merged to milestone branch
2. **HQ declares milestone complete:** HQ evaluates milestone completion criteria (from milestone spec) and declares milestone complete
3. **PR created:** `milestone/<id>` → parent branch (`phase/<id>` or `develop` or `main`)
4. **Human reviews consolidation:** Review PR to verify all milestone work is present and correct
5. **Merge completes:** PR merged, milestone work consolidated into parent branch
6. **Milestone declared fully closed:** HQ declares milestone fully closed (not just "complete")
7. **Next milestone branch created:** Next milestone branch created from merged parent branch

**B. Branch hierarchy consolidation:**
- Epic branches merge to milestone branches
- Milestone branches merge to phase branches (or `develop`/`main` if no phase branch)
- Phase branches merge to `develop` or `main` (when phase completes)

**C. Milestone closure vs. completion:**
- **Milestone complete:** All planned Epics executed and accepted
- **Milestone fully closed:** Milestone complete AND consolidated into parent branch

**D. Parent branch determination:**
- If phase branch exists: milestone merges to phase branch
- If no phase branch: milestone merges to `develop` or `main`
- Next milestone branches from same parent

**E. Example milestone closure:**
```markdown
Example: Milestone M4 closure
1. E4.1, E4.2, E4.3, E4.4 all complete and merged to milestone/M4
2. HQ evaluates M4 completion criteria (all satisfied)
3. HQ declares M4 complete
4. Create PR: milestone/M4 → phase/P1
5. Human reviews (all M4 work present)
6. Merge PR (commit 1784fe0)
7. HQ declares M4 fully closed
8. Create milestone/M5 from phase/P1
```

### **2. AI-OPERATING-GUIDELINES.md Update**

**File:** `docs/AI-OPERATING-GUIDELINES.md` (currently v1.3.0 or v1.3.1 after E5.2)

**Add new section:** "3.4 Milestone Closure" (after section 3.3)

**Must define:**

**A. HQ Chat milestone closure behavior:**

When all milestone Epics are complete:

1. **Evaluate completion criteria:** Review milestone spec completion criteria
2. **Check Epic status:** Verify all planned Epics are executed, reviewed, accepted, and merged
3. **Declare milestone complete:** If criteria satisfied, declare "Milestone <id> complete"
4. **Prompt for consolidation:** Inform human that milestone consolidation is required:
   - "Milestone <id> is complete. To fully close this milestone, create PR: milestone/<id> → <parent-branch>"
   - Identify parent branch (phase branch or develop/main)
   - Provide PR title and description guidance
5. **After merge:** Declare "Milestone <id> fully closed"
6. **Next milestone setup:** Confirm next milestone branch created from merged parent

**B. Milestone closure declaration format:**

```markdown
# MILESTONE CLOSURE DECLARATION — M<id>

**Milestone:** M<id> — <Name>
**Status:** CLOSED ✅
**Closure Date:** YYYY-MM-DD
**Closed By:** HQ Chat (<username>)
**Merge Commit:** <sha>

## Closure Verification
✅ All Epics complete: [list Epics]
✅ All Epics accepted: Human review approved
✅ PR created: milestone/<id> → <parent>
✅ PR merged: Consolidation commit <sha>
✅ Branch hierarchy preserved: Milestone work now in <parent>

## Milestone Summary
[Brief summary of what was delivered]

## Next Steps
- Create milestone/<next-id> from <parent> branch
- Begin planning for next milestone
```

**C. Milestone completion criteria evaluation:**

HQ Chat MUST:
- Review milestone spec completion criteria section
- Verify each criterion is satisfied
- Document verification in milestone closure declaration
- Do NOT declare milestone complete if criteria unsatisfied
