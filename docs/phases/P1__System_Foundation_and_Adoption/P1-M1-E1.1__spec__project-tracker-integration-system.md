# Epic E1.1 — Project Tracker Integration System (Foundation)

## Purpose

Establish the **Project Tracker Integration System** as a documented, non-normative system reference that enables optional external project tracker integration without compromising the canonical project structure defined in PROJECT-SYSTEM-GUIDELINES.md.

This epic ensures:
- The system is formally defined and versioned
- Integration patterns are explicit and optional
- Projects can opt in or out of tracker integration without affecting governance
- Coding Agents understand integration semantics and constraints

## Scope

### In Scope

1. **System Reference Document Exists**
   - [DONE] [docs/systems/PROJECT-TRACKER-INTEGRATION-SYSTEM.md](../../systems/PROJECT-TRACKER-INTEGRATION-SYSTEM.md) is present and complete
   - The document defines canonical vs projected models
   - The document specifies mapping strategy and constraints

2. **Governance Alignment**
   - The system reference is properly linked in AI-OPERATING-GUIDELINES.md (Section 8: External Tracker Semantics)
   - PROJECT-SYSTEM-GUIDELINES.md is the authoritative source; the system reference is non-normative

3. **Project-Level Integration Contract (Optional Per Project)**
   - When a project chooses tracker integration, it MUST declare in `docs/context/project-tracker.md`
   - For this project (ai-project-system): No tracker integration is currently declared
   - The declaration is optional; projects without it have no tracker integration

4. **Coding Agent Semantics**
   - AI-OPERATING-GUIDELINES.md Section 8 is accurate and complete
   - Coding Agents understand: never invent mappings, respect declarations, stop if mappings are missing
   - Coding Agents know the system reference is the contract, not the governance layer

### Out of Scope

- Implementing automation or CLI tooling for tracker synchronization
- Creating project-tracker.md for any specific project (each project decides independently)
- Integrating this project (ai-project-system) with an external tracker
- Modifying governance documents beyond linking/referencing this system

## Deliverables

1. **System Reference is Stable and Versioned**
   - [docs/systems/PROJECT-TRACKER-INTEGRATION-SYSTEM.md](../../systems/PROJECT-TRACKER-INTEGRATION-SYSTEM.md) exists with complete sections 1-10
   - Document is linked appropriately from AI-OPERATING-GUIDELINES.md

2. **Documentation Exists for Optional Integration**
   - This project declares its own tracker status in docs/context/project-tracker.md (declaring no integration)

3. **No Breaking Changes to Governance**
   - PROJECT-SYSTEM-GUIDELINES.md remains unchanged
   - AI-OPERATING-GUIDELINES.md is updated only to clarify existing principles
