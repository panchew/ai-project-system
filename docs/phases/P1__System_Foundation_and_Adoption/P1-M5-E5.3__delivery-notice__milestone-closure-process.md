## CONTEXT

This Epic formalizes the milestone closure process to address a critical governance gap discovered during Milestone M4 closure (2026-02-17).

**The Gap:** Epic closure was well-defined, but milestone closure was not documented. During M4 closure, we had to manually discover that milestone branches must merge to parent branches before the next milestone can be created.

**This Epic:** Defines the 7-step milestone closure process and HQ Chat behavior, parallel to the existing Epic closure process.

## NOTES

**Context from M4 Closure:**
The user observation during M4 closure (2026-02-17) was:
> "I just realized that if we are closing Milestone 4, then we should have a PR from Milestone 4 branch into Phase 1 branch, so I can proceed to create Milestone 5 branch."

This Epic ensures future milestone closures won't require this manual discovery. The process is now explicitly documented and HQ Chat will guide users through it.

**Governance Style Consistency:**
Both new sections maintain the prescriptive, clear, and actionable tone of existing governance. They use structured formats, verification checklists, and explicit examples (M4 closure).

**Parallel to Epic Closure:**
The milestone closure process intentionally mirrors Epic closure:
- Completion → Declaration → Consolidation Prompt → Human Review → Merge → Full Closure
- This consistency makes the system easier to learn and apply
