# Epic E5.4 — Epic Execution Chat Starter Format

## Context

During E5.1 planning (2026-02-17), a usability issue was identified with Epic Execution Chat Starters:

**The Issue:**
- HQ Chat produces Epic Execution Chat Starters as plain text in chat responses
- Users must manually select and copy the entire text (risk of partial selection)
- Poor user experience compared to copyable code blocks
- No visual indication of where chat starter begins/ends

**User observation (from E5.1 planning):**
> "Epic Execution Chat Starter should be in a code block in markdown format for me to copy. If that is not in the governance, it should be."

**Current behavior:**
- HQ Chat presents chat starter as plain markdown in chat
- User manually selects text
- Easy to miss sections or copy incomplete content

**Desired behavior:**
- HQ Chat presents chat starter in markdown code block (four backticks)
- Include filename in header: `name=<epic-id>-epic-execution-chat-starter.md`
- User copies entire block with one click/action
- Clear visual boundary of chat starter content

This Epic formalizes the chat starter format requirement in governance.

---

## Problem Statement

Current governance (AI-OPERATING-GUIDELINES.md) does not specify format requirements for Epic Execution Chat Starters produced by HQ Chat:

**Missing specifications:**
1. How chat starters should be presented (plain text vs. code block)
2. Whether filename should be included
3. Visual boundaries for copyability
4. User experience considerations

**Impact:**
- Inconsistent chat starter presentation
- Poor user experience (manual selection, risk of incomplete copy)
- No guidance for HQ Chat on how to format output
- Users must request format changes manually

**Solution:** Define chat starter format requirements in AI-OPERATING-GUIDELINES.md.

---

## Goals

By the end of this Epic, governance must:

1. Specify that Epic Execution Chat Starters MUST be presented in markdown code blocks
2. Define code block format (four backticks, filename in header)
3. Ensure HQ Chat behavior aligns with user experience needs
4. Provide clear guidance for consistent chat starter formatting

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Change chat starter content (content structure is already defined)
- Create automated chat starter generation (manual HQ Chat generation is fine)
- Define formatting for other HQ outputs (only chat starters)
- Retroactively reformat past chat starters
- Change governance for Coding Agent outputs (only HQ Chat)

### Epic Execution Chat Starter Format

When HQ Chat produces an Epic Execution Chat Starter, it MUST:

1. **Present in markdown code block:**
   - Use four backticks (````) to fence the code block
   - Ensures code blocks inside chat starter (triple backticks) are properly escaped
   
2. **Include filename in header:**
   - Format: `name=<epic-id>-epic-execution-chat-starter.md`
   - Example: `name=E5.1-epic-execution-chat-starter.md`
   - Helps users identify and save the file if needed

3. **Use markdown language identifier:**
   - Specify `markdown` as language for proper syntax highlighting
   - Full header format: ````markdown name=<epic-id>-epic-execution-chat-starter.md`

4. **Provide brief instruction:**
   - After code block, include: "Copy the entire chat starter above and paste into your Coding Agent chat to begin execution."
   - Clear call-to-action for user

**Rationale:** Code blocks provide clear visual boundaries, enable one-click copying, and prevent incomplete content selection. This significantly improves user experience when starting Epic execution.
