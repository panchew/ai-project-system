# Epic E3.1 — Governance Propagation & Authority Declaration

## Context

The AI Project System governance is intended to be reused across
multiple projects.

Practical use has revealed that:
- HQ chats do not have live access to GitHub repositories
- Governance cannot propagate automatically or implicitly
- Projects require a formal, explicit way to declare governance adoption
- Authority boundaries must be respected to avoid ambiguity

This Epic formalizes how governance is distributed, adopted, and enforced
across projects under these constraints.

## Goals

- Declare this repository as the authoritative governance source
- Define a reference-based governance adoption model
- Introduce a standard mechanism for projects to declare governance source
- Make governance propagation explicit and intentional
- Document known constraints and non-goals

## Non-Goals

- No CLI or automation tooling
- No automatic synchronization
- No live governance polling
- No changes to existing governance rules

## Scope

This Epic will:

1. Define the **Governance Propagation Model**
2. Introduce `docs/governance-source.md` as the canonical adoption mechanism
3. Clarify how HQ Chats enforce adopted governance
4. Document constraints of ChatGPT-based HQ environments
5. Align Epic Execution Chat Starters with governance resolution by reference

## Deliverables

- `docs/systems/governance-propagation.md`
- `docs/governance-source.md` template
- Updated Epic Execution Chat Starter guidance
- Epic Completion Report

## Definition of Done

- Governance authority and propagation are explicitly documented
- Projects have a clear, minimal adoption mechanism
- No assumption of automatic governance awareness remains
- The system is self-consistent and non-magical
