# Epic E30.4 — Reference-don't-display reconciliation (SN-23)

## Context

E30.4 was added to M30 mid-flight by the P9 phase spec **v1.1.0** amendment (`e490394`,
2026-07-18) executing HQ's triage of **SN-23** (Creation Chat, 2026-07-18, both decisions
CFO-ratified/human-confirmed). The governance framework still mandates echoing artifact
*bodies* into chat context — full fenced starter blocks in parent output, Delivery-Notice
paste into parent chats, producers re-displaying what they just wrote to file — a
transport pattern that predates committed-file practice and the IDE-attach workflow, and
whose cost lands in the sessions E30.2's audit proved costliest (parent mixed sessions =
53% of the ≈$623 window; cache re-reads 48.5% of weighted cost). E30.4 reconciles the
mandating surfaces to **reference-first handoff, paste-as-fallback**.

**Binding SN-23 decisions (already made — not open for re-debate):**
1. An artifact on disk is passed **by reference**, never by paste or full-body display.
   IDE-attach + one-line-intent is the canonical manual-mode handoff.
2. Copy-paste transport **remains documented as a fallback** for genuinely repo-less
   setups — platform agnosticism preserved. Paste is not deleted.

## Problem Statement

Three governance surfaces mandate ingesting artifact bodies into chat context beyond the
committed file itself, at 2.2–2.8K (starters) and 1.0–1.3K (notices) duplicated tokens
per handoff, re-read at cache rates for the remaining life of the costliest sessions the
system runs. Transport — the problem paste was written to solve — is already solved by
the repository plus a one-line pointer; the audit trail never depended on paste (the
committed file was always the record). The mandates are obsolete; until they are edited,
every governed chat is required by governance to burn the tokens M30 exists to save.

---

## Goals

By the end of this Epic:

1. **AOG §3.1.1 mandates reference-first:** when a starter is a committed, git-tracked
   file, the parent emits the **path + a one-line summary** (and, in IDE contexts, the
   attach workflow) instead of the full fenced block; the four-backtick fenced full-body
   form is retained, demoted to the documented **fallback** for repo-less delivery. The
   three starter templates' boilerplate updated to match.
2. **Protocol §Integration with Manual Mode mandates reference handoff:** IDE-attach or
   path + frontmatter summary replaces paste as the canonical flow; paste retained as
   the documented repo-less fallback (SN-23 Decision 2, verbatim).
3. **The no-echo rule exists:** producing chats do not display bodies of artifacts they
   have written to file (path + one-line summary instead); consuming chats read
   selectively (frontmatter + Summary + DoD/QA suffices under §11.6 default-accept).
   Its documentation home is a design decision (below).
4. **`governance/EPIC-EXECUTION-CHAT-STARTER.md`'s paste instruction** replaced with the
   reference handoff (fallback noted).
5. **Before/after evidence via E30.1's mechanism** for the per-handoff echo cost
   (honest-bound framing — see Hard Constraint application).
6. **Full test suite passes** (307 baseline, no new skips).

## Non-Goals

This Epic explicitly does **not**:

- **Delete paste.** Both SN-23 decisions are binding: reference-first, paste documented
  as the repo-less fallback. A delivery that removes the fallback fails review.
- **Touch E30.3's surfaces beyond rebasing:** the load-list/scoping content E30.3 puts
  into the templates is not this epic's to rework — E30.4 edits the handoff/boilerplate
  aspect of the same files, after E30.3 has merged.
- **Change what artifacts exist, their schemas, or the acceptance model** — §11.6
  default-accept, Delivery Notices, review flow all stand; only the *transport/display*
  mandates change.
- **Build tooling** (no attach automation, no daemon changes, no `bin/` edits — this is
  a governance-prose epic; `bin/measure-token-burn` is read-only evidence tooling here
  unless Design Decision 3 of E30.3 already extended it, in which case use what exists).
- **Claim billed-median improvements as achieved** — forward-looking only, per the M30
  discipline (future captures verify).
- **Re-debate SN-23** — both decisions are CFO-ratified; the epic implements them.

## Hard Constraint (binding — embedded verbatim from the Milestone spec)

> **The frontier-vs-local policy and the `models:` refresh MUST be derived from the
> captured measurements — not from pre-existing assumptions.** Real captured data is the
> bar; estimates do not count (phase acceptance criterion). If a measurement cannot be
> captured for some level or task type, **record the gap explicitly** in the report
> rather than substituting a guess — a policy row grounded in a recorded gap is
> acceptable; a policy row grounded in an unlabeled assumption is not. This constraint
> governs E30.2 directly and sizes E30.3: no reduction work may be scoped from the prior
> 24K/157K estimates alone.

For E30.4 specifically (phase spec v1.1.0 binds the evidence requirement to E30.1's
mechanism): the before/after claim is the **per-handoff mandated-echo cost** — "before"
= mechanism-tokenized bodies of the real M30 starters and Delivery Notices that
governance required into parent context (measurable today from committed files);
"after" = the reference line replacing them (path + one-line summary, tens of tokens).
**State the honest bound exactly as SN-23 does:** reference-first does not make
ingestion free — the consumer still reads the file once, selectively; the eliminated
cost is the duplication (producer echo, full-body parent display, second ingestion on
paste), not ingestion itself. Proxy numbers carry G10 error bars; billed-median effects
are forward-looking. Anything unmeasurable is a recorded gap (continuing the G-series),
never a guess.

## Design Decisions (yours to resolve — decide, document, move; do not escalate to ask)

1. **The no-echo rule's documentation home** — inside AOG §3.1.1 (making the section the
   general artifact-handoff rule, not just starter format), a new AOG subsection, or the
   protocol doc. Pick the home that future chats will actually load; document the
   reasoning in the Delivery Notice. All three mandating surfaces must end up pointing
   at one coherent rule, not three divergent paraphrases.
2. **The reference-handoff format** — the minimal canonical form (artifact path + one
   line: type, id, status; e.g. "Epic E30.4 Delivery Notice —
   `docs/phases/.../P9-M30-E30.4__delivery-notice.md`, delivered, suite 307/0"). Define
   it once, in the rule's home, and have every edited surface cite it rather than
   restate it.
3. **Before/after presentation** — a short evidence note beside the token-measurement
   artifacts (recommended:
   `.ai-project/artifacts/reference/token-measurement/echo-cost-note.md` or a section in
   E30.3's context-scoping standard if that landed and fits) with the mechanism-produced
   numbers; reproducible by rerun.
4. **AOG version bump size** (v2.9.0 → v2.10.0 minor is the expected shape for a
   normative-rule change; confirm against AOG's own changelog conventions) and the
   protocol/starter-doc version rows — follow each document's existing discipline.

## Execution Notes

- **Practice the rule while landing it.** Deliver your own Delivery Notice by reference
  (path + one-line summary in chat). Do not echo the bodies of the files you edit into
  chat output — cite paths and diffs summaries. This epic's own session is the first
  demonstration of the workflow it codifies.
- **One rule, cited everywhere — not four paraphrases.** The historical failure mode of
  multi-surface prose edits (see P6 E25.4/E25.5 reconciliation history) is divergent
  restatements. Write the rule once in its home; every other surface gets one sentence
  plus a pointer.
- **Preserve the fallback prominently enough to be findable.** Platform agnosticism is a
  ratified decision (SN-23 Decision 2 exists because of it); a fallback buried so deep a
  repo-less adopter can't find it fails the spirit. A short "Fallback: no repo access?"
  note at each edited surface pointing to the full fallback description is the shape.
- **Check test assertions before editing templates**
  (`grep -rn "Copy the entire chat starter" tests/ governance/` first) — update
  coherently, never route around with skips.
- **Verify anchors at execution time** (GH-2): AOG §3.1.1 line span, protocol line 408,
  EPIC-EXECUTION-CHAT-STARTER line 83, template boilerplate lines — all cited as of
  2026-07-18, and E30.3's merge will have shifted the template files.
- Default-accept (PSG §11.6 / AOG §14) governs this Epic's delivery: a clean delivery is
  accepted by silence; the epic-PR merge is human-authorized in-chat (SN-19); a Review
  Decision is the exception path only.
