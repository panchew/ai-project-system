# P9-M31-E31.1 — Both-Modes Demonstration Evidence

Epic spec Deliverable 4 / Acceptance Criterion 2: "a working-level chat can demonstrably
be started in either mode, and the mode is recorded per instance" — met with real,
non-mocked evidence for both Execution Modes, not a described hypothetical.

## Manual instance

**This Epic Execution Chat itself** —
[`P9-M31-E31.1__epic-execution-chat-starter.md`](P9-M31-E31.1__epic-execution-chat-starter.md),
authored by the Milestone Chat on `milestone/M31` before this section's declaration
mechanism existed. Its header carries no `Execution Mode` field. Per the mechanism this
epic records (`governance/systems/chat-hierarchy.md`, "Execution Mode: Manual vs.
Agentic" § Declaration), **no field present means manual** — and this session, executed
by a human-supervised Coding Agent chat reading and acting on that starter directly, is
the real manual instance: no orchestrator dispatch, no unattended loop, every decision
(the three Design Decisions, the demonstration design below) made in-session and
recorded here.

`P7-M26-E26.3-PROVE`), was authored and dispatched for real through the existing,
unmodified `bin/ai-project-orchestrator` → `bin/run-dev-agent` mechanism — no new
agentic infrastructure was built (per the Epic spec's Technical Constraints).

## What this does and does not prove

This demonstrates the **declaration mechanism** (a reader determines Execution Mode
from each instance's own starter, absence resolving to manual) and that an **agentic
Epic-level dispatch is real and functional today**, per the mode model's own
"what exists mechanically today" note. It does not extend agentic dispatch to
Phase/Milestone levels (no such mechanism exists yet — recorded as a gap in the mode
model itself, not a defect here) and does not touch the paid-vs-local policy logic
(E31.2's surface).
