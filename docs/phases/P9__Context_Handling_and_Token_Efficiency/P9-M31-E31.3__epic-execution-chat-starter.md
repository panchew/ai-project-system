### Summary

Build the manual-mode counterpart to E31.1's declaration and E31.2's agentic decision
logic: a level→model mapping definition covering all five manual-capable targets (Creation,
HQ, Phase, Milestone, Epic), a documented self-model verification method (the harness's own
self-report is the only mechanism observed to exist), a verify-and-refuse startup
instruction on every template surface a manual chat actually starts from — not just the
three Execution Chat Starters — and real, committed refusal evidence.

### Binding constraints (carry into every decision)

**Hard Constraints (verbatim from the Milestone spec, all five carried; #1 and #3 are this
epic's direct surface):**

1. **Refusal means refusal** — this epic's central constraint. The startup instruction
   must be unambiguous and unconditional on mismatch. Evidence is a demonstrated refusal,
   not an assertion.
2. No agentic default — a mismatch means *stop*, never *reroute to agentic*.
3. **Policy consumed, not re-authored; divergence is an error** — read the policy and
   `models:` block, don't edit rows; policy↔block divergence refuses, consistent with
   E31.2's existing enforcement.
4. Local loadability never assumed (if the mapping ever names a local model manually).
5. Suite green at every merge — 349 baseline, no regressions, no new skips.

**Scope-honesty constraint (from the Epic spec's grounding):** manual chats have no code
wrapper to gate them the way agentic dispatch does. The "refuse" this epic builds is a
documented instruction the agent must follow, enforced by compliance like every other
AOG/PSG MUST — not a technical impossibility-to-proceed. State this plainly in the
delivery; do not overclaim.

### Design Decisions (yours to resolve — decide, document, move; do not escalate to ask)

1. **The level→model mapping definition.** Reuse `.ai-project.yml`'s existing keys for
   Phase/Milestone/HQ and add what's missing (a Creation key — yml-spec bump — and a manual
   Epic answer distinct from the `epic_dev`/`epic_qa` role split), or build a separate
   companion mapping. Either way: state the absent-block/absent-key behavior explicitly
   (fresh projects have no `models:` block at all — `bin/ai-project-init` confirms it).
   Epic spec §Design Decisions 1 has the full tradeoff discussion.
2. **The self-model verification method.** Document the harness self-report mechanism
   (cite this session's own example), state its limits (not independently verifiable).
3. **Where the verify-and-refuse instruction lives, on each of the five template
   surfaces**, phrased so it reads as a real refusal rule. The three Execution Chat
   Starters already have a "Prerequisite Verification" section (natural fit);
   `hq-chat-opener.md` and `genesis.md`/`seed.md` don't — decide where the equivalent goes.
4. **How the policy↔block divergence check is implemented** for the manual mapping —
   extend `tests/test_model_config.py` if the mapping lives in `.ai-project.yml`, or build
   an equivalent check if it lives elsewhere (Design Decision 1B). Keep it consistent with
   E31.2's existing divergence semantics.
