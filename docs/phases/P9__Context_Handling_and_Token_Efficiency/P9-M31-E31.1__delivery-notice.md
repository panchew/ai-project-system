## Execution Summary

Recorded the manual/agentic mode model for Phase/Milestone/Epic chats in
`governance/systems/chat-hierarchy.md`, a new "Execution Mode: Manual vs. Agentic"
section placed right after the existing Hierarchy Summary Table. The naming collision
flagged in the grounding was resolved up front: the table's existing "Mode" column
(HQ/Phase/Milestone/Epic level selection) is untouched; the new manual/agentic axis is
always spelled out **"Execution Mode"**, never bare "mode."

The declaration mechanism is a per-instance `Execution Mode` field added to the header
block of all three Execution Chat Starter templates
(`governance/templates/{phase,milestone,epic}-execution-chat-starter.md`), filled in by
the issuing parent chat at the moment it produces the starter. Absence of the field
means manual (Hard Constraint 2) — stated in the same section that defines the levels.
`.ai-project.yml` was not touched (Design Decision 1B was chosen over 1A/1C), so no
yml-spec version bump was needed.

Creation Chat and HQ Chat are recorded manual-only, permanently, in the same section
(SN-22) — neither level's opener gains an Execution Mode field.

G7 (one-task-one-session) is adopted as labeled, measured-evidence-based guidance: M30's
audit found milestone/phase mixed-task sessions were 53% of measured spend versus 23%
for single-task epic execution sessions (audit-report.md §2.2) — recorded as guidance,
not a requirement, applying uniformly to manual and agentic instances.

**Both-modes demonstration evidence** (Deliverable 4 / Acceptance Criterion 2) is real,
not simulated — full detail in
[`P9-M31-E31.1__demonstration-evidence.md`](P9-M31-E31.1__demonstration-evidence.md):
- **Manual:** this Epic Chat itself — its own starter carries no `Execution Mode`
  field, resolving to manual per the mechanism; this session (human-supervised,
  in-chat) is the real manual instance.
- **Agentic:** a proving vehicle, `P9-M31-E31.1-PROVE` (in the tradition of
  `P7-M26-E26.3-PROVE`), whose starter declares `Execution Mode: agentic`, dispatched
  for real through the unmodified `bin/ai-project-orchestrator` → `bin/run-dev-agent`
  path (local-execution fallback — the sandbox route is documented-unreachable for a
  bare `alpine:latest` image, the same finding E26.3 recorded) against a real local
  Ollama endpoint (`qwen2.5-coder:14b`, genuine inference, no mocks). Converged on
  attempt 1 of 3; run artifacts committed at
  `.ai-project/artifacts/agentic-runs/P9-M31-E31.1-PROVE/`.

## Design Decisions (spec §Design Decisions, resolved)

1. **Declaration mechanism = 1B (Execution Chat Starter field only).** Rejected 1A/1C:
   a project-wide `.ai-project.yml` field cannot represent "this session is agentic, the
   next is manual" without becoming a constantly-edited, drift-prone value; the starter
   is already produced fresh per concrete instance by the natural author (the parent
   chat) at the natural moment (instance creation).
2. **Governance home = `chat-hierarchy.md`.** Already the single authoritative reference
   for the four levels; the new section sits immediately after the Hierarchy Summary
   Table it disambiguates against, and cross-links the starter templates where the
   declaration physically lives.
3. **G7 = adopted, as guidance.** M30's own closure declaration offered it as a
   recommendation, not a requirement; the measured-evidence framing (53% vs. 23%) is
   stated so a future reader can judge whether it still applies rather than treating it
   as an unconditional rule.
