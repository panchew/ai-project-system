### Summary

Record the manual/agentic mode model for Phase/Milestone/Epic chats: per-instance
declaration mechanism, per-level semantics, absence-means-manual default, Creation/HQ
recorded manual-only permanent. Produce real demonstration evidence of a chat instance
started in each mode. This epic is governance recording only — no runtime code, no
model-routing changes.

### Binding constraints (carry into every decision)

**Hard Constraints (verbatim from the Milestone spec, all five carried; #2 and #5 are this
epic's direct surface):**

1. Refusal means refusal — a warning is not a guardrail (E31.3 enforces; E31.1 must not
   record semantics that would let a future guardrail be bypassable).
2. **No agentic default** — absence of a per-instance declaration means manual. This is the
   constraint E31.1 directly executes: every level's semantics text must say so.
3. Policy consumed, not re-authored — E31.1 does not touch `model-routing-policy.md`; if it
   references the policy, link only, never restate.
4. Local loadability never assumed — not E31.1's code surface, but its agentic-semantics
   text must not imply a local model is always available.
5. Suite green at every merge — 307 baseline, no regressions, no new skips.

**Naming collision (from the Epic spec's grounding):** `chat-hierarchy.md` already uses
"Mode" for level selection (HQ/Phase/Milestone/Epic). Do not reuse that word for the new
manual/agentic axis — pick a distinct term (e.g. "Execution Mode") and say so explicitly
where you introduce it.

### Design Decisions (yours to resolve — decide, document, move; do not escalate to ask)

1. **Declaration mechanism** — `.ai-project.yml` field, a section in each instance's own
   Execution Chat Starter, or both. The Epic spec's Design Decision 1 lays out the
   tradeoffs (yml is project-global and fits "per instance, one by one" poorly on its own;
   starters are already produced fresh per concrete instance). Whatever you choose must
   let a reader determine any instance's mode from its declaration, with absence resolving
   to manual.
2. **Governance home** for the mode model + manual-permanence rule —
   `governance/systems/chat-hierarchy.md` (recommended anchor — already owns "what each
   level is"), the yml-spec, or AOG. Resolve the naming collision explicitly wherever you
   land.
3. **G7 (one-task-one-session) disposition** — adopt into the mode model's
   session-discipline prose as labeled, measured-evidence-based guidance, or record
   explicitly that it is not adopted and why. Either is compliant; silence is not.
