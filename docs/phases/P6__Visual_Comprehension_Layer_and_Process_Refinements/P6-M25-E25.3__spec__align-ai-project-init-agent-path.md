# Epic E25.3 — Align `ai-project-init` agent path (P6-GH-11)

## Context

P5 established **`.ai-project/agents/`** as the canonical, tool-neutral location for agent files —
documented in QUICK-START and the integration guides. But `bin/ai-project-init` still writes
**`.github/agents/`**. The initializer's script and the framework's own docs disagree: a fresh
project scaffolded by the CLI lands its HQ agent in a GitHub-specific directory the docs say is only
a tool-specific copy. This is the third P5 carry-forward (P6-GH-11) — a small, self-contained
script + test + doc fix, fully independent of the visual layer (M23/M24) and of the default-accept
work (E25.1/E25.2/E25.4/E25.5).

This Epic changes the initializer to write the canonical **`.ai-project/agents/`** path, **adds a
test** (none references either agent path today), and **reconciles QUICK-START** so the docs and the
script agree. It is a genuinely small epic — a path change, one test, and a doc alignment.

> **Provenance:** Authored by the Milestone Chat (P6-M25) on 2026-07-03 under GH-8 adjacency (the
> Milestone Chat authors this Epic spec + Starter; the Coding Agent performs the edits). E25.3 is the
> **last** M25 epic; on its merge, M25 is ready for its Closure Declaration.

> **Source:** P6 phase spec (P6-GH-11); P5 carry-forward; M25 Milestone spec, "Epic Detail → E25.3".
> Settled intent — not for re-debate.

**Grounding (verified on `milestone/M25`):**

- `bin/ai-project-init` writes `.github/agents/` in three places:
  - **L133** — `mkdir -p "$project_dir/.github/agents"` (directory scaffolding).
  - **L327** — `local agents_dir="$project_dir/.github/agents"` (in `install_hq_agent()`), which
    drives `dest_file="$agents_dir/hq.agent.md"` (L329) and `mkdir -p "$agents_dir"` (L331).
  - **L408** — `git add .github/agents/hq.agent.md`.
  - The source is `governance/agents/hq.agent.md`; the installed file is **`hq.agent.md`**.
- **No test references either agent path** (`grep -rn "\.github/agents\|\.ai-project/agents" tests/`
  returns nothing) — E25.3 must **add** coverage.
- **QUICK-START.md** documents `.ai-project/agents/` as canonical and a `.github/agents/` copy:
  - **L92** — `.ai-project/agents/governance.agent.md`. *"(The CLI also writes a copy to
    `.github/agents/`, which …)"* — the doc claims a dual write.
  - **L166**, **L735** — `.ai-project/agents/governance.agent.md` (canonical, tool-neutral).
  - **L736** — `.github/agents/governance.agent.md` (GitHub Copilot auto-detection copy).
- **Naming discrepancy (flag, do not fix here):** the script installs **`hq.agent.md`**; QUICK-START
  refers to **`governance.agent.md`**. E25.3 aligns the *path* (`.github/agents/` →
  `.ai-project/agents/`), not the *filename*. The `hq.agent.md`-vs-`governance.agent.md` mismatch is
  a **separate pre-existing discrepancy** — note it in the Delivery Notice as a candidate
  follow-up; do not resolve it in E25.3 (out of scope; avoids scope creep).

## Problem Statement

The canonical agent location is `.ai-project/agents/` (tool-neutral, per P5), but the one piece of
tooling that scaffolds a project — `bin/ai-project-init` — writes `.github/agents/`. Docs and script
disagree, no test guards either path, and a newly-initialized project puts its HQ agent where the
docs say only a tool-specific copy belongs. This Epic makes the initializer write the canonical path,
adds a test to guard it, and reconciles the docs.

---

## Goals

By the end of this Epic, the system must:

1. **`bin/ai-project-init` writes the canonical `.ai-project/agents/`** — the `agents_dir` (L327),
   the scaffolding `mkdir` (L133), and the `git add` path (L408) all target `.ai-project/agents/`.
2. **A test asserts** the initializer writes `.ai-project/agents/hq.agent.md` (none exists today).
3. **QUICK-START (and any sibling doc) agrees with the script** — the path the CLI writes matches the
   docs; the `.github/agents/` copy is documented consistently with whatever the script actually does.
4. **Full test suite passes.**

## Scope of Work

### 1. `bin/ai-project-init` — write the canonical path

Change the three `.github/agents` occurrences to **`.ai-project/agents`**:
- **L327** `agents_dir="$project_dir/.ai-project/agents"` (this alone fixes L329 `dest_file` and
  L331 `mkdir`, which derive from `agents_dir`).
- **L133** `mkdir -p "$project_dir/.ai-project/agents"`.
- **L408** `git add .ai-project/agents/hq.agent.md`.

**Design call (Epic-level, within M25 scope) — the `.github/agents/` copy:** the phase spec directs
the canonical write to `.ai-project/agents/`, "not `.github/agents/`." Whether to **also** keep a
`.github/agents/` tool-specific copy (which QUICK-START L736 documents as a GitHub Copilot
auto-detection convenience) is this Epic's call:
- **Option A (recommended — simplest):** write **only** `.ai-project/agents/`; reconcile QUICK-START
  (L92 parenthetical, L736 row) to reflect that the CLI writes the canonical path (drop or soften the
  `.github/agents/` "the CLI also writes a copy" claim so docs match the script).
- **Option B:** write `.ai-project/agents/` **and** also a `.github/agents/` copy (matching
  QUICK-START's documented dual write); then the canonical write is `.ai-project/agents/` and
  QUICK-START L92/L736 already agree.
Either way, **the canonical write MUST be `.ai-project/agents/`**, and **docs must match the final
script behavior** (no claim that the CLI writes a path it doesn't).

### 2. Add a test

Add a test (in the existing `tests/` suite, matching its style — e.g. the initializer/CLI test
module) that runs `bin/ai-project-init` (or its agent-install path) against a temp project and
**asserts `.ai-project/agents/hq.agent.md` exists**. If Option B is chosen, the test may also assert
the `.github/agents/` copy; the **required** assertion is the canonical `.ai-project/agents/` path.

### 3. Reconcile the docs

Update **QUICK-START.md** so the CLI's documented behavior matches the script: the path the
initializer writes is `.ai-project/agents/`; the `.github/agents/` mention (L92 parenthetical, L736
row) is accurate for whatever Option (A/B) the script implements. Check for sibling docs (integration
guides) that describe the CLI writing `.github/agents/` and align them too.
