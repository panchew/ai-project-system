# Epic E25.2 — Codify SN-13 default-accept (P6-GH-10)

## Context

The delivery model actually in force is not the one written down. **SN-13 default-accept** — *a
parent chat auto-accepts a clean child delivery by silence; a Review Decision is the exception path
only* — has governed **every** delivery since P5, including all of M23, M24, and (just now) E25.1.
P5's own closure declaration records it explicitly: *"HQ accepted P5 without issuing a Phase Review
Decision artifact. The clean delivery … authorized the merge by silence … A Phase Review Decision
artifact was initially committed and then reverted as inconsistent with SN-13."* The same
declaration flags the fix: *"SN-13 formal codification (GH-10) is an open follow-up item — the
protocol operated correctly during P5 but is not yet written into AOG/PSG or the Execution Chat
Starter templates."*

Meanwhile the codified text still describes the **superseded always-review model**: PSG §11.5's
flow ends *"Acceptance Recorded in Review Decision,"* PSG §13A/§13B and AOG §3.6/§3.7 say the parent
*"issues Review Decisions … when all … are accepted,"* and the two Execution Chat Starter templates
carry *"Stage 2: … issue Review Decisions."* The written model and the operating model disagree.
This Epic closes P6-GH-10 by writing the default-accept model into **AOG + PSG + the two starter
templates** and **reconciling** the contradictory always-review language — **without** deleting the
Layer-8 human-review requirement.

This is the **subtle epic of M25.** It is a **reconciliation, not an append**: codify default-accept
*and* remove the contradiction, while preserving human review where the framework mandates it. The
same "name the surfaces, don't let it leak" discipline the M23 by-link reversal used applies here —
every contradictory surface is named below and must be reconciled; nothing may be left asserting the
old happy path, and nothing that carries the human-review requirement may be deleted.

## Problem Statement

Two models coexist in the framework and contradict each other. The **operating** model (SN-13
default-accept) has silently governed every delivery since P5: a parent chat accepts a clean child
delivery by silence, and a Review Decision is issued only when a delivery is not clean. The
**codified** model (always-review) still says the opposite: the happy path *ends* in a Review
Decision artifact ("Acceptance Recorded in Review Decision"), the parent *"issues Review Decisions,"*
and acceptance is *"recorded in the Review Decision."* Because the written model is wrong, every new
Execution Chat Starter generated from the templates inherits the superseded happy path, and any
reader trusting the docs would produce an artifact SN-13 says not to produce (exactly the reverted
Phase Review Decision P5 describes). This Epic makes the written model match the operating model —
codifying default-accept and removing the contradiction — while **preserving** the Layer-8
human-review requirement that default-accept does *not* abolish.

---

## Goals

By the end of this Epic, the system must:

1. **Codify default-accept normatively in AOG and PSG.** A new subsection in each defines the model:
   **happy path** = the parent chat accepts a clean child delivery **by silence** (no Review Decision
   artifact; the merge + acknowledgment is the acceptance record); **exception path** = a **Review
   Decision** is issued only when a delivery is **not** clean (reject / accept-with-follow-ups).
2. **Reconcile the contradictory always-review language** at every named surface (PSG §11.5
   flow + rules 3/5, §12, §13A/§13B, §1A; AOG §3.6/§3.7 and lines ~728/~817; both starter templates)
   so **no** remaining text asserts the Review-Decision-as-happy-path-artifact model.
3. **Preserve the Layer-8 human-review requirement.** Default-accept governs the **parent-chat → child
   acceptance gate** and the **acceptance-artifact** question — it does **not** delete human review.
   Scope precisely which gate each governs; where §1A / §11.5 could read as conflicting with
   silence-accept, disambiguate rather than delete the human-review steps.
4. **Update the two Execution Chat Starter templates** so newly generated Phase/Milestone starters
   describe default-accept (issue a Review Decision only on the exception path).
5. **Wire the downstream pointers:** E25.1's §5C Step 6 and the phase-closure-declaration template's
   `acceptance_model` reference resolve to the new subsection.
6. **Record the change** (AOG v2.5.1 → v2.6.0, PSG v2.2.0 → v2.3.0, Changelog rows) and **keep the
   full test suite green.**

---

## Non-Goals

This Epic explicitly does **not** aim to:

- **Delete or weaken Layer-8 human review.** The human's independent review (§11.5 "Human Review",
  Rule 2 "Humans OWN review") and human judgment as authoritative are **preserved**. Default-accept
  is about *whether a Review Decision artifact is mandatory on the happy path* and *the parent-chat
  silence-accept of a clean child*, not about removing the human from the loop.
- **Redefine the Review Decision or Epic Review Seal artifacts.** Their templates and structure are
  unchanged; E25.2 changes *when* a Review Decision is issued (exception only), not *what* it is.
- **Rework the §5C phase-closure sequence or the closure gates.** E25.1's §5C stands; E25.2 only
  ensures §5C Step 6's by-reference pointer resolves to the new normative text.
- **Touch the initializer** (`bin/ai-project-init` — E25.3) or any **M23/M24 visual surface**
  (AOG §17, guide §5/§7/§8).
- **Change the branch/PR promotion mechanics** (§5B consolidation, hierarchy). Only the *acceptance
  model* around them is reconciled.
- Re-debate SN-13 or the default-accept intent.

## Scope of Work

### 1. Normative default-accept definition (AOG + PSG)

Add a normative subsection to **PSG** (recommended **§11.6 "Default-Accept (SN-13)"**, immediately
after §11.5 — exact number/placement is the Coding Agent's design call within M25's scope) and a
corresponding block to **AOG** near the Stage-2 review/acceptance guidance (§3.6/§3.7 and the
lines ~728/~817 region).

**Must define:**
- **Happy path (default-accept):** a parent chat accepts a **clean** child delivery **by silence** —
  a delivery meeting its Definition of Done, acceptance criteria, and spec is accepted **without** a
  Review Decision artifact; the **merge (+ in-chat acknowledgment)** is the acceptance record.
- **Exception path:** a **Review Decision** (and, at Epic level, the Epic Review Seal) is issued
  **only when a delivery is not clean** — to reject or accept-with-follow-ups.
- **Which gate default-accept governs:** the **parent-chat → child** acceptance gate (Phase Chat
  accepts a clean Milestone; Milestone Chat accepts a clean Epic; HQ accepts a clean Phase), and the
  **acceptance-artifact** question (silence vs. Review Decision).
- **What is preserved:** **Layer-8 human review** remains available and authoritative; where the
  framework requires human confirmation (e.g., a human-authorized merge on an epic PR), that
  requirement stands. Default-accept removes the *mandatory Review Decision artifact on the happy
  path*, not the *human's review*.

### 2. Reconcile the always-review language (the named surfaces)

Edit each surface so no text asserts the Review-Decision-as-happy-path model, while preserving the
human-review requirement:

- **PSG §11.5** — the **flow diagram** last step (`Acceptance Recorded in Review Decision`) and
  **Rules 3 and 5** must reflect default-accept (silence = acceptance on the happy path; Review
  Decision on the exception path). **Rule 2 (Humans OWN review) and the "Human Review" definition
  stay.** Point to the new §11.6.
- **PSG §12** — the "recorded separately in the Review Decision" sentence reconciled to "on the
  exception path" (a clean delivery produces no Review Decision).
- **PSG §13A / §13B** — "issues Review Decisions … when all … are accepted" → default-accept
  phrasing (accepts clean deliveries by silence; issues a Review Decision only on the exception path).
- **PSG §1A** — steps 3–6: **preserve** the Human Review / Epic Review Seal gate but reconcile the
  "explicit HQ delivery authorization *per epic*" / always-review reading with silence-accept.
  Disambiguate the two gates in-place (or via a pointer to §11.6); **do not delete** the human-review
  steps. *This is the most delicate edit — get the gate-scoping right.*
- **AOG §3.6 / §3.7** — the "issues … Review Decisions" clauses → default-accept phrasing (keep the
  E25.1 §5C delivery language in §3.6 intact).
- **AOG lines ~728 / ~817** — "record them in the Review Decision" / "Acceptance is documented in the
  Review Decision and becomes immutable" → scope to the exception path (a Review Decision, *when
  issued*, is immutable; the happy path issues none).

### 3. Execution Chat Starter templates

Update both `governance/templates/phase-execution-chat-starter.md` and
`governance/templates/milestone-execution-chat-starter.md` Stage-2 lines so a generated starter
describes default-accept: *oversee delivery, accept clean deliveries by silence, issue a Review
Decision only on the exception path, and merge when all children are accepted.*

### 4. Downstream continuity

- Ensure **§5C Step 6**'s by-reference pointer and the **phase-closure-declaration template**'s
  `acceptance_model` note resolve to the new §11.6 (add the cross-reference; do not alter §5C's
  steps).

### 5. Changelog + version bumps

- **AOG v2.5.1 → v2.6.0** (minor: new normative acceptance model) + Changelog row citing E25.2.
- **PSG v2.2.0 → v2.3.0** (minor) + Changelog row citing E25.2.

## Technical Constraints

- **Format:** Markdown (AOG, PSG, two templates). No code, no plumbing.
- **Reconciliation, not append:** codify default-accept **and** remove the contradiction. An
  additive subsection that leaves §11.5's flow/rules and the "issues Review Decisions" phrasings
  intact **fails** — the contradiction must be gone.
- **Do not over-delete:** preserve §11.5 "Human Review" + Rule 2, and §1A's human-review / Epic
  Review Seal steps. Default-accept scopes the *acceptance artifact* and the *parent-chat→child
  silence-accept*, not the *existence of human review*. When in doubt, disambiguate the gate rather
  than delete the sentence.
- **Two gates, stated explicitly:** (A) **Layer-8 human review** — preserved; (B) **parent-chat →
  child acceptance artifact** — default-accept (silence on the happy path, Review Decision on the
  exception path). The epic's normative text must make the distinction unambiguous so future readers
  do not re-collapse them.
- **Scope of files:** `governance/PROJECT-SYSTEM-GUIDELINES.md`,
  `governance/AI-OPERATING-GUIDELINES.md`,
  `governance/templates/phase-execution-chat-starter.md`,
  `governance/templates/milestone-execution-chat-starter.md`. Do **NOT** touch `bin/ai-project-init`
  (E25.3), the visual surfaces (M23/M24), the §5C **steps** (E25.1 — only wire Step 6's pointer),
  or the Review Decision / Epic Review Seal artifact templates.
- **PSG contention with E25.1 is resolved:** E25.1 is **merged** to `milestone/M25`; branch
