# Epic E25.5 — Reconcile default-accept in the artifact templates tier (P6-GH-10, final follow-on)

## Context

E25.2 codified **SN-13 default-accept** in the normative docs (PSG §11.6 / AOG §14); E25.4 aligned
the reference/protocol/role/diagram tier. A **definitive `governance/`-wide sweep during E25.4's
Stage-2 review** confirmed the reconciliation is complete **except for a small, bounded remainder in
the artifact templates tier** — three template files still frame the **Review Decision as the
mandatory merge gate** on the happy path, which default-accept has superseded (a clean delivery is
accepted by silence and merges on parent acceptance; a Review Decision is the exception path only).

This Epic closes that last remainder, so **no codified text contradicts default-accept** (milestone
criterion #4) framework-wide. It is deliberately small: aligning the template framing to the model
E25.2 codified — **referencing PSG §11.6 / AOG §14, not restating them** — and **preserving** the
artifacts themselves (the Review Decision template, and the Merge Authorization artifact, which is
the **human-authorized merge signal §11.6 explicitly preserves**).

> **Provenance:** Authored by the Milestone Chat (P6-M25) on 2026-07-03. **E25.5 was added to M25 by
> Phase Chat decision this session** (the final default-accept close-out; the Phase Chat also chose
> to defer the separate ordering inconsistency below as a carry-forward). Per GH-8 adjacency, the
> Milestone Chat authors this Epic spec + Starter; **updating the M25 Milestone spec's epic list to
> include E25.4 and E25.5 is the Phase Chat's to make**. The Coding Agent performs the edits.

> **Source:** SN-13 (P5); P6-GH-10; E25.2 (the normative codification); the E25.4 Stage-2 sweep. The
> default-accept model is settled — not for re-debate.

**Grounding (verified on `milestone/M25` after E25.1/E25.2/E25.4 — the templates-tier residual):**

- **`governance/templates/merge-authorization.md`** — the intro says the Merge Authorization *"is
  the explicit 'you may now merge' signal that **follows an accepting Review Decision** — no merge
  may happen without it"* (L11–12), and Related artifacts lists *"[Review Decision] (**must precede
  this**)"* (L15). Under default-accept a clean delivery has **no** Review Decision, yet still merges
  (on parent acceptance) — so "follows an accepting Review Decision / must precede this" contradicts
  the model. **The Merge Authorization artifact itself stays** — it is the human-authorized merge
  go-ahead §11.6 preserves; only its *coupling to a mandatory Review Decision* is reconciled. (Uses
  `last_updated`, no version field.)
- **`governance/templates/completion-notice-epic.md`** — the "Next Action" block (L66–69): *"Parent
  Chat reviews this artifact, then issues either: Review Decision (Accept) → authorizes merge /
  Review Decision (Reject) → requires rework."* This frames a Review Decision as the mandatory
  next action for **every** completion. Reconcile: a clean delivery is accepted by silence (parent
  acceptance authorizes merge, no artifact); a Review Decision is issued only on the exception path.
- **`governance/templates/README.md`** — the catalog row (L37): *"Review Decision | … | Reviewing
  chat issues Accept or Reject on a Completion Notice."* Light touch: note the Review Decision is the
  **exception path** (a clean delivery is accepted by silence).
- **`governance/templates/epic-review-seal.md`** (L24, L177) — *"the decision is recorded in the
  Review Decision."* **Borderline / design call:** the Epic Review Seal is itself the **exception-
  path** artifact (§11.5, post-E25.2, states the Seal is produced "exception path only"), so this
  describes an exception-path relationship and is arguably already consistent. **Preferred:** leave
  it, or add a one-line "on the exception path" clarifier — do **not** redefine the Seal.
- **Preserve:** `governance/templates/review-decision.md` (the Review Decision artifact template —
  untouched); the Merge Authorization artifact (kept); any worked REJECT content (exception path).
- **Versions:** these template files carry **no version field** (they use `last_updated`) — so
  **no version bumps**; update `last_updated`. **PSG/AOG are NOT re-bumped** — E25.5 references the
  already-codified §11.6/§12.

**Separate carry-forward (NOT in this Epic — recorded for the Phase Chat):** the pre-existing
**P4.1-vs-PSG §12 ordering inconsistency** — the P4.1 artifact-protocol lifecycle
(Completion Notice → review → merge → Delivery Notice) differs from PSG §12's
Delivery-Notice-precedes-review Epic lifecycle (execution → Delivery Notice → [STOP] → review).
This is **not** a default-accept issue. Per the Phase Chat's decision this session it is deferred as
carry-forward **P6-GH-14**; the Phase Chat records it at phase level (roadmap / phase spec). E25.5
does not touch it.

## Problem Statement

Three artifact-template files still teach that a Review Decision is the mandatory merge gate on the
happy path — the last place the superseded always-review model survives after E25.2 + E25.4. Every
Completion Notice or Merge Authorization generated from these templates would inherit the wrong
model, and milestone criterion #4 ("No codified text contradicts default-accept") cannot be
certified framework-wide until they are reconciled. This Epic aligns the template framing to
§11.6/§12 — preserving the Review Decision and Merge Authorization artifacts themselves — so the
whole framework, normative through template, tells one story.

---

## Goals

By the end of this Epic, the system must:

1. **Reconcile `merge-authorization.md`** so the Merge Authorization follows **parent acceptance**
   (silence-accept of a clean delivery per §11.6, or an exception-path Review Decision) — not a
   mandatory Review Decision — while **keeping the Merge Authorization artifact** (the preserved
   human-authorized merge signal).
2. **Reconcile `completion-notice-epic.md`** so the "Next Action" describes default-accept (clean →
   accepted by silence, parent acceptance authorizes merge; Review Decision only on the exception
   path).
3. **Reconcile `README.md`** catalog row to note the Review Decision is the exception path.
4. **Resolve `epic-review-seal.md`** (leave as an exception-path artifact, or add a one-line
   clarifier) — do not redefine the Seal.
5. **Reference §11.6/§12, not restate;** preserve the Review Decision + Merge Authorization
   artifacts; **no version/PSG/AOG bumps** (update `last_updated`).
6. **Grep-prove** no template-tier text asserts Review-Decision-as-mandatory-happy-path, and **keep
   the suite green.** With E25.2 + E25.4 + E25.5, **criterion #4 is met framework-wide.**

## Scope of Work

### 1. Reconcile the three template files (reference §11.6/§12)

- **`governance/templates/merge-authorization.md`** — reword the intro *"follows an accepting Review
  Decision — no merge may happen without it"* and the Related-artifacts *"Review Decision (must
  precede this)"* so the Merge Authorization follows **parent acceptance** (silence-accept per §11.6,
  or an exception-path Review Decision). Keep the artifact and its "no merge without this
  authorization" force (that is the preserved human-authorized merge gate). Update `last_updated`.
- **`governance/templates/completion-notice-epic.md`** — reword the "Next Action" block (L66–69):
  a clean delivery is **accepted by silence** (parent acceptance authorizes merge; no Review
  Decision); a Review Decision is issued **only on the exception path** (reject / accept-with-
  follow-ups). Update `last_updated`.
- **`governance/templates/README.md`** — annotate the Review Decision catalog row (L37) as the
  **exception path** (clean deliveries are accepted by silence). Update `last_updated` if present.

### 2. Resolve `epic-review-seal.md` (design call)

Leave L24/L177 as-is (the Epic Review Seal is the exception-path artifact, so "recorded in the
Review Decision" is consistent), **or** add a one-line "on the exception path" clarifier. Do **not**
redefine the Seal or its schema.

### 3. Reference + preserve; no bumps

- Point to PSG §11.6 / AOG §14; do not restate the model. **No version bumps** (templates use
  `last_updated`); **PSG/AOG not re-bumped**.
- Preserve `review-decision.md` and the Merge Authorization / Epic Review Seal artifacts.
