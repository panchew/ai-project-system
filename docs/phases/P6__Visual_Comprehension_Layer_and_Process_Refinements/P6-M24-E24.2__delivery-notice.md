## Execution Summary

Documented the **clip convention** as governance, not plumbing. A clip is a short video that renders
**one** governance node's proposed→implemented arc (§16.6, established by the merged E24.1) as motion —
the most CFO-facing visual, doubling as publishable media. Two surgical, additive edits:

- **AOG §16.7 "Clips"** states the policy: a clip is **single-parent** (binds to exactly one epic /
  milestone / phase via the §7 binding with `What: clip`, narrating that node's two tracks, not
  spanning the cascade), **hosted and linked, never committed** (by-link holds for `.webm` as for
  images), and the **no-cross-cutting-reel boundary** (a project-spanning montage is deferred in P6).
  It points to guide §8 for production and publish and **references §7 for the schema** rather than
  restating it.
- **Guide §8 "Clips"** is the how-to: **production from the arc** on the verified LTX-Video path
  (`ltxv-video.json` → `.webm` via `--type video --workflow`), **citing** the preserved reference
  bundle for the exact command and verified parameters (768×512, 97 frames @ 25 fps) — no
  re-transcription, no new plumbing; a **worked §7 clip binding** (`What: clip`, hosted `.webm` link,
  `implemented`); the **publish path as reuse** of the same hosted asset; and the recorded resolution
  of **Open Design Question A — reference, not vendor**.

No code, helper, schema, config, or storage-prose change. `clip` was used as the existing §7 `What`
value (not re-added). Full suite green.
