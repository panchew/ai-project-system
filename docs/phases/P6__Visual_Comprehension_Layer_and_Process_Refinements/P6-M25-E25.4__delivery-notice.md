## Execution Summary

Aligned the reference tier to the SN-13 default-accept model E25.2 codified, referencing
PSG §11.6 / AOG §14 throughout — never restating or re-bumping the normative model. All
seven named surfaces now teach: a clean delivery is accepted by silence (merge + in-chat
acknowledgment; no artifact); a Review Decision is the exception path only.

**The two hard contradictions:**
- `artifact-communication-protocol.md` Workflow Rule 2 — *"A Review Decision (Accept)
  MUST precede a Delivery Notice"* — reconciled to: parent **acceptance** must precede
  the merge and its Delivery Notice; on the happy path that acceptance is silence (no
  Review Decision exists); on the exception path the Review Decision (Accept with
  follow-ups) must precede them.
- `roles-authorization-team-governance.md` Epic-Agent gate — *"Cannot merge PR without
  Review Decision (Accept)"* — reconciled to: cannot merge without **parent acceptance**
  (silence-accept of a clean delivery per §11.6, or an exception-path Review Decision);
  a rejected delivery must not merge.

**ACCEPT worked examples:** the milestone starter's ACCEPT example was **reframed as a
silence-accept narration** (in-chat acknowledgment + merge, no artifact) so the section
now shows both paths side by side; the protocol's and HQ starter's ACCEPT examples were
**reframed as exception-path accept-with-follow-ups** artifacts (keeping the schema
demonstration of `decision: accept` legitimate). All worked **REJECT** examples kept,
retitled "(exception path)".

**Bugfix carve-out:** `bugfix-epic-workflow.md` gained a carve-out note in the Expedited
Review Process section — the Bugfix Workflow is a deliberate exception to §11.6: HQ
always issues an explicit Review Decision (Accept or Reject) under the 4-hour SLA, never
silence-accept. Explicit review and the SLA are unchanged (v1.2.0).
