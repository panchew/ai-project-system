### Summary

Reverse the v5.0.0 **commit-the-binary** storage guidance to **by-link** across four named
surfaces, leaving **no** instruction to commit a generated binary anywhere, and record the change
**as a reversal of v5.0.0** in the AOG changelog and a guide changelog. This is
**governance/documentation, not plumbing** — the helper's runtime behaviour does not change; only
its output *guidance* is clarified.

### Problem Statement

Shipped v5.0.0 guidance tells adopters to commit generated binaries into
`.ai-project/visuals/<level>/<id>.<ext>` so each visual "travels with its decision record." SN-16
(ratified 2026-06-29) reverses this: generated visual material is **referenced by link, never
committed to git**, and the **adopter owns the storage backend**. The instruction to commit appears
across four surfaces; missing any one lets a binary leak back into git, so every surface must move
to by-link and the reversal must be recorded as a reversal.

### Goals

1. **Describe by-link on every named surface** — guide (§4 prose, §1 source-repo note, §5 + §3
   examples), AOG §16.5, helper output guidance — with **no commit-the-binary instruction remaining
   anywhere** (residual `.ai-project/visuals/` example paths count).
2. **Leave the helper's behaviour unchanged** — clarify only the docstring example and `--output`
   help text (`--output` = local working file to host and link, not commit). No upload step.
3. **Confirm the test is already by-link-consistent** and record that — no make-work edit.
4. **Record the reversal as a reversal of v5.0.0** in the AOG changelog and a guide changelog.
5. **Leave structural-diagram (Mermaid/PlantUML) guidance untouched.**
