# Epic E24.2 — Clips as documentation + publishable media (P6-VC-4)

## Context

Milestone M24 has two halves. E24.1 (merged to `milestone/M24`, merge `0dcd14a`) turned M23's
binding *mechanism* into routine *behavior*: AOG §16.6 now directs every enabled level to produce
**both** a *proposed* and an *implemented* visual, recorded via the §7 `State` field. This Epic
delivers the **second half** — the **clip convention**. A **clip** is the single most CFO-facing
artifact: it takes one governance node's proposed→implemented arc (exactly the two-track behavior
E24.1 established) and renders it as a short video the CFO can watch to follow the flow, and which can
be published to social channels as a byproduct.

Everything a clip needs already exists. `clip` is **already a `What` value in §7**
(`image | infographic | mockup | diagram | clip`) — this Epic does **not** add it. The **LTX-Video
path is verified end-to-end** (SN-16): the reference bundle documents `ltxv-video.json` → `.webm` via
`bin/ai-project-visual --type video --workflow …`, and the helper already accepts `--type video` with
a supplied `--workflow` graph. What is missing is the **convention**: that a clip binds to **exactly
one** node (single-parent), how it is **produced** from the proposed→implemented arc on the existing
path, and how it is **published** (the same hosted asset reused, not a separate production). This Epic
documents those three things and records the resolution of Open Design Question A.

This is **governance/documentation, not plumbing and not new schema.** No helper, producer, config,
or §7-schema change. The Coding Agent documents the clip convention at policy altitude (AOG §16) and
as how-to + a worked example (the guide), referencing — never rebuilding — the verified LTX-Video
path and the merged §7 binding.

**Grounding (verified on `milestone/M24` after the E24.1 merge — anchors this Epic plans against):**

- **`clip` is already a `What` value in §7** — `image | infographic | mockup | diagram | clip`. A clip
  is bound like any visual: a §7 block whose `Level` is the one node it belongs to and whose `What` is
  `clip`. E24.2 documents the convention (single-parent, production, publish); it does **not** add the
  value or restate the schema.
- **The two-track behavior a clip narrates is now live (E24.1 / §16.6).** A clip *is* one node's
  proposed→implemented arc rendered as video — it builds directly on §16.6. This Epic depends on that
  merged behavior.
- **The LTX-Video path is verified end-to-end (no new plumbing).** The reference bundle
  (`.ai-project/artifacts/reference/comfyui-endpoint/`, git-tracked: `ltxv-video.json`,
  `flux-schnell.json`, `sdxl.json`, `VISUAL-ARTIFACTS.md`) documents `ltxv-video.json` → `.webm` via
  `bin/ai-project-visual --type video --workflow <graph>`; `VISUAL-ARTIFACTS.md` records LTX-Video →
  valid `.webm` as verified (defaults 768×512, 97 frames @ 25 fps). The helper already accepts
  `--type video` and requires a supplied `--workflow` graph — the exact command lives in the bundle's
  `VISUAL-ARTIFACTS.md`, which E24.2 **cites** rather than re-transcribing.
- **By-link covers video (M23, unchanged).** A clip is hosted and linked via §7, **never committed** —
  the by-link reversal covers `.webm` exactly as it covers images. Do not regress this.
- **Single-parent + no cross-cutting reel (SN-16 decision 3).** A clip binds to exactly **one** node
  (one epic, milestone, or phase). A project-spanning editorial montage is **explicitly deferred** in
  P6 — this boundary must be stated.
- **AOG §16 home.** §16 now runs §16.1–§16.5 plus §16.6 (E24.1). The clip policy lands as a **new
  subsection** (e.g. **§16.7 "Clips"**); the production/publish how-to + worked example land as a
  **new guide section** (e.g. **§8 "Clips"**, after §7, before "Related documents"). Exact numbers are
  this Epic's design call within M24's scope. AOG minor bump follows §16's history: v2.4.0 → **v2.5.0**.

## Problem Statement

The most CFO-facing artifact — a **clip** that narrates a node's proposed→implemented arc and can be
published to social channels — has a verified production path (LTX-Video) and a `What: clip` slot in
§7, but **no documented convention**. Nothing states that a clip binds to exactly one node
(single-parent), how it is produced from the proposed→implemented arc on the existing path, or that
publishing it is *reuse of the same hosted asset* rather than a separate production. Without the
convention, agents have no guidance on how to bind a clip, will be tempted to build a cross-cutting
reel P6 has deferred, may reach for new plumbing that already exists, and have no stated publish path.
And Open Design Question A (vendor vs. reference the workflow JSONs) is resolved in the milestone spec
but not yet recorded in the governance surfaces. This Epic supplies the clip convention (single-parent
binding, production-from-the-arc, publish-as-reuse), states the no-cross-cutting-reel boundary, and
records the ODQ A resolution.

---

## Goals

By the end of this Epic, the system must:

1. **Document the clip convention as single-parent.** A clip binds to exactly **one** governance node
   (epic / milestone / phase) via §7 (`What: clip`), tells that node's proposed→implemented story, and
   is **hosted-and-linked, never committed** (by-link). The **no-cross-cutting-reel** boundary is
   stated (deferred in P6).
2. **Document clip production from the arc.** How a clip is produced from the proposed→implemented arc
   on the **verified LTX-Video path** (`ltxv-video.json` → `.webm`, via `bin/ai-project-visual
   --type video --workflow …`), referencing the existing contract bundle — **no new helper
   capability**.
3. **Document the publish path as reuse.** The publish path (YouTube / TikTok / IG / FB) is the **same
   hosted asset reused**, not a separate production — infrastructure-agnostic (no pipeline, no
   hosting built).
4. **Record the resolution of Open Design Question A** (reference, not vendor) in the governance
   surfaces, and **keep the suite green** (no plumbing touched).

---

## Non-Goals

This Epic explicitly does **not** aim to:

- **Add the `clip` `What` value or restate the §7 schema.** `clip` is already a §7 `What` value; a
  clip binds via the existing five-element block. E24.2 references §7 (documented once); it does not
  redefine or restate it.
- **Build a cross-cutting / project-spanning editorial reel.** Explicitly deferred in P6 (SN-16
  decision 3). A clip is single-parent; the montage is a separate later capability if ever wanted.
- **Add plumbing or a new helper capability.** ComfyUI and `bin/ai-project-visual` are done and
  verified; `--type video --workflow` already exists. No helper flag, no upload step (Open Design
  Question B stays resolved from M23), no config key.
- **Ship a runnable `workflows/` directory in-repo (Open Design Question A).** Resolution is
  **reference, not vendor** — the workflow JSONs + models stay CFO-side; the verified reference bundle
  is the documented reference E24.2 points at.
- **Regress by-link or touch storage prose.** A clip (`.webm`) is hosted and linked, never committed;
  AOG §16.5 / guide §4 are read, not edited.
- **Stand up or host a storage/publishing backend.** Where the clip is hosted/published is the
  adopter's decision (infrastructure-agnostic).
- **Re-open E24.1, the §7 schema, or the three SN-16 ratified decisions.**

## Technical Constraints

- **Format:** Markdown (AOG + guide). No code, no helper change, no config key, no upload step, no
  `workflows/` directory shipped in-repo.
- **Behavior/convention, not schema:** reference the §7 binding schema (documented once in guide §7);
  do **not** restate or redefine the five-element block or the `What`/`State` fields. `clip` is an
  **existing** `What` value — do not re-add it.
- **No new plumbing:** production references the **existing** verified LTX-Video path
  (`--type video --workflow`) and cites the reference bundle; do not modify `bin/ai-project-visual`,
  add a flag, or add an upload/publish step.
- **Bind a link, never a path:** the clip's binding `Link` is a hosted URL to the `.webm`; do not
  reintroduce `.ai-project/visuals/<level>/…` committed paths (that would regress by-link).
- **Reference, not vendor (ODQ A):** point at the CFO-side workflow contract via the preserved
  reference bundle; do not ship a runnable `workflows/` directory.
- **Surgical, additive edits:** add the AOG subsection and the guide section; do not restructure §16's
  existing subsections, §5/§7, or the guide's existing sections, and do not edit §16.5 / guide §4
  storage prose.
- **Scope of files:** `governance/AI-OPERATING-GUIDELINES.md` and `governance/guides/visual-artifacts.md`
  only. Do **NOT** touch `bin/ai-project-visual`, the reference bundle (read-only), the integration
  test, `ai-project-yml-spec.md` §3.5, or any template.
