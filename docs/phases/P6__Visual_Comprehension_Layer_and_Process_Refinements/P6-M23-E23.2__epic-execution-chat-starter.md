### Summary

Define the **link + metadata binding convention** that makes by-link survivable: a documented
**binding schema** (a link plus four load-bearing metadata fields) and a **per-level placement
convention** (where a binding attaches at Creation / HQ / Phase / Milestone / Epic), with the guide
and the relevant per-level templates updated so each level has a defined place to record a binding.
**Documentation only** — no code, no helper change, no upload step.

### Problem Statement

Under by-link (E23.1), the only thing in git is a **link** — and a bare link rots. The framework has
no defined way to record what the link points to, which level it belongs to, whether it shows the
proposed or implemented state, or a description that outlives the link — and no defined place at each
level to put that record. This Epic supplies the schema and the per-level placement.

### Goals

1. **Document a binding schema** in `governance/guides/visual-artifacts.md`: a **link** + four
   metadata fields (*what* / *which level* / *proposed-vs-implemented* / *short description*).
2. **Define a per-level placement convention** (Creation / HQ / Phase / Milestone / Epic): which
   artifact a binding attaches to and how the link gets there.
3. **Update the guide and the relevant per-level templates** so each level has a defined place to
   record a binding, consistent with the by-link model (binds a link, never a committed path).
4. **Keep the suite green**; leave E23.1's reversal and structural-diagram guidance intact.

## Required Content — the schema and where it lives

**The binding's five elements** (the exact representation — labeled list vs. compact table — is your
design call within M23's scope; it must carry all five and bind a link, never a path):

- **Link** — hosted URL of the generated visual (required; never a `.ai-project/visuals/...` path).
- **What** — `image` / `infographic` / `mockup` / `diagram` / `clip`.
- **Level** — `Creation` / `HQ` / `Phase` / `Milestone` / `Epic`.
- **State** — `proposed` or `implemented` (the two-track signal; a level may carry one of each).
- **Description** — short text that survives link rot (what the visual shows and why).

Recommended representation (refine the wording within the convention):

```markdown
**Visual binding**
- **Link:** <hosted URL>
- **What:** image | infographic | mockup | diagram | clip
- **Level:** Creation | HQ | Phase | Milestone | Epic
- **State:** proposed | implemented
- **Description:** <short text that survives link rot>
```

**Per-level placement (verified homes — precise location within each is your design call):**

| Level | Artifact | Home |
|-------|----------|------|
| Creation | `governance/templates/seed.md` | **Rule 4 → Project Brief's _Visual success_ element** (visual intent is already elicited here). |
| HQ | `governance/templates/genesis.md` | **HQ Context Packet** / HQ architecture record. |
| Phase | `governance/templates/phase-spec.md` | A **defined** binding placement (e.g., a short "Visual bindings" section). |
| Milestone | `governance/templates/milestone-spec.md` | A **defined** binding placement. |
| Epic | `governance/templates/epic-spec.md` | A **defined** binding placement. |

The convention must state explicitly that a binding records a **link** (never a committed path) and
that proposed/implemented is the **State** field — so a level can carry both a `proposed` and an
`implemented` binding.
