# Epic E26.1 — The `run-dev-agent` adapter (CONTRACT §7 shim)

## Context

The P3 orchestrator's Agentic Mode is proven (verify-loop 5/5) but every proven run substituted
mocks: `bin/ai-project-orchestrator:317` already defaults `dev_command` to `./bin/run-dev-agent`
— **a file that does not exist**. The execution engine (`local-agent-runner`, sibling repo) is
v1.0.0-proven standalone (155 tests) with P2 runner-side support delivered (`--context` on the
CLI, coding tools, permission model); its gate is cleared (HQ ruling 2026-07-11). This Epic
builds the one remaining piece: the thin, governance-aware adapter between them, per
`local-agent-runner/CONTRACT.md` §7.

> **Provenance:** Authored by the Milestone Chat (P7-M26) on 2026-07-12 per GH-8 adjacency.
> The Coding Agent implements it. First Epic of M26; the HQ-ruling sequence is binding:
> **E26.1 (adapter) → E26.2 (wiring) → E26.3 (live run)** — no parallelization.

> **Source:** M26 Milestone spec (Epic Detail → E26.1); P7 phase spec P7.1 step 1; HQ ruling
> 2026-07-11; `local-agent-runner/CONTRACT.md` §2/§4/§6/§7; GH issue #111.

**Grounding (verified on `phase/P7` / `milestone/M26`, 2026-07-12):**

- `bin/ai-project-orchestrator:317` — `dev_cmd = trigger.get("dev_command", "./bin/run-dev-agent")`.
  The trigger also carries `epic_id` (L313), `epic_spec_path` (L314), `sandbox_env` (L315),
  `validation_command` (L316), `run_dev_initially` (L318).
- `run_in_sandbox` (`bin/ai-project-orchestrator:270`) executes the `dev_command` inside a Docker
  sandbox: **only** `-e AI_PROJECT_ACTIVE_MODEL={active_model}` is injected (L281); the repo is
  mounted at `/workspace` (L282) with workdir `/workspace` (L283). **The trigger's fields are NOT
  passed through the environment** — but the mounted repo includes `.ai-project/queue/`, so the
  trigger JSON is readable from the working directory. When Docker is unavailable there is a
  **local-execution fallback** (L301–307): same command, `AI_PROJECT_ACTIVE_MODEL` env-injected,
  run from the project root.
- `.ai-project.yml:26` — model values carry a **`local:` prefix** (`local:llama3:8b`); the runner's
  `--model` expects the **bare ollama tag**. The adapter maps `local:<tag>` → `<tag>`.
- Runner CLI (CONTRACT §2): `--model / --task / --task-text / --tools / --context / --system /
  --max-iterations / --endpoint / --transcript`. Exit codes: `0` completed · `2` did-not-converge ·
  `3` config/tool error · `4` runtime error (one-line reason on stderr).
- Tool permissions via `tools.json` (CONTRACT §4): `enabled`, `allow_paths`, `allow_commands`,
  `deny_commands`, `timeout`, `allow_subcommands` (for `git`).
- Token discipline (CONTRACT §6; the local-model-epic-execution audit): scoped epic material
  ≈ 24K tok vs. full governance ≈ 157K tok. **Full-governance context is a defect.**

---

## Problem Statement

The orchestrator and the runner are each proven in isolation but have never been connected: the
orchestrator names an adapter that does not exist, so no epic has ever executed for real. This
Epic delivers `bin/run-dev-agent` — the *only* governance-aware piece of the execution path —
so E26.2 can wire the live path and E26.3 can run the first real epic.

---

## Goals

By the end of this Epic:

1. **`bin/run-dev-agent` exists** and implements CONTRACT §7: invocable by the orchestrator as
   `dev_command` with no orchestrator changes; reads `AI_PROJECT_ACTIVE_MODEL`; builds the runner
   Task; invokes the runner; **returns the runner's exit code unaltered**; writes the transcript
   into the epic's artifacts.
2. **The `local:` prefix maps correctly:** `AI_PROJECT_ACTIVE_MODEL=local:<tag>` drives
   `--model <tag>` (bare ollama tag); a bare value passes through unchanged.
3. **Token discipline holds:** `--task` = the epic's Definition of Done; `--context` = the
   **scoped** epic spec/starter — **never full governance** (binding).
4. **The coding tool set is defined:** a git-tracked `tools.json` per CONTRACT §4, scoped to the
   repo (paths under the repo/workspace root; command allowlist for the test/lint surface).
5. **The contract is tested:** model mapping, Task construction, exit-code passthrough
   (all four codes), transcript write — runner stubbed; the **live** invocation is E26.3's job.
6. **No `final_answer` parsing anywhere in the adapter** (binding — SN-3 / runner P1 audit).

## Non-Goals

This Epic explicitly does **not**:

- **Touch the runner** (`~/soft-dev/local-agent-runner` — cross-repo; a runner-side defect is
  escalated to HQ, never fixed from here).
- **Switch models or retire mocks** — `.ai-project.yml:26` and `DEFAULT_MODELS` stay untouched;
  that is **E26.2**.
- **Perform the live run** — runner invocation is stubbed in tests; the first real run is **E26.3**.
- **Modify the orchestrator's `handle_epic_execution` contract** — the adapter fits the existing
  invocation (env + mounted repo), not the other way around. (A change here is a blocker to
  escalate, not a workaround to implement.)
- Parse, log-scrape, or branch on the runner's `final_answer` — anywhere (binding).

## Scope of Work

### 1. `bin/run-dev-agent` (the CONTRACT §7 shim)

Executable script (recommended: Python 3, matching the repo's other `bin/` tooling; the Epic may
choose otherwise and document it). Behavior:

1. **Read `AI_PROJECT_ACTIVE_MODEL`** from the environment. Map `local:<tag>` → `<tag>` for
   `--model`; pass a bare tag through; a missing/empty value is a config error (exit `3`-class
   failure with a one-line stderr reason — do not invent a default).
2. **Locate the epic's DoD and scoped spec.** Recommended route (the trigger's fields are not in
   the env): read the trigger JSON from `.ai-project/queue/` in the working directory
   (`04_epic.json`-mechanism trigger) and take `epic_spec_path` from it; extract the spec's
   "Definition of Done" section as `--task` (or `--task-text`), and pass the **whole scoped epic
   spec** (plus starter, if present) as `--context`. Exact extraction mechanics are the Epic's
   call — decide and document in the adapter. **Never full governance** as context (binding).
3. **Build and invoke the runner:** `--model` = mapped tag, `--task`/`--task-text` = the DoD,
   `--context` = the scoped spec/starter, `--tools` = the coding-set `tools.json`,
   `--transcript` = the epic's artifact path. Runner binary discovery and Ollama-endpoint
   reachability from the execution context (sandbox vs. documented local fallback; `--endpoint`
   override if needed) are Epic design decisions — **decide, document in the adapter or this
   spec's Execution Notes, and move** (escalate only if genuinely blocked).
4. **Return the runner's exit code unaltered** to the orchestrator (0/2/3/4 pass through as-is).
5. **Write the transcript into the epic's artifacts** — git-visible and stable (it is also the
   cross-repo E3.2 evidence). Recommended convention:
   `.ai-project/artifacts/agentic-runs/<epic_id>/transcript.json` (+ the adapter's own one-line
   run metadata if useful). Exact convention is the Epic's call — document it.

### 2. `tools.json` — the coding set scoped to the repo

Per CONTRACT §4: `enabled` = the coding set (`read_file`, `write_file`, `edit_file`, `list_dir`,
`run_command`, `git`); `allow_paths` scoped to the repo/workspace root; `allow_commands` limited
to the test/lint surface (e.g. `pytest*`); a sane `timeout`. Git-tracked at a stable path the
adapter references (recommended: alongside the adapter's config, e.g. `.ai-project/agents/
tools.json` — the Epic decides and documents).

### 3. Tests

Cover the adapter contract with the runner **stubbed** (a fake runner script/entry the tests
control):

- `local:` prefix mapping (and bare-tag passthrough; missing env → config error)
- Task construction: `--task` receives the DoD, `--context` the scoped spec, `--tools` the
  coding set, `--transcript` the artifact path — and **context is never governance corpus**
- Exit-code passthrough for `0`, `2`, `3`, `4`
- Transcript written to the epic's artifact path
- **Absence guard:** no `final_answer` handling in the adapter (e.g. a source-level assertion
  that the adapter never reads that field)

Full suite must pass (260 passed / 1 skipped baseline + the new adapter tests).

## Technical Constraints

- **The adapter fits the existing invocation:** env (`AI_PROJECT_ACTIVE_MODEL`) + mounted repo
  (workdir = repo root in both sandbox and local-fallback paths). No orchestrator changes.
- **Exit-code semantics are the interface:** Epic success is decided by the QA
  `validation_command` exit code + transcript downstream — the adapter must neither absorb nor
  translate runner exit codes, and must not consult `final_answer` (binding).
- **Token discipline (CONTRACT §6):** scoped spec/starter only in `--context`. Full governance
  (~157K tok) is a defect, not a convenience.
- **Runner is a black box at v1.0.0:** consume the CONTRACT §2 CLI exactly; any runner-side
  change needed → escalate to HQ (cross-repo), do not reach across.
- **Scope of files:** `bin/run-dev-agent` (new), the `tools.json` location (new), `tests/`
  additions, this Epic's Delivery Notice. Do **NOT** touch `bin/ai-project-orchestrator`,
  `.ai-project.yml`, `tests/mocks/` or `tests/integration/test_agentic_mode.py` (E26.2's
  surfaces), governance documents, or any file in `~/soft-dev/local-agent-runner`.

## Execution Notes

- **The trigger is the input channel.** `run_in_sandbox` passes only the model env var; read the
  trigger JSON from `.ai-project/queue/` (working directory = repo root in both execution paths)
  to obtain `epic_spec_path`. Fail with a clear one-line stderr reason if the trigger or spec is
  missing (config-error class), never silently.
- **Reachability is the likely first snag** (milestone spec, Notes): the runner binary and the
  Ollama endpoint must be reachable from wherever the `dev_command` runs — sandbox image
  contents, `--endpoint` override, host networking, or the documented local fallback are all
  valid answers. Decide, document, move; escalate only if genuinely blocked. (For this Epic's
  tests the runner is stubbed, so the decision must be *documented* here/in the adapter and is
  *exercised* in E26.3.)
- **Transcript is evidence.** The path must be git-visible and stable — E26.3 hands it to
  `local-agent-runner` P2-M3 as E3.2 evidence.
- **No `final_answer`, structurally:** don't read the field even for logging; the transcript
  JSON is written through as the runner produced it.
- Default-accept (PSG §11.6 / AOG §12) governs this Epic's own delivery: a clean delivery is
  accepted by silence; the epic-PR merge is human-authorized in-chat (SN-19); a Review Decision
  is the exception path only.
