# Escalation Notice — E26.3 Live Run Blocked: `tools.json`'s `allow_paths` Glob Cannot Match Under the Local-Execution Fallback

**Issued by:** Epic Chat (P7-M26-E26.3)
**Issued to:** Milestone Chat (P7-M26 — First Real Agentic Run)
**Date:** 2026-07-13
**Blocking E26.3 execution:** Yes — a genuine, real, non-mocked run completed all 3 attempts;
the model behaved correctly and was denied every single time by a tool-permission bug.
**Blocking M26 closure:** Yes — E26.3 is M26's sole remaining, binding exit event.

## What Was Found

Per the Milestone Chat's resolution of the second escalation (`97637af` → this commit
series), the wrapper was re-pointed at a `git worktree` of `local-agent-runner`'s
`milestone/M3` (has `--context`). The real run then executed cleanly end to end — Ollama
inference genuinely ran (confirmed live `llama-server` process, real wall-clock duration per
invocation, e.g. 74796ms and 12627ms across different dev-command invocations) — and **every
single `write_file` call the model made was denied**, regardless of the path form it tried.

From the transcript of one full attempt (`.ai-project/artifacts/agentic-runs/
P7-M26-E26.3-PROVE/transcript.json`), the model wrote genuinely correct content — stdlib +
PyYAML, reading `governance.version`, printing it — and tried four different path spellings
across its iterations, all denied identically:

```
write_file  bin/ai-project-version    -> denied
write_file  ./bin/ai-project-version  -> denied
write_file  .bin/ai-project-version   -> denied
write_file  .//bin/ai-project-version -> denied
```

Denial message (verbatim, `local_agent_runner/tools.py`'s `_MSG_PATH_DENIED`):

```
write_file: access to path '/home/panchew/soft-dev/ai-project-system/bin/ai-project-version'
is denied. Only paths matching these allow_paths globs are permitted: /workspace/**, ./**
```

**Root cause — a real bug in `.ai-project/agents/tools.json`'s design, not the model:**

- `tools.py`'s `path_permitted()` (line 176-180):
  ```python
  def path_permitted(self, path):
      resolved = str(Path(path).resolve())
      return any(fnmatchcase(resolved, glob) for glob in self.allow_paths)
  ```
  `Path(...).resolve()` **always** returns an absolute path
  (`/home/panchew/soft-dev/ai-project-system/bin/ai-project-version`). A literal glob
  `"./**"` can only match a string that begins with the two characters `./` — an absolute
  path never does, by construction. **This glob can never match anything, for any input,
  under any execution route.** Only `"/workspace/**"` can ever match — and only when the
  process's cwd is literally `/workspace` (the Docker-sandbox mount point), which is not
  the case under the local-execution fallback (cwd = the real repo root).
- `tools.json`'s own `_comment` field states the intent plainly: *"Paths cover the Docker
  sandbox mount (`/workspace`, the primary execution context) and the orchestrator's
  documented local fallback (working directory = project root, relative paths)."* The
  intent to support local fallback is explicit and on record — the mechanism chosen
  (a literal `"./**"` glob checked against `Path.resolve()`'s always-absolute output) simply
  cannot deliver on that intent. This is a real implementation gap, not a documentation gap.
- Net effect: **under the local-execution fallback route — the route this Epic's first two
  escalations authorized as necessary and correct for this host — no `write_file` call can
  ever succeed**, for any path, regardless of model quality. `edit_file`/`read_file`/
  `list_dir` share the same `path_permitted()` check and are equally affected.

This sits inside `.ai-project/agents/tools.json`, a frozen E26.1/E26.2 surface (also part of
`local-agent-runner`'s own `tools.py`, a different repository — Technical Constraints forbid
touching either).

## Decision Needed

Given `tools.json` is a frozen E26.1/E26.2 surface (and its logic partly lives in
`local-agent-runner`'s own `tools.py`, a different repository), this Epic has no
unilateral fix available — unlike the prior two escalations, there is no invocation-time
environment choice (curated `PATH`, worktree pinning) that routes around a glob-matching
bug baked into the tool implementation itself. Options:

1. **Authorize a scoped `tools.json` amendment** for this run only (e.g., an `allow_paths`
   entry that matches the real repo root's absolute path on this host, such as
   `"/home/panchew/soft-dev/ai-project-system/**"`, or a fix on the `local-agent-runner`
   side changing `"./**"` to a glob that can actually match resolved absolute paths, e.g.
   `f"{Path.cwd()}/**"` resolved at permission-load time). Either touches a surface this
   Epic's Technical Constraints reserve for explicit authorization, not unilateral epic-level
   action.
2. **Accept the current, complete, real, non-mocked evidence as this Epic's delivered
   outcome** — a genuine non-convergence with a precisely identified, root-caused blocker,
   not a manufactured or ambiguous failure. This is arguably the most honest reading of "the
   live run is meant to prove or surface" exactly this class of gap, and this instance is
   fully diagnosed, not a mystery.
3. **Escalate further** (Phase Chat / HQ) if a `tools.json` fix requires coordinating with
   `local-agent-runner`'s own repository/governance (since the same bug independently exists
   in that repo's `tools.py`, which this Epic cannot touch under any authorization it has
   received so far).
