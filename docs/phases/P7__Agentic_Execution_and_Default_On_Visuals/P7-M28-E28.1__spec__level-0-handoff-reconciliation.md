## Problem Statement

The Level-0 (pre-governance) handoff is defined two incompatible ways across four documents,
and one of those four documents contradicts itself. `seed.md` converges the Creation Chat on a
**Project Brief + HQ Chat Opener** pair that hands off to an **HQ Chat**. `genesis.md` and
`chat-hierarchy.md` converge the same Creation Chat on a single **`genesis.md`** artifact that
hands off to a **Phase Chat** directly — no HQ Chat ever opens. `governance/systems/
start-a-project.md` embeds both flows in sequence and tells the reader to define Phase 1 twice,
through two different chats, with its own Step 3 "Next step" already having sent the reader to
a Phase Chat before Steps 5-6 send them to an HQ Chat to do the same thing again. A second,
stale, pre-submodule-era file sharing the name `start-a-project.md` sits undocumented in `docs/
systems/`, diverging silently. No HQ Chat Opener template exists in `governance/templates/`
where every other fillable starter lives.

---

## Goals

By the end of this Epic:

1. **The Level-0 handoff model is stated once, coherently, in all four named docs.** Per Open
   Design Question B's recommended default: both flows are codified as explicitly
   scale-dependent — a lightweight `genesis.md` → Phase Chat path for small/single-phase
   bootstraps, and a full `seed.md` → Project Brief + HQ Chat Opener → HQ Chat path for
   ongoing, multi-phase projects that need a persistent control plane. `seed.md`,
   `genesis.md`, `start-a-project.md`, and `chat-hierarchy.md`'s Level-0 section each state
   this fork (or the relevant half of it) explicitly and agree with each other.
2. **`governance/systems/start-a-project.md` no longer contradicts itself.** Its Step 3 (or
   an equivalent fork point) makes the choice between the two paths explicit **before** the
   reader is sent anywhere, rather than sending them down both paths in sequence.
3. **The `docs/systems/start-a-project.md` duplicate is resolved**, not left silently
   divergent — determined here as a stale, pre-submodule-era file with zero live references,
   recommended for removal (see Scope item 2 for the exact decision and rationale to record).
4. **An HQ Chat Opener template exists in `governance/templates/`**, with
   `governance/diagrams/repository-structure.md` updated to match its new location.

## Scope of Work

### 1. Codify the scale-dependent Level-0 fork across the four named docs

Amend each of the four docs to state the same fork explicitly:

- **`seed.md`**: keep Rule 3/Rule 4's existing Project Brief + HQ Chat Opener → HQ Chat
  convergence as the **full/ongoing-project path**, but add explicit framing (near Rule 4,
  or as a new short note before it) that this is the path for projects expecting a persistent,
  multi-phase control plane — and that a single-phase/small bootstrap should instead use
  `genesis.md` directly to a Phase Chat, per `governance/systems/start-a-project.md`.
- **`genesis.md`**: keep the existing direct-to-Phase-Chat convergence as the
  **lightweight/small-bootstrap path**, and add a short note (near the "Next Step" section or
  the top-level HTML comment) that ongoing projects needing a persistent HQ control plane
  should instead use `seed.md`'s Project Brief + HQ Chat Opener flow.
- **`governance/systems/start-a-project.md`**: restructure Step 3 (or insert a fork
  immediately after it) so the reader makes an explicit choice **once**, before proceeding —
  e.g., "If this is a small, single-phase bootstrap: stop here and open a Phase Chat directly
  using this committed `genesis.md` (see Step 3's Next Step). If this is an ongoing,
  multi-phase project that needs a persistent control plane: continue to Step 4 onward using
  `seed.md`'s Project Brief + HQ Chat Opener flow to spawn an HQ Chat." Steps 4-7 remain as
  the full-flow continuation, now clearly gated behind the choice rather than presented as
  mandatory next steps that duplicate Step 3's own instruction.
- **`chat-hierarchy.md`** "Level 0: Creation Chat" section: add a short note cross-referencing
  the scale-dependent fork — this section may keep its existing genesis.md-centric framing as
  the lightweight path's description, but must not read as the *only* Level-0 model once
  `seed.md`'s path is reconciled to exist alongside it.

**Must include:**
- All four docs state the same two-path model in compatible language (no doc implies its path
  is the only path)
- `start-a-project.md`'s Step 3 (or equivalent) resolves the self-contradiction — the reader is
  never told to define the same first Phase through two different chats without an explicit
  choice point

### 2. Resolve the `docs/systems/start-a-project.md` duplicate

Determine and document the decision. Grounding above establishes: this file is P1-era
(`last_updated: 2026-01-17`), describes a pre-submodule, pre-`ai-project init`, pre-Creation-
Chat process (manual copy of governance docs into `docs/`), and has zero live in-repo
references outside two frozen P2-era historical completion records. **Recommended
determination: stale duplicate, superseded in full by `governance/systems/
start-a-project.md`.** Remove the file; if any residual concern surfaces during execution that
argues for reconciling rather than removing, state that reasoning explicitly instead of
defaulting silently to removal.

**Must include:**
- An explicit, documented decision (remove or reconcile) with stated reasoning
- If removed: confirm no live reference breaks (grep before and after)
- If reconciled instead: the file no longer contradicts `governance/systems/
  start-a-project.md` on any point

### 3. Promote `hq-chat-opener.md` into `governance/templates/`

Move (recommended — a template belongs in one tier, not two) `governance/systems/
hq-chat-opener.md` to `governance/templates/hq-chat-opener.md`. Update
`governance/diagrams/repository-structure.md`'s tree listing (currently under `systems/` at
line 38) to reflect the new location under `templates/`. Confirm no other in-repo path
reference needs updating (grep confirms only the diagram references the path; the two P2-era
historical completion records reference the file by name in a historical migration table and

**Must include:**
- `governance/templates/hq-chat-opener.md` exists; `governance/systems/hq-chat-opener.md` no

  why in the Delivery Notice)
- `governance/diagrams/repository-structure.md` updated to match the new location
- Confirmation on record that no other live path reference needed updating
