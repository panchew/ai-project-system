## Problem Statement

M26 and M27's own Milestone/Phase Execution Chat Starters already demonstrate, in practice,
that Epic/Milestone acceptance and the PR-merge authorization are in-chat acts requiring no
ceremonial artifact — the harness enforces human merge authorization regardless of any
document. But the canonical templates those starters were drafted from
(`governance/templates/{milestone,phase}-execution-chat-starter.md`) still carry a full
"Epic/Milestone Delivery Authorization" ceremonial section each, and the three
`governance/systems/` mirrors carry the same ceremonial language even more deeply embedded —
not as one deletable block, but scattered across responsibilities lists, communication-scope
tables, dedicated sections, and (a finding beyond the Milestone spec's own description)
Session Lifecycle steps. AOG itself asserts the requirement normatively in three places. Every
new Milestone or Phase Chat session that starts from these canonical sources today would
re-introduce the ceremony M26/M27/M28 have already shown is unnecessary in practice.

## Goals

By the end of this Epic:

1. **Both templates' "Epic/Milestone Delivery Authorization" sections are retired**, replaced
   with the M26/M27/M28-demonstrated in-chat pattern — a short section (or Execution
   Instructions addition) stating the standing merge instruction is an in-chat act, with the
   load-bearing **merge instruction itself preserved**, not dropped.
2. **All four touch points in each of the two `governance/systems/` Milestone/Phase mirrors**
   are individually addressed — the Milestone spec's named three (responsibilities step,
   communication-scope table row, dedicated section) plus the Session Lifecycle step this
   Epic's own grounding found in each.
3. **All three touch points in `governance/systems/hq-execution-chat-starter.md`** (diagram
   label, Bugfix Workflow instruction, Phase-level Session Lifecycle step) are individually
   reworded — the diagram's ASCII art, the prose instruction, and the lifecycle step each need
   their own edit, not a single deletable block.
4. **AOG §1A step 6, line 716's "Epic Delivery Authorization decision" phrase, and line 756**
   all read in-chat authorization language.
5. **The in-chat merge authorization requirement itself is preserved, unchanged, everywhere**
   the ceremonial block is retired — this Epic removes the *artifact*, not the *human
   authorization gate* the harness enforces.
6. **The Bugfix Workflow's CFO Deployment Authorization is explicitly untouched** — confirmed
   distinct from the epic-start "Delivery Authorization" language this Epic retires.
7. **AOG version bumped** (2.8.0 → 2.9.0) with a changelog row.
