## Open Design Question A — Resolved

**Question:** what Epic does the first live run execute?

**Resolution (default taken, per the Milestone spec's recommendation):** a **purpose-built
minimal, self-contained proving-vehicle epic**, defined below. It isolates the run from
unrelated scope, keeps M26 independent of M28 ordering, and gives the loop a real
`validation_command` that can genuinely fail before the dev step runs.

### The proving-vehicle epic: `P7-M26-E26.3-PROVE`

**What it is:** a tiny, throwaway-scoped, file-scoped change — not a "real" product Epic, and
not tracked as a fourth M26 Epic. It exists solely so the orchestrator has something real to
execute end-to-end.

**Deliverable the live run must produce:** `bin/ai-project-version` — a Python 3 script
(stdlib + PyYAML, matching the repo's other `bin/` tooling), **invoked as
`python3 bin/ai-project-version` (not `./bin/ai-project-version`)** — the coding tool set the
model has access to (`write_file`) cannot set an executable bit, so this Epic does not require
one (amendment, 2026-07-12). It reads `governance.version` from `.ai-project.yml` at the repo
root and prints it to stdout followed by a single newline, exiting `0`. No other behavior.

**The proving-vehicle spec (authored by *this Epic's* Coding Agent, not by the Milestone
Chat — GH-8 adjacency: Epic-level content is the Epic's own deliverable):**

- **File:** `docs/phases/P7__Agentic_Execution_and_Default_On_Visuals/
  P7-M26-E26.3-PROVE__spec__version-script-proving-vehicle.md`, committed to
  `epic/P7-M26-E26.3` **before** the trigger is written (it is what `epic_spec_path` names).
- **Must contain a literal `## Definition of Done` heading** (the adapter's DoD-extraction
  regex requires this exact form) whose body instructs, in full: create `bin/ai-project-version`
  as specified above; the script must exit `0` and print exactly the `governance.version` value
  from `.ai-project.yml` plus a trailing newline when run as `python3 bin/ai-project-version`;
  do not modify any other file. **Do not instruct the model to make the file executable** —
  the coding tool set cannot set permission bits (amendment, 2026-07-12).
- The rest of the spec (Context/Goals/etc.) may be brief — it exists to be consumed as
  `--context`, not to satisfy the framework's normal Epic-spec depth requirements (this is a
  proving vehicle, not a governed product Epic).

**The proving-vehicle test (authored by this Epic's Coding Agent, committed to
`epic/P7-M26-E26.3` *before* the trigger fires — this is what gives the run a real,
failable `validation_command`):**

- **File:** `tests/test_ai_project_version_script.py`.
- Assertions: `bin/ai-project-version` exists; running `python3 bin/ai-project-version` via
  `subprocess` exits `0`; its stdout, stripped, equals the `governance.version` value read
  independently from `.ai-project.yml` (parse with PyYAML in the test, not by string-matching
  the script). **No executable-bit / `os.X_OK` assertion** (amendment, 2026-07-12 — no
  available tool can set one).
- Before the dev step runs, this test **fails** (the script does not exist yet) — a real,
  observable QA failure, not a rigged pass.

**The trigger** (written by this Epic's Coding Agent at run time — **not** a git-tracked
deliverable; `.ai-project/queue/` only tracks `README.md`, confirmed):

```json
{
  "epic_id": "P7-M26-E26.3-PROVE",
  "epic_spec_path": "docs/phases/P7__Agentic_Execution_and_Default_On_Visuals/P7-M26-E26.3-PROVE__spec__version-script-proving-vehicle.md",
  "sandbox_env": "alpine:latest",
  "dev_command": "./bin/run-dev-agent",
  "validation_command": "python3 -m pytest tests/test_ai_project_version_script.py -q",

}
```

`sandbox_env` stays `alpine:latest` in the trigger for documentation continuity, but on a host
where the sandboxed route is structurally unreachable (per the amendment above), invoke the
orchestrator with a curated `PATH` that omits `docker` so `run_in_sandbox()`'s own

— the `sandbox_env` value is then inert. Document in the run record which route actually ran.

`epic_id` is deliberately distinct from `E26.3` itself, so the run's artifacts
(`.ai-project/artifacts/agentic-runs/P7-M26-E26.3-PROVE/`) are clearly separated from E26.3's
own spec/starter/Delivery Notice.

## Non-Goals

This Epic explicitly does **not**:

- **Contact `local-agent-runner`, its chats, or its repository, directly or indirectly** — no
  chat in this repo does. Escalation is strictly upward through this repo's own chat
  hierarchy: Epic → Milestone Chat → Phase Chat → HQ → CFO (shared Layer-8, who carries it

- **Issue the cross-repo Escalation Notice itself.** That artifact (Milestone Chat (P7-M26) →
  Phase Chat (P7)) is the **Milestone Chat's own act**, performed after this Epic's delivery is
  reviewed and accepted — not an Epic deliverable. (Producing it here would skip a governance
  layer: an Epic escalates to its own parent only, per `governance/templates/
  escalation-notice.md`.)
- **Modify `bin/run-dev-agent`, `tools.json`, `.ai-project.yml`, or any E26.1/E26.2 surface.**
  Those are delivered and frozen; this Epic *uses* them, does not change them.
- **Register `P7-M26-E26.3-PROVE` as a real M26 Epic.** It is a disposable proving vehicle
  inside E26.3's own scope — its files land in the same PR as E26.3's other deliverables, not
  as a separate Epic branch/PR.
- **Debate Open Design Question A further** — resolved above; execute it.
- Parse or depend on `final_answer` anywhere in the run, the record, or the acceptance argument
  (binding, architectural — carried from M26's other Epics).
