## Problem Statement

`bin/ai-project-init` installs `governance/agents/hq.agent.md` into every new project as
`.ai-project/agents/hq.agent.md` — but that file's own content declares itself superseded by
`governance/agents/governance.agent.md`, "the single... agent [that] replaces all separate
agent files." Every new project bootstrapped today receives a stub that tells its first reader
to go find a different file. The regression test guarding this install path
(`tests/test_init_agent_path.py`) asserts the superseded filename, so the defect is
test-covered as correct. A live CLI usage guide (`docs/systems/cli-usage-guide.md`) documents
the superseded filename in two places while its own troubleshooting section already assumes
the canonical one.

---

## Goals

By the end of this Epic:

1. **`bin/ai-project-init` installs `governance/agents/governance.agent.md` as
   `.ai-project/agents/governance.agent.md`** — both the source path (line 328) and the
   destination filename (line 329) and the later `git add` (line 408) updated consistently.
2. **`tests/test_init_agent_path.py` asserts the canonical filename**, not the superseded one.
3. **`docs/systems/cli-usage-guide.md`'s two superseded-filename references are reconciled**
   to match its own already-correct troubleshooting section.
4. **No other live, current-facing doc is left asserting the superseded filename as what the
   initializer installs.**
