### Summary

Flip visual-artifact production from opt-in/off-by-default to default-on/opt-out across AOG
§17.1, `ai-project-yml-spec.md` §3.5, and `bin/ai-project-orchestrator`'s
`DEFAULT_VISUAL_ARTIFACTS`/`resolve_visual_artifacts()`; add a new enforcement-setting key
(defaulted `true`); rewrite the tests that assert the old default; reconcile
`governance/guides/visual-artifacts.md`'s opening framing; decide and document whether this
repo's own `.ai-project.yml` opt-out changes.

### Binding constraints (carry into every decision — verbatim from the Milestone spec)

- **Default-on with an explicit opt-out** — `enabled: false` becomes the opt-out, not the
  baseline (SN-17 decision 1).
- **Enforcement is a defaulted-true config setting, not a hard gate** (SN-17 decision 4).
- **This Epic does not decide structural-vs-generative trigger behavior** — that is E27.2. E27.1
  only flips whether the capability is active by default.
- **The enforcement-setting key is new schema, not a rename** (confirmed by grep) — name it
  `visual_required_for_specs` (recommended default; resolve non-blocking, do not escalate Open
  Design Question C).

### Design points (yours to resolve — decide, document, move; escalate only if truly blocked)

1. **Enforcement-key naming** (Open Design Question C) — recommended: single
   `visual_required_for_specs: true`. Add per-type keys only if a real need surfaces.
2. **Whether `.ai-project.yml`'s own `visual_artifacts` block changes** — structural visuals need
   no endpoint and are not "generated binaries" (§17.5), so the original reason for
   `enabled: false` (keep the suite green without a live ComfyUI endpoint) does not, on its face,
   force the whole capability off once default-on ships. If you change the file, you must also
   update `tests/test_ongoing_artifacts.py::TestVisualArtifactsRepoConfig::test_ai_project_yml_carries_visual_artifacts_disabled`
   and reconcile `governance/AI-OPERATING-GUIDELINES.md:924-926` (§17.5's sentence citing this
   repo's `enabled: false` as an instance of the no-generated-binaries rule) in the same commit
   set — document the reasoning either way.
