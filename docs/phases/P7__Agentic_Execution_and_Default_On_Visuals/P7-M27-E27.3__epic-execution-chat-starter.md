### Summary

Produce a documented GPU/VRAM coexistence design for the confirmed Ollama+ComfyUI single-GPU
contention, and implement the primary mitigation as an in-repo software guardrail:
`bin/ai-project-visual` checks the orchestrator's existing execution lock before a generative call
and refuses cleanly (new exit code) when a live agentic epic run is in flight. No infrastructure
changes to `~/soft-dev/ai-stack`.

### Binding constraints (carry into every decision — verbatim from the Milestone spec / grounding)

- **Do not modify `~/soft-dev/ai-stack`** unless the CFO explicitly directs otherwise during
  execution — it is a different repository, outside this repo's scope (Non-Goal).
- **Reuse, don't duplicate, the orchestrator's PID-liveness check** — `bin/ai-project-orchestrator`
  already implements correct stale-lock recovery; a second implementation is a maintenance hazard.
- **No live GPU or live ComfyUI endpoint in tests** — stub the lock file; use the test process's
  own PID or a short-lived spawned subprocess for the "live PID" case.
- **Do not build a general-purpose scheduler** — one lock check, one new exit code. Resist scope
  growth.
- **Do not touch E27.1/E27.2's surfaces** (AOG §17, yml-spec, `resolve_visual_artifacts()`,
  `visual_required_for_specs`, `visual-artifacts.md` §1-§9) beyond the exit-code table update this
  Epic's own deliverable requires.

### Design points (yours to resolve — decide, document, move; escalate only if truly blocked)

1. **Design-doc placement** — recommended: new guide `governance/guides/gpu-coexistence.md`,
   cross-linked from `visual-artifacts.md`'s "Related documents" table (one new row). A section
   appended to `visual-artifacts.md` instead is acceptable if you judge the split not worth a new
   file. Document the choice.
2. **New exit code value** — recommended `5` (next available after 0/2/3/4). Document in the
   helper's docstring and the guide's exit-code table.
3. **Where the PID-liveness reuse lives** — via the existing `load_orchestrator()` pattern, or a
   small shared helper factored out of `bin/ai-project-orchestrator` if that proves cleaner. Your
   call; document it.
