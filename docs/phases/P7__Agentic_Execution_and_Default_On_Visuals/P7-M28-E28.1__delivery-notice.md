## Execution Summary

Codified the Level-0 handoff as an explicit, scale-dependent fork (Open Design Question B's
recommended default) across all four named docs, rather than picking a single canonical
output:

- **`governance/systems/start-a-project.md`** gained a new "Choose Your Path" section
  immediately after Step 3: *lightweight* (small, single-phase bootstrap — stop and open a
  Phase Chat directly using the committed `genesis.md`) vs. *full* (ongoing, multi-phase
  project — continue to Step 4 onward, converging the Creation Chat on `seed.md` Rule 4's
  Project Brief + HQ Chat Opener and spawning an HQ Chat). This resolves the
  self-contradiction: Step 3's own "Next step" no longer asserts the lightweight path
  unconditionally, and Steps 4-7 are now explicitly labeled as the full-path continuation
  rather than a second mandatory pass that redefined Phase 1 through a different chat. Step
  5 was also reworded: the HQ Chat now opens from the promoted `hq-chat-opener.md` template
  (filled per `seed.md` Rule 4) together with `genesis.md`'s HQ Context Packet/Phase 1
  Scope — previously it named only `genesis.md`'s HQ Context Packet, which never actually
  existed as a mechanism `seed.md` itself described.
- **`seed.md`** (Rule 4) gained a framing note: this convergence is the full path, for
  ongoing/multi-phase projects; single-phase bootstraps should fill `genesis.md` directly
  instead.
- **`genesis.md`** (Next Step) gained the reciprocal note: this is the lightweight path;
  ongoing projects needing a persistent control plane should use `seed.md`'s flow instead.
  Line count after the edit: 106 (well under the template's 150-line ceiling).
- **`chat-hierarchy.md`**'s Level 0 section gained an intro paragraph naming the section as
  the lightweight path's description, cross-referencing the full path and the
  `start-a-project.md` fork, plus a Documentation-block entry for the full-path template
  (`seed.md`). The existing Role/Produces/Authority/Stopping-Condition subsections needed no
  edits — they read correctly once scoped by the new intro sentence.

**`docs/systems/start-a-project.md` duplicate — removed, not reconciled.** Confirmed via
direct read and grep: P1-era (`last_updated: 2026-01-17`), pre-submodule (Step 2 instructs
copying governance docs into `docs/` — a model `ai-project init` has since replaced), no
Creation Chat/`seed.md`/`genesis.md`/submodule concept anywhere in it, and zero live
references anywhere in the repo outside two frozen P2-era historical completion records
(`P2-M6-E6.1`, `P2-M6-E6.2` — migration-table entries, left untouched) and this milestone's
own M28 planning artifacts (which discuss the duplicate by name, not as a live link).
Removal was the defensible default per the Epic spec's own grounding; nothing surfaced
during execution that argued for reconciling instead.

**`hq-chat-opener.md` — moved, not copied**, per the recommended default (single canonical
location, matching every other fillable template in `governance/templates/`). No concrete
reason to keep both surfaces active surfaced during execution.
`governance/diagrams/repository-structure.md`'s two affected tree-listing lines were updated
to match (removed from the `systems/` listing, added to the `templates/` listing).
