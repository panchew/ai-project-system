# Epic Delivery Notice — E27.1

**Epic:** E27.1 — Default-on flip + enforcement setting
**Status:** Execution Complete, Delivered for Review
**Delivery Date:** 2026-07-13

## Execution Summary

Flipped visual-artifact production from opt-in/off-by-default to default-on/opt-out across the
three surfaces that assert the default (AOG §17 intro + §17.1, `ai-project-yml-spec.md` §3.5,
`bin/ai-project-orchestrator`'s `DEFAULT_VISUAL_ARTIFACTS` / `resolve_visual_artifacts()`), added
the new enforcement-setting key `visual_required_for_specs` (defaulted `true`) end-to-end (schema,
validation, resolution, docs, tests), reconciled `governance/guides/visual-artifacts.md`'s opening
framing (plus its now-inconsistent "Enabling the capability" example and exit-code table entry),
and confirmed `governance/agents/` and `governance/templates/` carry no opt-in/off-by-default
language needing reconciliation (re-confirmed at execution time by grep, zero hits, matching the
spec's grounding).

**Enforcement-key name (Open Design Question C):** `visual_required_for_specs`, per the spec's
non-blocking recommendation — no concrete need for per-type keys surfaced during execution.

**Source-repo `.ai-project.yml` decision:** Kept `enabled: false` (the explicit opt-out) — **this
reverses an initial in-flight decision.** I first attempted to dogfood default-on restricted to
`types: [diagrams]`, on the theory (grounded in the spec's own reasoning) that structural diagrams
need no ComfyUI endpoint. Running the suite against that config surfaced a fact the spec's grounding
hadn't checked: `bin/ai-project-visual`'s `--type diagrams` is a ComfyUI-generative call in the
current implementation (a txt2img workflow) — not the endpoint-free Mermaid/PlantUML "structural"
mode AOG §17.3 describes. This is a pre-existing naming collision between the yml-spec's
`types: diagrams` value (used by the *generative* helper's `--type` flag) and AOG §17.3's
"structural" diagrams (produced directly by agents as text, never through the helper). Enabling the
capability in this repo's config un-skips `tests/integration/test_visual_artifacts_helper.py::
test_helper_generates_against_endpoint`, which then fails with connection-refused against
`localhost:8188` — confirmed empirically, not assumed. Reverted to `enabled: false` to preserve the
suite-green requirement; documented the full reasoning inline in `.ai-project.yml`, in AOG §17.5,
and in the AOG changelog row. `visual_required_for_specs: true` was still added to the block
(inert while `enabled: false`, but present so the file demonstrates the full schema).

**Follow-up not actioned (out of scope):** `bin/ai-project-visual`'s docstring/error-message strings
(e.g. "enabled is false / block is absent" as parallel disabled-causes) are now stale relative to
the default-on flip, but the file is outside E27.1's Technical Constraints scope (not listed, and
Non-Goals bars touching E27.2/E27.3 surfaces). Flagging for a future carry-forward rather than
editing out-of-scope files.
