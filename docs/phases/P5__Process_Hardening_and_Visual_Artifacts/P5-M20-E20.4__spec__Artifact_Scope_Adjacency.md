# Epic P5-M20-E20.4 — Artifact scope adjacency (GH-8)

## Context

Milestone M20 hardens five governance process gaps. This Epic closes **GH-8**: chats producing
artifacts for non-adjacent levels.

In practice, Phase Execution Chats have produced Epic Execution Chat Starters — skipping the
Milestone Chat layer entirely. This collapses the hierarchy, removes a review gate, and gives a
chat authority over artifacts that belong to a non-adjacent level. SN-12 (2026-06-25) made the
adjacency rule a binding decision (concern SN-12a).

> **Live worked example (this milestone):** during M20's Stage-1 delivery the Phase Chat
> produced Epic Execution Chat Starters for E20.1–E20.3 — itself an instance of the GH-8 gap.
> By HQ decision (2026-06-25, Option B) those three were retained as Phase-provided drafts for
> the Milestone Chat to reconcile and re-issue. Consistent with GH-8, **no** Phase Epic starters
> were produced for E20.4 or E20.5 — the Milestone Chat authors those (and all Epic specs) as its
> own deliverables. This Epic's own spec and starter being authored by the Milestone Chat is the
> rule in action.

> **Source:** SN-12 (2026-06-25), concern SN-12a — binding decision.

---

## Problem Statement

The governance model does not state, in the places a chat actually reads (the starter templates'
Critical Rules and AOG §3.6/§3.7), that a chat produces artifacts only for its direct parent or
direct children. Without that explicit rule:

- A chat can produce a **grandchild** artifact (e.g., a Phase Chat producing an Epic starter),
  bypassing the intermediate level's review gate.
- A chat can produce a **grandparent** artifact, overreaching into a level above its authority.

Both are process failures that are easy to commit and hard to notice, because the produced
artifact looks valid in isolation.

---

## Goals

By the end of this Epic, the system must:

1. State the artifact scope adjacency rule in the **Critical Rules** section of both the **Phase**
   and **Milestone** Execution Chat Starter templates.
2. Add the corresponding rule to **AOG §3.6** (Phase Execution Chat) and **§3.7** (Milestone
   Execution Chat).
3. Add the SN-12a adjacency table (Chat → may produce / must NOT produce) to
   `governance/systems/chat-hierarchy.md`.

## Scope of Work

### 1. Adjacency rule in the two starter templates' Critical Rules

Add, to the **Critical rules** section of both
`governance/templates/phase-execution-chat-starter.md` and
`governance/templates/milestone-execution-chat-starter.md`:

> A chat produces artifacts only for its direct parent or direct children — no grandchild
> artifacts (e.g., a Phase Chat must not produce Epic Execution Chat Starters) and no grandparent
> artifacts.

Phrase it for each template's own level where helpful (the Phase template can name "must not
produce Epic specs/starters"; the Milestone template can name "must not produce Milestone specs
or code").

### 2. AOG §3.6 and §3.7

Add the adjacency rule to **§3.6** (Phase Execution Chat) and **§3.7** (Milestone Execution
Chat) in `governance/AI-OPERATING-GUIDELINES.md`, cross-referencing the chat-hierarchy.md table.

### 3. Adjacency table in `chat-hierarchy.md`

Add the SN-12a table to `governance/systems/chat-hierarchy.md`, transcribed exactly:

| Chat | May produce | Must NOT produce |
|------|-------------|-----------------|
| Phase Execution Chat | Milestone Specs, Milestone Execution Chat Starters | Epic Specs, Epic Execution Chat Starters |
| Milestone Execution Chat | Epic Specs, Epic Execution Chat Starters | Milestone Specs (parent's job), code (grandchildren's job) |
| Epic Execution Chat | Code, tests, PRs | Epic Specs (parent's job), Milestone Specs (grandparent's job) |

Include the one-line consequence note: a violation either bypasses a review gate (grandchild
production) or overreaches into a parent's authority (grandparent production).
