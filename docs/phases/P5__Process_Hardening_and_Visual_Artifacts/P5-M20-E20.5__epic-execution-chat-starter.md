### Problem Statement

The model defined upward artifacts (Escalation/Completion Notices) but never defined downward
propagation, especially when one parent must reach several concurrent children. Without a rule,
parents are tempted to reach into running child sessions; levels may skip a parent to reach a
grandparent. SN-12b makes the model binding.

### Goals

1. Add a "Communication Protocol" section to `governance/systems/chat-hierarchy.md` covering all
   four SN-12b decisions.
2. Add the corresponding rules to AOG §3 and PSG.
3. Add amendment-issuing guidance to both the Phase and Milestone Execution Chat Starter templates.

## Required Content — BINDING DECISIONS (SN-12b)

Represent these four decisions faithfully (do not soften or extend):

1. **Upward communication is always 1-to-1.** Every level has exactly one parent. Escalations and
   completion notices travel up one level; the receiving level decides whether to absorb or
   escalate further. No level skips its parent to reach a grandparent.
2. **Downward communication is solved by the spec file, not by broadcasting.** A parent amends its
   own spec; children (including those mid-execution) read from that same source at any time. One
   write, many readers — no separate message per child.
3. **The level spec file has a dual role:** *planning artifact* (what was planned) and *live
   contract* (the authoritative state of scope/constraints/directives, including amendments).
4. **Mid-flight updates escalate UP, never reach into running sessions.** If a directive changes
   after children are running, the parent amends the spec and — if blocking — escalates **up** to
   its parent to decide whether to pause/cancel affected children. Downward reach into running
   sessions is not permitted.

**Amendment-issuing guidance** (both starter templates): to change scope mid-flight, **amend the
spec, note the change (e.g., an amendment-history entry), and notify the parent chat** — never
reach into running child sessions.
