# Epic P5-M22-E22.2 — Guidelines, templates, and agent integration (VA-1 full implementation)

## Context

Milestone M22 delivers visual artifacts as a first-class, opt-in capability. **E22.1 delivered the
config layer** — `.ai-project.yml` now carries a validated `visual_artifacts` block (`enabled`,
`comfyui_url`, `types`). This Epic delivers the **full implementation on top of that contract**: the
operating guidance that tells each chat level what visual to produce and how, the inception-time
elicitation of visual intent, a callable ComfyUI helper, an integration guide, and an integration
test that **skips gracefully when the capability is disabled** so the suite stays green without a
live endpoint.

## Problem Statement

E22.1 made the capability *configurable*, but nothing yet *uses* it. An agent enabling
`visual_artifacts` has no guidance on what visual its chat level should produce or how; a new
adopter is never asked what success looks like visually; there is no callable path from a prompt to
a generated image/video; and there is no documentation or test exercising the endpoint. This Epic
closes that gap: guidance (AOG), inception elicitation (`seed.md`), a helper (`bin/ai-project-visual`),
a guide (`governance/guides/visual-artifacts.md`), and a skip-on-disabled integration test.

---

## Goals

By the end of this Epic, the system must:

1. **Guide every chat level** — add a "Visual Artifact Production" section to AOG: the SN-11
   abstraction table (what each level produces), structural (Mermaid/PlantUML) vs. generative
   (ComfyUI) modes, **tool-capability gating** (capability — not the chat-level label — is the gate),
   and what files to commit and where.
2. **Elicit visual intent at inception** — update `seed.md` Rule 4 (Convergence Target) so the
   Creation Chat asks **"What does success look like visually?"** before the Project Brief is
   finalized (visual intent originates at the Creation Chat and propagates down the artifact cascade).
3. **Ship a callable ComfyUI helper** — `bin/ai-project-visual` (or equivalent), usable by any
   tool-capable agent: takes a prompt, a type, and an output path; reads `comfyui_url`/`enabled` from
   `.ai-project.yml`; calls the ComfyUI API; writes the result; fails clearly when disabled or no
   endpoint is configured.
4. **Document it** — `governance/guides/visual-artifacts.md`: endpoint configuration, structural-diagram
   tooling, output formats, and a worked example per chat level (per the abstraction table).
5. **Test it without a live endpoint** — an integration test that exercises the helper and
   **skips gracefully when `visual_artifacts.enabled` is `false`** (the repo default), keeping the
   suite green.

## Scope of Work

### 1. AOG "Visual Artifact Production" section

Add a new section to `governance/AI-OPERATING-GUIDELINES.md` (placement to fit the document's
structure — a new numbered section; reconcile with the doc's existing numbering). It must cover:

- **Opt-in gating:** the capability is active only when `visual_artifacts.enabled: true`
  (absent/`false` ⇒ off). Cross-reference `ai-project-yml-spec.md` §3.5.
- **Per-level abstraction (SN-11 table):**

  | Chat level | Visual type |
  |------------|-------------|
  | Creation Chat | Concept / vision imagery |
  | HQ Chat | System architecture |
  | Phase Chat | Phase scope diagram |
  | Milestone Chat | Component + flow diagrams |
  | Epic Chat | UI mockups, before/after, implementation diagrams |

- **Two modes:** *structural* (Mermaid/PlantUML diagrams) and *generative* (ComfyUI imagery/video).
- **Tool-capability gating:** an agent produces visuals only if it can call tools; the gate is
  capability, not the chat-level label.
- **What to commit and where:** where visual artifacts are stored in a consuming project (e.g., under
  the `.ai-project/` artifact namespace) and how they are referenced.
- **Version bump:** bump the AOG version (minor: **2.1.0 → 2.2.0**) and add a Changelog row citing
  E22.2 (P5-M22), mirroring how E22.1 versioned the yml-spec.

### 2. `seed.md` Rule 4 — visual-intent elicitation

In `governance/templates/seed.md`, **integrate into the existing "Rule 4 — Convergence Target"**
(do not add a second Rule 4; do not renumber). Add visual-intent elicitation so the Creation Chat
asks **"What does success look like visually?"** as part of converging on — and **before
finalizing** — the Project Brief. Concretely: add a "Visual success" element to the Project Brief
contents and/or a short elicitation prompt within Rule 4, consistent with Rule 1 (elicitation, not
assumption) and Rule 2 (anti-assumption — tag proposals). Keep it additive and in the existing voice.

### 3. ComfyUI helper — `bin/ai-project-visual`

A new helper under `bin/` (Python, consistent with `ai-project-orchestrator`/`ai-project-daemon`),
callable by any tool-capable agent. Contract:

- **Inputs:** a prompt, a `type` (one of the configured `types`), and an output path.
- **Config:** reads `comfyui_url` and `enabled` from `.ai-project.yml` — **reuse E22.1's single
  source** (`load_yml_config()` / `resolve_visual_artifacts()` in `bin/ai-project-orchestrator`)
  rather than re-implementing divergent parsing.
- **Behavior:** when enabled and an endpoint is configured, calls the ComfyUI API and writes the
  result to the output path.
- **Failure modes (clear, non-zero exit):** `enabled: false` ⇒ a clear "capability disabled" message;
  no/invalid endpoint ⇒ a clear configuration error; endpoint unreachable ⇒ a clear runtime error.
- The exact helper name/location is an Epic-level decision; `bin/ai-project-visual` is recommended.

### 4. Integration guide — `governance/guides/visual-artifacts.md`

A new guide covering: enabling the capability (`visual_artifacts` block, endpoint configuration),
structural-diagram tooling (Mermaid/PlantUML), generative usage via the helper, output formats, and
**a worked example per chat level** (one visual per row of the abstraction table). Mirror the voice
and structure of the existing `governance/guides/` documents.

### 5. Integration test — skip-on-disabled

An integration test under `tests/integration/` that exercises the helper against the ComfyUI
endpoint and **skips when `visual_artifacts.enabled` is `false`** (the repo default). It must read
the effective config through E22.1's resolver (load the orchestrator via `SourceFileLoader`, as
`tests/test_visual_artifacts_config.py` does) and `pytest.skip(...)` / `skipif` when disabled — so
the full suite passes (skips, no failures) with no live endpoint.
