### Prerequisite verification (do this first — it is what this Epic hardens)

Before relying on the spec, confirm it is **git-tracked on the expected branch**, not merely
present on disk:

```
git ls-files --error-unmatch docs/phases/P5__Process_Hardening_and_Visual_Artifacts/P5-M20-E20.1__spec__Prerequisite_Git_Tracking_Verification.md
```

Disk presence is not proof of commit: an untracked file passes a file-exists check but is
absent from a fresh worktree clone, producing a false-green prerequisite. (Closing exactly
this gap is the point of this Epic.)

### Summary

Close GH-1: replace disk-existence prerequisite checks in the Milestone and Epic Execution
Chat Starter templates with explicit git-tracking verification, so a prerequisite declared
"committed" is actually tracked in git on the expected branch.

### Problem Statement

During M19, a prerequisite artifact was declared "✅ committed" in a spec but was untracked
in git. The Stage 1 prerequisite check verified file existence on disk only — a fresh
worktree clone would have lacked the artifact entirely. Disk presence is not proof of
commit.

### Goals

1. Make `git ls-files --error-unmatch <path>` on the expected branch the prerequisite
   verification in the Milestone Execution Chat Starter template.
2. Add the same verification instruction to the Epic Execution Chat Starter template.
3. Add a one-sentence inline rationale to each, so a reader knows the check is intentional.
4. Add test coverage asserting the verification wording is present in both templates.
