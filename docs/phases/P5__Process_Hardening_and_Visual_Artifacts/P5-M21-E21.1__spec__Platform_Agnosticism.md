# Epic P5-M21-E21.1 — Platform agnosticism (GH-5)

## Context

Milestone M21 closes three adoption-facing gaps. This Epic closes **GH-5**: governance delivery
is silently tied to a single tool's convention. The adoption-facing guides present
`.github/agents/governance.agent.md` (a GitHub Copilot convention) as the canonical
agent-delivery path, and reference GitHub Copilot as the assumed tool. A new adopter on Claude
Code, Cursor, or Windsurf reaches the "register the agent" step and finds only a GitHub-specific
route — a platform dead end.

> **Provenance:** Authored by the Milestone Chat (P5-M21) under its own authority on 2026-06-27.
> Per the GH-8 adjacency rule (E20.4, now governance law), the Phase Chat produced only the
> Milestone spec and Milestone Execution Chat Starter; the Milestone Chat authors this Epic spec
> and its Epic Execution Chat Starter.

> **Source:** P5 phase spec, P5-GH-5; M21 Milestone spec, "Epic Detail → E21.1".

**Grounding (verified on `milestone/M21`, 2026-06-27):**
- No `.github/agents/` directory exists in this repo — the lock-in is in the **guides'
  references/instructions**, not a tracked directory. Decoupling targets the documentation.
- The agent source file is git-tracked at `governance/agents/governance.agent.md` (consumed in a
  submodule install as `.governance/governance/agents/governance.agent.md`).
- `.github/agents/` and/or GitHub Copilot appear in the current adoption-facing guides at:
  - `governance/guides/ADOPTION-GUIDE.md`: lines ~168, 267–296 (Step 3 — Configure HQ Agent),
    and the reference table (~468).
  - `governance/guides/QUICK-START.md`: lines ~43, 91, 160, 727.
- The `.ai-project/` namespace already exists in-repo (`.ai-project/artifacts/`,
  `.ai-project/logs/`, `.ai-project/queue/`), so `.ai-project/agents/` is a natural,
  consistent home for the tool-neutral convention.

---

## Problem Statement

The framework documents `.github/agents/governance.agent.md` as **the** place the governance
agent lives and how a tool consumes it. That path is meaningful only to GitHub Copilot. Every
other tool — Claude Code, Cursor, Windsurf — has no documented route from "I cloned/added the
governance submodule" to "I have a governance agent open." The single "Other IDEs / chat tools"
bullet in `ADOPTION-GUIDE.md` §3.2 punts to "consult your tool's documentation," which is not a
route. The result: governance adoption silently assumes GitHub Copilot, and a non-Copilot adopter
hits a dead end in the first ten minutes.

---

## Goals

By the end of this Epic, the system must:

1. Define a **tool-neutral agent-delivery convention** — a canonical, platform-independent path
   where the governance agent lives — and document it as the canonical path, demoting the
   implicit `.github/agents/` (Copilot) assumption to one option among equals.
2. Provide **per-tool integration guides** for Claude Code, Cursor, and Windsurf (alongside the
   existing Copilot guidance), each answering: where the governance agent lives, how that tool
   consumes it, and how to open a governance chat with it.
3. Update the **adoption-facing guides** (`ADOPTION-GUIDE.md`, `start-a-project.md`, and
   `QUICK-START.md` where it names Copilot) to reference the neutral path and link the per-tool
   guides, so no GitHub-specific path is *required* to reach the agent-delivery step.

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Build a per-platform installer or any automation that auto-installs agents (M21 documents the
  convention and guides; no installer — Milestone Non-Goal).
- Retro-edit closed `docs/phases/P2__.../` records that mention `.github/agents/` as historical
  record — scope is the *current* adoption-facing guides only.
- Change `governance/agents/governance.agent.md` content, or `genesis.md` / `seed.md` content.
- Touch the GH-6 disambiguation note or the GH-4 "Step 0" opener — those are E21.2.
- Restructure or reflow the guides beyond what decoupling the path requires — additive,
  surgical edits.

## Scope of Work

### 1. Define the platform-agnostic delivery convention

Adopt **`.ai-project/agents/governance.agent.md`** as the canonical, tool-neutral path where the
governance agent is installed in a consumer project (consistent with the existing `.ai-project/`
namespace already used for `artifacts/`, `logs/`, `queue/`). Document it as the canonical install
location, replacing `.github/agents/governance.agent.md` as the *default*. `.github/agents/` is
retained as the **Copilot-specific** location (Copilot auto-detects only that path), documented
in the Copilot integration guide as that tool's consumption step — not as the framework default.

The install copy becomes, in the adoption guide:
`cp .governance/governance/agents/governance.agent.md .ai-project/agents/governance.agent.md`
(with the Copilot guide additionally copying to `.github/agents/` for auto-detection).

> The exact neutral path string is this Epic's design decision; `.ai-project/agents/` is the
> recommended choice and the Milestone fixes only the requirement (tool-neutral, documented,
> linked). If execution selects a different neutral string, it must be applied consistently
> across all edited guides and the per-tool guides.

### 2. Per-tool integration guides

Create a guide per tool under `governance/guides/integrations/`:

- `governance/guides/integrations/claude-code.md`
- `governance/guides/integrations/cursor.md`
- `governance/guides/integrations/windsurf.md`
- `governance/guides/integrations/github-copilot.md` (transcribe/relocate the existing Copilot
  specifics — `.github/agents/` auto-detection, the agent selector step — so Copilot stays a
  first-class, equal option)

Each guide answers, in the same shape:
1. **Where the governance agent lives** — the neutral path (and, for Copilot, the `.github/agents/`
   copy it auto-detects).
2. **How this tool consumes it** — agent-file registration, custom-instructions, or copy-paste,
   per the tool's actual mechanism.
3. **How to open a governance chat** — the concrete action that gets a governance session running
   in that tool.

Add a short index (e.g., `governance/guides/integrations/README.md`, or an "Integrations" list in
the guides `README.md`) linking the four.

### 3. Adoption-doc updates (decouple from the GitHub path)

- `governance/guides/ADOPTION-GUIDE.md` — in **Step 3 (Configure HQ Agent)** §3.1/§3.2 and the
  reference table: install to the neutral `.ai-project/agents/` path; replace the
  Copilot-specific "Register the Agent" content with a **"pick your tool"** step linking the four
  integration guides; move the `.github/agents/` troubleshooting into the Copilot guide.
- `governance/systems/start-a-project.md` — where it reaches the agent-delivery / HQ-agent step,
  reference the neutral path and link the integration guides (do not introduce a GitHub-only
  route). (Coordinate with E21.2, which also edits this file — see Dependencies.)
- `governance/guides/QUICK-START.md` — at the lines that name `.github/agents/` and "GitHub
  Copilot" as the assumed tool (~43, 91, 160, 727): present the neutral path and the per-tool
  guides; keep Copilot as one named example, not the default.

Keep Copilot as **one option among equals** throughout — do not delete Copilot support, demote it
to peer status.

## Technical Constraints

- **Format:** Markdown; additive, surgical edits — decouple the path and link the guides, do not
  restructure the host documents.
- **Consistency:** if a neutral path string other than `.ai-project/agents/` is chosen, apply it
  identically across every edited guide and every integration guide; no mixed conventions.
- **Preserve Copilot:** Copilot remains fully supported (its own integration guide) — it is
  demoted to a peer, never removed.
- **Technology:** documentation only; no new dependencies, no installer/automation.
- **Scope of files:** edit only the integration guides (new), `ADOPTION-GUIDE.md`,
  `start-a-project.md`, `QUICK-START.md`, and the integrations index. Do not edit closed
  `docs/phases/P2__.../` records or `governance/agents/*.agent.md`.
