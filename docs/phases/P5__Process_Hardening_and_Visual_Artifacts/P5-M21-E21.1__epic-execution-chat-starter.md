### Summary

Close GH-5: decouple governance agent delivery from the GitHub Copilot `.github/agents/`
convention. Define a tool-neutral canonical path, add Claude Code / Cursor / Windsurf integration
guides alongside Copilot, and update the adoption-facing guides so a non-Copilot adopter reaches
the agent-delivery step with no GitHub-specific dead end.

### Problem Statement

The adoption-facing guides present `.github/agents/governance.agent.md` (a Copilot convention) as
the canonical agent-delivery path and assume GitHub Copilot as the tool. Claude Code, Cursor, and
Windsurf adopters have no documented route from "governance submodule added" to "governance agent
open." No `.github/agents/` directory exists in the repo — the lock-in is in the **guides'
references/instructions**, which is what you will change.

### Goals

1. Define a **tool-neutral agent-delivery convention** (recommended: `.ai-project/agents/
   governance.agent.md`) and document it as canonical, demoting `.github/agents/` to a
   Copilot-specific option.
2. Add **Claude Code, Cursor, and Windsurf** integration guides under
   `governance/guides/integrations/`, alongside a Copilot guide.
3. Update `ADOPTION-GUIDE.md`, `start-a-project.md`, and `QUICK-START.md` to reference the neutral
   path and link the per-tool guides — no GitHub-specific path required to reach the agent step.
