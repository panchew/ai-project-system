# Epic P5-M20-E20.3 — Scope direction protocol (GH-3)

## Context

Milestone M20 hardens five governance process gaps. This Epic closes **GH-3**: scope direction
to an in-flight Epic had no documented, mandatory, auditable channel.

The Creation Chat / CFO (Layer 8) could direct scope changes to a running Epic informally —
with no Steering Note, no spec amendment, and no re-issued starter — leaving no audit trail and
inviting ambiguity about what the Epic is actually executing against. HQ ratified the routing
rule on 2026-06-20; this Epic writes that ratified rule into the governance documents.

> **Worked example (this milestone, live):** the Phase Chat's Stage-1 authority conflict
> (Starter vs AOG §3.6 on who may commit Epic starters) was routed **upward** via Escalation
> Notice → HQ Ruling
> (`P5-M20__escalation-notice__phase-chat-commit-authority.md` →
> `P5-M20__hq-ruling__phase-chat-commit-authority.md`) instead of being silently self-resolved
> — a live demonstration of the escalate-up-don't-self-resolve principle this protocol codifies.

> **Source:** M19 Escalation Notice, Gap 3; ratified by HQ (2026-06-20).

---

## Problem Statement

Without a mandatory channel, scope direction can reach an in-flight Epic through any informal
path (a chat message, a hand-edited starter pasted into a running session). The consequences:

- **No audit trail** — there is no artifact tying the scope change to a decision and a spec
  version, so later it is impossible to reconstruct why the Epic's scope changed.
- **Ambiguity** — the Epic may end up executing against direction that never made it into the
  committed spec/starter, so "what is in scope" becomes a matter of memory, not record.

A real instance occurred in P4 (the CFO PR review gate arrived via a Creation-Chat-revised
starter pasted into a running chat, bypassing the Milestone Chat; it had to be retroactively
formalized via Steering Note SN-9 + spec amendment v1.1).

## Scope of Work

### 1. "Scope Direction Protocol" section in `chat-hierarchy.md`

Add a new section to `governance/systems/chat-hierarchy.md` that contains the ratified rule
**exactly as written** (do not paraphrase, soften, reorder, or extend):

> Scope direction from the Creation Chat or CFO (Layer 8) to any in-flight Epic must
> flow as Steering Note → HQ Chat → spec amendment → Milestone Chat re-issues amended
> starter. The only exception is a P0 production emergency, where an unblocking directive
> may be issued verbally and formalized within the same session via a Steering Note and
> retroactive spec amendment.

In addition to the verbatim rule, the section must include:
- The **P0 exception** called out clearly (it is part of the rule above; present it explicitly).
- A **one-paragraph rationale**: the channel preserves an audit trail (every scope change is
  traceable to a Steering Note and a spec amendment) and prevents ambiguity (an Epic only ever
  executes against its committed, re-issued starter).

### 2. AOG §3 rule reference

Add a corresponding rule to `governance/AI-OPERATING-GUIDELINES.md` §3 stating the routing
requirement and cross-referencing the new `chat-hierarchy.md` "Scope Direction Protocol" section.
