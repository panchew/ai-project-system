# Epic P5-M21-E21.2 — Adoption documentation clarity (GH-6 + GH-4)

## Context

Milestone M21 closes three adoption-facing gaps. E21.1 (merged) closed GH-5 (platform lock-in).
This Epic closes the remaining two:

- **GH-6** — the `governance/` vs `.governance/` distinction is never explained before
  path-sensitive instructions appear, so an adopter who clones the framework and follows the
  adoption/sync guide hits silent path failures.
- **GH-4** — `start-a-project.md` explains how to fill in `genesis.md` but never tells the
  adopter to first open a Creation Chat by pasting `governance/templates/seed.md` into a Claude
  session. A new adopter has no Creation Chat and no guidance on how to start one.

> **Provenance:** Authored by the Milestone Chat (P5-M21) under its own authority on 2026-06-27,
> per the GH-8 adjacency rule (E20.4). The Phase Chat produced only the Milestone spec and
> Milestone Execution Chat Starter; the Milestone Chat authors this Epic spec and its starter.

> **Source:** P5 phase spec, P5-GH-6 and P5-GH-4; M21 Milestone spec, "Epic Detail → E21.2".

**Grounding (verified on `milestone/M21` post-E21.1, 2026-06-27):**
- `governance/systems/start-a-project.md` runs **Step 1 … Step 7** (no Step 0). The Creation Chat
  is only referenced at **Step 3** ("Run the Creation Chat (produce and commit `genesis.md`)") —
  there is no opener telling the adopter to paste `seed.md` first.
- `governance/templates/seed.md` is the Creation Chat opener (front-matter `purpose: Initialize
  the Creation Chat for a new project`; body "You Are the Creation Chat") — the artifact GH-4
  points adopters to.
- `governance/guides/ADOPTION-GUIDE.md` has a **partial** "Note on submodule path" deep in Step 2
  (~line 214) that says `.governance/` is canonical — but **no top-of-file** note distinguishing
  `governance/` (framework source) from `.governance/` (submodule), and it appears *after*
  path-sensitive instructions, not before. `GOVERNANCE-SYNC-GUIDE.md` and `start-a-project.md`
  have no such note at all.

---

## Problem Statement

Two distinct directories exist: `governance/` (the framework SOURCE repo, used when dogfooding —
this repository) and `.governance/` (the submodule path inside a consumer project). The adoption
and sync guides reference both — and use bare `governance/...` paths — without ever explaining the
split up front. An adopter following the guide in a consumer project, where governance lives at
`.governance/`, silently mis-resolves `governance/...` paths (GH-6). Separately, `start-a-project.md`
drops the adopter straight into `genesis.md` mechanics without ever telling them to open the
Creation Chat that produces it (GH-4). Both are first-ten-minutes blockers.

---

## Goals

By the end of this Epic, the system must:

1. Explain the **`governance/` vs `.governance/`** distinction in a short note at the **top** of
   each adoption-facing guide — before any path-sensitive instruction — so the reader knows which
   path applies to their situation (GH-6).
2. Give `start-a-project.md` a **"Step 0: Open the Creation Chat"** that directs the adopter to
   paste `governance/templates/seed.md` into a Claude session, *before* filling in `genesis.md`
   (GH-4).
3. **Sweep** the current adoption-facing guides for any other path-sensitive instruction that
   suffers the same `governance/` vs `.governance/` ambiguity and fix it.

## Scope of Work

### 1. `governance/` vs `.governance/` disambiguation note (GH-6)

Add a short note — heading **"Self-referential vs. submodule: how to read this guide"** — to the
**top** of, ahead of any path-sensitive instruction:

- `governance/guides/ADOPTION-GUIDE.md`
- `governance/guides/GOVERNANCE-SYNC-GUIDE.md`
- `governance/systems/start-a-project.md`

The note explains, in 3–5 lines:
- `governance/` = the **framework SOURCE repo** (this repository; used when dogfooding the
  framework on itself).
- `.governance/` = the **submodule path inside a consumer project** (where adopters' governance
  lives after `ai-project init`).
- Therefore: in a consumer project, read bare `governance/...` paths in this guide as
  `.governance/governance/...`; if your project *is* the framework source, use `governance/...` as
  written.

Reconcile with the existing partial "Note on submodule path" in `ADOPTION-GUIDE.md` Step 2 — the
new top note is the canonical statement; keep the Step 2 note only if it adds non-duplicative
detail (else fold it into the top note / cross-reference). No contradiction between the two.

### 2. "Step 0: Open the Creation Chat" (GH-4)

Add a **"Step 0: Open the Creation Chat"** section to `governance/systems/start-a-project.md`,
*before* Step 1, directing the adopter to:
- Paste `governance/templates/seed.md` into a Claude session to open the Creation Chat, and
- (Link to the E21.1 integration guides for how to load the Governance Agent in their tool, since
  Step 0 is where a tool/agent is first needed.)

Step 0 establishes the Creation Chat that Step 3 then uses to produce `genesis.md`; make the
Step 0 → Step 3 relationship explicit (renumbering is acceptable if it stays additive and the
existing Step 1–7 flow is preserved in order).

### 3. Ambiguity sweep

Review the **current** adoption-facing guides (`ADOPTION-GUIDE.md`, `GOVERNANCE-SYNC-GUIDE.md`,
`QUICK-START.md`, `start-a-project.md`, and the E21.1 `integrations/` guides) for any other
path-sensitive instruction with the same `governance/` vs `.governance/` ambiguity; fix any found
(or confirm, in the Delivery Notice, that none remain). Do not touch closed `docs/phases/P2__.../`
records.
