**Full spec:** `docs/phases/P12__Completion_Fail_Closed_Defaults_and_the_Drivr_MVP/P12-M46-E46.3__spec__three-governance-rules-unrepresentable.md`

The Epic spec is the authoritative copy of **Deliverables (D1–D3), Definition of Done, Acceptance
Criteria, Binding Constraints, Technical Constraints, Design Decisions Delegated, Non-Goals and
Notes.** **This starter does not duplicate them.** Cite the spec by path and branch — **not** by
a version number or sha.

**The five things easiest to get wrong, flagged here and specified there:**

1. **Validating when the milestone asks for unrepresentable.** A control that renders the
   forbidden state and refuses it is the *validated* form V4 explicitly rules out.
2. **Flattening rule 1 into rule 2.** Creation/HQ are manual-only (rule 1); Phase/Milestone are
   agentic-or-manual but dispatch-less (rule 2). Forbidding agentic at Phase/Milestone contradicts
   the ratified matrix.
3. **A constructibility test that passes only on today's code.** It must be shown to *fail* when
   the forbidden state is re-added (Hard Constraint 2) — otherwise it is not demonstrating the
   absence, it is asserting it.
4. **A check "forgotten, disabled, or raced."** If the model can express `agentic` at `creation`
   and a check refuses it, the rule is not unrepresentable, whatever the test says.
5. **Finishing on the epic branch only.** The model and its tests must be on Drivr `main` (BC9).
