## Deliverables

### D1 — The one normative statement, and every contradicting surface corrected ✅

**Normative home (delegated decision 1): PSG §11.6 "The Model".** One statement, quoted
verbatim from the committed file:

> **The parent performs the merge.** At the Phase→Milestone and Milestone→Epic gates,
> the merge of a child's branch is performed by the **parent** that accepted the
> delivery — a child never holds merge authorization. A Merge Authorization is the
> **parent's own record of an act it performed**, never an instruction issued to a
> child (E43.1, P12-M43). The bypass class `P9-GH-1` / `P10-GH-9` record is
> structurally unavailable, not merely discouraged.

**Why §11.6, not §8** (recorded in the D3 record §1.1): §11.6 already makes "the merge
plus the in-chat acknowledgment" the acceptance record at exactly the parent→child
gates; §8's opening line ("Only Coding Agents … are permitted to mutate the
repository") already contradicts the Milestone/Phase chats' own commit-and-PR role, so
placing the statement there would have required unravelling that inconsistency. §11.6
is one place.

**Corrected surfaces** (each corrected to name the parent as actor; itemized in the D3
record §2.4): PSG §1A step 7, §11.5 Key Rules 5 and 10, §13B; AOG §1A step 7, §3.7;
`governance/EPIC-EXECUTION-CHAT-STARTER.md` step 3 ("you merge the PR" →
the parent Milestone Chat performs the merge); `review-decision.md`;
`artifact-communication-protocol.md`; `chat-hierarchy.md` (Epic Delivery
Authorization merge instruction + Code merge authority row);
`epic-closure-notice.md`; `templates/README.md`. No live governance surface
contradicts the one statement (re-swept; the only remaining "merges" text is the
`phase/* → master` case, deliberately out of this epic's two-gate scope — recorded,
not silently omitted).
