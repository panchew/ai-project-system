# E45.1 Bar — The Trustworthy-Completion-Signal Rubric

**This is the bar.** It is the first commit on `epic/P12-M45-E45.1` so that its precedence over
the work is a property of the history, not a claim (the E41.2 form: D3 as first commit).
It is the rubric E45.2–E45.4 are judged against; it **changes nothing** in the signal.

**Measure-and-commit instance.** E45.1 does not repair the completion signal. It states what
"trustworthy" means, and measures where the signal stands against it today, so that a later change
to the signal is *shown* to have worked rather than *claimed* to.

---

## 1. What the bar scores (the layer)

**The bar scores the `Reading` verdict — the coarse, three-Valued verdict a board consumes**
(`completed` / `did-not-complete` / `undetermined`), per M45 finding **Y3** (two enums, two layers).

- The `Reading` layer is what this bar judges, because that is what a board consumes and what
  E45.4 carries end to end.
- The fine-grained `Completion` layer is **recorded** but **not** scored by the bar. A change at
  the `Completion` layer is not a pass until its `Reading` projection is correct under this bar.
- There is **no `Completion.UNDETERMINED`** (Y3). `undetermined` is a `Reading` member, and a
  reference to `undetermined` anywhere in this bar means `Reading.UNDETERMINED`.

Every term below names the layer it acts on.

## 2. The scoring rule

Each case in the declared evidence set (D2) is scored **correct** or **incorrect** by comparing the
signal's `Reading` verdict to the case's **expected verdict**, declared with the case **before** the
run. Score is 1 if they match, 0 otherwise.

**The `undetermined`-scores-correct rule (D5) — a term of the bar, not a footnote:**

> `undetermined` is a **correct** answer on a case whose evidence is genuinely absent — a case
> where a run produced no observable effect and nothing verifies whether the task's deliverable
> exists. On such a case, `undetermined` is the honest verdict, and it **scores correct**, never
> as a miss. **Penalising honest uncertainty trains the signal to guess**, which is the defect
> P12 exists to close. `undetermined` is **not** correct on a case whose evidence is present and
> complete (those are expected to be `completed` or `did-not-complete`).

Layer: this rule acts on the **`Reading`** layer — it is about the three-valued verdict, and it
does not invent any new `Completion` member.

## 3. Pass conditions (what the signal must meet)

All four must hold. The signal passes the bar if and only if every one holds.

| # | Pass condition | Assessed how | Value that passes | Layer |
|---|---|---|---|---|
| **PC1** | **The read-only case is answered honestly.** A run that read state and wrote nothing is not reported as a failure. | Score the read-only case (C1) against its expected verdict, `reading=undetermined`. | Signal returns `Reading.UNDETERMINED` on C1. | `Reading` |
| **PC2** | **The signal can still say "no".** It did not over-correct into "everything is undetermined" — a run that genuinely did not complete is still flagged. | Score the flag case (C2) against its expected verdict, `reading=did-not-complete`. | Signal returns `Reading.DID_NOT_COMPLETE` on C2. | `Reading` |
| **PC3** | **The signal can still say "yes".** A run that produced work and verified it is passed. | Score the pass case (C3) against its expected verdict, `reading=completed`. | Signal returns `Reading.COMPLETED` on C3. | `Reading` |
| **PC4** | **The signal beats the degenerate baseline.** It carries information a constant does not. | Compare the signal's correct-count on the declared set to the degenerate baseline's correct-count on the **same** set (the baseline always answers `completed`). | Signal's correct-count is **strictly greater** than the baseline's, and the baseline's count is recorded **beside** the signal's. | `Reading` (aggregate) |

**PC4 is a pass condition, not a footnote.** M39 recorded that the judgment **loses to** a baseline
that always answers "completed"; a signal that loses to a constant carries no information. PC4
records both numbers so the comparison is checkable, not asserted.

**PC4 is necessary but not sufficient.** Beating the baseline alone does not make the signal
trustworthy — a signal that already beats the baseline can still be wrong about the class P12 is
about (a read-only run). That is why PC1 is separate: the signal must beat the constant **and**
answer the read-only case honestly.

## 4. The evidence set the bar is measured against (D2, D4)

The bar is measured against the evidence set declared in the same commit as this bar's successor
artifact, `P12-M45-E45.1__evidence-set.md`. **Declared before it is run.** Every case carries its
ground truth and its expected verdict. The declared case count must equal the reported case count;
a case that cannot be run is a **loud, named failure**, never a silently shortened list (E41.2 S3).

| Case | Shape (live run) | Ground truth | Expected verdict |
|---|---|---|---|
| **C1 — read-only (D4, Y1 class)** | a run that reads files and writes nothing — ledger entries carrying `Role.INSPECTION`, no effects, `files_changed=()` | wrote nothing; the evidence that the deliverable exists is **absent** | `reading=undetermined` (scored correct per D5) |
| **C2 — flag (negative control)** | a run that did not do the work — no observable effect | the work was not performed | `reading=did-not-complete` |
| **C3 — pass (positive control)** | a run that produced work **and** verified it | the work was performed and verified | `reading=completed` |

A bar with no negative control (C2) and no positive control (C3) is satisfied by a signal that
always answers one thing. Both controls are in the set.

## 5. Repository and measurement discipline (Hard Constraint)

- **The measurement repository is Drivr.** The signal under measurement and the live-run engine
  live in `~/soft-dev/drivr`; `drivr/judgment/completion.py`, `drivr/judgment/projections.py`,
  `drivr/judgment/evidence.py` are read at the pinned ref **`f15e239`** (re-measured from the
  planning ref `f60164c`; the judgment modules are unchanged between them — see the record).
- **Every measured number names its repository, ref, and source.** "Suite green here" (this
  repository) does not cover a judgment measured in Drivr, and no number here is a measurement
  without the ref of the Drivr code it measured.
- **Only a live run evidences the signal's current behaviour.** The scores in this bar's record are
  produced by running the live OpenCode engine and then Drivr's own projection and judgment
  (`from_execution_result` → `judge_completion`), not by re-reading this repository's source.
- **The signal is not changed here.** `completion.py`, `projections.py`, `_decide` and all Drivr
  judgment code are **untouched** by E45.1. A bar that changes the thing it measures has failed its
  only job.

## 6. Non-negotiability

- **First commit.** The bar is the first commit on this branch — shown by `git log`, not asserted
  in the delivery notice.
- **Declared before run.** The evidence set and its expected verdicts precede the measurement.
- **No post-hoc re-tuning.** If the committed bar turns out wrong, that is an escalation and an
  amended commitment — never a quiet edit.
