## Spec References (load-one-reference-the-other, AOG §3.1.1)

**Full spec:** `docs/phases/P12__Completion_Fail_Closed_Defaults_and_the_Drivr_MVP/P12-M42-E42.1__spec__sandbox-absence-fails-closed.md`

The Epic spec is the authoritative copy of **Deliverables (D1–D4), Definition of Done, Acceptance
Criteria, Binding Constraints, Technical Constraints, Design Decisions Delegated, Non-Goals and
Notes.** **This starter does not duplicate them.**

**The five things easiest to get wrong, flagged here and specified there:**

1. **"Log louder" is not the answer.** The disposition must be an **abort** (`LOCAL_UNAVAILABLE_EXIT`
   + escalation + archive), not a more prominent warning.
2. **Don't `sys.exit(5)` from inside `run_in_sandbox` and skip the record.** The escalation shape and
   the trigger-file archive live at the **caller** (`handle_epic_execution`); `run_in_sandbox` returns
   a tuple. The reason must reach the record, and the trigger file must be archived so the run is not
   silently retried. Decide the propagation and say so.
3. **The opt-in is not decorative.** If a host path survives, the **run record states the opt-in was
   taken, naming it** — a reader must tell sandboxed from unsandboxed *without the invocation*.
4. **"Docker missing" and "Docker broken (daemon not running)" are different failures.** The code path
   you touch raises `FileNotFoundError`; a daemon that is installed and not running does not. Each must
   fail closed, not silently take a different path.
5. **Cite by anchor.** The file drifted +4; the number in your title is stale the day it prints.
