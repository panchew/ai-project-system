## D2 — A readiness check that is run, not asserted

### Mechanism (delegated design decision)

The check is a small Python script (`.ai-project/artifacts/agentic-runs/P12-M47-E47.2/readiness-check.py`)
that **parses the live `.ai-project.yml`** of the selected project, confirms a `models:` block
exists, and **classifies the epic lanes** (`epic_dev`/`epic_qa`) against the proof's route:

- **The proof's route (E47.1, established):** remote agentic dispatch through Drivr's OpenCode
  adapter on a `remote:`-resolvable engine.
- **The standard:** local inference is **PARKED** (SN-43, per the model-routing-policy's baseline
  lineup). A `local:`-prefixed lane is a parked lane — not a dispatchable engine for the remote
  route. A `remote:`-prefixed lane (or a bare resolvable model string like `opencode/…`) is.

The classification is deterministic, the output is JSON, and **the verdict is the record** — the
exit status is recorded for convenience and never relied on (Hard Constraint: never the lane's own
report; never an exit status).

### Run 1 — FAIL (the parked-lane gap, caught)

Result recorded at `.ai-project/artifacts/agentic-runs/P12-M47-E47.2/readiness-check-fail.json`:

```json
{
  "check": "E47.2 readiness check",
  "project": "/home/panchew/soft-dev/panchew-io",
  "yml_exists": true,
  "models_block_present": true,
  "epic_lanes": {
    "epic_dev": { "value": "local:qwen3-coder:30b", "classification": "PARKED_LOCAL" },
    "epic_qa": { "value": "local:qwen3-coder:30b", "classification": "PARKED_LOCAL" }
  },
  "verdict": "FAIL — epic lanes not dispatchable for the remote route (parked local: epic_dev, epic_qa — SN-43: local inference PARKED)"
}
```

**The check caught exactly the gap the spec exists to catch.** A `models:` key present is not the
lanes resolving: "has a models block" and "can dispatch" were **both** true at once, the first for
`models:` and the second false because the epic lanes are parked. An assert that checked for the
string `models:` would have passed this. The run did not.

### The fix — CFO-authorized

Per the E47.2 spec's "fix or escalate before E47.3" path and the Question Policy (a readiness fix
changes the project's config and requires CFO authorization), the failure was presented to the CFO
in this chat. **The CFO authorized the fix.** The edit to
`~/soft-dev/panchew-io/.ai-project.yml`:

```diff
-  epic_dev: local:qwen3-coder:30b
-  epic_qa: local:qwen3-coder:30b
+  epic_dev: remote:deepseek-v4-flash
+  epic_qa: remote:deepseek-v4-flash
```

**The value is the fleet baseline** (SN-41, per the model-routing-policy's baseline lineup — the
same value `ai-project-system` itself configures for its own epic lanes), and the same engine class
E47.1 dispatched (`opencode/deepseek-v4-flash`). The fix is committed to `panchew-io` at **`863eb49`**
(commit message names E47.2 and the CFO authorization).
