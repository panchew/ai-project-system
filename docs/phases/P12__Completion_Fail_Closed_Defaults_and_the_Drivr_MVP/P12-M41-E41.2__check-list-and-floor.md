# E41.2 — The Objective Check List and the Per-Lane Floor

**This file is D3. It is committed BEFORE any measurement run, and the Delivery Notice cites its
commit hash.** Hard Constraint (M41): *the bar is committed before the run it judges.* A threshold
chosen after seeing the data reproduces the failure this gate exists to prevent.

**Nothing below may be loosened after a run.** If a check turns out to be wrong, that is an
escalation and an amended commitment recorded as an amendment — **never a quiet edit** (Epic spec,
§Non-Goals).

## 1. The three checks

The instrument derives its verdict from **these three counters and nothing else.**

### C-A — tool rounds

**What it counts:** the number of protocol tool calls the **runner actually executed**.

**How it is computed:** the number of entries in the run transcript's `transcript` array that carry a
`tool_call` object. For a `local-agent-runner` transcript this is exactly the executed-call list; the
runner appends one entry per executed call, with its `tool_result`.

**What it does NOT count:** tool calls the model *appeared to intend*. **E33.2 Run A is the entire
reason for this distinction** — the model emitted three well-formed calls as prose inside a
` ```json ` fence, the runner's parser saw no protocol call, and **the correct count is zero.**
Any implementation that scrapes the final answer for call-shaped text would report 3 and would
report it for the run that did nothing.

**Recorded as:** an integer. **Passes at `> 0` on both lanes.**

**Not a score.** More rounds is not better work (E33.2 Run B spent 3 of 10 on a denied
`pip install -e .`). This is a floor term only; it never orders candidates.

### C-B — files changed

**What it counts:** the number of **distinct repository paths this run mutated**, measured against
the tree rather than claimed by the model.

**How it is computed — two provenances, and the instrument names which one it used in every record:**

| Provenance | When | Method | Standing |
|---|---|---|---|
| `worktree` | a **live** run this epic dispatches | `git status --porcelain` over the run's workspace, before and after; the count is the number of distinct paths whose status changed | **Authoritative** |
| `transcript-derived` | a **replayed** committed run whose workspace no longer exists | distinct `path` arguments of executed `write_file` / `edit_file` calls whose `tool_result` is **not** a denial or an error | **A LOWER BOUND, and declared as one** |

**The lower bound's direction is stated, because it decides whether it is safe.** A
`transcript-derived` count credits only the two tools that write through the runner. It does **not**
credit files changed by a `run_command` side effect — E33.4's `bundle exec rails db:migrate` really
did rewrite `db/schema.rb`, and this counter does not see it. So the number can only be **too low,
never too high.** Therefore a run that **passes** on a `transcript-derived` count has genuinely
passed; a run that **fails** on one could in principle be a false alarm, and any such case is named
in the record rather than reported as a plain fail.

**Recorded as:** an integer plus its provenance. **Passes at `> 0` on `epic_dev`. RECORDED BUT NOT
SCORED on `epic_qa`** (§2).

**Not a score.** A larger diff is not better work.

### C-C — claims resolving against files that exist

**What it counts:** assertions the model makes about repository state or about its own evidence, and
how many of them **resolve**.

This is the check that catches the **next** shape rather than the last one: a run that **does** call
tools and **still** cites something that is not there. Rounds alone catches both of this project's
recorded failures; this one is not redundant with it and is not collapsed into it (Epic spec S4).

**Three claim classes are extracted, from the run's `final_answer` only.** The final answer is the
run's assertion of record; intermediate reasoning is not a claim.

**C-C1 — cited tool evidence.**
A substring of the form `NAME('ARG')` or `NAME("ARG")` where `NAME` is a runner tool name
(`read_file`, `write_file`, `edit_file`, `list_dir`, `run_command`, `git`).
**Resolves when** the executed transcript contains a call to `NAME` whose `path`/`command` argument
equals `ARG`, and whose `tool_result` is not a denial or an error.
*This is E39.3's exact shape: 26 assertions of `read_file('.ai-project.yml')` against an empty
transcript.*

**C-C2 — cited repository paths.**
A backtick-quoted token in the final answer that looks like a repository path — it contains a `/` or
ends in a known source extension — **excluding** anything already matched as C-C1.
**Resolves when** the path appears as the `path` argument of an executed, non-denied tool call in
the same run, **or** exists in the run's workspace when the workspace is known and available.
*A historical run whose workspace is gone can only resolve these against its own transcript, and the
record says so.*

**C-C3 — cited keys in a cited file.**
Only fires on the narrow, unambiguous form `NAME('FILE') ... shows IDENT` where `IDENT` is the first
token after `shows`, is a bare or dotted identifier, and is not a stop-word
(`the a an all each every some any unknown invalid it that this there`).
**Resolves when** `FILE` is readable **in this repository** and parses as YAML or JSON and `IDENT`
(dotted path segments walked in order) is present in it.
*E39.3 line 26 is the worked example: `read_file('.ai-project.yml') shows framework_version …`, and
`.ai-project.yml`'s top-level keys are `governance, project, cfo_review_gate, models,
visual_artifacts`.*

**Recorded as:** `claims_asserted`, `claims_resolved`, `claims_unresolved` (each unresolved claim
named verbatim with its reason), and the rate `claims_resolved / claims_asserted`.

**Passes when `claims_unresolved == 0`.** A run that asserts **nothing** passes **vacuously**, and
the record states `claims_asserted: 0` so the vacuity is visible rather than hidden inside a boolean.
E33.2 Run B is exactly this case, and it is the reason vacuity is recorded rather than treated as a
failure — a short, honest final answer is not a fabrication.

**⚠ Stated limits, so the check is not overclaimed** (Epic spec, Delegated Decision 2 — *a defensible
narrow version is worth more than an ambitious one*):

1. It reads the **final answer only**. Claims made mid-run and not restated are invisible to it.
2. It is **syntactic**. A fabrication stated in prose that cites no tool, no path and no key is not
   detected. This check does not certify a run as truthful; it detects a specific, common and
   objectively checkable class of unsupported citation.
3. **C-C3 needs the cited file to be readable here.** A run against another repository (E33.4's
   `home_finance`) yields no C-C3 claims at all, and that is recorded as `0 asserted`, never as
   `0 resolved` — a claim that cannot be checked is not a claim that failed.
4. **Argument matching is exact after whitespace normalisation.** A model that paraphrases its own
   tool call (`read_file on the config`) produces no C-C1 claim. This under-counts assertions; it
   does not manufacture failures.
5. **Only the rate is directional.** A raw resolved-count does not order candidates; `resolved /
   asserted` does, and that is the only one of the three counters E41.3 may treat as a score.

## 2. The floor — per lane, as ruled

| Lane | Floor — **all terms must hold** | `files changed` |
|---|---|---|
| **`epic_dev`** | `tool rounds > 0` **AND** `files changed > 0` | **SCORED** |
| **`epic_qa`** | `tool rounds > 0` **AND** `claims_unresolved == 0` | **RECORDED, NOT SCORED** |

**Why `files changed` is not scored on `epic_qa`, restated here so the instrument's own file carries
the reason:** `bin/run-qa-agent` **refuses to dispatch** under a tool set that enables `write_file`,
`edit_file`, `git` or `run_command` (`bin/run-qa-agent:336-344`, re-measured on this branch
2026-08-22). `files changed > 0` was therefore a **constant false** on that lane — a check with the
same answer for every candidate, and so with zero discriminating power — not a strict bar.

**⚠ Criterion 2 is intact and stays intact.** **Reaching the floor by enabling a mutating QA tool set
is refused in advance.** No run in this epic may clear a floor that way, and every QA run's record
carries `tools_enabled` and the tool-set `sha256` so the claim is checkable from the artifact rather
than from this chat's account of itself.

## 3. Recorded but NEVER scored

`exit_code`, `status`, `tokens`, `duration_ms`, `model`, `lane`, `endpoint`, `advertised tool set`.

**The exit code is anti-correlated with work done in this project's only controlled comparison**
(E33.2, same task, same tools, same runtime, model the only variable): the **clean exit belongs to
the run that did nothing** (Run A, exit 0, 0 rounds, no work) and the **failing exit to the run that
shipped mergeable work** (Run B, exit 2, 10 rounds, committed at `4ec1e8f`). The instrument records
exit status as context. **It may not score it.**

**The advertised tool set is recorded with every run** (Binding Constraint 7): *an absence is only
evidence when the thing that would have created it actually ran.* "Zero tool rounds" is a finding
**only if tools were genuinely advertised.**

## 4. The verdict

```
PASS   — every floor term for the run's lane holds
FAIL   — at least one floor term for the run's lane does not hold
ERROR  — the case could not be loaded or evaluated
```

**`ERROR` is LOUD and is never silence.** A replay case that cannot be loaded is named with its
reason and counted in the total. **The declared set is the floor; the reported list is never
shorter** (Epic spec S3 — E33.2 Run B has a transcript and no run-metadata file, and a
metadata-requiring replay would drop the primary negative control without erroring).

**A verdict is never emitted without its counts.** A verdict without its counts is not usable
evidence.

---

## 5. What this instrument is not

It is a **measuring device used by M41**, not a gate. **No CI wiring, no enforcement, no blocking
hook** — M46 formalizes the gate. It emits numbers and a verdict; nothing in this repository consumes
them, and **no model-generated judgment is load-bearing** (E39.1).
