## Summary

**Build the role registry — a Drivr-owned mapping from role (`hq` / `phase` / `milestone/M<n>` /
`epic/<id>`) to the session address that holds it — and enforce exclusivity at claim time, so a
second claimant (including an agreeing fork that is correct and converging) is refused the moment
it claims, not at merge and not by a reader.**

Two facts are the epic's load: **V1** — a session can now state its own address (`ListAgents`
self-report, since 2026-08-27), but a name still carries no role; and **V2** — a fork that agrees
is invisible, and exclusivity must be enforced **outside the state the forks write** (V2b), never
by a tie-break derived from shared state and never by a form resting on implicit `HEAD` (V2c).

**Full spec:** `docs/phases/P12__Completion_Fail_Closed_Defaults_and_the_Drivr_MVP/P12-M46-E46.1__spec__role-registry-and-exclusivity.md`

The Epic spec is the authoritative copy of **Deliverables (D1–D3), Definition of Done, Acceptance
Criteria, Binding Constraints, Technical Constraints, Design Decisions Delegated, Non-Goals and
Notes.** **This starter does not duplicate them.** Cite the spec by path and branch — **not** by
a version number or sha.

**The five things easiest to get wrong, flagged here and specified there:**

1. **Trusting V1 from memory.** `ListAgents`'s self-address report is the claim the whole
   registry rests on. Re-measure it at build time (Hard Constraint 4).
2. **Check-then-act.** A claim built as two calls with a gap between them is a lost race — the
   exact defect `SpendLog`'s `O_EXCL` exists to remove.
3. **A tie-break computed from shared state.** Any "most recently touched X holds the role" rule
   is self-legitimizing and is refused in advance (V2b).
4. **A three-valued lookup collapsed to two.** "Could not read the registry" must never read as
   "no holder" — `held` / `vacant` / `undetermined` are distinct (the V2d pattern).
5. **Finishing on the epic branch only.** The registry and its guard must be on Drivr `main`
   (BC9), not merely pushed to the epic branch.
