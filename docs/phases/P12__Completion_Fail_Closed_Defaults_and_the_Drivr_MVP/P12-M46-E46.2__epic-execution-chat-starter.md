**Full spec:** `docs/phases/P12__Completion_Fail_Closed_Defaults_and_the_Drivr_MVP/P12-M46-E46.2__spec__the-board-and-undetermined-rendered.md`

The Epic spec is the authoritative copy of **Deliverables (D1–D3), Definition of Done, Acceptance
Criteria, Binding Constraints, Technical Constraints, Design Decisions Delegated, Non-Goals and
Notes.** **This starter does not duplicate them.** Cite the spec by path and branch — **not** by
a version number or sha.

**The five things easiest to get wrong, flagged here and specified there:**

1. **A fold introduced "for display".** The contract forbids folding `undetermined` into
   `done`/`not-done` *at render time*; the guard is what catches a well-meaning markup
   simplification.
2. **Reading `exit_code` from the `DispatchRecord`.** It is there for the audit trail, not the
   board's signal (BC3). The board-state function's signature must not receive it.
3. **A bare count where a list belongs.** "3 undetermined" is not the pressure; the itemized list
   is (Hard Constraint 1).
4. **Reasoning about a state name without reading the enum (Y5).** `Conclusion` has three members;
   there is no `Completion.UNDETERMINED`.
5. **Finishing on the epic branch only.** The board and its guard must be on Drivr `main` (BC9).
