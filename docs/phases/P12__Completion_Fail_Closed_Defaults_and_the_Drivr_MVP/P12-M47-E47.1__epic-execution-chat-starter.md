**Full spec:** `docs/phases/P12__Completion_Fail_Closed_Defaults_and_the_Drivr_MVP/P12-M47-E47.1__spec__remote-agentic-dispatch.md`

The Epic spec is the authoritative copy of **Deliverables (D1–D5), Definition of Done, Acceptance
Criteria, Binding Constraints, Technical Constraints, Design Decisions Delegated, Non-Goals and
Notes.** **This starter does not duplicate them.** Cite the spec by path and branch — **not** by
a version number or sha.

**The five things easiest to get wrong, flagged here and specified there:**

1. **Exit status as evidence.** A dispatch whose only evidence is an exit code has not been shown
   to have dispatched (E33.2 Run A exited 0 having done nothing).
2. **A confined `XDG_DATA_HOME` reading as "every engine down."** One failure shape that reports
   *all* engines unreachable at once is the credential defect, not a fleet outage. Record the
   effective credential path so the two are distinguishable.
3. **A transport success read as a loop success.** E35.5's back-test is single-turn and tool-free;
   a packet sent and scored is not a loop that made tool calls.
4. **Rebuilding M41's substrate.** Transport was established on three remote engines; this epic
   uses it, it does not re-derive it.
5. **A route chosen by "what I got working first" instead of on Z5's defect analysis.** The route
   decision must say which defects it inherits and why the trade was taken.
