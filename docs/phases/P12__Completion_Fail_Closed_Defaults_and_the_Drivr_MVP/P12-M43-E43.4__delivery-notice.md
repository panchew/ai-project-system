## Summary

**The system has its first fail-closed default, and it is itself validated.** E43.4
installs the counterweight the phase is balanced on: **exhausted rework — the E43.3
definition, 3 attempts plus any written `+1` — flips the receiving parent to manual
Execution Mode**, opt-out, on by default. The switch (`rework_exhaustion_flip:
enabled`) is **blessed** — a §3 schema entry and a §4 rule — together with the
unblessed precedent it was told to copy, `cfo_review_gate` (finding W1 closed: the
first fail-closed default does not ship as a key nothing validates). The flip is stated
normatively (PSG §11.6); the **committed-starter invariant survives** because **Drivr
performs and records the flip** — never by rewriting the committed starter, so the
flip is discoverable from the record; and **resume** — which appeared in **no**
normative document (finding W5) — is now specified: **restores, never promotes;
returns the mode, not the budget**. The Drivr half lands in **its own repository**
(`~/soft-dev/drivr`, a new `drivr/modes/` recorded-mode-transition package), and its
verification is named separately — **"suite green here" is not claimed for it.**

## Deliverables

### D1 — The switch (repository: `ai-project-system`) ✅

`.ai-project.yml` gains `rework_exhaustion_flip: enabled` — a **top-level** key, values
`enabled`/`disabled`, on the `cfo_review_gate` pattern: **on by default, disabled
deliberately**. The name names the trigger (rework *exhaustion*, E43.3's definition)
and the action (the *flip*); the comment states the behaviour in full. This repository
runs the flip **enabled** — the default, not an exemption.

### D2 — The blessing (repository: `ai-project-system`) ✅

`governance/ai-project-yml-spec.md` v2.9.0: **§3.7** (`cfo_review_gate`) and **§3.8**
(`rework_exhaustion_flip`) schema entries plus **§4 rules 27/28** (value must be
`enabled` or `disabled`; both keys optional, absent ⇒ enabled). `bin/ai-project-validate`
recognises both keys and enforces the value constraint — **no validator warning for
either key**. `cfo_review_gate` is blessed **in the same change** (the delegated
decision, stated): W1's defect is the precedent itself being unvalidated, so blessing
the successor while leaving the precedent warned would leave a standing warning on this
repo's own config — both are blessed so the whole top-level opt-out surface is
validated. The remaining schema-drift keys (`created_at`, `submodule_path`) stay
escalated, and the pre-existing `model_verification` warning is **measured,
pre-existing, and out of E43.4's scope** — stated, not hidden.

### D3 — The normative flip statement (repository: `ai-project-system`) ✅

PROJECT-SYSTEM-GUIDELINES.md §11.6 **"The Rework-Exhaustion Flip"** (v2.7.0): exhausted
rework **flips the receiving parent to manual** — the system's **first fail-closed
default**; **opt-out, on by default** (`rework_exhaustion_flip` in `.ai-project.yml`);
**Drivr performs the flip and records it** — the committed starter is never rewritten,
so the flip is discoverable from the record; **resume** restores the declared mode,
never promotes manual → agentic, and returns the mode, not the budget.

### D4 — The committed-starter invariant preserved (repository: `ai-project-system`) ✅

`chat-hierarchy.md` (v1.5.0), immediately after the Declaration-mechanism invariant
(`:229-231`): a new subsection **"The rework-exhaustion flip: the invariant survives,
the record is the source"** — the committed starter stays the source of truth; the flip
is discoverable **from the record**, never from a mutated committed file; the flip is
stated **by reference** to PSG §11.6 (one statement, no second copy).

### D5 — Resume specified normatively (repository: `ai-project-system`) ✅

`chat-hierarchy.md`, new subsection **"Resume: restores, never promotes; returns the
mode, not the budget"** — resume's **normative home** (W5: it existed in no normative
document). **Restores, never promotes** — only an agentic-declared committed starter
may be resumed to agentic; no control moves manual → agentic. **Returns the mode, not
the budget** — no rework-counter reset, or the flip's own trigger would make the limit
unenforceable by the very control meant to recover from it.

### D6 — The Drivr-side mechanism (repository: **Drivr**) ✅ verification named separately

**Drivr** (`~/soft-dev/drivr`, branch `epic/P12-M43-E43.4`): new package
**`drivr/modes/`** — the **recorded mode transition**. `ModeTransitionStore`
(append-only NDJSON) performs and records the flip (`flip_to_manual`) and the resume
(`resume`), reading the declared mode from the committed starter
(`read_declared_mode`; absent field ⇒ manual). **Never promotes by construction**
(effective after resume = declared); **never resets the budget** (no counter field in
the record; `resume` takes no counter argument). **Verification: Drivr's own pytest

root; 452 → **469 passed** at `af3904d`. **This repository's suite does not reach
Drivr, and "suite green here" is not claimed for it.**

**Drivr has no remote — stated, not skipped.** `git remote -v` in `~/soft-dev/drivr`
