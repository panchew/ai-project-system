# Delivery Notice: P11-M38-E38.4 — `local-agent-runner` Retention Assessment

## Summary

**Retain `local-agent-runner` for now, and retire nothing.** OpenCode 1.18.10's real `serve` API
distinguishes ordinary finish, crash and abort in structured output, but a configured `maxSteps`
ceiling returns the same `finish: "stop"` shape as ordinary finish. It therefore does **not** cover the
runner's load-bearing C3 distinction between `completed`, `max_iterations_exceeded` and `error`.

OpenCode also has no Python in-process entry point for Python-based Drivr (C1), and its tested JS/TS
plugin boundary passes mistyped primitives through to a typed handler rather than coercing or rejecting
them (C2). The C3 result is the retention reason M39 needs: one engine already exposes the distinct
ceiling-exhausted status that the sole roster engine does not.

No completion judgment was built. G11 was not claimed. `local-agent-runner`, OpenCode and
`bin/run-dev-agent` were not modified.

## C1 — result

**Not covered for E38.1's chosen stack, Python 3.** The runner exports the measured
`run(model, task, permissions, *, endpoint, max_iterations, system, context, options, client) -> Result`
with injectable client. OpenCode binary 1.18.10 exposed a real OpenAPI 3.1 `serve` API with 162 paths,
and a real plugin tool registered and executed. Its installed in-process surfaces are JS/TS SDK/plugin
1.15.13, not an importable Python library. For Python Drivr they remain HTTP or subprocess boundaries.
If Drivr were JS/TS, this answer would need re-testing against version-matched packages.

## C2 — result

**Not covered at the tested OpenCode plugin boundary.** Against a real plugin argument declared
`z.number()`, numeric `8` arrived as a number; string `"8"` arrived as a string; and unusable string
`"banana"` arrived as a string while the structured tool state reported `completed`.

This is neither recovery nor validation. `local-agent-runner` retains the narrower measured capability:
coercion of mistyped primitives under a flat schema, with string properties uncoerced, unknown
properties passed through and missing/unusable typed values rejected.

## C3 — explicit result

**OpenCode partially covers C3 but is not equivalent to the runner's four-exit/three-status contract.**

| Tested outcome | OpenCode 1.18.10 structured result |
|---|---|
| ordinary finish | HTTP 200; assistant `finish: "stop"` |
| crash: nonexistent model | HTTP 500; typed `UnknownError` body |
| abort | SSE `session.error` with `MessageAbortedError`; activity status busy → idle |
| `agent.build.maxSteps: 1` ceiling | server logged `step=1` then `exiting loop`; caller received `finish: "stop"`, no error, no tool execution |

The runner's measured contract is exit 0 / `completed`, exit 2 / `max_iterations_exceeded`, exit 3
configuration error, and exit 4 / `error`. OpenCode distinguishes crash and abort, but **does not
distinguish ran out of steps from finished in the returned structure**. That is the load-bearing gap.

The structured abort signal is a useful fourth finding, not a fourth candidate.

## Judgment and M39 input

**Retention judgment: retain for now, principally for C3.** The B3.1 field evidence first showed the
runner return exit 2 plus `max_iterations_exceeded` while OpenCode `run` exited 0 after doing no work.
This `serve` assessment narrows but does not remove the difference.

M39 can plan from the measured fact that the sole roster engine folds configured ceiling exhaustion
into ordinary `finish: "stop"`, while `local-agent-runner` already exposes a distinct
`max_iterations_exceeded` result. This Epic did not build the judgment that consumes those facts.

**Nothing was retired.** P9/P10's local-inference evidence remains unaffected.
