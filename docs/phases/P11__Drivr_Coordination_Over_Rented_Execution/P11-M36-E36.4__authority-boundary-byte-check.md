## The command

Content-anchored, not line-number-based: this Epic **adds a section to `system-hq.md`**, shifting
every line below it, so a line-number check would break or — worse — silently compare the wrong range
and report a false pass.

```bash
extract() { awk '/^> \*\*System HQ Authority Boundary\.\*\*/{f=1} f{if(/^$/)exit; print}' "$1"; }
for f in governance/systems/system-hq.md \
         governance/systems/system-hq-seed.md \
         governance/systems/chat-hierarchy.md; do
  printf '%s  %s  (%s lines)\n' "$(extract "$f" | sha256sum | cut -c1-16)" "$f" "$(extract "$f" | wc -l)"
done
```

The anchor was verified against all three documents before use — it matches exactly one line per file
(`system-hq.md:61`, `system-hq-seed.md:77`, `chat-hierarchy.md:1077`), and the terminating blank line
closes the block at 11 lines in each.

### Independent cross-verification (after)

```
after 1v2:  IDENTICAL
after 1v3:  IDENTICAL
before-vs-after (system-hq.md):  IDENTICAL — the block itself is unchanged by the edit
full sha256: baecaad4dbc2146c74e02236297c085e7d1a68d9ee92e018e56af0d2282a4a43
byte counts: 939 / 939 / 939
```

The third line is the one that matters most: the after-block was compared **against the before-block
byte-for-byte**, so the check proves the block did not change, not merely that the three documents
still agree with each other. Three documents could in principle agree *and* all be wrong; this
comparison closes that gap. Only `system-hq.md` was edited, so `system-hq-seed.md` and
`chat-hierarchy.md` were never candidates for divergence — but the check covers all three anyway,
because that is what the DoD item requires and because the value of the check is that it is run
mechanically rather than reasoned about.

**No divergence occurred, so the revert path (and the explicitly forbidden "make the other two
agree" path) was never entered.**
