# Epic E37.1 — System-tier versioning convention (P10-GH-8)

## Context

**⚠ This Epic runs AGENTIC / LOCAL — `models.epic_dev` (`local:qwen3-coder:30b`) — by CFO decision,
2026-08-05** (Milestone spec v1.1.0, §Execution Posture — SPLIT). M37's two epics run under different
postures deliberately: **E37.1 agentic/local, E37.2 manual/paid.** Running one local and one paid
inside a single milestone, on comparable subject matter and adjacent files, produces a **controlled
comparison** rather than one ambiguous result — evidence M38 and M39 want, gathered here because
E37.1 has a **cheap ground truth**: after the run, either all seventeen documents comply or they do
not, checkable in one command.

**Two guardrails follow from that posture and are binding: G1 and G2** (see §Binding Constraints, and
§The verbatim rows). **This Epic must be DISPATCHED through `bin/ai-project-orchestrator`, not opened
as a chat.**

**Mode is not authority.** Stage-2 acceptance and merge authorization remain human-keyed; the Milestone
Chat's review is unchanged in depth and remains manual/paid; **all nine binding constraints and the
Hard Constraint apply identically.** Agentic mode is not a licence to build enforcement, reconstruct
history, or renumber anything.

**This is M37's first epic, and it lands first by binding decision** — see §Dependencies. M37 is the
milestone the CFO carved out of old-M37 on 2026-08-05 so that corpus record conventions get decided
and applied **once**, inside a fence, rather than accumulating as hygiene routed into "the milestone
with room."

**Read the governing ruling through the renumbering table.** HQ Ruling 2026-08-04 places this work at
**`M37/E37.6`**. That citation predates the 2026-08-05 five-milestone restructure and **is correct at
its date**; it is deliberately not rewritten (HQ Ruling 2026-08-01, Decision 4 — *a bookkeeping defect
never rewrites a citation* — and the SN-15 precedent). **Read `E37.6` as `E37.1`.** Do not "fix" the
ruling.

**The convention is already decided. This Epic applies it.** HQ decided it once for all seventeen
documents precisely so it would not be settled per-document under a passing edit — which is what
P10-M35's E35.1 correctly refused to do, and what made the carry-forward note well-formed. **Nothing
in this Epic is a design question about whether or how documents should be versioned.**

## Problem Statement

**Ten of seventeen `governance/systems/` documents cannot record their own amendments**, and the set
has not shrunk in five weeks: new documents are created with the convention, existing ones never gain
it. **The gap is calcifying, not closing.**

P10-GH-8's revisit trigger fired inside M36, and the demonstration was a single commit. E36.1 wrote
precise changelog rows into `artifact-communication-protocol.md` (v1.4.1), `fleet-operator.md`
(v1.2.1) and `fleet-operator-brief.md` (v1.0.1) — and could record **nothing** for its single largest
change, a ~74-line new normative section in `creation-chat-guide.md`. **The convention works exactly
where it exists and is silently absent where it does not**, under one author and one spec. That is
structural, not a matter of diligence.

The ten include the two most-amended and most-cited documents in the directory: `chat-hierarchy.md` —
per P10-GH-8's own note, *"cited by more artifacts than any other document in the directory"* — and
`creation-chat-guide.md`.

## Design decisions — decided by the Milestone Chat, apply them

The Milestone spec assigns E37.1's starting-version scheme to the Epic Chat; the Milestone Execution
Chat Starter assigns it to the Milestone Chat. **The Starter outranks the Milestone spec in the
governance hierarchy, so the Milestone Chat decides it here**, and the discrepancy is recorded rather
than resolved silently. The executing agent **applies** these decisions and does not re-litigate them.

> **The 2026-08-05 posture switch settles this discrepancy rather than complicating it.** This Epic now
> runs **agentic / local**, and the milestone spec's phrase *"the Epic Chat's design decision"* was
> written when it was expected to run manual/paid. **An agentic run should not be making corpus-wide
> design decisions at all** — which is the same reasoning that produced G1. D1–D4 are decided here for
> the same reason the `chat-hierarchy.md` row is quoted verbatim: **judgment belongs in the spec, not
> in the run.**

### D1 — Starting version is `1.0.0` for all ten, uniformly

**Every seeded document starts at `version: 1.0.0`.** Not `0.1.0`, not a per-document guess, not a
figure inferred from how much the document has changed.

**Reasoning:** the seeding row does not claim to be the document's first revision — it claims to be
**the first revision recorded under this convention**, which is exactly what a uniform `1.0.0` says.
Any non-uniform scheme requires knowing how much history preceded it, and knowing that requires
exactly the commit archaeology Constraint 1 puts permanently out of scope. **`1.0.0` is the only
scheme that is honest without archaeology, and uniformity is what keeps ten near-identical rows from
becoming ten small judgment calls.**

Note that `fleet-operator-brief.md` — one of the seven — sits at `1.0.1`, so `1.0.0` is consistent
with how the directory already reads.

### D2 — For the three documents with no front matter, create a minimal block; **do not invent a date**

Create:

```yaml
---
type: system
status: active
version: 1.0.0
---
```

**`type` and `status` are determinable from the document itself** (it is a system reference in
`governance/systems/`, and it is in force). **No date key is added.** Both `effective_date` and
`last_updated` would require a value nobody can supply honestly without commit archaeology, and
inventing one is backdated reconstruction wearing a different hat.

**Exception — `epic-execution-chat-starter.md` already declares `type: template`, not `type: system`.
Leave that as it is.** It is one of the seven-with-a-block, so this decision does not reach it; it is
called out because the mismatch is visible and tempting. See §The adjacent tidy-ups.

### D3 — `## Changelog` goes at the end of the document, matching the seven

The seven compliant documents place `## Changelog` as a trailing section. Match that. Where a document
ends with a "Related Documentation" / references block, **place `## Changelog` after it** — last
section in the file — so the seventeen read alike.

### D4 — The row wording is not authored during the run; it is transcribed

**Superseded in form by G1, and strengthened.** The rows are **not** composed at execution time. All
three shapes are provided as literal strings in **§The verbatim rows** above — the eight uniform rows
(one `<PATH>` substitution), `chat-hierarchy.md`, and `creation-chat-guide.md`.

Every row satisfies, by construction: (a) the convention was adopted on **HQ Ruling 2026-08-04
(P10-GH-8)**'s authority; (b) it **points at git for prior history**; (c) it cites **E37.1 (P11-M37)**;
(d) it is dated **2026-08-05**, uniformly.

**The Delivery Notice still states the wording once** — but as a confirmation that the literals were
transcribed unmodified, which is a check a reviewer can run with `grep`, not a claim to be trusted.

## Execution Notes

**Suggested order:**

1. **Check your branch first** — `git branch --show-current`. This shared worktree is worked by
   multiple sessions and gets left on whatever branch the last one used; **M36's Finding 4 records a
   false "content is missing" alarm from exactly this.** Re-check before your first commit and before
   any verification you intend to report.
2. **Re-run the compliance measurement** before editing anything, and record the output. The
   seventeen/seven/ten split is a planning-time fact, not a guarantee.
3. **Transcribe `chat-hierarchy.md`'s G1 row first** — while the erratum is fresh and before ten rows
   of momentum make it feel like just another row. **It is the one row a reviewer will check
   hardest.**
4. **Then the eight uniform rows**, then `creation-chat-guide.md`'s. **All from §The verbatim rows.**
5. **Then verify the seven are untouched** and produce the diagram.

**On the shape of the risk, and why G1 addresses it directly.** This Epic is **broad but shallow**.
There is no hard problem in it. The risk is that **a single consistency lapse lands in ten governance
documents at once** — and the specific lapse this posture makes likeliest is **flattening**: nine rows
say one thing, one row says something longer and different, and the tenth quietly becomes the ninth.
*"One exception among ten uniform items"* is precisely the shape a weaker model regularizes.
**G1 removes the composition step entirely.** The rows are supplied as literals; the task is
transcription and a single `<PATH>` substitution.

**Verify by comparison, not by reading.** The check that the rows are right is a **string comparison
against this spec**, not a judgment that they read sensibly. A flattened row reads perfectly well —
that is what makes it dangerous.

**On the exit code — G2, and it is not a formality.** `bin/run-dev-agent`'s exit status is
untrustworthy in **both** directions on this stack: **E33.2 Run A exited 0 having done zero work**;
**E33.4 exited 2 having done complete, green work** (P10-GH-7). **Record the exit code. Do not
conclude anything from it.** The verdict comes from re-running the compliance measurement and
comparing the ten rows against this spec's literals.

**If the run refuses to start**, `bin/run-dev-agent` exits with **class 5** when the local model is
genuinely unavailable (P9-M31-E31.2, *"local loadability is never assumed"*). **That is a clean,
informative failure** — record it and report to the Milestone Chat; do not work around it by opening
a chat instead.

**On P10-GH-10 — read before interpreting a red suite.**
`tests/test_artifact_router.py::test_daemon_extensions_error_branches` fails **~3 in 10 full-suite
runs** (measured across M36, upgraded from a recorded ~10%), passes 5/5 in isolation, and is
**untouched by anything in M37**. **A red suite on that test alone is not evidence of a defect in this
Epic** — re-run, and **record both results rather than only the green one.** Out of scope: do not fix
it, skip it, or mark it.

**Environment:** `python` is not on `PATH` in this worktree. Use `python3 -m pytest`.

**On counts.** This phase has now produced repeated instances of *a record stating a count that omits
its own contribution* — including HQ's own Decision 5, which is the reason Constraint 3 exists.
**When this Epic states how many documents it seeded or how many amendments a row records, count
carefully and show the measurement.**
