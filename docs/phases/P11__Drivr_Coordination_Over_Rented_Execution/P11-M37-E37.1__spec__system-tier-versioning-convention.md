# Epic E37.1 — System-tier versioning convention (P10-GH-8)

## Context

**This is M37's first epic, and it lands first by binding decision** — see §Dependencies. M37 is the
milestone the CFO carved out of old-M37 on 2026-08-05 so that corpus record conventions get decided
and applied **once**, inside a fence, rather than accumulating as hygiene routed into "the milestone
with room."

**Read the governing ruling through the renumbering table.** HQ Ruling 2026-08-04 places this work at
**`M37/E37.6`**. That citation predates the 2026-08-05 five-milestone restructure and **is correct at
its date**; it is deliberately not rewritten (HQ Ruling 2026-08-01, Decision 4 — *a bookkeeping defect
never rewrites a citation* — and the SN-15 precedent). **Read `E37.6` as `E37.1`.** Do not "fix" the
ruling.

**The convention is already decided. This Epic applies it.** HQ decided it once for all seventeen
documents precisely so it would not be settled per-document under a passing edit — which is what
P10-M35's E35.1 correctly refused to do, and what made the carry-forward note well-formed. **Nothing
in this Epic is a design question about whether or how documents should be versioned.**

---

## Problem Statement

**Ten of seventeen `governance/systems/` documents cannot record their own amendments**, and the set
has not shrunk in five weeks: new documents are created with the convention, existing ones never gain
it. **The gap is calcifying, not closing.**

P10-GH-8's revisit trigger fired inside M36, and the demonstration was a single commit. E36.1 wrote
precise changelog rows into `artifact-communication-protocol.md` (v1.4.1), `fleet-operator.md`
(v1.2.1) and `fleet-operator-brief.md` (v1.0.1) — and could record **nothing** for its single largest
change, a ~74-line new normative section in `creation-chat-guide.md`. **The convention works exactly
where it exists and is silently absent where it does not**, under one author and one spec. That is
structural, not a matter of diligence.

The ten include the two most-amended and most-cited documents in the directory: `chat-hierarchy.md` —
per P10-GH-8's own note, *"cited by more artifacts than any other document in the directory"* — and
`creation-chat-guide.md`.

## Design decisions — decided by the Milestone Chat, apply them

The Milestone spec assigns E37.1's starting-version scheme to the Epic Chat; the Milestone Execution
Chat Starter assigns it to the Milestone Chat. **The Starter outranks the Milestone spec in the
governance hierarchy, so the Milestone Chat decides it here**, and the discrepancy is recorded rather
than resolved silently. The Epic Chat **applies** these decisions and does not re-litigate them.

### D1 — Starting version is `1.0.0` for all ten, uniformly

**Every seeded document starts at `version: 1.0.0`.** Not `0.1.0`, not a per-document guess, not a
figure inferred from how much the document has changed.

**Reasoning:** the seeding row does not claim to be the document's first revision — it claims to be
**the first revision recorded under this convention**, which is exactly what a uniform `1.0.0` says.
Any non-uniform scheme requires knowing how much history preceded it, and knowing that requires
exactly the commit archaeology Constraint 1 puts permanently out of scope. **`1.0.0` is the only
scheme that is honest without archaeology, and uniformity is what keeps ten near-identical rows from
becoming ten small judgment calls.**

Note that `fleet-operator-brief.md` — one of the seven — sits at `1.0.1`, so `1.0.0` is consistent
with how the directory already reads.

### D2 — For the three documents with no front matter, create a minimal block; **do not invent a date**

Create:

```yaml
---
type: system
status: active
version: 1.0.0
---
```

**`type` and `status` are determinable from the document itself** (it is a system reference in
`governance/systems/`, and it is in force). **No date key is added.** Both `effective_date` and
`last_updated` would require a value nobody can supply honestly without commit archaeology, and
inventing one is backdated reconstruction wearing a different hat.

**Exception — `epic-execution-chat-starter.md` already declares `type: template`, not `type: system`.
Leave that as it is.** It is one of the seven-with-a-block, so this decision does not reach it; it is
called out because the mismatch is visible and tempting. See §The adjacent tidy-ups.

### D3 — `## Changelog` goes at the end of the document, matching the seven

The seven compliant documents place `## Changelog` as a trailing section. Match that. Where a document
ends with a "Related Documentation" / references block, **place `## Changelog` after it** — last
section in the file — so the seventeen read alike.

### D4 — One seeding-row wording, applied uniformly

Write the row once and reuse it verbatim except for the document-specific amendment column. It must:
(a) state that the convention was adopted on **HQ Ruling 2026-08-04 (P10-GH-8)**'s authority; (b)
**point at git for prior history**; (c) cite **E37.1 (P11-M37)**. **State the chosen wording once in
the Delivery Notice**, so a reviewer can confirm uniformity without diffing ten rows against each
other.

Two documents' rows carry document-specific content and are **deliberately different** — see
Deliverables 2 and 3. **Everything else about their rows matches the other eight.**

### The file-contention decision (binding — reproduce the reasoning if asked)

Both epics amend `creation-chat-guide.md`: **E37.1** adds front matter and a trailing `## Changelog`;
**E37.2** adds a new section alongside the existing §Steering Note ID Allocation. **The regions
differ**, so this is not a textual conflict — it is a **record-consistency** question, and it has
exactly two resolutions:

| Order | Who owns reconciliation |
|---|---|
| **E37.1 first (CHOSEN)** | **E37.2** adds its own row to the `## Changelog` E37.1 created, and bumps `version` `1.0.0` → `1.1.0` |
| E37.2 first (rejected) | **E37.1**'s seeding row would have to record E37.2's change *as well as* M36's two |

**E37.1 first is chosen** because the alternative puts a *second* irregularity into a set of ten
deliberately-uniform rows — `creation-chat-guide.md` would then differ from the other eight in two
ways, on top of `chat-hierarchy.md` already differing in one. **Ten near-identical rows with one
deliberate exception is reviewable; with three it is a set of decisions.** It also runs the natural
direction: the section that records amendments exists before the amendment that must be recorded in
it. The phase spec names E37.1 first independently.

**Consequence, stated plainly:** the two epics run **serially, not in parallel**. That is a real cost
in a five-day milestone and it is accepted deliberately.
