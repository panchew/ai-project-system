# Epic E38.3 — Three-State Fleet Registry, Classification Pass, P10-GH-5 Validator, P10-GH-1 Schema Entry

**Stage A. Parallel to E38.2 — no dependency in either direction.**

---

## Context

**The fleet is a memory, not a data structure.** **Fifteen** project directories on the machine,
**thirteen** enrolled *(re-measured 2026-08-11, after E38.1 delivered `drivr`; the spec's own v1.0.0
figures were 14 and 12 — **correct at their date and already stale**, which is the point)*, and the
authoritative list of them lives in prose across a dozen phase artifacts, each correct at its date and
none correct now. `panchew-io` is enrolled in the governance system and named in **no
phase artifact at all** until M38's planning found it.

SN-27 decision 5 makes the registry Drivr's foundation: **Drivr reads fleet state to decide what to
coordinate.** A registry over configs that degrade quietly is the same defect class as a scheduler over
an untrustworthy exit code — which is the exact failure M39 exists to fix and M40 waits behind.

This Epic does three things that turn out to be one thing:

1. **Builds the three-state registry** and classifies **every** project on the machine.
2. **Builds a validator for `ai-project-yml-spec.md` §4** (P10-GH-5), whose rules have been normative and
   unenforced since they were written.
3. **Schema-blesses `framework_version`** (P10-GH-1), folded in by Phase Chat decision, with a recorded
   escape.

**Building the registry forces the classification pass**, which is how `ai-stack` and `character-factory`
resolve — **as registry work, not as a separate decision.** That framing is the Epic's spine.

**Four gaps, all measured 2026-08-08 and all worse than the record states.**

2. **`ai-project-yml-spec.md` §4's validation rules are normative and unenforced.** **Verified: there is

4. **The fleet is invalid more widely than recorded, and so is the framework's own tooling** (Findings 1
   and 2).

## ⚠ Finding 5 — `ai-project-system`'s own missing `framework_version` has a strong available answer

**The milestone spec requires this to be decided deliberately, not silently exempted and not filed as a
defect. The Phase Chat named it a review criterion. Here is the evidence; the decision is yours.**

**This repository's own `.ai-project.yml` carries:**

```yaml
governance:
  source: ./governance
  version: "7.1.0"
  ref: master
```

**`governance.version` is already `"7.1.0"` — the current framework version.** Under §8's canonical
self-referential pattern, the governance source points `source` at its own `./governance` and pins
`version` to itself.

**So the available reading is that for the governance source, `governance.version` *is* the framework
version, and `framework_version` would be a second field recording the same fact — structurally
redundant rather than missing.** An adopting project needs both because they differ: `governance.version`
is what it pinned, `framework_version` is what it adopted. **For the source, they are the same number by
construction.**

**Decide it, record the reasoning, and make it checkable.** If you decide differently, say why — the
evidence above is an argument, not a ruling, and this Epic owns the call.

> **The registry consequence, which is the part that must not be silent:** whatever you decide,
> **`ai-project-system` must still be classified**, and the registry must represent a project whose
> framework version is knowable from `governance.version` rather than `framework_version` **without
> that looking like missing data.**

## The Hard Constraint — and this Epic's specific drift

**Drivr rents. It does not build what it can invoke.**

> **The drift here is not building an engine. It is building M40's coordination one convenience at a
> time.**
>
> A registry that knows every project's state is one short step from a thing that **decides which
> project to work on next** — and that is **M40's derived gate queue**. A transition log is one short
> step from a thing that **transitions automatically** — and Constraint 5 forbids exactly that, as a
> returned CFO proposal rather than a settled question.
