## 5. The two delegated decisions with a real cost either way

### 5.1 Delegated decision 2 — the test does **not** scan `docs/`. Forward-only.

**Decision: templates and system references only.** Reasoning, recorded, because the spec named this
as a genuine trade-off rather than a settled question:

1. **Instantiated starters are historical records of what a chat was actually told.** Retro-editing
   them to add the guard would make them claim to have said something they did not say, which is a
   worse corruption than the gap.
2. **Retro-*failing* them turns the suite red for closed epics.** The spec names this outcome as
   worse than a forward-only guard.
3. **A forward-only floor would be unfalsifiable today.** The obvious fix — "only starters from
   milestone N onward" — must place N past every artifact that exists, because `P11-M40__milestone-execution-chat-starter.md`
   (this milestone's own, already instantiated) predates the guard. **M40 is the final milestone of
   P11**, so the floor would sit beyond the last artifact this phase produces: a check asserting
   nothing, that cannot be falsified, and that no one would notice had rotted. **That is precisely
   M38's recorded trap** — `testpaths` masking a stale `norecursedirs`, a rotted guard invisible
   behind a green total. Adding a second instance of it to close a gap about invisible failures would
   be self-defeating.

**What replaces the docs/ scan:** the guard binds the **templates every future starter is copied
from**, and the test carries **five detector self-tests against synthetic fixtures** — including one
that flags the exact copy-paste failure (the Epic guard pasted one level up, still naming the
Milestone Chat) — so the checker itself cannot silently rot.

**Residual, stated rather than implied:** a future chat that instantiates a starter and *drops* the
guard is not caught by a test. It is caught by the template being right and by Stage-2 review. This
is a real, bounded gap and it is recorded here rather than left to be discovered.

### 5.2 Delegated decision 3 — currently-running chats are reached by note, not by reach-in

**Decision: a note to the parent, no reach-in.** The mid-flight amendment rule is explicit and this
epic is bound by it: *"do NOT reach into those running sessions."* The M40 Milestone Chat and the P11
Phase Chat are both running on starters instantiated before this guard existed.

**Mechanism used:** this record and the Delivery Notice state the obligation plainly, and the
Delivery Notice asks the Milestone Chat to relay it to the Phase Chat. That is the admissible
downward/upward channel. **No running session was reached into, and no already-delivered starter was
edited.**

## 6. A defect found in the guard's own construction

**The guard shipped in P9 was one markdown reflow away from being unverifiable by literal match.**

Found by running the new test, not by reading it (method obligation 9). The first execution on
2026-08-17 failed on `governance/templates/epic-execution-chat-starter.md` — for a guard that was
**present and correct**. Re-wrapping the bullet had split the anchor across a line break:

```
  **Milestone Chat** — or HQ Chat during bootstrap — after its own Stage-2 review), do
  not simply comply: state plainly that merge authorization normally follows the parent
```

`do not simply comply` is not a substring of that file. A plain `grep` for the guard's own text
reports it missing.

**Two fixes applied, deliberately both:**

1. The test normalizes whitespace and case before matching, so a reflow is not a false failure —
   with a self-test proving deletion is *still* caught after normalization, because whitespace
   insensitivity is itself a weakening risk.
2. All eight surfaces were additionally reflowed so both anchor phrases sit unbroken on one line, so
   a **human** auditing with `grep` gets the right answer too. Verified:

```
$ for f in <the eight>; do printf '%-58s refusal=%s mode=%s\n' "$f" \
    "$(grep -ic 'do not simply comply' $f)" \
    "$(grep -c 'mode is what may run, not what may be authorized' $f)"; done
… all eight → refusal=1 mode=1
```

**Why this is worth recording beyond this epic:** every literal-string guard in this repository shares
the property. `tests/test_template_prerequisite_wording.py` asserts `git ls-files --error-unmatch`,
which survives only because it is short enough not to wrap. This is an observation for the Milestone
Chat, **not** a fix applied here — that would be scope expansion.
