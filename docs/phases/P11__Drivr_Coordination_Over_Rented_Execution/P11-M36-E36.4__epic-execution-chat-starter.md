## The Byte Check — the item most likely to be done wrong

**Verified baseline on `milestone/M36`:** `sha256` prefix **`baecaad4dbc2146c`**, **11 lines**,
**identical across all three** documents today.

**Use a content-anchored check, not line numbers.** You are **adding a section to `system-hq.md`**,
which shifts every line below it. A line-number check would break — or worse, silently compare the
wrong range and report a false pass. This was written and run against `milestone/M36` at planning
time; **verify it yourself rather than trusting it:**

```bash
extract() { awk '/^> \*\*System HQ Authority Boundary\.\*\*/{f=1} f{if(/^$/)exit; print}' "$1"; }
for f in governance/systems/system-hq.md \
         governance/systems/system-hq-seed.md \
         governance/systems/chat-hierarchy.md; do
  printf '%s  %s  (%s lines)\n' "$(extract "$f" | sha256sum | cut -c1-16)" "$f" "$(extract "$f" | wc -l)"
done
```

**Run before the edit. Run after the edit. Commit both outputs.**

**If it diverges after your edit, you changed the block.** Revert your change to it. **Do NOT adjust
the other two documents to match** — the block is verbatim-frozen by Decision 4, and "making them
agree again" by editing the other two is the failure this check exists to catch.
