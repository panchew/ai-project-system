### Summary

Build the **thin surface, headless-first**, holding **gates in-app only**, with **signed one-time-link
approval** — minted in-app, used once, **shown to fail on reuse** — and **show that no chat reply can
authorize anything.**

### The four properties, and why the spec splits them

The milestone spec asks for one demonstration: minted, used once, fails on reuse. **The Epic spec
splits the link's binding into four separately testable properties**, because three of them fail
silently if left implicit:

| Property | Negative test owed |
|---|---|
| **Signed** | a link the surface did not mint is rejected |
| **One-time** | a second use of a valid link is rejected |
| **Bound to one gate** | a link for gate A cannot approve gate B |
| **Expiring** | an expired link is rejected |

**Every rejection fails closed** — no partial authorization, no retry that succeeds, no silent no-op a
caller could mistake for approval.

**And the load-bearing distinction:** *the link is the inbound channel; the authorization artifact is
still minted in-app.* **An epic that treats the link as the authorization has rebuilt the chat reply
with extra steps.**

### The constraint that must not bend

**Constraint 3: a chat reply NEVER authorizes — prohibited, not deferred.** The Hard Constraint names
this specifically: *"an approval path that accepts a chat reply, even as a convenience, is prohibited
rather than discouraged."*

**The shape this fails in is a convenience path added "just for local testing."** If you need one to
test, **it must not exist in the delivered artifact, and you must show it does not.**
