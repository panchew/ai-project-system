**`sha256` before deletion and after recomputation are the same digest.** `diff` reports no
differing lines.

*(The CLI's "86396 bytes" is a character count and `wc -c`'s 86,602 is a byte count; the
document contains multi-byte characters — `§`, em dashes. Both figures are of the same
file and neither moved between the two computations.)*

**Reproduce it:**

```bash
drivr/bin/drivr-gate-queue --repo ~/soft-dev/ai-project-system \
                           --measured-on 2026-08-17 --out /tmp/q.md
sha256sum /tmp/q.md && rm /tmp/q.md
drivr/bin/drivr-gate-queue --repo ~/soft-dev/ai-project-system \
                           --measured-on 2026-08-17 --out /tmp/q.md
sha256sum /tmp/q.md
```

`--measured-on` is **required and never defaulted to the clock.** A report that dated itself
could not compare equal to its own recomputation, which would make D2 unfalsifiable rather
than satisfied.

### The snapshot is itself inside a read root, and the queue notices

The figures above are the corpus **as it stood before this Epic's own artifacts were
committed.** Re-running after committing them:

```
    21  declared-open

822 → 825 files, and `needs-a-human` 245 → 246. The three added documents are this evidence
file and the D3 account — both carrying frontmatter, both classified — **and the snapshot,
which the CLI emits without frontmatter and which therefore surfaces as `needs-a-human`.**

This is left as it is rather than papered over. Adding frontmatter to the snapshot would make
the *"reproduce it"* command above stop matching the committed file, and the alternative
reading — a queue that quietly excluded its own output from its own corpus — is a
special-case exemption of exactly the kind that makes a coverage number untrustworthy. **The
queue reads what is there, including what this Epic put there**, and both counts are stated
with the moment each was taken.

It is also the cheapest possible demonstration that **every inventory is a floor**: this one
went stale during the commit that recorded it.

## Why an exact match proves anything

A constant reproduces exactly too. Three further properties are under test in
`drivr/tests/test_queue_derivation.py`, because byte-equality alone is satisfied by a
mechanism that ignores the corpus:

| Property | Test |
|---|---|
| The output **changes when the artifacts change** | `test_the_queue_changes_when_the_artifacts_change` — adding a ruling removes the escalation it answers |
| Computing the queue **leaves the tree byte-identical** — there is nowhere for a cache to hide | `test_the_queue_has_nowhere_to_persist` |
| Ordering is **total and content-derived**, not filesystem order | `test_ordering_is_total_and_content_derived` |

D1's *"no hand-maintained store is the source of truth for any entry"* is enforced by there
being no store: `compute_queue()` takes a **repository path**, not a queue file, and there is
nowhere in `drivr/queue/` for one to live.

**Read that against the full run.** The narrow queue is not visibly broken. It is *tidier*:

reading 204 of 822 files, 25% of the corpus. It raises no error and reports no shortfall
beyond the roots line a reader has to notice and think about.

> **This is the failure mode, executed rather than described.** A queue that is wrong loudly
> costs a human ten seconds. This one is wrong quietly, and looks *better* for it.

## The guard, falsified

The conservation invariant — every enumerated file lands in the result — was verified by
**introducing the defect it exists to catch**: a single filter dropping `UNCLASSIFIED`
entries at the end of `read_corpus`, which is the shape a `try/except: continue` would take.

```

guard was made to fail on purpose before being relied on.
