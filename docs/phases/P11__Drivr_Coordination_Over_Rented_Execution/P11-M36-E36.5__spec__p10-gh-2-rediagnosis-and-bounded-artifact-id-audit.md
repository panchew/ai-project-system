# Epic E36.5 — P10-GH-2 re-diagnosis + bounded artifact-ID audit

## Context

**This is M36's final epic.** E36.1–E36.4 are merged (`f1a5e75`, `65a512e`, `d8f4871`, `5012dcc`).
On this Epic's merge the Milestone Chat produces the Milestone Closure Declaration (`is_final:
false`) and hands back to the Phase Chat for M37 planning.

Two items, both about **the record's honesty about itself.**

The first corrects a carry-forward that points a future owner at the wrong file. The second measures
whether the defect E36.1/E36.2 just fixed in one artifact family exists in the others — **and stops

**This Epic is where M36's scope pressure lands, and the milestone spec says so in terms.** SN-28

## Problem Statement

### 1. P10-GH-2 points at a file that needs no change

P10-GH-2 is recorded as *"the Creation Chat Seed does not implement the E31.3 model-verification
check."* **That premise is false, and the falseness is verifiable in one command.**

Verified independently at planning time:
- `governance/templates/seed.md` has carried the **Prerequisite Verification** section since commit
  **`d7ee7cd` (2026-07-19)** — **nine days before** the 2026-07-28 ruling that filed the gap.
- `governance/templates/genesis.md` carries it from the same commit.
- The 2026-07-31 Creation Chat session, opened from `seed.md`, **ran the check.**

The real defect — now closed by **E36.3** — was that a session re-opened by
`creation-chat-guide.md`'s ritual received three artifacts, **none of which carried a model check**,
because the only one that would (`genesis.md`) does not exist in this project.

**As filed, P10-GH-2 points a future owner at a file that needs no change, and the actual defect
would survive the fix** (HQ Ruling 2026-08-01, Decision 8).

### 2. Only one artifact family has ever been audited

SN-28 audited **steering notes only**. **Rulings, escalation notices, and the `GH-` gap-record
series allocate IDs the same unenforced way**, and `GH-` is **cited far more widely** than `SN-`.
Nobody has ever checked. Given that the unaudited family produced two collisions, a clean result in
the others would be the surprising outcome — **which is exactly why the boundary below matters.**

## The Hard Boundary — read this before running the audit

**The audit reports. It does not remediate. This is the load-bearing rule of the epic.**

The temptation is asymmetric and worth naming in advance: **fixing a collision found mid-audit will
feel cheaper than escalating it.** It is a two-line edit; an escalation is an artifact, a routing
hop, and a wait. That asymmetry is precisely why the constraint exists — it is the same pressure that
turns a bounded cleanup into an open-ended one, inside the milestone whose entire value proposition
is that cleanup lands **bounded and governed**.

**The disposition table is not a judgment call:**

| What the audit finds | Disposition |
|---|---|
| No collision in a family | **Record it.** A clean family is a finding, not an absence of one |
| The family **does not allocate its own IDs at all** | **Record that as the finding.** Do not manufacture a collision check that does not apply |
| A collision confined to **project-internal, non-normative** artifacts | **Report and leave.** Do not renumber |
| A collision **cited in the normative tier** (`governance/`) | **ESCALATE to HQ.** M36 does not fix it and does not widen to accommodate it |
| A convention inconsistency (not a collision) | **Characterize and record.** Not a defect to fix here |

**Make escalating the path of least resistance.** If a normative-tier finding appears, write the
escalation notice using `governance/templates/escalation-notice.md`, issue it to the **Milestone
Chat (P11-M36)** — one level up, per SN-25 — and continue the rest of the audit. **Do not stop the
epic, and do not fix it while you are there.**

**The distinction that bounds this work — apply it, and state it:**

- **A restatement of the false premise** → **amend.** The text asserts the Seed lacks the check.
- **A mere mention** → **leave.** e.g. *"alongside P10-GH-2 and P10-GH-3"*, or the *"no renumbering
  of P10-GH-1…"* lists in the P10-GH-4/5/6 carry-forward notes. These name the item without
  restating its premise; amending them adds noise without adding truth.
- **Already carries the re-diagnosis** → **leave.** SN-26, SN-28, the 2026-08-01 ruling (Decision 8),
  and the 2026-08-01 HQ opener already state the item is misdiagnosed.

> **Amend, do not rewrite history.** These are closed-record artifacts — a phase closure declaration,
> a milestone closure declaration, two HQ documents. **The correction is a dated amendment or
> footnote that leaves the original claim legible**, in the same spirit as E36.2's rename footnotes
> and E36.3's inline dated notes. **The record's honesty is the point.**

**The corrected premise, for reuse:** the Seed has carried the check since `d7ee7cd` (2026-07-19);
