# Delivery Notice: P11-M38-E38.5 — Milestone-Context Evidence for `qwen3-coder:30b`

## Summary

**`qwen3-coder:30b`, through Ollama's native `/api/generate` endpoint at its loaded window of 32,768 tokens, silently truncates the Milestone Chat's defined session-start context.** A live marker-method probe of the defined corpus (147,571 bytes of prescribed source content, tested as a 147,626-byte superset including a 55-byte section-boundary residue) processed 38,465 input token IDs — 5,697 above the loaded window — and lost the position-0 marker, returning tail content instead. No error or warning was emitted. The model is not at fault; the 32,768-token window inherited from the deployment is smaller than the corpus it must hold. (The OpenCode adapter uses the `/v1` endpoint, which cannot adjust the loaded denominator; the probe correctly used the native endpoint that powers that transport.)

A further HQ call decides row P4 on this evidence. This Epic does not decide it.

### Failure mode

**SILENT TRUNCATION.** The model processed only the last ~32,767 tokens of the prompt. The position-0 marker was lost without any error, warning, or signal. The model generated output (`"END"`) from the visible tail, behaving as though nothing was wrong.

The defined session-start corpus (147,626 bytes, ~36,900+ tokens at Ollama's own tokenization rate) exceeds the 32,768-token loaded window by a margin large enough that Ollama's `prompt_eval_count` hit 32,767 before reaching position 0. The excess is silently dropped from the beginning. This is the exact risk the phase spec names as the live danger.

### Additional evidence — full-document probe (252,583 bytes)

An earlier probe (reported in the initial submission) used a larger corpus of 252,583 bytes assembled from the milestone spec, phase spec, PSG, and AOG **in full** (the defined session-start sections plus the sections scoped as "do not load" and "load on trigger"). That probe also produced silent truncation (32,764 prompt tokens, lost position-0 marker). The result is consistent with and corroborates the exact-corpus finding, but the exact-corpus probe above is the primary evidence for the defined scope.

## 5. The honest finding: the model is fine, and the window is too small

This measurement says nothing about the model's quality. The variable that moved is the deployment: the `/v1` OpenAI-compatible endpoint used by the OpenCode adapter cannot set `num_ctx` (phase spec §P11.3 measured note), so 32,768 tokens is a fixed denominator through this path. At that window, the Milestone Chat's session-start context does not fit — the exact-corpus probe proves it truncates silently.

**"The model is fine and the window is too small"** is the correct sentence. The finding is about the deployment, and a different deployment would produce a different result.
