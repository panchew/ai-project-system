# Delivery Notice: P11-M39-E39.1 — Completion Judgment That Does Not Rest on the Exit Code

## Summary

**There is now a component that answers *"did this run complete?"* from evidence, and returns a
verdict carrying that evidence.** M35's handback rule has had no detector beneath it since the day
it was recorded. That is no longer true.

**The mechanism is ordering.** A verification is evidence about the state a run left behind
**only if no effect follows it.** That one rule separates the two runs that agree on every signal
the fleet has ever read:

| Case | `status` | exit | iters | last effect | last verification | Verdict |
|---|---|---|---|---|---|---|
| E33.2 Run B | `max_iterations_exceeded` | 2 | 10 | **#9** `edit_file` | #5 `pytest -q` → 2 | `EFFECTS_UNVERIFIED` |
| E33.4 | `max_iterations_exceeded` | 2 | 10 | #5 `edit_file` | **#6** `bundle exec rspec` → 0 | `EFFECTS_VERIFIED` |

Run B's failing test is **stale** — it describes a tree that was edited afterwards. Calling that a
contradiction would be wrong; calling it *nothing happened* would be wrong too. The third position
is what the spec's §F5 said a boolean could not hold, and it is why the vocabulary has five
members.

**The code lands in drivr; this PR carries the governance record.** Nothing under `governance/`
or `bin/` in this repository is modified, and no normative document is amended.

      carries all four dispositions — used / absent / ignored / noted — verified for every
      corpus-shaped case by `test_every_corpus_case_yields_a_verdict_carrying_all_four_dispositions`.

      Demonstrated two ways, one behavioural and one structural:
      **(a) By mutation** — `tests/test_judgment_independence.py` rewrites `status`,
      `final_answer` and the exit code, individually and in combination, across all six
      corpus-shaped cases to every value observed anywhere in the corpus, and asserts the verdict
      does not move.

## The QA-pass decision, restated — and what it means for E39.3

The Epic spec settled this at planning time and it was **binding, not reopenable**:

> **The verdict MUST NOT be load-bearing on any model-generated judgment.**

**Honoured, and enforced structurally rather than by intention.** No model-generated assessment
is a term in any rule; the rules read an ordered ledger and a snapshot delta and nothing else.
`model-generated judgment` appears on **every** verdict in the `ignored` list with its reason, so
a reader can see it was considered and excluded rather than never contemplated. The evidence-item
list is the admissible home for an advisory model assessment, as the spec allows — and **no
speculative seam was built for one**, per the spec's explicit instruction.

**Consequence for E39.3, consumed rather than discovered:** the `epic_qa` dispatch path **does
not exist and this epic did not create it.** `ExecutionRequest` still has no `role` field —
re-verified at `drivr@715099c`, unchanged from `31dad51`. **E39.3 therefore builds it on its own
terms under milestone constraint 4, or reports G11 still open with the reason.** Nothing here
constrains which of those it chooses.

## C3 — used, not merely acknowledged

M38 retained `local-agent-runner` principally for C3: it exposes `max_iterations_exceeded` where
OpenCode returns an ordinary finish reason. **It is used**, and precisely:

`Termination` projects `max_iterations_exceeded` → `CEILING_REACHED` and `completed` →
`SELF_DECLARED_DONE`, and the distinction is recorded as an advisory note on every verdict. It
answers **why** a verification is missing — a run that hit its ceiling ran out of room; a run that
declared itself done stopped believing there was more to do. Those are different facts for a
coordinator to act on, and the worst combination in the corpus is legible because of it: Run A is
`SELF_DECLARED_DONE` **with an empty ledger** — it stopped, believing it had finished, having done
nothing.

**It is a term in no rule**, and `test_termination_is_projected_from_status_but_stays_out_of_the_rules`
pins that: flipping the termination changes the note and leaves the verdict where it was.

## Engine-neutrality — and the one dependency, stated because M40 inherits it

The judgment reads the normalized record and **nothing else**. `drivr/judgment/` does not import
`drivr/execution/` — asserted by `test_the_judgment_layer_does_not_import_the_execution_layer` —
and `from_execution_result` reads attributes rather than importing types. Adding a third evidence
source is one function in `projections.py` and **no change to the judgment**.

> **Single-adapter dependency:** the ordered effect ledger is available from
> `local-agent-runner` transcripts and **from no adapter on today's roster.** OpenCode emits no
> machine-readable status (`engine_status` is documented as *always* `None`) and drivr's adapter
> extracts no tool-call stream from its NDJSON.
>
> **A live OpenCode run therefore projects with `effect_ledger=None`, ordering is unavailable, and
> it can never reach `EFFECTS_VERIFIED`** — only `EFFECTS_UNVERIFIED`, `NO_EFFECTS_OBSERVED` or
> `INDETERMINATE`. `test_a_live_opencode_result_can_never_reach_verified` pins the reachable set.

This is a real limit on the roster, **not** a defect in the judgment: verification coverage is an
ordering claim and there is nothing to order. Closing it means an adapter that projects an ordered
ledger, and OpenCode's `--format json` stream is the obvious candidate. **It was not built** —
nothing in this milestone needs it, and a seam built on speculation is the generality this phase
has been explicit about refusing.

**drivr still rents.** Nothing added owns inference, a model loop, or an agent client
(constraint 6).

**One judgment call worth flagging to the reviewer**, since it is mine and not the spec's: a
`run_command` that executes is classified as a **verification** and not as an effect, because
whether an arbitrary shell command mutates the tree is not decidable from a ledger. The
consequence — a run whose only effects are made through the shell registers no effect — is
recorded as a known limitation in `docs/completion-judgment.md` §9, and the `INDETERMINATE`
verdict for *commands ran, nothing recognised, no snapshot* exists so that the case fails safe
rather than reading as *nothing happened*.
