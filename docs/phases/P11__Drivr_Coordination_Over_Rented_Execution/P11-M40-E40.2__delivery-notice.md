## Findings for the Milestone Chat

1. **The obvious rule cannot work in this framework.** PSG §11.6 line 586 accepts a clean
   delivery **by silence** with no artifact, so absence-based rules read the happy path as
   the backlog — **98** entries for deliveries with no merge authorization, **29** for
   completions with no review decision — and read *more* of it as the corpus grows.
   **Better recognition makes the rule worse: F5's shape, met independently, at a different
   layer, from a different cause.**
2. **The strict parser reaches 28 of 822 files (3.4%)**, not the 48 of 203 the planning
   measurement implied — because **42 of the 70 registered-type artifacts fail their own
   schema**, 31 of them holding a date with a citation appended in prose where an ISO-8601
   string is required.
3. **55 artifacts carry frontmatter that is not valid YAML**, all from an unquoted scalar
   containing `": "`. Five are milestone closure declarations, including **M39's**.
4. **The `status` key is uncontrolled** — 30+ values, five spellings of *waiting*.
5. **The queue is reporting stale gates accurately.** `B2.1` reads `status: open` though it
   merged 2026-08-07; seven P4 completion notices still read `ready_for_review`. **Reported,
   not remediated** — the spec makes that a finding, not a work item.
6. **The corpus is bi-located** (101 of 106 delivery notices under `docs/`). Recorded as an
   observation; **a 600-file move is not this epic**.
