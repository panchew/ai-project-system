## The stack choice and its full reasoning

**drivr is a Python 3 project.** Standard library `subprocess`, standard library assertions run
under `pytest`, and **PyYAML as its single runtime dependency**.

**The reasoning was written down and committed before drivr existed** — commit `34f5d20`,
`P11-M38-E38.1__stack-decision.md`, which precedes drivr's own initial commit. The spec asked for
the reasoning *"before you create anything… it is easier to write honestly before the code exists"*;
**making that verifiable from git history rather than asserted is the point.**

### Against the five constraints

| # | Constraint | How Python 3 satisfies it |
|---|---|---|
| 1 | Invoke a CLI tool as a subprocess; read exit code, stdout, stderr | stdlib `subprocess` returns all three from one call. No dependency. |
| 2 | Read YAML | PyYAML, declared in `requirements.txt` |
| 3 | Be testable | pytest present on the host; baseline established at 2 passed, each test falsified |
| 4 | Be headless | No GUI, no window, no interactive entry point — the package has no entry point at all |
| 5 | No inference SDK, model client, or agent framework | `requirements.txt` is one line, `PyYAML>=6.0` |

### The tiebreak, stated

**Python and Go both satisfy all five and both would carry exactly one runtime dependency, so the
spec's "fewer dependencies" tiebreak does not resolve them.** The resolving fact is measured, on the
host, 2026-08-10: **`go` is not installed.** Choosing it would make "establish a test baseline"
require installing a toolchain — **adding infrastructure to satisfy a *lightest infrastructure*
constraint, which is self-defeating.**

Rejected on their merits: **POSIX shell fails C2 and C3** (YAML needs `yq`, testing needs `bats`,
neither installed). **Node/TypeScript and Rust** both satisfy all five but carry 2+ dependencies
and a heavier tree.

Two **supporting** reasons, recorded as supporting rather than as the decision: the idiom is already
the fleet's (this repository's own suite is pytest, so a reviewer re-measuring drivr's baseline
needs no new tool), and a one-line requirements file is the cheapest possible place to demonstrate
Constraint 1.

### On PyYAML being declared but unused

**Constraint 2 is a capability requirement on the stack, not an instruction to write a loader.**
drivr must be *able* to read YAML because **E38.3's registry** will. Writing the loader here is
precisely the drift both the spec and the starter name. **PyYAML is declared — and its availability
is asserted by a real test — while no loader is written.** The declaration is E38.1's deliverable;
the loader is E38.3's.

### The fifth defect — a correction, not an addition, and the spec did not enumerate it

**`governance.version: v7.1.0` is §4-invalid.** Rule 5 requires *"a quoted semver string matching
`\d+\.\d+\.\d+`"* and init's value fails on **both** counts — v-prefixed and unquoted. **Corrected
to `"7.1.0"`.**

**Cause, from reading the source:** `create_ai_project_yml` writes `version: $governance_version`
(`:261`), where `$governance_version` is the **git ref** taken from `--governance-version` and
passed through `validate_git_ref`. **A single CLI argument feeds two fields the schema deliberately
separates** — `version` (a semver) and `ref` (a git ref). **That is also why `ref` is missing: init
has no concept of it as distinct from `version`.** The two defects share one root cause, which the
four-addition framing obscured by treating the missing `ref` as an omission.

**So enrollment is `bin/ai-project-init` plus FOUR additions plus ONE correction.** Stated plainly
because the spec's own history on this point is a count that grew from two to four; **this is the
same measurement being completed again, and the next reader should treat five as a floor too.**

**Notably, FM 7 predicted this and the Epic spec's addition list did not.** FM 7's text names both
sub-shapes — *"`governance.ref` absent"* **and** *"`governance.version` holding"* a non-semver.
**The hazard checklist was more complete than the spec derived from it.**

**FM 5 — provisionally "Likely closed"; it FIRED.** No `hq.agent.md` was installed, so P6-GH-15's
*literal* form is closed. But the **class** — *the installed agent is not the canonical one* — fired

**Epic spec Finding 4's instruction — "check the artifact, not the script" — is the only reason this

**FM 9 — provisionally "Inapplicable — no prior `.gitmodules`"; it FIRED.** The reasoning was that a

`git config -f .gitmodules submodule.governance.branch v7.1.0` (`:298`), producing `branch = v7.1.0`

**Left in place, not removed.** Reasoning: the recorded pin and the actual pin **agree today**
(`v7.1.0` both), so there is no live disagreement to fix; the spec's disposition toward init's
outputs is *record, do not tidy*; and **removing it would destroy the evidence for the escalation**
and hide the real shape from E38.3's validator. **It becomes live at drivr's first bump**, where FM
9 applies as written — flagged here so that bump does not rediscover it.

### The twelfth failure mode

**FM 12 — `bin/ai-project-init` installs a placeholder agent, not the canonical one, on every
submodule-based install.**

`install_hq_agent` computes its source as
`src_file="$project_dir/governance/agents/governance.agent.md"` (`:328`). **The submodule mounts the
entire `ai-project-system` repository at `governance/`, and the agent lives at `governance/agents/`
*within* it — so the real path is `governance/governance/agents/governance.agent.md`, one level
deeper.** The `[[ -f "$src_file" ]]` test at `:333` is false, and the `else` branch (`:335-345`)
writes the stub.

**The doubling is structural, not incidental:** `add_governance_submodule` hardcodes the submodule
path as `governance` (`:274`, `:294`), and the framework repo keeps its corpus in a directory *also*
named `governance/`. Both are correct in isolation; the source path was written against neither.

**And its own validation passes the stub.** `:348-353` requires the destination to be readable,
non-empty, and to start with `#` or `---`. **The 230-byte stub satisfies all three.** That is a
third validator in this tool that accepts what it should reject — alongside the two Finding 2
already named.

**Why this is genuinely new rather than a restatement.** FM 3 says the installed agent can go
*stale*. FM 5 says a *legacy* install may carry a placeholder. **Neither says the current tool
creates one at enrollment time.** It also supplies **the missing origin story for
`ai-project-system-mcp`'s 230-byte stub**, which E34.1 recorded as found without establishing where
it came from — the byte count and wording match exactly.

## Rework — the governance submodule moved to `.governance`

**Required by the Review Decision and Epic spec v1.2.0. Complete and re-verified.** Full command
transcript in confirmation evidence §12.

**The correction is accepted without argument.** The Epic recorded the deviation and left it because
its spec said to; **the spec measured what `bin/ai-project-init` defaults to and never measured what
the fleet uses.** `.governance` is the convention **8 to 3**, and the three exceptions are exactly
the init-created projects. The Epic had that measurement available and did not take it — **"the tool
does X by default" is not evidence about what the fleet does**, and treating it as such is
`P11-GH-2`'s class one more time.

### The five required steps, plus a sixth found by doing them

| # | Step | Result |
|---|---|---|
| 1 | `git mv governance .governance`, `.gitmodules` `path` **and** section key | done — **`git mv` updates only `path`**; the section key needed `git config -f .gitmodules --rename-section` |
| **1b** | **`.git/config` re-registered under the new name** | **NOT in the Review Decision's five — see below** |
| 2 | `.ai-project.yml`: `submodule_path: .governance/`, comments, `# Spec:` line at `:3` | done |
| 3 | `pyproject.toml`: `norecursedirs` | done |
| 4 | `README.md`: deviation note **removed**, one line in its place | done |
| 5 | Re-verify: §4, submodule resolution, agent sha256, baseline | **all four pass** |

> **Step 1b — a sixth step the five did not name.** Renaming the `.gitmodules` section key
> **desynchronises `.git/config`**, and `git submodule status` then reports the submodule
> **uninitialized** (`-` prefix). It needed `git config --remove-section submodule.governance`
> followed by `git submodule init`. **A rework that executed exactly the five listed steps would have
> left a repository whose submodule does not resolve** — and **step 5's own "`git submodule status`
> resolving" check is what caught it.** The check was load-bearing, not ceremonial.

|---|---|

| `git submodule status` resolves | **yes** — ` bb727a52… .governance (v7.1.0)` |
| Installed agent sha256 | **`66404389…`, 14711 bytes — UNCHANGED** |
| **Drivr's baseline** | **still 2 passed — did not grow** |

`governance/` strings — it is the canonical installed agent, its sha256 must not change, and those
strings are the framework's own generic text rather than drivr path references.

**The Review Decision counted `README.md` ×2; there were 3.** Recorded because inventories here are
floors, including the reviewer's.

### ⚠ The baseline guard is not the line the Review Decision identified

The Review Decision warned that `norecursedirs` is *"exactly the change that silently starts
collecting the vendored submodule's suite."* **Right about the risk, wrong about which line carries
it** — established by falsification:

| `testpaths` | `norecursedirs` | Collected |
|---|---|---|
| `["tests"]` | **stale** | **2** |
| *removed* | **stale** | **239 tests + 3 collection errors** |
| *removed* | correct | **2** |

**`testpaths = ["tests"]` alone holds the baseline at 2 even with a fully stale `norecursedirs`.**

> **The finding is the masking, not the redundancy. Had `norecursedirs` been left stale, the baseline
> would still have read `2 passed`, and nothing would have signalled that the guard had rotted.** The
> check the Review Decision specified **cannot detect the failure it was written to catch**, because
> a second, unmentioned line makes the answer come out right for the wrong reason.
>
> **This is the same family as FM 12 and init's third validator — a check that passes the artifact it
> exists to reject — and it is the shape `P10-GH-7` names, which M39 owns.** Both lines are now
> correct, so drivr is right either way; **the detection method is recorded as unreliable** because
> the next person to move a vendored directory will reach for the same check.

### Recorded, not acted on — `.governance/.git` is a directory, not a file

The rest of the fleet carries a `.git` **file** pointing into `.git/modules/`. drivr's is an

`git submodule add -f`, which does not absorb the git directory. **It works** — and it is why
`git mv` moved the submodule so cleanly. `git submodule absorbgitdirs` would normalise it;
**not done, as it is outside the five steps and changes nothing observable.** Recorded so **E38.3**
is not surprised if it enumerates submodule layouts.
