### Summary

Configure **GitHub Copilot plus at least one competing model** to review PRs for **performance,
security and scalability**; get **at least one real PR reviewed**; capture the findings **in this
repository**; and **demonstrate that nothing was auto-applied or auto-resolved** and that **no
configuration grants any model authority.**

### The hard part is the configuration, not the review

**Review tools are built to be believed.** Their surrounding controls — resolve, apply suggestion,
request changes, required checks — are designed to convert a finding into a change with one click.

**The risk is not that a model says something wrong. It is that the configuration makes a model's
opinion load-bearing without anyone deciding that it should be.** So the acceptance bar is
adversarial: ***the configuration cannot be read as granting review authority.***

**Five paths are prohibited, and the Epic spec's §The Authority Ceiling records all six clauses:**
consensus/voting, required status checks, `CODEOWNERS` approval, auto-application or auto-resolution,
and substitution for §11.6.1.

**And the verification-layer warning:** `.github/` is **absent** in this repo — but **branch
protection lives on GitHub, not in the tree.** Reading the tree and concluding "nothing grants
authority" is **verification at the wrong layer**, which is `P11-GH-2`'s recorded defect. **Read it
from GitHub.**

### The expected evidence is an unresolved finding

**A finding nobody acted on is a normal outcome, not a defect to clean up before merge.** If every
finding is resolved by delivery, that is *itself* a signal worth examining — it may mean findings
were treated as instructions.
