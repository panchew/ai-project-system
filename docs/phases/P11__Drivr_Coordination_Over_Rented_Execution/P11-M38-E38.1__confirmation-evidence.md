`install_hq_agent` computes its source as
`src_file="$project_dir/governance/agents/governance.agent.md"` (`bin/ai-project-init:328`). **The
submodule mounts the entire `ai-project-system` repository at `governance/`, and the agent lives at
`governance/agents/` *within* that repository — so the real path is
`governance/governance/agents/governance.agent.md`, one level deeper.** The `[[ -f "$src_file" ]]`
test at `:333` is therefore false on every submodule install, and the stub is written instead.

**The doubling is not incidental — it is structural.** `add_governance_submodule` hardcodes the
submodule path as `governance` (`:274`, `:294`), and the framework repository keeps its governance
corpus in a directory *also* named `governance/`. Both halves are correct in isolation; the source
path in `install_hq_agent` was written against neither.

**The file's own validation cannot catch this:** `:348-353` checks the destination is readable,
non-empty, and starts with `#` or `---`. **The stub satisfies all three** — it is 230 non-zero
bytes beginning with `# HQ Chat Agent`. **A third validator, and it passes the artifact it should
reject.**

## 11. Reproducing this on another new project

The Acceptance Criterion is that a reader can **reproduce the enrollment on a different new project
without rediscovering that the bump procedure does not apply to greenfield targets.** The short
form:

1. **Do not use the v7.0.0 bump procedure.** Its own §Scope excludes brand-new projects and names
   `bin/ai-project-init`. Use its 11 failure modes as a **hazard checklist**, classified
   individually — **six of the eleven fire on a greenfield target.**
2. **Run init against a path that does not yet exist.** It creates the repository, the git repo and
   the initial commit. It refuses any non-empty directory, so it cannot be applied to a repo you
   made first.
3. **Expect init's output to be §4-INVALID on four rules.** Add `governance.ref` and
   `project.description`; **correct `governance.version` to a quoted bare semver**; add
   `framework_version` and `models:`.
4. **Do not trust the installed agent.** Check `sha256sum .ai-project/agents/governance.agent.md`
   against the canonical hash. If it is 230 bytes, init wrote the placeholder — copy the real file
   from `<submodule>/governance/agents/governance.agent.md` (**note the doubled path segment**).
5. **Check `.gitmodules` for a `branch =` line.** init's fallback writes one containing a tag, which
   git cannot resolve as a branch (FM 9).
6. **Move the submodule to `.governance`.** init hard-codes `governance` at `:262`, `:294`, `:298`
   and offers no flag. **`.governance` is the fleet convention 8 to 3.** `git mv` updates only the
   `path` — **you must also rename the `.gitmodules` section key AND re-register in `.git/config`**
   (`git config --remove-section submodule.<old>` then `git submodule init`), or
   `git submodule status` reports the submodule uninitialized. Then update `submodule_path`,
   `norecursedirs`, and the README. **Do this before any code references the path.**
7. **Record, do not tidy**, `created_at` and the `submodule_path` **key**; and **do not fix the
   tool** — escalate.
