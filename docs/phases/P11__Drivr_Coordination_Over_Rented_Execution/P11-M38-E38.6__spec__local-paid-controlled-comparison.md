# Epic E38.6 — Local/Paid Controlled Comparison

**Stage B — the most tightly gate-bound epic in the milestone. Escalates rather than scaffolds.**

---

## Context

**This Epic is the CFO's decision arriving where it works.**

The intent was an early, low-risk local data point with cheap ground truth. In M37 that would have
required scaffolding around an engine under retirement assessment, an unsandboxed run across ten
governance documents, or M38 work pulled forward across a binding order. **HQ relocated it here on
2026-08-06 (Decision 3), and the CFO's split-posture decision was preserved rather than discarded.**

**Here it is native.** The adapter surface exists (E38.2), OpenCode is the engine (A1.1), and the work
is **code-shaped** — the shape B3.1's engine comparison measured `qwen3-coder:30b` at its **strongest**
on, where M37's dense prose was its weakest.

**E38.6 is the exception to M38's manual posture by construction.** It *is* the local/paid comparison,
so it runs the same work **both** ways. **That is its subject, not a posture choice.**

---

## Problem Statement

**The framework routes work by model tier on evidence that has never included a controlled comparison of
the same work done both ways.**

`model-routing-policy.md` assigns tiers per level. P9/P10 produced real evidence — the runtime decision,
the model-tier finding, E35.5's blinded back-test — **but none of it ran identical work through both a
local and a paid path and compared the outputs.** B3.1 came closest and **compared two engines, not two
tiers**, with a confound it recorded honestly.

**And the cheap ground truth the CFO asked for has become available**: M38's own delivered epics landed,
were reviewed, and their defects and corrections are on the record.

## ⚠ Finding 1 — the count-error tally has a collision, and it is an instance of its own class

**G1's entire justification is that tally, so its number matters here more than anywhere.**

| Source | Claim |
|---|---|
| **M37 / M38 milestone spec line 800** | *"M37's tally reached **eight** count errors, **six** by paid frontier chats including HQ's own."* |
| **E38.3's spec, Finding 1** (Milestone Chat, 2026-08-08) | `ai-project-yml-spec.md` §4 rule 3 says *"All four required fields"* and lists five — **claimed as instance nine** |
| **E38.5's ceiling correction** (Phase Chat, 2026-08-10) | Finding 1's ceiling row overstated by 58,247 bytes — **also called instance nine** |

**Two different defects were each independently numbered nine, by two different chats, each correctly
adding one to the same recorded base of eight — neither knowing about the other's increment.**

> **So the tally is at least TEN, and "nine" is ambiguous between two instances.**
>
> **This is the inventory-is-a-floor failure occurring inside the counter of inventory failures**, and it
> is the tenth instance arriving by the mechanism the first eight established: **a shared number
> incremented from a stale base.**

**Binding on this Epic — and it is not a digression, because G1 exists because of this tally:**

- **State the tally as a floor, with the date, the base you counted from, and what you counted.**
- **Do not cite "nine" without saying which instance.**
- **Report the collision to the Milestone Chat** so the record can be reconciled once, in one place, by
  whoever owns it. **Do not renumber anything yourself** — *the record names the disposition; the
  identifier names the origin.*

**And note what it does to G1's argument: it strengthens it.** *It was never about model tier* — this
one was produced by **two paid frontier chats being individually right and jointly wrong**, which is
precisely the failure mode a verbatim-quoting rule removes.

## ⚠ Finding 2 — the comparison material is an open question, and blinding is its crux

**The milestone spec says "one epic's work run both ways… on comparable material." By the time this Epic
executes, M38's own epics are delivered.** So *which* work, and where does ground truth come from?

**The strongest available design, and the reasoning is given so it can be argued with rather than
inherited:**

**Re-run work whose ground truth is already on the record.** M38's delivered epics have knowable
outcomes — what landed, what the Stage-2 review found, which corrections the Phase Chat required. **That
is the "cheap ground truth" the CFO's original intent asked for**, and it is now free.

**But it carries a contamination risk that would silently invalidate the comparison:**

> **If the material is a delivered epic, the delivered answer is in git.** A local arm with repository
> access can find the delivery, the Delivery Notice, and the review — and **an arm that reads the answer
> is not being measured on the work.** B3.1 recorded an engine anchoring on a spec's own front-matter
> field and drifting; **an engine anchoring on the committed answer would look like excellent
> performance.**

**E35.5 solved exactly this problem and its method is available:**

- **Blinded packets** built from the material *as it stood at the moment of the decision*.
- **The packets committed**, so a reader can verify the blinding rather than trust an account of it.
- **A scoring rubric pre-registered and committed BEFORE any run** — in the same commit as the packets.
- **Nothing in any packet contains the finding, the fix, or a document referencing them.**

**Adopt it, adapt it, or replace it — but state which, and defend the blinding.** **An unblinded
comparison over committed material is not a comparison; it is a retrieval test.**

## ⚠ Finding 3 — B3.1's confound is now yours, one level up

**B3.1's own conclusion, addressed to the adapter surface:**

> *Arm B ran with a **constrained** toolset (path-restricted), a **10-iteration ceiling**, and scoped
> context. Arm A ran with OpenCode's full toolset and no ceiling imposed. **Constraint may be doing the
> work.** … If constraint is what kept arm B on task, then the adapter surface should impose the
> constraint regardless of which engine sits behind it.*

**E38.2 has now decided the adapter's constraint policy.** So when E38.6 runs local-through-the-adapter
against manual/paid, **the adapter's constraints are a variable in the comparison** — and if they go
unrecorded, **this Epic reproduces B3.1's confound with a new label.**

**Binding: record what constraints the adapter imposes on the local arm** — tool restrictions, iteration
ceilings, context scoping — **and state whether the paid arm operated under comparable ones.** **If they
are not comparable, say so plainly.** A comparison with an unstated asymmetry is worse than no
comparison, because it will be cited.

### 1. Choose the comparison material, and defend the blinding

- **State what work is being compared and why its ground truth is knowable.**
- **Defend the blinding explicitly** (Finding 2). **Commit the packets or their equivalent** so a reader
  can verify the blinding rather than trust an account of it.
- **Pre-register the scoring rubric and commit it BEFORE any run** — in the same commit as the material.
  **A rubric written after seeing outputs is fitted to them.**

### 2. Run both arms

- **Local:** agentic, through **E38.2's adapter**, in the environment E38.2 decided.
- **Paid:** manual, at `models.epic_manual` (`remote:claude-opus-5`).
- **Record the dispatch path** — which engine, which adapter, what environment.
- **Record the adapter's constraints** and whether the paid arm's were comparable (Finding 3).
- **Record wall-clock timing for both** (Finding 4).

### 3. Score, honour G1 and G2, and record both outcomes

**G1 — remove derivation steps.** *(The generalized form; M37's original bound it to a specific changelog
row.)* **Any input with exactly one non-uniform element gets that element quoted verbatim rather than
described.** M37's tally reached **eight** count errors — **six by paid frontier chats including HQ's
own** — and Finding 1 shows the tally itself then produced a ninth-and-tenth by the same mechanism.
***It was never about model tier.***

**G2 — the reviewer re-measures; the executor's report is not the evidence.** **P10-GH-7: exit codes are
untrustworthy in both directions** — E33.2 Run A exited 0 having done zero work; E33.4 exited 2 with
complete green work; B3.1 reproduced both. **Record the exit code; do not rely on it.** **And never
trust an agent's prose:** in B3.1 *the prose lied in both arms* while the structured signal was correct
in the same run.

**Record both outcomes, whichever way they fall.** **A poor local result is evidence, not failure.**

### 4. State what the comparison does not establish

**Borrow B3.1's own discipline** — it carried a §What this does NOT establish, and it is the reason its
findings survived contact with three later epics. **State the sample size, the confounds, and the
conclusions a reader must not draw** — chiefly that **no routing policy changed as a result.**
