## ⚠ Do this in your first ten minutes — it may change your architecture

**Reproduce Finding 1 yourself. One command:**

```
docker run --rm -v /home/panchew/.opencode/bin/opencode:/tmp/opencode:ro \
  ai-project-sandbox:latest sh -c '/tmp/opencode --version'
```

**Measured 2026-08-08, it prints:**

```
sh: /tmp/opencode: not found
```

**The file is there and readable.** That message is musl's report for a **missing ELF interpreter**. The
sandbox image is **Alpine — musl-only, with no `/lib64/ld-linux-x86-64.so.2`** — and the `opencode`
binary is **glibc-linked** (`file` says *"interpreter /lib64/ld-linux-x86-64.so.2, for GNU/Linux"*), and
**179 MB**.

**Why this matters more than it looks.** The milestone spec records `opencode` as **ABSENT** from the
image. **The truth is stronger: it cannot run there at all.** So *"this repo's sandbox gains OpenCode"*
is **not `apk add opencode`** — it means **changing the sandbox base image off Alpine**, which affects
**every** sandboxed operation in this framework, or shimming glibc under a 179 MB dynamically-linked
binary.

**This does not decide your question. It prices it** — and it is the fact most likely to change your
answer, so meet it by running the command rather than by being told.

> **Does Drivr execute through *this* repository's `bin/ai-project-orchestrator` sandbox at all?**

## Three more findings you must not rediscover

**All measured 2026-08-08. Full detail in the Epic spec.**

**Finding 2 — Constraint 3 has an ordering problem, and it is how the 8× overpack happened.**

| Endpoint | Reports | When available |
|---|---|---|
| **`/api/ps`** | the **loaded** context — `"context_length": 32768` | **only after the model is loaded**; otherwise **`{"models":[]}`** |
| **`/api/show`** | `qwen3moe.context_length` = **262144** — the **trained maximum** | **always** |

**`opencode.json` declares 262144.** **The overpack is not a typo — it is what you get by reading the
endpoint that answers without being asked twice.** So: an adapter reading `/api/ps` at startup gets
**nothing**, and the always-available endpoint gives **the wrong number**. **How you resolve that is
your design decision** — load-then-query, query-after-first-invocation and cache, refuse to declare
until observed, or fail closed. **What is binding: "empty" must never degrade to "use the trained
max."**

> The `/api/ps` behaviour was verified with **`qwen2.5-coder:7b`**, deliberately — **the GPU is 16 GB,
> shared with ComfyUI, on a serialized lane. Do not load a 30B model to prove something a 7B can
> prove.**

**Finding 3 — OpenCode's config lives at `~/.config/opencode/opencode.json`** — host, user-level,
**outside any project mount**. Its provider `baseURL` is **`http://localhost:11434/v1`**, which **inside
any container means the container, not the host** — B2.1's loopback→gateway rewrite exists for exactly
that class of mistake. **A decision about where the engine runs is also a decision about where its
configuration comes from. Record how OpenCode gets its config in whichever environment you choose.**

**Finding 4 — the CLI surface, measured.** `opencode run` takes **`--format json`** (raw JSON events —
the likeliest basis for a machine-readable result), `-m/--model` in `provider/model` form, `--agent`,
`--dir`, `--attach <url>`, `-s/--session`, `-c/--continue`, and **`--auto`** *("auto-approve permissions
that are not explicitly denied (dangerous!)"* — its own help says that; **required for unattended runs,
so note the trade-off wherever you use it**). `opencode serve` is *"a headless opencode server"* with
`--port`, `--hostname`, `--cors`. **Record what you learn about `serve` even if your adapter doesn't use
it — E38.4 assesses three retention candidates against `serve` mode and inherits whatever you found.**

## The Hard Constraint — the drift lives HERE, and it will not feel like drift

**Drivr rents. It does not build what it can invoke.**

> **You need to know whether an invocation succeeded in order to return anything useful. That is not a
> licence to build M39's completion judgment.**

> The path is short and every step looks reasonable:
>
> 1. The adapter returns an exit code.
> 2. The exit code is known to lie — **measured, first-party: OpenCode exited 0 having done zero work.**
> 3. So the adapter checks whether files changed.

> **By step three it is a trustworthiness layer, and M39 has been pre-empted by an epic with less
