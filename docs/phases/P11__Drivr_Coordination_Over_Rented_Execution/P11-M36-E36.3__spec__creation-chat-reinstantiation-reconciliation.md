# Epic E36.3 — Creation Chat re-instantiation reconciliation (SN-26)

## Context

M36's first two epics are merged: E36.1 (`f1a5e75`) recorded the allocation and separating rules,
E36.2 (`65a512e`) renumbered the misnumbered note and discharged B3.1's obligation. **This Epic has
no hard dependency on either** and may run in parallel with E36.4 and E36.5.

It is, however, **M36's only epic carrying a genuine open design decision.** Every other epic in this
milestone executes a ruling. This one is handed a defect, a constraint that pulls against the obvious
fix, and the instruction to decide. The milestone spec names it *"the likely long pole"* for that
reason.

SN-26 (2026-07-31) found that **three surfaces describe how a Creation Chat is re-opened and they do
not agree** — and that the one artifact both rituals name first does not exist in this project.
HQ Ruling 2026-08-01 **Decision 9** placed it in M36 and made one thing explicit: SN-26's Carry-Over 1
working practice stays **working practice, not canon, "until M36 canonizes whatever it canonizes."**
That sentence is this Epic's mandate — the practice is currently undocumented, and leaving it that
way is not one of the available outcomes.

**Verified on `milestone/M36` at planning time (`82c69ab`), not inherited:**

| Surface | What it says to pass | Location |
|---|---|---|
| `governance/templates/seed.md`, Rule 5 | *"this Genesis artifact plus the current Project Brief"* | line 114 |
| `governance/systems/creation-chat-guide.md`, Ritual Step 3 | *"exactly three artifacts and nothing else"*: `genesis.md`, latest Steering Note, latest Progress Digest | lines 59–68 |
| **What this repository actually holds** | **Neither a rendered `genesis.md` nor a Project Brief** | — |

Only the blank *template* `governance/templates/genesis.md` exists. **Both rituals are therefore
unexecutable as written**, each blocked on its own artifact #1.

---

## Problem Statement

**1. The ritual cannot be executed as written.** Its first artifact does not exist. A reader
following `creation-chat-guide.md` literally cannot open a Creation Chat.

**2. The E31.3 model check is absent from the path the ritual prescribes.** This is the real defect
behind the observed 2026-07-28 failure — a Creation Chat that ran `claude-opus-5` against a
then-configured `remote:claude-opus-4-8` and **opened anyway**. Verified on `milestone/M36`: lines
28–84 of `creation-chat-guide.md` contain **no model check, no E31.3 reference, no verification step
of any kind.** The check exists in `seed.md:22` and in the `genesis.md` template — **and is absent
from the path actually taken**, because the only prescribed artifact that would carry it
(`genesis.md`) does not exist here.

**3. One normative statement is duplicated into three copies free to drift.** This is the same defect
class P10 closed twice by ruling — *governance names the tier, routing names the model*; *governance
names the role, P11 names the thing that runs it.*

**4. The working practice that actually functions is undocumented.** SN-26 Carry-Over 1 records that
sessions should open with the Seed **plus** the latest Steering Note **plus** the latest Progress
Digest — the union of the two documented rituals minus the artifacts that do not exist. Decision 9
keeps it non-canon until this Epic acts.

**The observed cost, from SN-26, is concrete and worth keeping in view.** In the 2026-07-31 session:
the model check ran **only because the Seed was pasted**; the Progress Digest was read **only because
it happened to be open in the operator's editor** — luck, not ritual; and the most recent Steering
Note **was not handed to the session at all**, despite being live input to the P11 scoping that
session existed to perform.

## Goals

By the end of this Epic:

1. **A reader can open a Creation Chat by following the canonized statement alone**, passing only
   artifacts that exist.
2. **The canonized path itself carries the E31.3 model check** — not merely a template that path may
   not include.
3. **Exactly one normative statement governs re-instantiation**; the other surfaces cite it rather
   than restating it.
4. **The `genesis.md` / Project Brief question is decided and recorded**, either way.
5. **Carry-Over 1's working practice is canonized or explicitly superseded** — not left undocumented.
6. **The Seed still causes verification to happen when pasted alone** (constraint 7).

## Scope of Work

### 1. Decide the `genesis.md` / Project Brief question — and record it

**Does `ai-project-system` render its own `genesis.md`? Is a Project Brief expected for a framework
repository that reached P11 without one?**

**Both answers are acceptable. The current state — a normative ritual naming a non-existent file —
is not.** This is the Epic Chat's design decision to make, document, and proceed on. **It is NOT an
escalation.**

The two coherent directions, stated fairly:

| | **Render a `genesis.md`** | **Stop naming artifacts this project does not produce** |
|---|---|---|
| Ritual artifact #1 | exists | replaced by the Seed |
| E31.3 check | rides along — the `genesis.md` template already carries it | must be placed on the path deliberately |
| Relationship to Carry-Over 1 | supersedes the practice | **canonizes** it (Seed + latest SN + latest Digest) |
| Cost | authoring a real Genesis artifact for a self-bootstrapped repo | the ritual stops matching the generic template's language |

**Decide on the merits and record the reasoning.** Note that direction 2 is what SN-26's Carry-Over 1
already describes as the union that works, and that Decision 9 explicitly left the door open for
canonizing it.

### 2. Reconcile three surfaces to ONE normative statement

The others **cite** it rather than restating it. **Which surface holds the normative statement is
this Epic's design decision.**

> **The crux, named so it is not discovered late.** The obvious home is
> `creation-chat-guide.md` — it is system-tier, it already holds the four-step ritual, and the
> templates are consumers. **But constraint 7 pulls against a pure citation.** `seed.md` is *pasted
> into a fresh session as its opening prompt*; a Seed reduced to *"follow the guide's ritual"* may
> not cause the check to run at all, which is exactly the property the 2026-07-31 session proved
> valuable.
>
> **A distinction worth drawing:** *"cite rather than restate"* governs the **ritual's content** —
> which artifacts, in what order, and why. It need not govern an **operative instruction the Seed
> must still execute.** A Seed that cites the ritual for its content while retaining the E31.3 check
> as a live step is not a duplicated normative statement; it is a pointer plus an action.
> **The Epic is free to resolve it that way, another way, or to place the normative statement in the
> Seed instead — but it must resolve it deliberately and say why.**

### 3. Put the E31.3 check on the canonized path itself

Verified absent today: `creation-chat-guide.md` lines 28–84 carry no model check. Whatever path is
canonized must carry it **on the path**, not only in a template the path may not include.

Reference for the check's existing wording: `governance/templates/seed.md:22–30` — Creation Chat is
manual-only permanently (SN-22), compare harness self-report against `.ai-project.yml`'s
`models.creation`, with `governance/systems/chat-hierarchy.md` "Manual Chat Model Verification" for
the mapping and the absent-block/absent-key permissive default.

### 4. Honour constraint 7 — and show it

**Pasting `seed.md` alone must still cause verification to happen.** The DoD requires this
**shown, not assumed.** A walkthrough of what a fresh session receives when the Seed is pasted, and
where the check fires in that sequence, is sufficient evidence; a bare assertion is not.

### 5. Settle Carry-Over 1 explicitly

Canonize the working practice, or explicitly supersede it. **Silence is a DoD failure** — Decision 9
made this the epic's to close.

### 6. Structural diagram (constraint 8)

Per the constraint. It must show **what was deliberately frozen** — at minimum the Seed's
verification behaviour — and that **authority flowed nowhere new.**

### 7. Record the unversioned amendment (Decision 5)

Name the document, name the amendment, cite HQ Ruling 2026-08-04, in a form the Milestone Closure
Declaration can lift directly.
