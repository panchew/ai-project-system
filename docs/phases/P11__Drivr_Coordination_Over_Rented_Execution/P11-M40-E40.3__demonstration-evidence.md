**Every result below was executed on 2026-08-17.** Nothing here is a described intention.

**Layer, time and scope, per `P11-GH-2`** — this document reports **three distinct layers**, and
does not let one stand in for another:

| Layer | What it exercises | Where |
|---|---|---|
| **Operator** | `bin/drivr-gate` + `curl` against a live daemon on a real socket | §1, the full transcript |
| **HTTP** | the routes, over loopback, inside the suite | `drivr/tests/test_surface_end_to_end.py` |

The four bindings are demonstrated at the operator layer **and** re-demonstrated at the HTTP and
primitive layers, because a guard can hold in the library and be bypassed by the route in front of
it.

2026-08-17). **`drivr` has no git remote**, so the evidence is committed here — per the Epic spec's

### 1.4 Two vacuous results found and corrected before this capture

Recorded because the Hard Constraint names **declaring rather than measuring** as the drift to
avoid, and both of these would have declared.

1. **The first run's every step failed** — `bin/drivr-gate` was committed without the executable
   bit, so `serve` and `mint` both returned `Permission denied` and every `curl` returned `000`.
   Fixed with `chmod +x` (and `git update-index --chmod=+x`).
2. **In the second run, step 4's `GET` reached nothing.** The link was minted with the CLI's
   *default* base (`:8787`) while the daemon was on `:8791`, so the request went to a closed port.
   The step's conclusion — *"the spend log does not exist, so `GET` spent nothing"* — was **true and
   worthless**: it would have read identically had the guard been absent, because no request
   arrived. Corrected by minting with `--base`, and the step now shows a real **200** with the
   confirmation form and a genuinely absent `spent/`.

The second is the more instructive: **an absence is only evidence when the thing that would have
created it actually ran.**

## 2. Falsification — B2.1's standard

*"The guard was falsified by deleting the line and observing 7 failures. Meet it."* Each guard below
was deleted or inverted, the **full `drivr` suite** re-run, and the file restored. Executed
2026-08-17.

| Guard falsified | File | Result |
|---|---|---|
| signature verification — the **signed** binding | `drivr/surface/links.py` | **7 failed**, 445 passed |
| the `spend` call in `Surface.redeem` — the **one-time** binding | `drivr/surface/app.py` | **7 failed**, 445 passed |
| expiry check — the **expiring** binding | `drivr/surface/links.py` | **4 failed**, 448 passed |
| gate-binding check — the **one gate** binding | `drivr/surface/links.py` | **4 failed**, 448 passed |
| `O_EXCL` → `O_TRUNC` in `SpendLog.spend` — **atomicity**, not merely presence | `drivr/surface/store.py` | **7 failed**, 445 passed |
| `ACCEPTED_FIELDS` widened to `{"t", "decision"}` — D4's seam | `drivr/surface/app.py` | **1 failed**, 451 passed |

**After restoring everything: `452 passed`.**

The `O_EXCL` case is the one worth naming: swapping it for `O_TRUNC` leaves the spend log *present
and being written* — the file still appears, the code still runs — and single use silently stops
working. It is caught by 7 tests including `test_spend_is_atomic_under_concurrency`. A guard that is
merely *there* is not the property; the property is that the operation is atomic.

### 2.1 One honest weakness in this set

**Widening `ACCEPTED_FIELDS` breaks only one test**, and that number is correct rather than
disappointing: the constant is a **declaration with a tripwire on it**, not the enforcement. The
enforcement is that `_token_from_body` asks for the key `t` by name and never iterates the submitted
fields — so adding `"decision"` to the frozenset does not, by itself, cause any field to be read. A
genuine second path would require *new code that reads it*, which this falsification does not write.

Stated plainly so a reader is not misled by the "1": **the tripwire catches the declaration
changing, not every way the behaviour could change.** Method obligation 6 — this inventory is a
floor.
