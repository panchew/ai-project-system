## The limits statement

**Reproduced here in full because M40 inherits it with the verdicts.** Evidence artifact §4 carries
all eight items.

1. **Two cases falsify and do not generalize.** The pair shows the judgment is not wrong where every
   prior signal was. It does not show it is right in general.
2. **The corpus is imbalanced five to one** — five *completed*, one *did not complete*.
3. **A mechanism that always answers *completed* scores 5/6 on the corpus and 1/2 on the binding
   pair.** The judgment scores **2/6 strict** and **2/2 on the binding pair**. On strict scoring it
   **loses to the degenerate baseline**; on contradictions it beats it (0 vs 1). **Neither
   degenerate strategy dominates it and it dominates neither** — always-*undetermined* would score
   0/6 strict with 0 contradictions.
4. **There is exactly one negative case in the whole corpus.** One case is not a false-positive rate.
5. **Every case comes from one runner (`local-agent-runner`); none from OpenCode. Engine generality
   is untested — not weakly supported, untested.** Worse for M40: E39.1 records that a live OpenCode
   run projects `effect_ledger=None`, so **it can never reach `EFFECTS_VERIFIED`.** The engine on
   today's roster cannot produce the positive verdict this epic validated.
6. **`undetermined` on four of six** is the correct in-run reading, and is also **a real operational
   limit**: a coordinator wanting yes-or-no gets neither, two thirds of the time on corpus-like runs.
7. **Result-string matching is one runner's vocabulary**; a wording change degrades the ledger to
   `UNCLASSIFIED` — visible, not silent.
8. **This validation is historical.** Six stored transcripts, no new runs.

## Findings for the Milestone Chat

**Finding 1 — E39.1's Acceptance Criterion 2 holds; the mechanism was run from the description
alone.** `drivr/docs/completion-judgment.md` §7's snippet ran **unmodified** on the first binding
case. **No file under `drivr/judgment/` was read at any point.** The criterion existed to be tested,
and this epic was the test.

**Finding 2 — one inaccuracy in that description, reported rather than papered over.** §4's table
lists `annotations` as carrying the exit code **uniformly for both projections**. For a transcript
projection it is **unfillable** — no transcript in the corpus contains the key — so it is always
`None` and surfaces on the verdict as `[ignored] exit_code … verbatim: 'None'`. **A reader of a
verdict alone could take that line as deliberate rejection when it records absence** — Trap 2
arriving through the description rather than the procedure. It did not block this epic. **Whether
E39.1 amends the description is the Milestone Chat's call**; the mechanism is not at fault and was
not touched.

**Finding 3 — the Starter's corpus inventory is short by three files.** Each `-PROVE` directory also
carries a tracked `context.md`: **18 tracked files, not 15**. Nothing turns on it — `context.md` is
the prompt, not evidence about the outcome — and it is recorded because **every inventory is a
floor**, which is partly why this epic exists.

**Finding 4 — the two binding runs targeted other projects' epics.** Run A's sidecar records
`epic_id: P3-M4-E4.1`, E33.4's `epic_id: P2-M1-E1.1`. **Available metadata the judgment ignores**,
and it sharpens why the naive repository-state delta was ruled out at milestone v1.0.1: the state
these runs left behind is not in this repository at all.
