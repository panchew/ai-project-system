# E38.1 Stack Decision — Drivr's runtime

**Written before the Drivr repository existed.** This file is committed ahead of any Drivr artifact
so that the ordering required by the Epic spec (§Execution Notes step 3: *"write down the reasoning
before creating anything — the reasoning is a deliverable and it is easier to write honestly before
the code exists"*) is verifiable from git history rather than asserted.

**Layer note (`P11-GH-2`):** every measurement below was taken **on the host**, 2026-08-10, outside
both repositories. Toolchain availability is a host fact and is cited only as one.

---

## The decision

**Drivr is a Python 3 project.** Standard library `subprocess` for CLI invocation, standard library
`unittest` discovery run under `pytest`, and **PyYAML** as its single declared runtime dependency.

---

## The five constraints, and how each candidate scores

The constraints come from §Scope 1 of the Epic spec. They are **capability requirements**, not a
named technology, and they derive from SN-24's headless-first posture and *"as agentic as we can →
lightest infrastructure."*

| # | Constraint | Why it exists |
|---|---|---|
| 1 | Invoke a CLI tool as a subprocess; read exit code, stdout, stderr | The entirety of what E38.2's adapter surface needs from the runtime |
| 2 | Read YAML | E38.3's registry reads `.ai-project.yml` across the fleet |
| 3 | Be testable | Deliverable 4 is a stated baseline; a baseline of zero measures nothing |
| 4 | Be headless | The thin surface is M40's, explicitly not this |
| 5 | Pull in no inference SDK, model client, or agent framework | Constraint 1 (Drivr rents) is enforceable at the dependency list, and that is the cheapest place to enforce it |

### The tiebreak, stated

Python and Go both satisfy all five constraints on their merits, and both would carry exactly **one**
runtime dependency. **The spec's tiebreak is "fewer dependencies"; they tie there, so it does not
resolve them.** The resolving fact is C3: **Go is not installed on this host**, so choosing it would
make "establish a test baseline" require installing a toolchain — infrastructure added to satisfy the
*lightest infrastructure* constraint, which is self-defeating.

**Two supporting reasons, recorded as supporting and not as the decision:**

- **The idiom is already the fleet's.** This governance repository's own suite is pytest (393 tests),
  so a reviewer re-measuring Drivr's baseline needs no new tool and no new mental model.
- **The dependency list stays trivially auditable.** A one-line requirements file is the cheapest
  possible place to demonstrate Constraint 1 — that Drivr implements no inference — and demonstrating
  it is an Acceptance Criterion, not an assertion.

### On PyYAML being declared but unused at E38.1

**Constraint 2 is a capability requirement on the stack, not an instruction to write a loader.**
Drivr must be *able* to read YAML because **E38.3's registry** will. Writing the config loader here
is precisely the drift the Epic spec and the starter both name — *"a config loader is ten minutes…
and all three will look like progress"* — and it belongs to E38.3.

So PyYAML is **declared** (satisfying C2 demonstrably, at the dependency list where C5 is also
checked) and **no loader is written**. The declaration is the deliverable; the loader is E38.3's.

### On the test runner

`pytest` runs the suite; the test itself is written against stdlib `unittest`-compatible plain
`assert`, so **Drivr's suite has no test-framework lock-in** and could be run by `python3 -m unittest`
if a future epic preferred it. pytest is a **development** dependency, kept separate from the runtime
dependency list so that the runtime list remains the clean evidence for Constraint 1.

## What this decision does NOT settle

Named explicitly so a later epic does not read this file as broader than it is:

- **Packaging** beyond what the one real test requires — E38.2 and E38.3 may add to it.
- **The adapter surface's shape.** C1 says the runtime *can* invoke a subprocess. **How** Drivr
  invokes one, what the adapter's interface is, and what it returns are **E38.2's**, and this file
  takes no position on any of them.
- **The registry's schema or the validator's shape** — **E38.3's**.
- **Any scheduler, gate queue, thin surface, or completion judgment** — M39 and M40.
