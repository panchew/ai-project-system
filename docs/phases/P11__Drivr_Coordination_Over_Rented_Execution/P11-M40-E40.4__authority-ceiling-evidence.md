**Three findings stand unresolved and will remain so on delivery.** Per the ceiling's clause 6 and
the Epic starter, *"a finding nobody acted on is a normal outcome, not a defect to clean up before
merge"* — and *"if every finding is resolved by delivery, that is itself a signal worth examining."*
**This delivery resolves none of them, on purpose.** The twenty local-model findings were never
posted to GitHub at all, so there was nothing there to resolve.

### No suggestion was applied

Copilot produced **no `suggestion` blocks** in any of its three comments — they are prose. Nothing
offered a one-click apply, and nothing was applied. The local reviewer **cannot** apply anything: its
script calls no GitHub API and writes exactly one file, its own findings record.

### No model could have blocked or compelled a merge

- Copilot's review state is **`COMMENTED`** — not `CHANGES_REQUESTED`, so it does not even register
  as an objection in GitHub's own model, and not `APPROVED`, so it satisfies no approval requirement.
- With **no branch protection and no rulesets**, no status check is required; the
  `copilot-pull-request-reviewer` check run's `success` conclusion gates nothing.
- **`allow_auto_merge` is `false`**, so no combination of green checks completes a merge by itself.
- No `CODEOWNERS` exists, and **no model holds write access** — `panchew` is the only account with
  push or admin.

### The honest limits of this evidence

1. **The window is four minutes.** These snapshots prove nothing changed between `19:47:44Z` and
   `19:51:32Z`. They cannot prove nothing will change later; that is what the standing unresolved
   threads and the committed blob SHAs are for.
2. **GitHub App installations were not enumerated** — a user token cannot (`repos/.../installations`
   → 404, `user/installations` → 403). Recorded as a gap in the configuration record, not resolved.
3. **The `--paginate` capture of timeline events emits one JSON array per page**, so that field in
   the snapshots is three concatenated arrays rather than one. The events themselves are intact and
   were read correctly; the shape is noted so a later reader parsing the file is not surprised.

## D5 — The precedent note

**R1 recorded that this repository had no `.github/` and no review configuration of any kind. It
still does not.** This epic added **no** repository-side review configuration — no workflow, no
ruleset, no `CODEOWNERS`, no `.github/`. What it added is a **script that asks a local model for an
opinion** and a **record of what two models said**.

**A later reader will treat this as the precedent. Read it as this:** *the reviewers were invited,
per PR, by a human, and given nothing.*

### What a later reader must not do

1. **Do not make any model review a required status check.** The `copilot-pull-request-reviewer`
   check run already exists on reviewed commits and already reports `success`. It is one settings
   toggle from being required, and **that toggle would convert a comment into a merge gate** without
   any document in this repository changing. This is the shortest path from here to a violated
   ceiling.
2. **Do not add a model to `CODEOWNERS`.** There is no `CODEOWNERS` file. Creating one to route
   approval to an automated reviewer makes a model's approval load-bearing for merge.
3. **Do not treat agreement between models as a resolution.** There is no consensus path, no voting,
   no scoring, and clause 2 of the ceiling prohibits building one — *prohibited, not merely
   unnecessary*. In this run the two reviewers **overlapped on nothing**, so the question never
   arose; that is luck, not a safeguard.
4. **Do not auto-apply suggestions or auto-resolve conversations.** Note especially that this run
   found **every line number from the local reviewer to be wrong** while the findings themselves were
   substantively real. Applying findings at the locations given would have edited unrelated code.
   Accuracy of a finding and safety of applying it mechanically are **different properties.**
5. **Do not let a model's review stand in for the CFO's PSG §11.6.1 diff review.** Findings **feed**
   that review. The CFO reviews the diff regardless of what any model said, and regardless of how
   many models said it.
6. **Do not read `conclusion: "success"` as approval.** It means the review job ran. Copilot's actual
   verdict on this PR was `COMMENTED`. Likewise the legacy commit-status API returns
   `state: "pending"` when **zero** statuses exist — a word that suggests a gate where there is none.
7. **Do not verify any of this by reading the tree.** `.github/` is absent from this repository *and*
   an `active` GitHub Actions workflow (`dynamic/agents/copilot-pull-request-reviewer`) exists and
   produces check runs. Branch protection, rulesets, required checks and auto-merge all live on
   GitHub. **Read them from GitHub.** This is `P11-GH-2`'s recorded defect and this epic reproduced
   it live, in its own prerequisite check.
8. **Do not accept `requested_reviewers` as the answer to "is a model reviewing this PR?"** It does
   not enumerate bot reviewers. It read `[]` while Copilot was actively reviewing. Use the timeline
   or GraphQL. A negative control confirmed the endpoint returns **HTTP 200 for a reviewer that does
   not exist**, so the status code is not evidence either.

### One affordance to be aware of

Copilot's own review body ends with an invitation to **create `.github/skills/code-review/SKILL.md`**
via a pre-filled GitHub "new file" link, to give it tailored review instructions. That is a genuine
feature and it is not prohibited — but note what it does: **it is the first `.github/` file in this
repository, offered as a one-click convenience, in the same message as the findings.** If a future
epic wants it, that is a decision to take deliberately, with the ceiling in view — not a link to
click while reading a review.
