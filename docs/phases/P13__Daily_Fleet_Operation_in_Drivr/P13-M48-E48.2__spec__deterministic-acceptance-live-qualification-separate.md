# Epic E48.2 — Deterministic Acceptance, Live Qualification Separate

## Context

**"Suite green" is the gate every acceptance in this phase reports against** — the P13 phase spec
says so, and the M48 milestone spec assigns the flaky part of that gate here. The source suite mixes
deterministic acceptance with a live endpoint: with `visual_artifacts.enabled: true`,
`tests/integration/test_visual_artifacts_helper.py::test_helper_generates_against_endpoint` runs for
real against local ComfyUI at `http://localhost:8188` by default, and is skipped only when
`visual_artifacts.enabled` is false or `AI_PROJECT_SKIP_LIVE_ENDPOINT_TESTS=1` is set. On a machine
without ComfyUI, or with it stopped, or rate-limited, that test's pass/fail depends on machine-local
endpoint availability — not on the source.

That is Finding 8 of the M48 milestone spec, carried here **as an input, not re-derived**: make
deterministic suite status stable, report live qualification separately, and never convert an
expected live check into an unreported skip or mock.

**Re-measured at planning (2026-09-08, this chat):** the live test exists exactly as Finding 8
describes — `skipif` on `enabled`/`_SKIP_LIVE_ENDPOINT`, then a real `subprocess.run` against
`bin/ai-project-visual` whose pass requires the endpoint to produce a non-empty artifact. The three
exit paths already live there (disabled ⇒ 2; unconfigured type ⇒ 3; unreachable endpoint ⇒ 4;
execution-lock live ⇒ 5). The missing pieces are **stable deterministic acceptance** and a
**separate, explicit live-qualification channel plus pass/fail/skip semantics with regression
coverage for all three endpoint states.**

## Problem Statement

Every P13 acceptance reports against "suite green," but that suite today contains one test whose
result depends on whether a local ComfyUI endpoint happens to be reachable. That makes the phase's
primary gate **unfalsifiable** — a red suite proves nothing (was the change wrong, or was ComfyUI
down?), and a green suite proves nothing either (was the endpoint skipped silently?). The phase
spec flags this as a named risk; E48.2 is its assignment.

## Goals

By the end of this Epic, the system must:

1. Make **deterministic acceptance** reproducible from identical source and an unchanged declared
   test mode — no machine-local endpoint availability influencing the pass result.
2. Keep **live ComfyUI qualification separate and runnable**, with its own explicit
   pass/fail/skip semantics rather than a hidden skip or a mock.
3. Report **deterministic suite totals and live qualification independently** in every delivery
   report, including the environment and reason for any intentional skip.
4. Add **regression coverage for endpoint available, unavailable, and explicitly skipped** states.

## Non-Goals

This Epic explicitly does **not** aim to:

- **Delete, mock, or silently skip the live check.** It stays runnable; it just stops being the
  deterministic gate.
- **Change `visual_artifacts.enabled`'s default or semantics.** The confnfig contract stands.
- **Build new visual tooling or fix the ComfyUI helper** itself beyond the acceptance/qualification
  boundary.
- **Change Drivr code.** No Drivr implementation is authorized by M48.

## Scope of Work

### 1. Deterministic acceptance boundary (D1)

Establish a separation layer so that the deterministic suite result is stable given identical
source and an unchanged declared test mode.

**Must include:**
- The live endpoint test (or its live-qualification equivalent) **excluded from the deterministic
  acceptance signal**, with the exclusion stated explicitly and reported, never silent.
- A clear convention for how "deterministic source suite" is invoked and reported (command + counts).

### 2. Live qualification channel (D2)

Keep live qualification runnable and honest.

**Must include:**
- Explicit **pass / fail / skip** semantics, each with a stated environment and reason.
- **skip** is opt-in and recorded (e.g. `AI_PROJECT_SKIP_LIVE_ENDPOINT_TESTS=1` or an explicit
  opt-out) — not a silent default, not a mock, not an unreported fallback.

### 3. Regression coverage for the three endpoint states (D3)

**Must include:**
- Endpoint **available** (deterministic, without depending on whether a live ComfyUI happens to be
  reachable in CI/any machine — via a controlled fixture or a deterministic stub that is not a
  hidden skip of the real check).
- Endpoint **unavailable** (closed port ⇒ the existing exit-4 path).
- Endpoint **explicitly skipped** (opt-out flag ⇒ not run, and the reason recorded).

### 4. Delivery-report separator (D4)

Define how P13 delivery reports state deterministic suite totals and live qualification as two
distinct lines/fields, so no report folds live qualification into the suite-green aggregate.

## Deliverables

This Epic must produce:

- [ ] **D1** — Deterministic acceptance boundary, implemented and tested (live check excluded from the acceptance signal, stated not silent)
- [ ] **D2** — Live qualification channel with explicit pass/fail/skip semantics
- [ ] **D3** — Regression coverage for endpoint available, unavailable, and explicitly skipped
- [ ] **D4** — The delivery-report separator: deterministic totals and live qualification stated independently
- [ ] **Epic Delivery Notice**

## Binding Constraints

Settled above this epic — **not re-decidable here** (M48 milestone spec):

1. **Static validation is not operational proof** — but the deterministic suite must be honestly
   deterministic; separating live qualification is not the same as deleting it.
2. **The non-deterministic suite is assigned to M48** (phase spec risk). E48.2 is that assignment.
3. **M48 authorizes no Drivr implementation.**
4. **`undetermined`, unavailable endpoint, and an explicit opt-out remain distinct** (Finding 10
   family). A live check that cannot run is reported as such, never relabeled.

## Definition of Done

Epic E48.2 is complete when:

- [ ] Deterministic acceptance no longer depends on machine-local endpoint availability
- [ ] Live qualification remains runnable and is never represented as deterministic coverage
- [ ] Pass, fail, and skip semantics are explicit and tested
- [ ] Regression tests cover endpoint available, unavailable, and explicitly skipped
- [ ] A P13 delivery report can state one unambiguous source-suite gate plus a separate live-qualification status
- [ ] Deterministic suite is green (`PYTHONPATH=. pytest -q`); live qualification reported separately
- [ ] Delivery Notice committed; PR opened from `epic/P13-M48-E48.2` to `milestone/M48`

## Technical Constraints

**Repository:** all E48.2 code, tests, and the Delivery Notice land in `ai-project-system` on
`epic/P13-M48-E48.2`. The subject source is `tests/integration/test_visual_artifacts_helper.py`
and its supporting `bin/ai-project-visual` / `bin/ai-project-orchestrator` (this repository only).

**Invocation:** `PYTHONPATH=. pytest -q`. Live qualification uses
`AI_PROJECT_SKIP_LIVE_ENDPOINT_TESTS` and `visual_artifacts.enabled` as the existing, unchanged
controls; no credential value is involved or read.

**Constraint — no hidden skip:** a skip is a recorded, reasoned state. A mock that claims to be the
live endpoint is not acceptable; a deterministic stub used *only* to prove the available-path
plumbing is permissible only if it is clearly labeled and never substituted for the real live
check in a qualification report.

**Blockers**

  input to the "unavailable" regression path, not a blocker.
