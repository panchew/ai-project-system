# Epic E48.2 — Deterministic Acceptance, Live Qualification Separate

## Context

**"Suite green" is the gate every acceptance in this phase reports against** — the P13 phase spec
says so, and the M48 milestone spec assigns the non-deterministic part of that gate here (phase-spec
risk "a flaky suite makes every acceptance unfalsifiable"). The source suite mixes deterministic
acceptance with a live endpoint: with `visual_artifacts.enabled: true`, one integration test —
`tests/integration/test_visual_artifacts_helper.py::test_helper_generates_against_endpoint` — runs
for real against local ComfyUI at `http://localhost:8188` by default, and is skipped only when
`visual_artifacts.enabled` is false or `AI_PROJECT_SKIP_LIVE_ENDPOINT_TESTS=1` is set. On a machine
without ComfyUI, or with it stopped or rate-limited, that single test's pass/fail depends on
machine-local endpoint availability rather than on the source.

That is M48 Finding 8, carried here **as the scope, not re-derived**: make deterministic suite status
stable, report live qualification separately, and never convert an expected live check into an
unreported skip or mock.

**Re-measured at planning (2026-09-08, this chat):** the live test exists exactly as Finding 8
describes — a `skipif` on `enabled`/`_SKIP_LIVE_ENDPOINT`, then a real `subprocess.run` against
`bin/ai-project-visual` whose pass requires the endpoint to produce a non-empty artifact. The
helper already returns distinct exits — disabled ⇒ 2, unconfigured type ⇒ 3, unreachable endpoint
⇒ 4, live execution-lock ⇒ 5. What is missing is the **separation layer**: a deterministic
acceptance command that excludes the live call, an explicit live-qualification command that reports
each pre-call vs runtime outcome (pass/fail/skip/deferred/config-error) with its environment and
reason, and regression coverage for the endpoint states.

## Problem Statement

Every P13 acceptance reports against "suite green," but that suite today contains one test whose
result depends on whether a local ComfyUI endpoint happens to be reachable. That makes the phase's
primary gate **unfalsifiable** — a red suite proves nothing (was the change wrong, or was ComfyUI
down?) and a green suite proves nothing either (was the endpoint skipped silently?). The phase spec
flags this as a named risk; E48.2 is its assignment: make deterministic acceptance reproducible,
keep live qualification honest and separate, and report the two independently.

## Goals

By the end of this Epic, the system must:

1. Provide an **executable deterministic-acceptance command** whose result is reproducible from
   identical source and an unchanged declared test mode — no machine-local endpoint availability
   entering the pass result.
2. Provide **`bin/suite-gate live`**, a structured live-qualification path that invokes
   `bin/ai-project-visual` directly, preserves its raw exit code, and maps it to
   **pass / fail / skip / deferred / config-error** with a recorded environment + reason.
3. Provide **`bin/suite-gate`**, the single integration point that runs the deterministic command and
   `suite-gate live`, emits the two machine-parseable signals, and whose two fields a P13 delivery
   report records — so every P13 delivery report states deterministic totals and live qualification
   **independently**, never folded into one aggregate.
4. Add **regression coverage for endpoint available, unavailable, and explicitly skipped** states.

## Non-Goals

This Epic explicitly does **not** aim to:

- **Delete, mock, or silently skip the live check.** It stays runnable; it stops being what the
  deterministic gate depends on.
- **Change `visual_artifacts.enabled`'s default or semantics.** The config contract stands.
- **Change `bin/ai-project-visual`'s exit codes** (disabled=2, unconfigured-type=3, unreachable=4,
  live-lock=5). They are the qualification signal, not the acceptance signal.
- **Change Drivr code.** No Drivr implementation is authorized by M48.

## Scope of Work

### 1. The deterministic acceptance boundary (D1)

Introduce an explicit marker/label so the deterministic acceptance command excludes the live
endpoint invocation.

**Must include:**
- A pytest marker on the live test (e.g. `@pytest.mark.live_endpoint`) so the deterministic
  acceptance is a **specific command** — e.g. `pytest -m "not live_endpoint"` — that never reaches
  ComfyUI.
- An **explicit, tested invariant**: identical source + unchanged declared test mode ⇒ identical
  deterministic result, regardless of whether a local ComfyUI happens to be reachable.
- The deterministic command, its exact marker string, and its reported **totals** (passed/failed
  counts) stated in the committed record — not described in prose.

### 2. The live-qualification channel (D2)

Keep live qualification runnable and honest, with its own executable command and result semantics.

**Must include:**
- A **structured live-qualification interface** that preserves the helper's raw exit code, because
  `pytest -m live_endpoint` alone does not: the live test uses `@pytest.mark.skipif` (which collapses
  the "disabled"/opt-out states to a pytest *skip*) and `assert result.returncode == 0` (which
  collapses every non-zero helper exit to a pytest *fail*). Those collapses lose exits 2/3/4/5.
- **The qualification path is `bin/suite-gate live`**, which invokes the **helper directly** — a
  plain subprocess call to `bin/ai-project-visual` with a fixed smoke prompt/`--type`/`--output` —
  and captures the **raw `returncode`** (0/2/3/4/5), never round-tripping through a pytest
  assertion. An explicit opt-out (`AI_PROJECT_SKIP_LIVE_ENDPOINT_TESTS=1`) is checked *before*
  invocation and yields `skip` without calling the helper.
- **Encoding/schema — fixed** (the `live` result object): `{"outcome": <pass|fail|skip|deferred|config-error>,
  "helper_exit": <int>, "environment": {"enabled": <bool>, "comfyui_url": <str>}, "reason": <str>}`.
- **Outcome mapping — fixed table**, committed and tested:
  - returncode `0` → `pass` — non-empty artifact produced by the real generation call.
  - returncode `4` (`EXIT_RUNTIME`) → `fail` — **the only runtime-failure state**: the live call ran
    and failed (unreachable / error / no output / download failed).
  - returncode `2` (`EXIT_DISABLED`), or the pre-checked opt-out → `skip` — not attempted by config
    intent; reason names "disabled" or "opted out".
  - returncode `5` (`EXIT_LOCKED`) → `deferred` — not attempted; a live execution lock is held.
  - returncode `3` (`EXIT_CONFIG`) → `config-error` — not attempted; a configuration defect.
  - any other returncode → `undetermined` (reported, never guessed).
- **Pre-call vs runtime is encoded by the mapping, not by prose:** exits 2/3/5 map to pre-call
  non-runtime outcomes (skip/deferred/config-error); only exit 4 maps to a runtime `fail`. Verify the
  mapping against `bin/ai-project-visual`'s control flow (§"6. Generate" is the only runtime call).
- **No hidden skip, no mock.** Every non-`pass` outcome is recorded with its distinct reason; a
  pre-call outcome is never reported as a runtime `fail`, and a mock standing in for the live
  endpoint is not acceptable.

### 3. Regression coverage for the endpoint states (D3)

**Must include** tests covering:
- **available** — deterministic plumbing proof (a controlled fixture / labeled stub that is never
  substituted for the real check in a qualification report);
- **unavailable** — closed port ⇒ the existing exit-4 path;
- **explicitly skipped** — opt-out flag or `enabled: false` ⇒ not run, reason recorded;
- **locked** — a live execution lock ⇒ exit-5 `deferred`, reason recorded;
- **config-error** — malformed `comfyui_url` / unconfigured `--type` ⇒ exit-3 `config-error`, reason
  recorded.

### 4. The suite-gate interface — one command, one consumer (D4)

One committed command — **`bin/suite-gate`** — is the single integration point; the live command is
not a separate reporting channel.

**Must include:**
- **`bin/suite-gate`** internally runs, in order: (1) the deterministic acceptance
  (`pytest -m "not live_endpoint"`) and (2) the live qualification **via `bin/suite-gate live`** (the
  structured helper-direct invocation + exit→outcome mapping from D2), and emits **exactly two
  machine-parseable fields**:
  - `deterministic`: the not-live totals ("773 passed, 0 failed");
  - `live`: the structured `live` result object (`outcome`, `helper_exit`, `environment`, `reason`).
- **Consumer — the M48 delivery report records it (no invented subsystem).** `bin/suite-gate`'s
  two fields are what a P13 **delivery report / delivery notice** records as the source-suite gate:
  the report states the `deterministic` totals as the one source-suite gate and the `live` outcome
  alongside it. There is no separate "delivery-report gate" component; the delivery report is the
  consumer and it records the command's output. This is M48's narrower requirement, not a new gate.
- **Exit behavior — specified:** `bin/suite-gate`'s exit code reflects **`deterministic` only**: 0
  when `deterministic` shows zero failures, non-zero otherwise. A live `fail`/`skip`/`deferred`/
  `config-error` **never changes `bin/suite-gate`'s exit** — it is reported in the `live` field and
  nothing else.
- A test asserting the interface: `deterministic` green + `live: skip` ⇒ `bin/suite-gate` exits 0;
  `deterministic` failing + `live` anything ⇒ non-zero. Live outcome never alters `bin/suite-gate`'s
  exit.

## Binding Constraints

Settled above this epic — **not re-decidable here** (M48 milestone spec):

1. **The non-deterministic suite is M48's assignment** (phase-spec risk). E48.2 is that assignment.
2. **Static validation is not operational proof**, but the deterministic suite must be honestly
   deterministic; separating live qualification is not the same as deleting it.
3. **An unreported skip or a mock is forbidden.** The live check either runs honestly or is a
   recorded skip.
4. **M48 authorizes no Drivr implementation.**
5. **`undetermined`, unavailable endpoint, and an explicit opt-out remain distinct.** A live check
   that cannot run is reported as such, never relabeled.

## Technical Constraints

**Repository:** all E48.2 code, tests, and the Delivery Notice land in `ai-project-system` on
`epic/E48.2`. The subject source is `tests/integration/test_visual_artifacts_helper.py` and its
supporting `bin/ai-project-visual` / `bin/ai-project-orchestrator` (this repository only). No
write to Drivr or any fleet project.

**Invocation:** `bin/suite-gate` is the single integration point; internally it runs
`PYTHONPATH=. pytest -m "not live_endpoint"` (deterministic) then `bin/suite-gate live` (a direct
`bin/ai-project-visual` subprocess whose raw returncode is captured and mapped), and exits by the
deterministic result only. The unchanged controls are `visual_artifacts.enabled` and
`AI_PROJECT_SKIP_LIVE_ENDPOINT_TESTS`; no credential value is involved or read.

**Constraint — no hidden skip, no mock:** a skip is a recorded, reasoned state. A mock that claims
to be the live endpoint is not acceptable; a deterministic stub used *only* to prove the
available-path plumbing is permissible only when clearly labeled and never substituted for the real
live check in a qualification report.

**Order:**

   reproducible-result invariant.
5. Implement `bin/suite-gate` as the single integration point, and verify **through it**: it reports
   `deterministic` green and `live` separately, and its exit code tracks `deterministic` only.

**Traps already paid for by this project:**
- **An unreported skip or a mock.** Converting an expected live check into a hidden skip or mock is
  forbidden (Binding Constraint 3).
- **Folding live qualification into "suite green."** They are two signals, never one aggregate.
- **Mislabeling a pre-call exit as a runtime failure.** Exits 2/3/5 happen before generation; only
  exit 4 is a runtime `fail`. The exit-code meanings stay; the label must match them.
