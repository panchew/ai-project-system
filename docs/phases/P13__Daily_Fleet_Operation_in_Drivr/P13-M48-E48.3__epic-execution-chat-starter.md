## Spec References (load-one-reference-the-other, AOG §3.1.1)

**Full spec:** `docs/phases/P13__Daily_Fleet_Operation_in_Drivr/P13-M48-E48.3__spec__enrollment-completes-the-delivery-substrate.md`

The Epic spec is the authoritative copy of **Deliverables (D1–D6, D2a), Definition of Done,
Acceptance Criteria, Binding Constraints, Non-Goals, and Notes.** **This starter does not duplicate
them.** Cite the spec by path and branch — **not** by a version number or sha.

**The six things easiest to get wrong, flagged here and specified there:**

1. **Reachability as verification.** `git ls-remote` answering is not a relationship; enrollment
   proves tracking + pushed + ref equality at final `HEAD`.
2. **Local-only satisfying delivery-ready.** It is a valid, durable disposition but explicitly
   non-delivery-ready; only the three-part verification emits `delivery-ready` (detail `verified`).
3. **A partial contract.** The command has a query mode and a `detail` for every `status`; the
   local-only artifact has a fixed path, schema, and reader.
4. **Pre-amend SHA / nondeterministic recovery.** Enroll after the final amend, verify final `HEAD`;
   the pre-existing-origin rule is single-valued; no `git remote remove`.
5. **Emitting credentials.** Reject credential-bearing URLs before `.git/config` (`invalid-url`,
   `remote: null`); redact Git diagnostics; test redaction with a fake-stderr sentinel, not just the
   pre-Git rejection path.
6. **Letting enrollment change fleet state.** It configures a remote and records a disposition; it
   never activates, never dispatches, never writes fleet registry state.
