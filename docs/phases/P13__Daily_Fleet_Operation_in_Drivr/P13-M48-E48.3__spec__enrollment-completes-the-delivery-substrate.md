# Epic E48.3 — Enrollment Completes the Delivery Substrate

## Context

**Governed delivery depends on PRs, but initialization has never created a route to one.**

SN-45 names the gap: the framework assumes a configured remote, while `bin/ai-project-init`
establishes none. The P13 opening ruling ties SN-45 to Decision 2 (Drivr received a private remote
so its acceptance chain became operable) — the same defect met from the other side. M48 owns closing
it; M55 reverifies it in practice.

**Re-measured at planning (2026-09-08, this chat):** `bin/ai-project-init` runs `git init`, adds the
governance submodule (which adds a remote for the *submodule*, not the project), commits the
scaffold, then **amends** that commit to include the HQ agent file. It exposes only `--skip-git` and
`--skip-submodule` as git-related flags — no project-remote option, no `origin`, no tracking
verification. Two facts matter for this Epic: (1) there is no enrollment step at all; (2) the
project's **final `HEAD` is only known after the post-init amend**, so any enrollment that runs or
verifies before that amend reads a pre-amend SHA.

The M48 milestone spec's E48.3 detail is carried here **as the scope, not re-derived**: close SN-45
in the supported initialization path with remote present/absent/invalid-failing/intentional-local-only
coverage; keep enrollment distinct from fleet activation and dispatch; never create, store, or print
credentials.

## Problem Statement

A project initialized today is delivery-incapable: it has a local repository and no remote, and
there is no explicit step that establishes and verifies the remote/tracking relationship. The result
is that governed delivery silently degrades to local-only work that can never be merged, and the
framework has no way to distinguish **delivery-ready** from **local-only** from **remote absent** —
let alone to fail closed on the difference.

Five failure modes are the ones this Epic must specifically not reproduce:

1. **Reachability is not a relationship.** `git ls-remote <url>` proves only that the URL answers.
   It does not prove a tracking relationship, a pushed branch, or ref equality. Verification must
   prove all three.
2. **Local-only is not delivery-ready.** An intentional local-only choice is a valid, durable
   disposition — but it is **explicitly non-delivery-ready**. It must never satisfy the
   delivery-ready predicate; only the three-part remote verification does.
3. **No executable contract.** Without a committed command, input schema, output schema, reason
   taxonomy, and exit semantics, "enrollment" is prose, not a runnable, testable step.
4. **Ordering and recovery.** Enrollment that runs before the final commit amendment verifies and
   pushes a pre-amend SHA; a pre-existing `origin`, a partial push/upstream setup, or a failed
   verification must have defined, idempotent behavior.
5. **Secret safety.** A credential-bearing remote URL must never reach `.git/config`, and Git's own
   diagnostics (which echo URLs) must be redacted.

## Goals

By the end of this Epic, the system must:

1. Commit **one executable enrollment command** with mutually exclusive `--remote <url>` /
   `--local-only` inputs, an output schema, a reason taxonomy, and exit semantics.
2. Make **delivery-ready require the three-part remote verification exclusively**; keep local-only a
   durable, recorded disposition that is **explicitly non-delivery-ready**.
3. Preserve **distinct** `absent`, `credential-absent`, `authenticated-refusal`, `verification-failure`,
   `local-only`, and `undetermined` states.
4. Define **mutation ordering and recovery**: enrollment runs after the initializer's final commit
   amendment, verifies ref equality against final `HEAD`, and has defined behavior for a pre-existing
   `origin`, partial push/upstream setup, failed verification, and safe retry/idempotency.
5. Enforce **secret safety**: reject credential-bearing remote URLs before writing `.git/config`,
   redact Git diagnostics, and prove by test that no secret reaches config or output.
6. Document the boundary between enrollment and fleet eligibility; enrollment never changes fleet
   eligibility or execution state.

## Non-Goals

This Epic explicitly does **not** aim to:

- **Auto-activate or dispatch a project.** Enrollment is configuration, not eligibility, not
  activation, not dispatch (dispatch extension is M50+ and outside M48).
- **Create, store, or print credentials.** Any authentication needed to reach a remote is external;
  the remote URL and tracking branch are config, not a secret.
- **Change fleet-registry state.** Enrollment never writes `active`/`benched`/`archived`.
- **Change Drivr code.** No Drivr implementation is authorized by M48.

## Scope of Work

### 1. The executable enrollment command and status contract (D1)

Commit **one** supported command — `bin/ai-project-enroll <project-dir> {--remote <url> | --local-only}`
(or the equivalent supported option on `bin/ai-project-init`) — with a full, tested contract.

**Inputs (mutually exclusive, exactly one):**
- `--remote <url>` — attempt full enrollment and verification against that URL.
- `--local-only` — record the durable local-only disposition (no remote work).

**Output schema (machine-parseable, e.g. JSON):**
`{"status": <delivery-ready|local-only|not-delivery-ready>, "detail": <absent|credential-absent|authenticated-refusal|verification-failure|local-only|undetermined>, "reason": <str>, "remote": <url|null>, "tracking": <bool>, "pushed": <bool>, "ref_equal": <bool>}`

**Reason taxonomy — six distinct non-delivery-ready states:**
- `absent` — no remote configured and no local-only disposition recorded (fail-closed).
- `credential-absent` — remote configured but the transport requires credentials that are not
  available (distinct from "no remote").
- `authenticated-refusal` — remote reachable, authentication attempted, remote refused (distinct from
  credential-absent).
- `verification-failure` — remote set, but one of the three verification steps failed (push failed /
  tracking not recorded / ref mismatch).
- `local-only` — durable disposition recorded; **non-delivery-ready by definition**.
- `undetermined` — the step could not reach a determination (git missing / unexpected failure).

**Exit semantics:** exit `0` when a disposition was successfully recorded (`status: delivery-ready`
or `status: local-only`); non-zero for `not-delivery-ready` (`detail` carrying the specific reason).
`delivery-ready` is only ever emitted by the three-part verification.

### 2. Three-part verification — delivery-ready exclusively (D2)

`delivery-ready` requires **all three** of: (a) the upstream tracking relationship is recorded
(`<branch>@{upstream}` resolves); (b) the current branch exists on the remote (pushed); (c) **ref
equality** — the remote's ref for that branch equals the **final local `HEAD`** SHA. All three, or
not delivery-ready. Reachability alone is never sufficient.

### 2a. The durable local-only disposition — explicitly non-delivery-ready (D2a)

A durable, committed disposition record (e.g. `.ai-project/enrollment.yml` with `mode: local-only`
and a reason) survives restarts and is readable by the delivery gate. It is **non-delivery-ready**:
it records an intent, and it never satisfies the delivery-ready predicate.

### 3. The eligibility boundary (D3)

Document, in the artifact and code comments, that enrollment **configures a remote / records a
disposition** and does **not** change fleet eligibility or execution state. Enrollment alone never
activates or dispatches.

### 4. Mutation ordering and recovery (D4)

Define and test the ordering/recovery rules:

- **Ordering:** enrollment runs **after** the initializer's final commit amendment, and ref-equality
  verification is against the **final `HEAD`** (never a pre-amend SHA).
- **Pre-existing `origin`:** a prior remote is detected and reported (never silently overwritten);
  the enrollment either re-verifies it or fails with a stated reason.
- **Partial push/upstream setup:** if push succeeds but upstream tracking is not recorded (or vice
  versa), the step is fail-closed with `verification-failure`, not left half-configured.
- **Failed verification:** the step leaves no half-written state; it is safe to retry.
- **Retry/idempotency:** re-running enrollment with the same inputs is idempotent — it re-verifies
  the final `HEAD` and does not duplicate or corrupt state.

### 5. Secret safety — adversarial, not just no-emission (D5)

- **Reject credential-bearing remote URLs before any write:** a URL carrying userinfo
  (`https://user:token@host`) or token-shaped query/fragment is rejected before `.git/config` is
  touched, with a non-secret reason.
- **Redact Git diagnostics:** Git's own stderr (which can echo the URL) is redacted before it is
  printed or recorded; the reason strings never contain the credential-bearing URL.
- **Tests prove absence, not absence-of-fixture:** tests assert the synthetic secret is absent from
  `.git/config` **and** from all command output, using a credential-bearing fixture — not merely that
  a credential-free local bare fixture produced no secret.

### 6. Regression coverage (D6)

Tests cover: the three-part verification; the six reason states (including credential-absent vs
authenticated-refusal as distinct); the durable local-only record; the ordering (post-amend, final
HEAD) rule; pre-existing origin / partial push / failed verification / retry-idempotency; the
credential-URL rejection and redaction; and the no-credential invariant.

## Binding Constraints

Settled above this epic — **not re-decidable here** (M48 milestone spec):

1. **Static validation is not operational proof.** An enrollment step that only writes a config line
   without verifying is not the fix — and reachability is not verification.
2. **Eligibility requires explicit authority.** Enrollment never grants it, never infers it.
3. **Never create, store, or print credentials.**
4. **M48 authorizes no Drivr implementation.**
5. **`undetermined`, missing evidence, credential absence, and an authenticated refusal remain
   distinct.** An enrollment that cannot verify because credentials are absent reports
   `credential-absent`; a remote that refuses reports `authenticated-refusal`; neither is "no remote."

## Definition of Done

Epic E48.3 is complete when:

- [ ] `delivery-ready` is emitted **only** by the three-part verification (tracking recorded + branch
      pushed + ref equality at final `HEAD`); local-only is a durable, recorded disposition and is
      explicitly **non-delivery-ready**
- [ ] `bin/ai-project-enroll` is a committed, tested command with mutually exclusive inputs, output
      schema, reason taxonomy (absent / credential-absent / authenticated-refusal /
      verification-failure / local-only / undetermined), and exit semantics
- [ ] Enrollment runs after the initializer's final commit amendment and verifies ref equality
      against final `HEAD`; pre-existing origin, partial push, failed verification, and retry are
      defined and idempotent
- [ ] Credential-bearing remote URLs are rejected before `.git/config` is written; Git diagnostics
      are redacted; tests prove the secret is absent from config and output
- [ ] Diagnostics contain no credential values
- [ ] Enrollment alone changes neither fleet eligibility nor execution state (verified by test and documented)
- [ ] Suite green (`PYTHONPATH=. pytest -q`)
- [ ] Every validation claim states repository, ref, date, command/check, and result; no claim covers
      another repository's suite (M48 Binding Constraint 9 — repository claims are bounded)
- [ ] Delivery Notice committed; PR opened from `epic/E48.3` to `milestone/M48`

## Acceptance Criteria

- [ ] A newly initialized project cannot be reported delivery-ready without the three-part
      verification, and a durable local-only disposition is **not** delivery-ready
- [ ] Diagnostics contain no credential values
- [ ] Enrollment alone changes neither fleet eligibility nor execution state
- [ ] Automated tests cover all supported outcomes (three-part verification, six reason states,
      ordering/recovery, secret safety)

## Technical Constraints

**Repository:** all E48.3 code, tests, documentation, and the Delivery Notice land in
`ai-project-system` on `epic/E48.3`. The subject is `bin/ai-project-init` and the new
`bin/ai-project-enroll` (this repository only).

**Invocation:** `PYTHONPATH=. pytest -q`. Enrollment verification uses local `git init --bare`
fixtures so the full relationship (tracking + push + ref equality) is exercised without network;
secret-safety tests use a **synthetic credential-bearing URL fixture** (not a real secret) and assert
its absence from config and output.

**Constraint — no credentials:** no token, PAT, SSH passphrase, or secret-bearing value is accepted
into, stored in, or printed by the enrollment path; credential-bearing URLs are rejected before any
write.
