# Epic E13.3 — Auto-Merge Git Hooks & Conflict Resolver

## Context

Epic E13.1 and E13.2 introduced a background daemon capable of autonomously discovering trigger tasks and running them through the sandbox validation loop. When an Epic completes successfully, the system is currently stopped, requiring a human operator to manually commit, push, open a Pull Request, and merge changes back to the target milestone branch.

To complete the autonomous execution loop, this Epic implements automated git promotion hooks (`bin/ai-project-git-merge`). When the orchestrator or daemon registers a fully verified, successful run, this utility automatically pushes the local Epic branch, opens a GitHub Pull Request, approves/merges it via the GitHub CLI (`gh`), and shifts branches cleanly, handling merge conflicts gracefully by raising immediate human escalation alerts.

---

## Problem Statement

Manual code integration (opening PRs, manually checking approvals, resolving branches) slows down continuous autonomous development loops. However, programmatically forcing merges blindly can lead to untracked conflicts, code regressions, or breaking changes on target branches.

We need a safe, automated Git integration utility that interacts with local Git repositories and remote GitHub APIs using authenticated, strict workflows. If clean auto-merges fail due to merge conflicts or API errors, the system must immediately abort, prevent corrupted commits, write an explicit conflict escalation report under `docs/admin/`, and halt the queue to protect repository integrity.

---

## Goals

By the end of this Epic, the system must:

1. Build a strict git merge and promotion helper script (`bin/ai-project-git-merge`) to handle automated branch flows.
2. Automate GitHub Pull Request creation, self-approval, and merging using the GitHub CLI (`gh`) tool.
3. Enforce strict repository boundaries: only allow auto-merging from configured local `epic/E#.#` branches to parent `milestone/M#` branches.
4. Implement a graceful fail-safe conflict handler: when a merge conflict occurs, abort the operation safely, reset the branch state, write a clear Markdown escalation report to `docs/admin/escalation-conflict-<epic_id>.md`, and exit with code 1.
5. Provide automatic pre-flight checks to verify that the host machine has an authenticated `gh` session before executing any merge commands.

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Programmatically solve complex merge conflicts (any conflict must immediately trigger human escalation).
- Handle direct force-pushes to protected production branches (e.g., bypassing standard Pull Request and branch rules).
- Support git hosting providers other than GitHub (specifically relies on `gh` CLI).

---

## Scope of Work

### 1. GitHub CLI Integration & Pre-flight Checks
The auto-merge tool must ensure all dependencies are configured before running.

**Must include:**
- Verification that `git` and `gh` are installed.
- Executing `gh auth status` to verify the active host environment has valid credentials.
- Checking that the current git workspace is clean before initiating push/merge sequences.

### 2. Auto-Merge Workflow (`bin/ai-project-git-merge`)
Develop the CLI-driven pipeline for promoting successful epic branches.

**Must include:**
- Pushing the local active branch `epic/E#.#` to origin.
- Generating and submitting a pull request from `epic/E#.#` to the target `milestone/M#` branch.
- Automatically approving and merging the PR using `gh pr merge --auto --merge` or `gh pr merge --merge --admin` (if admin overrides are needed).
- Graceful branch deletion on remote and local workspaces upon successful merge.

### 3. Conflict Resolution & Human Escalation
Handle integration failures securely without corrupting the workspace.

**Must include:**
- Detection of merge conflicts or PR merge failures.
- Auto-reversion/abort: run `git merge --abort` or `git reset --hard` if local test merges encounter conflicts.
- Report generation: create `docs/admin/escalation-conflict-<epic_id>.md` describing the conflicting files and git diff outputs.
- Alert signaling: exit with a non-zero code to notify the calling daemon that human intervention is required, blocking subsequent queue triggers.

## Definition of Done

Epic E13.3 is complete when:

- [ ] `bin/ai-project-git-merge` script is fully implemented, executable, and passing all pre-flight checks.
- [ ] Auto-push and automated PR creation/merge via `gh` is verified with mock tests or temporary test branches.
- [ ] Merge conflicts are safely detected, aborted without dangling files, and generate a markdown escalation report.
- [ ] Unit/mock tests pass successfully via `bin/ai-project-git-merge --test`.
- [ ] Epic Completion Report is completed and committed to the branch.
- [ ] Pull request is opened to the `milestone/M13` branch.

---

## Acceptance Criteria

- [ ] Running `bin/ai-project-git-merge` when `gh` is unauthenticated fails gracefully with an informative error.
- [ ] Running the script on a successful epic branch pushes the code, opens a PR, and merges it successfully into the parent milestone branch without prompt interactions.
- [ ] If a merge conflict occurs during the auto-merge sequence, the script reverts the workspace, halts, creates `docs/admin/escalation-conflict-<epic_id>.md` listing conflicting files, and exits with code 1.
- [ ] Stale local and remote branches are successfully cleaned up post-merge if requested.

---

## Technical Constraints

**Format:** Python 3 standard library script.  
**Dependencies:** Requires `git` CLI and `gh` CLI installed and authenticated on the host.  
**Path Boundaries:** Only merge into branches matching `milestone/*` patterns. Direct pushes to `master` or `main` are strictly prohibited.  
**Location:** Script located at `bin/ai-project-git-merge`.
