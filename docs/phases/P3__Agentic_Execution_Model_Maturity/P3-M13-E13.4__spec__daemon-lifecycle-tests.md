# Epic E13.4 — Daemon Lifecycle Management & Integration Tests

## Context

With Epic E13.1 (daemon daemonization and commands), E13.2 (queue monitoring and scheduling), and E13.3 (git automated branch merges) complete, the orchestrator and daemon are structurally fully functional. However, running a persistent daemon unattended requires bulletproof validation. We must guarantee that the daemon starts, stops, reloads, handles crash locks, and redirects logs correctly under any host scenario.

This Epic addresses this validation gap by delivering a dedicated, end-to-end functional integration test suite (`bin/verify-daemon.sh`) designed to simulate real-world lifecycle interactions, verify standard and non-standard termination states, ensure clean lock-file management, and confirm continuous logging captures.

---

## Problem Statement

A background process that fails to clean up its state on shutdown, locks up under stale PID records, or experiences log file corruption degrades the stability of the entire development cluster. It is not enough to rely on unit tests mocking individual lines of Python. 

We need an authoritative, black-box integration verification script that actively spins up the daemon, executes commands (`start`, `stop`, `status`, `logs`), forcibly terminates the daemon, checks stale lock recoveries, and monitors standard out/err capturing. This script must run both in local environments and during continuous integration tests to prevent regression.

---

## Goals

By the end of this Epic, the system must:

1. Deliver a robust, comprehensive lifecycle integration testing bash harness (`bin/verify-daemon.sh`).
2. Verify all standard CLI commands (`start`, `stop`, `status`, `logs`) behave correctly on a live, double-forked background daemon instance.
3. Validate lock-file integrity: check that `.ai-project/locks/daemon.pid` is written on startup, correctly read by status checks, and safely removed upon graceful stop.
4. Validate crash recovery scenarios: simulate daemon crashes (such as `kill -9` signals) and confirm subsequent start commands cleanly recover and continue without locking up.
5. Validate continuous background log redirection: verify that heartbeat checks, queue poll events, and child orchestrator invocations are written to `.ai-project/logs/daemon.log`.

---

## Non-Goals

This Epic explicitly does **not** aim to:

- Test Docker container boundaries or Docker networking issues (handled in M12 and E13.2).
- Solve native host OS permissions issues outside the repository's path limits.

---

## Scope of Work

### 1. Integration Test Suite (`bin/verify-daemon.sh`)
Build an executable shell script that operates as a complete, self-contained functional test suite.

**Must include:**
- Clean workspace setup: resetting files, deleting pre-existing locks or log files.
- Command validation: asserting exit codes and output contents of `ai-project-daemon start`, `ai-project-daemon status`, `ai-project-daemon logs`, and `ai-project-daemon stop`.
- Signal testing: verifying that sending `SIGINT` or `SIGTERM` directly to the daemon's active background PID triggers graceful shutdown routines and unlinks files.

### 2. Edge Case & Crash Verification
Ensure the daemon survives unexpected state configurations.

**Must include:**
- Stale PID scenario: write a fake/inactive PID to `.ai-project/locks/daemon.pid` and verify that the next `start` command successfully overwrites it and boots.
- Active PID conflict scenario: write the PID of an actively running host process (like `$$` or `sleep`) to the PID lock and confirm that the daemon refuses to start, exiting with code 1.
- Log truncation and permissions check: verify that the daemon handles missing or unwritable directories gracefully, creating them automatically with standard permissions.

### 3. Verification Report Generation
Document test executions cleanly.

**Must include:**
- Assertion testing inside `bin/verify-daemon.sh` with clear green/red success outputs.
- Comprehensive logging of test outcomes and execution tracebacks.

## Definition of Done

Epic E13.4 is complete when:

- [ ] `bin/verify-daemon.sh` is fully implemented, executable, and covers all five core scenarios (standard start/stop, status POSIX compliance, lockfile validation, crash recovery, signal termination).
- [ ] Running `./bin/verify-daemon.sh` succeeds with exit code 0 and outputs full test summaries.
- [ ] Stale/active lock conflicts are verified to reject or recover correctly.
- [ ] Epic Completion Report is completed and committed to the branch.
- [ ] Pull request is opened to `milestone/M13`.

---

## Acceptance Criteria

- [ ] `./bin/verify-daemon.sh` executes all integration tests in under 30 seconds.
- [ ] All test cases pass successfully in a clean workspace environment.
- [ ] Graceful shutdowns on direct process signals are verified to completely clean up active PID lockfiles.
- [ ] Background daemon errors are cleanly isolated and do not lead to dangling, un-terminable processes on the host.

---

## Technical Constraints

**Format:** Bash shell script (`#!/bin/bash`).  
**Environment:** Standard Unix commands (`grep`, `kill`, `sleep`, `ps`, `cat`). No specialized test framework installation is required.  
**Cleanliness:** Must cleanly restore the repository's active state, deleting temporary test locks or logs before exit.  
**Permissions:** `bin/verify-daemon.sh` must be marked executable (`chmod +x`).
