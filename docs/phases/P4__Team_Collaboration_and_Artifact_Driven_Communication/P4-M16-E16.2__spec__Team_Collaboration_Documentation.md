# Epic P4-M16-E16.2: Team Collaboration Documentation

## Problem Statement

The AI Project System was designed for solo development. Adopting it as a team requires
explicit role definitions, clear authority boundaries, and decision matrices that any team
member can look up in under 30 seconds. Without these, teams encounter authority conflicts,
unclear escalation paths, and friction that kills adoption.

This Epic produces the documentation that makes team adoption practical: concise role
guides, an authority lookup matrix, and a step-by-step walkthrough using the E16.1
example project.

**Dependency:** E16.1 must be merged to `milestone/M16` before this Epic begins. The
Example Walkthrough references real artifact files from `examples/team-project-example/`.

---

## Requirements

### Functional Requirements

1. **Team Onboarding Guide**
   - Role definitions: CFO, Phase Lead, Contributor, Reviewer, HQ Agent, Milestone Agent
   - Authority matrix: who decides what (table format)
   - Escalation flowchart: when to escalate, to whom
   - Communication norms: chat-first, artifact-driven
   - Time commitment per role

2. **CFO Quick Start**
   - Target: < 1000 words, < 5 min read
   - Covers: your job (3–5 bullets), typical week, how to review Completion Notices,
     how to issue Review Decisions, how to authorize production deployment, time
     commitment (30 min – 2 hours/week)
   - Tone: direct, no fluff, actionable

3. **Contributor Guide**
   - Epic workflow: receive spec → implement → Completion Notice → await Review Decision → merge
   - Definition of Done: what "done" means before submitting
   - What to do if blocked (escalation path)
   - Example PR workflow

4. **Reviewer Guide**
   - Review checklist: tests passing, coverage, docs, spec compliance
   - How to provide feedback (tone, format)
   - How to block a merge and what happens next
   - Integration with the Review Decision process

5. **Phase Lead Guide**
   - Milestone planning: breaking a Phase into Milestones and Epics
   - Epic prioritization and sequencing
   - When and how to escalate to CFO
   - Working with Milestone Agents

6. **Decision Matrices**
   - Table format only (no prose)
   - Rows: Phase Scope, Milestone Planning, Epic Acceptance, Production Deployment,
     Escalation Trigger
   - Columns: Who decides, Criteria, Timing, Escalation path

7. **Example Walkthrough**
   - Traces the E16.1 example project (Epic E1.1 — User Authentication)
   - References actual artifact filenames from `examples/team-project-example/.ai-project/artifacts/`
   - Shows artifacts flowing between chats: Epic chat → Milestone chat → Phase chat → CFO
   - Demonstrates both manual mode (copy-paste steps) and agentic mode (daemon routing)
   - Decision points explicitly name the deciding role

8. **FAQ**
   - 10+ questions in Q&A format
   - Covers common blockers: "What if my PR fails review?", "Can I change the spec?",
     "Who do I ask if I'm blocked?", "What if CFO is unavailable?", etc.

9. **Troubleshooting Guide**
   - Format: Problem → Cause → Solution
   - Covers known issues from P4 design, common misunderstandings about authority,
     artifact routing errors, and escalation missteps

10. **Index README**
    - Entry point for `docs/team-collaboration/`
    - One-line description per guide with a link
    - Suggests reading order for new team members

11. **Main README Update**
    - Add "Team Collaboration" section to the repo's root or docs README
    - Link to `docs/team-collaboration/`

### Non-Functional Requirements

- **Consistency:** The same role is named for the same decision everywhere. CFO Quick Start,
  Team Onboarding Guide, and Decision Matrices must agree on every authority.
- **Self-contained role guides:** A contributor should be able to read only the Contributor
  Guide and know exactly what to do next.
- **No invented authorities:** Role descriptions derive from
  `governance/systems/roles-authorization-team-governance.md` — do not assign authorities
  not defined there.
- **Text-only:** No screenshots or images; all guides are Markdown.

## Design

├── cfo-quick-start.md           ← < 1000 words, 5-min read
├── contributor-guide.md         ← Epic workflow, DoD, escalation
├── reviewer-guide.md            ← Checklist, feedback, blocking
├── phase-lead-guide.md          ← Planning, prioritization, escalation

├── example-walkthrough.md       ← E16.1 full cycle trace
├── faq.md                       ← 10+ Q&A
└── troubleshooting-guide.md     ← Problem → Cause → Solution

### Content Length Targets

| Guide | Target Length | Tone |
|---|---|---|
| CFO Quick Start | < 1000 words | Direct, no fluff |
| Contributor Guide | 1500–2500 words | Supportive, practical |
| Reviewer Guide | 1000–2000 words | Procedural, clear |
| Phase Lead Guide | 1500–2500 words | Strategic, concise |
| Team Onboarding | 2000–3000 words | Welcoming, complete |
| Decision Matrices | Tables only | Reference |
| Example Walkthrough | 2000–3000 words | Tutorial |
| FAQ | 10+ Q&A | Conversational |
| Troubleshooting | 800–1500 words | Problem-solving |

### Decision Matrix Structure

| Decision Type | Who Decides | Criteria | Timing | If Blocked |
|---|---|---|---|---|
| Phase Scope | CFO | Strategic alignment | Phase planning | Escalate to CFO |
| Milestone Planning | Phase Lead / HQ Agent | Resource fit, sequencing | Start of Milestone | Phase Lead escalates |
| Epic Acceptance | Milestone Agent / Phase Lead | DoD satisfied, spec compliant | After Completion Notice | Phase Lead decides |
| Production Deployment | CFO | All Milestones complete, QA passed | End of Phase | Wait for CFO |
| Escalation Trigger | Any role | Blocked > 24h, authority conflict | Anytime | Follow escalation path |
