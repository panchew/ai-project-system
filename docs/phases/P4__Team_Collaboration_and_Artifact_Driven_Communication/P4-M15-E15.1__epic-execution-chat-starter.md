## Implementation Plan

### Phase 1: HQ Chat Handler Design (Day 1 AM)
Define HQ Chat Handler class:
- Issue detection from HQ Chat messages
- Parsing issue attributes (severity, scope, estimated time)
- Decision logic (Bugfix vs. defer)
- Create handler base class

### Phase 2: Issue Detection (Day 1 PM)
Implement issue detection:
- Pattern matching for "🔴 Potential Bugfix" format
- Extract: title, severity, status page, reported_by, scope estimate
- Validate issue has required fields
- Create Issue data class

### Phase 3: Severity Evaluation (Day 2 AM)
Implement severity evaluation:
- Map strings to severity levels (critical, high, medium, low)
- Business impact assessment
- Urgency determination
- Create Severity enum

### Phase 4: Bugfix Decision Logic (Day 2 PM)
Implement decision logic:
- Evaluate: is this a Bugfix Epic or defer?
- Rules: in-scope, time-sensitive, actionable, localized
- Produce decision: "Approve Bugfix Epic" or "Defer to Next Phase"
- Log decision with reasoning

### Phase 5: Spec Generation (Day 3 AM)
Implement minimal Bugfix Epic spec generation:
- Create Bugfix Epic spec template (B#.# format)
- Assign Epic ID (next available in phase)
- Commit to `docs/bugfixes/B#.#__spec__Brief_Title.md`
- Return spec path and content

### Phase 6: Authorization Issuance (Day 3 PM)
Implement Epic Delivery Authorization:
- Create authorization artifact
- Reference Bugfix Epic ID and severity
- Commit to `.ai-project/artifacts/`
- Return authorization artifact

### Phase 7: Testing (Day 4 AM)
Create comprehensive tests:
- Happy path: detect issue → create Bugfix Epic → issue authorization
- Rejection path: detect issue → defer to next Phase
- Edge cases: missing fields, invalid severity, unclear scope
- 20+ test cases

### Phase 8: Documentation (Day 4 PM)
Create documentation:
- API reference for HQ Chat Handler
- Decision flowchart: "Should this be a Bugfix Epic?"
- Example: full bugfix creation walkthrough
- Integration with artifact system

## Integration Points

1. **M14 Artifact System:**
   - Bugfix Epic specs stored with M14 artifact formats
   - Authorization artifacts use M14 schemas
   - Daemon can route if needed (though typically manual in HQ)

2. **HQ Chat:**
   - Handler integrates into HQ Chat Starter
   - Processes issue reports asynchronously
   - Produces decision (Approve/Defer)

3. **E15.2 (SLA Tracking):**
   - E15.1 creates Bugfix Epic with severity
   - E15.2 uses severity to determine SLA (4-hour for all bugfixes)
   - E15.2 depends on this Epic's output

4. **E15.3 (Post-Mortem):**
   - E15.1 assigns severity level
   - E15.3 uses severity to determine if post-mortem required (C/H only)
