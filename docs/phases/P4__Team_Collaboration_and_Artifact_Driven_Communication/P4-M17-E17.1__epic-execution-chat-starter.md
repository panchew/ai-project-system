## Implementation Plan

### Phase 1: Root Cause Analysis (Day 1 AM)
Investigate the issue:
- Current behavior: daemon fails with "orchestrator not found"
- Which projects affected: submodule v2.0.0
- Path where daemon looks: `bin/ai-project-daemon` typically
- Where orchestrator actually is: check submodule structure
- Why v3.0.0+ works: includes orchestrator? or different path logic?
- Test v2.0.0 on fresh checkout to reproduce

### Phase 2: Solution Evaluation (Day 1 PM)
Evaluate options:
- **Option A:** Make daemon search in `governance/bin/` as fallback
  - Pro: Works with v2.0.0, no submodule update needed
  - Con: Searches multiple paths, slightly slower
- **Option B:** Update submodule version to v3.0.0+
  - Pro: One path, official fix
  - Con: May have breaking changes, need to verify compatibility
- **Option C:** Build orchestrator on-demand during setup
  - Pro: Always available
  - Con: Build complexity, slower first run
- **Recommendation:** Evaluate and choose best option

### Phase 3: Implementation (Day 2 AM)
Implement chosen fix:
- If Option A: Add fallback path search logic
- If Option B: Update submodule reference, test compatibility
- If Option C: Implement build on-demand logic
- Update daemon to use new logic
