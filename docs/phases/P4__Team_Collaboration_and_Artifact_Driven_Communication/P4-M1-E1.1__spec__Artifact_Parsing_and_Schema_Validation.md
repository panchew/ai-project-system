# Epic P4-M1-E1.1: Artifact Parsing & Schema Validation

## Problem Statement

When Epic Agents complete work, they produce Completion Notice artifacts (YAML frontmatter + markdown body). These artifacts must be:
- Parsed for validity
- Schema-validated (required fields, types, references)
- Routed to the correct parent chat
- Stored for audit trail

Currently, there is no code to parse or validate these artifacts.

---

## Requirements

### Functional Requirements

1. **Parse YAML Frontmatter**
   - Extract YAML frontmatter from artifact files (Completion Notice, Review Decision, Delivery Notice)
   - Handle malformed YAML gracefully (error message, not crash)
   - Extract key fields: artifact_type, epic_id, milestone_id, phase_id, timestamp, status

2. **Schema Validation**
   - Define schema for each artifact type (3 types: completion_notice, review_decision, delivery_notice)
   - Validate required fields per type
   - Validate field types (string, int, date, URL, etc.)
   - Validate references (epic_id format: P#-M#-E#.#, or B#.# for bugfixes)
   - Return clear error messages if validation fails

3. **Artifact Type Detection**
   - Detect artifact type from frontmatter `artifact_type` field
   - Confirm consistency: artifact_type matches file name pattern or location
   - Example: file in `completion-notices/` should have `artifact_type: completion_notice`

4. **Reference Extraction**
   - Extract parent reference (epic_id → Milestone, or milestone_id → Phase, or phase_id → HQ)
   - Extract child reference (who issued the artifact)
   - Store references for routing in E1.2

5. **Storage & Indexing**
   - Create in-memory index of artifacts by epic_id, milestone_id, phase_id
   - Enable quick lookup: "get latest Completion Notice for epic P1-M1-E1.1"
   - Enable search: "get all Completion Notices for milestone P1-M1"

### Non-Functional Requirements

- **Performance:** Parse 100 artifacts in <1 second
- **Reliability:** No crashes on malformed input; graceful error handling
- **Testability:** Unit tests for each schema type and error condition
- **Maintainability:** Clear, documented parsing code; easy to add new artifact types

### Schema Example: Completion Notice

```yaml
artifact_type: completion_notice
artifact_version: 1.0
timestamp: ISO-8601 (required)
issuer_chat: string (required)
issuer_role: string (required)
status: string = "ready_for_review" (required)
epic_id: P#-M#-E#.# or B#.# (required)
milestone_id: P#-M# (required)
phase_id: P# (required)
project_name: string (required)
deliverables: array of {name: string, path: string, type: string, status: string}
blockers: array of {description: string, severity: string} (optional)
qa_status: passed|failed|blocked (required)
pr_details:
  number: string or "pending" (required)
  title: string (required)
  target_branch: string (required)
  url: string (required)
```

### Error Handling

**ArtifactParseError:** YAML parsing failed
- Message: "Failed to parse YAML: {syntax error}"
- Recovery: Skip file, log error, continue

**ArtifactSchemaError:** Schema validation failed
- Message: "Schema validation failed: {field} is missing | {field} has wrong type | {reference} is invalid"
- Recovery: Mark as invalid, do not route, report to HQ

**ArtifactNotFoundError:** Artifact not found in index
- Message: "No artifact found for epic_id {id}"
- Recovery: Return None, log as warning
