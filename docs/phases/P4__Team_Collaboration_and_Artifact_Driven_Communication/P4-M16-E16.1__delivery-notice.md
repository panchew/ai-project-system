## Design Choices and Notes

1. **"Taskflow" Task Management App** was used as the fictional project domain — generic enough to be relatable, specific enough to produce realistic, distinct Epic names.

2. **Rejection + rework cycle included** — E1.2 was rejected (test coverage 68% < 80% required) and resubmitted as v1.1. Both the rejected Completion Notice (v1.0) and the accepted one (v1.1) are in the artifacts directory, giving teams a concrete example of the rework flow.

3. **73 tests vs. the required 10+** — the test suite covers all artifact types exhaustively via parametrized fixtures. This gives a more useful validation tool than the minimum 10.

4. **Spec timestamps use PyYAML auto-parsing** — ISO-8601 timestamps in YAML front-matter are parsed as Python `datetime` objects by PyYAML. The timestamp test was updated to accept either format (string or datetime object), matching real-world parser behavior.

5. **B1.1 stored under M3** — the bugfix spec is placed under `M3__Polish_and_Deploy/` per the E16.1 spec design, even though the `bugfix-epic-workflow.md` suggests `docs/bugfixes/`. The spec design takes precedence as the authoritative source for this example.
