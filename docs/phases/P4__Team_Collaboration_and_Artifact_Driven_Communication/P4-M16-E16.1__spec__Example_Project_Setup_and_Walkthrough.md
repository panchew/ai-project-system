# Epic P4-M16-E16.1: Example Project Setup & Walkthrough

## Problem Statement

New teams adopting the AI Project System have no hands-on example to reference. Reading
governance documents explains the theory, but without a concrete example — real artifact
files, team assignments, and decision points — teams must guess how to apply the system
in practice. The result is slow adoption, inconsistent usage, and avoidable errors.

This Epic creates a ready-to-run reference project that makes the Phase → Milestone →
Epic workflow tangible for any new team member.

---

## Requirements

### Functional Requirements

1. **Example Project Directory**
   - Create `examples/team-project-example/` with realistic structure
   - Include `docs/phases/`, `.ai-project/artifacts/`, `src/`, `tests/`
   - Structure must be navigable without explanation

2. **Phase and Milestone Specs**
   - Phase P1 spec: realistic scope (not trivial), 3 Milestones
   - Milestone M1, M2, M3 specs: 2–3 Epics each
   - All specs use YAML front-matter per `governance/templates/`

3. **Epic Specs**
   - 7–9 Epic specs (E1.1–E3.2 range) with distinct, plausible content
   - Not copies of each other; each should feel like a real unit of work
   - At least one bugfix Epic using the expedited path

4. **Team Role Assignment**
   - 5 roles: CFO, Phase Lead, Developer 1, Developer 2, Reviewer
   - Fictional names and bios (not real project data)
   - `TEAM_SETUP.md` lists each role, person, and their decision authorities

5. **Sample Artifacts**
   - 3+ Completion Notices (one per Milestone minimum)
   - 2+ Review Decisions (at least one accept, one reject)
   - 3+ Delivery Notices (post-merge confirmations)
   - All stored in `.ai-project/artifacts/` subdirectories
   - Filenames: `<ISO-8601-UTC>__<P#-M#-E#.#>__<artifact-type>.md`
   - All artifacts use formats from `governance/systems/artifact-communication-protocol.md`

6. **Walkthrough Document**
   - Step-by-step trace of one complete Epic cycle: Phase approval → Epic assignment
     → Implementation → Completion Notice → Review Decision → Merge → Delivery Notice
   - Each step names the deciding role and explains what action they take
   - Shows at least two Epics executing in parallel during one Milestone
   - References the actual artifact files in `.ai-project/artifacts/`

7. **Validation Test Suite**
   - Located at `tests/test_example_project_artifacts.py`
   - 10+ test cases covering: YAML front-matter validity, required fields, artifact
     naming convention, epic_id/milestone_id format, team role consistency

### Non-Functional Requirements

- **Realistic content:** Example project scope must feel like real work (not "Hello World")
- **Fictional data only:** No real ai-project-system artifacts, names, or commit history
- **Daemon-compatible:** Artifacts must be parseable by the parser from E14.1/E15.2
- **Self-contained:** Example can be understood without reading the main repo
