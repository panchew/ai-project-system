## Test Scenario Details

### Scenario 1: Happy Path (Completion → Accept → Delivery)

**Test:** `test_artifact_happy_path()`

Steps:
1. Create Completion Notice in `.ai-project/artifacts/completion-notices/`
2. Run artifact processing (daemon or manual)
3. Verify routing trigger created for Milestone Chat
4. Create Review Decision (ACCEPT) in `.ai-project/artifacts/review-decisions/`
5. Run artifact processing
6. Verify routing trigger created for Epic Chat
7. Create Delivery Notice in `.ai-project/artifacts/delivery-notices/`
8. Run artifact processing
9. Verify routing trigger created for Milestone Chat
10. Assert: All artifacts processed, no errors, full audit trail

**Verification:**
```
✓ completion-notices/P4-M14-E14.1.md → .processed/
✓ Routing trigger: .ai-project/queue/route_completion_P4-M14-E14.1.json
✓ review-decisions/P4-M14-E14.1.md → .processed/
✓ Routing trigger: .ai-project/queue/route_review_P4-M14-E14.1.json
✓ delivery-notices/P4-M14-E14.1.md → .processed/
✓ All artifacts in processed state, no errors
```

### Scenario 2: Rejection & Rework

**Test:** `test_artifact_rejection_path()`

Steps:
1. Create Completion Notice (v1.0) for epic P1-M14-E14.1
2. Process artifact (routed to Milestone)
3. Create Review Decision (REJECT with feedback)
4. Process artifact (routed back to Epic)
5. Create new Completion Notice (v1.1) with rework
6. Process artifact (routed to Milestone)
7. Create Review Decision (ACCEPT)
8. Process artifact (routed back to Epic)
9. Assert: v1.0 marked rejected, v1.1 treated as new, workflow continues

### Scenario 3: Escalation

**Test:** `test_artifact_escalation_path()`

Steps:
1. Create Completion Notice at Epic level (epic_id: P1-M14-E14.1, milestone_id: P1-M14)
2. Route to Milestone Chat
3. Create Escalation Decision (Milestone escalates to Phase)
4. Route to Phase Chat
5. Create Review Decision at Phase level
6. Route back to Milestone, then to Epic
7. Assert: Escalation path works, no artifacts lost

### Scenario 4: Manual Mode

**Test:** `test_manual_mode()`

Verification:
- Artifact format is copy-paste friendly
- YAML frontmatter separates from markdown body
- No special characters that would break in text copy-paste
- Human can read and understand artifact intent from body

### Scenario 5: Agentic Mode

**Test:** `test_agentic_mode()`

Steps:
1. Create Completion Notice
2. Run daemon artifact monitoring
3. Verify daemon detects and routes
4. Verify routing trigger created
5. Verify artifact moved to .processed/
6. Verify daemon logs show routing decision

### Scenario 6: Error Scenarios

**Tests:** `test_error_scenarios()`

Cases:
- Malformed YAML → artifact moved to .failed/, logged
- Missing required field → artifact moved to .failed/, logged
- Invalid epic_id format → artifact moved to .failed/, logged
- File corruption → graceful error, logged

### Scenario 7: Parallel Execution

**Test:** `test_parallel_artifacts()`

Steps:
1. Create 5 concurrent Completion Notices (P1-M14-E14.1 through E1.5)
2. All write to completion-notices/ within 100ms
3. Run daemon processing
4. Verify all 5 routed correctly
5. Verify no duplicate routes
6. Verify no lost artifacts
7. Assert: Parallel processing works, no race conditions
