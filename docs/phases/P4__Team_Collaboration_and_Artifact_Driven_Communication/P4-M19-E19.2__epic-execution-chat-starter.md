## Implementation Plan

### Phase 1: Steering Note Template (Day 1 AM)
Create `governance/templates/steering-note.md`:
- YAML schema matching the 2026-06-19 reference instance (fields above)
- Sections: Purpose, Concerns for HQ Triage (one sub-section per concern with id/
  severity/detail/required-action), Decisions Already Made, Carry-Over Open Items,
  Next Action
- Guidance text in each section: brief, prescriptive, no cross-references needed
- Naming convention documented in template header

### Phase 2: Progress Digest Template (Day 1 PM)
Create `governance/templates/progress-digest.md`:

YAML front-matter:
```yaml
artifact_type: progress_digest
artifact_version: 1.0
timestamp: <ISO-8601>
issuer_chat: HQ Chat
target: Creation Chat
project_name: <project-slug>
period_covered: <ISO-date range>
```

Four sections — no more, no fewer:
1. **Phase Status** — one line per milestone (name, ✅/🔄/⏳, blocking issue if any)
2. **Open Decisions** — numbered list of decisions the user must make or confirm
3. **Next Actions** — 3–5 items max (what, who initiates, by when)
4. **Blocking Concerns** — zero to three items; write "None" if clean

Cold-read test: after writing, give the template to someone who hasn't read this spec
and ask them to fill it in. If they need to open another document, the template failed.

### Phase 3: Bouncer Work Log Template (Day 2 AM)
Create `governance/templates/bouncer-work-log.md`:

Minimal YAML:
```yaml
artifact_type: bouncer_work_log
timestamp: <ISO-8601>
project: <project-slug>
severity: <data-fix | user-request | system-op | other>
```

Body (four fields only):
1. **What happened** — one sentence
2. **What I did** — one sentence
3. **Side effects** — optional; omit if none
4. **Pattern flag** — `[ ] This is the 3rd+ occurrence → write Steering Note`

2-minute fill test: time yourself filling out a sample entry for a fictitious scenario.
If it takes more than 2 minutes, shorten the template until it passes.

Naming convention: `<ISO-datetime>__bouncer-work__<slug>.md`
Storage: `.ai-project/artifacts/bouncer-work-logs/`

### Phase 4: Re-instantiation Ritual (Day 2 PM)
Create `governance/systems/creation-chat-guide.md` with:

**Section: Re-instantiation Ritual**
Four steps, each specified precisely:
1. Before reset — produce and commit a Steering Note
2. What to include — open concerns, binding decisions, carry-overs, next action
3. How to re-open — pass genesis.md + most recent Steering Note + most recent Progress
   Digest to the new session
4. What the new session receives — complete project state, no memory required

**Section: When to Write a Steering Note**
- End of every session (pre-reset)
- When a blocking concern arises mid-session
- After 3+ Bouncer Work log entries of the same type (pattern detection)

**Section: When to Expect a Progress Digest**
- At the start of each new phase or milestone
- On request to HQ Chat

**Section: Bouncer Work Log → Steering Note Loop**
- Describe the pattern-detection flow
- What constitutes a "pattern": same severity + same type occurring 3+ times
