## Routing Logic Overview

### Determining Parent Chat

Completion Notice frontmatter contains: `epic_id`, `milestone_id`, `phase_id`

```
if milestone_id exists:
    parent = Milestone Chat
    parent_ref = milestone_id
elif phase_id only exists:
    parent = Phase Chat (or HQ if no phase delegation)
    parent_ref = phase_id
else:
    parent = HQ Chat
```

Example:
- `epic_id: P4-M14-E14.1`, `milestone_id: P4-M14` → routes to Milestone Chat
- `epic_id: P1-M15-E15.3`, `milestone_id: P1-M15` → routes to Milestone Chat for milestone P1-M15

### Artifact Lifecycle

```
1. Daemon polls .ai-project/artifacts/completion-notices/
2. New file detected (not in .processed/)
3. Acquire lock, wait for write to complete
4. Parse file using ArtifactParser (from E14.1)
5. Validate routing metadata (epic_id, milestone_id)
6. Create routing trigger in .ai-project/queue/
7. Move file to .processed/
8. Log success: "Routed Completion Notice P4-M14-E14.1 to Milestone Chat"
```

### Error Handling

```
Parse failure (malformed YAML)
    → Move to .failed/
    → Log error: "Parse failed: <reason>"
    → Continue to next artifact

Routing failure (invalid reference)
    → Move to .failed/
    → Log error: "Invalid epic_id format"
    → Notify HQ (or admin)
```
