# E34.2 — Dormant-project roll-forward roadmap

Per-project record for `Getawayinsured2023`, `footboard`, and `courtis`: verified state before the
Epic, the path to v7.0.0, the extent actually achieved in M34, and what remains. Every claim here is
confirmable against the target repo — the verbatim confirmation output is in
`P10-M34-E34.2__confirmation-evidence.md`.

recorded blocker with an honest stopping point would have satisfied the DoD). No blocker was needed.
That is the outcome, not a softened version of one — but see **What remains**, because "at v7.0.0
locally" is not the same as "published", and for two of the three it is not even independently
publishable.

`fieldledger-assesment` is out of scope (dropped from the fleet set by CFO instruction, milestone
spec Amendment A1) and is not treated as an omission anywhere in this document.

The Epic spec and starter both state that this project's **only** remote is Heroku. **That is not

**Owner's uncommitted work intact** — `git status --porcelain` after the bump is identical to the

### Branch base: the in-flight milestone branch — forced, not preferred (**FM11**)

The recommended base (`main`) is **unreachable without touching the owner's work**, demonstrated
rather than assumed:

```
$ git checkout main
error: Your local changes to the following files would be overwritten by checkout:
	docs/phases/P1__Online_1v1_MVP/P1__phase-spec.md
Please commit your changes or stash them before you switch branches.
Aborting
```

That file is modified-tracked **and does not exist on `main`**, so git must delete it to switch and
refuses. The only ways to `main` are to commit or stash the owner's work — both forbidden by this
Epic. So the bump was taken from the working branch. Git aborted cleanly; the pre-state was verified
unchanged afterwards.

### What remains after M34 — **the one real carry-forward**

**The bump commit is NOT independently publishable.** It inherits the milestone branch's 6 unmerged
commits as ancestry. To land the bump on `main`, the CFO must either:

1. merge the in-flight milestone branch to `main` first, then merge/fast-forward the bump; or
2. once the owner's uncommitted work is committed, **cherry-pick `b00bb16` onto `main`** — the commit
   touches only 3 governance paths, so it cherry-picks cleanly.

This is recorded as **FM11** in the procedure so the next operator decides the base deliberately
instead of discovering the constraint mid-bump.

Committed locally as **`a2e95a9`**. Exactly 4 paths staged:

- **Step 0 halted first, exactly as predicted.** `$SUB` resolved to two paths
  (`governance\n.governance`), the `[ -d "$SUB" ]` guard fired with *"submodule path not found —
  STOP"*, and **the halt was correct**. It was resolved by disambiguating against `git submodule
  status` (live submodules only) and on-disk existence — not by hand-editing around the guard. Full
  transcript in the confirmation evidence.
- `.governance` re-pinned `ab164d88` → `8044451c` (v7.0.0). FM2 confirmed live.

  `branch = v2.0.0` with it. Deleting only the `branch` line (FM9's remedy) would have left a
  declaration for a nonexistent path and Step 0 would keep tripping — the whole stanza was dead.
  Step 0 now resolves to a single path on this repo.
- `governance.submodule_path: .governance/` left as-is: consistent with `.gitmodules`, which is the
  authority, and not a bump field.

**Owner's uncommitted work intact.** All 4 modified tracked files still modified; all 5 untracked
owner files still untracked. The only inventory change is the agent file I installed moving
untracked → tracked, which is the intended effect. Note the porcelain *rendering* changed for one
line — pre-bump git collapsed the whole untracked directory as `?? .ai-project/`, and post-bump it
lists `?? .ai-project/artifacts/...` individually because `.ai-project/agents/` is now tracked. A
non-collapsed (`-uall`) inventory was captured before and after specifically so this is verifiable

## Judgment calls — decided

1. **Branch base** — decided per project, three different answers: `main` / in-flight milestone
   branch / `main`. Reasoning recorded above and generalized as **FM11**.
2. **How far `courtis` goes** — it went all the way. The Epic was prepared to accept a recorded
   partial; none was required. The two hazards that could have stopped it (the Step 0 halt and the
   inverted config pair) were both resolvable with evidence.
3. **Whether to run a first governed epic anywhere** — **no**, matching the spec's recommendation.
   None of the three is an obvious candidate: `Getawayinsured2023` and `footboard` both have
   unmerged in-flight governance work that an epic would collide with, and `courtis` has just moved
   three majors with a dirty tree and content that predates the corpus it now vendors. M34's
   remaining value was the roadmap and the procedure amendment, and spending the Epic there was the
   better use. No Agentic/Local run was performed, so the Hard Constraint's run-first clauses were
   not engaged.
