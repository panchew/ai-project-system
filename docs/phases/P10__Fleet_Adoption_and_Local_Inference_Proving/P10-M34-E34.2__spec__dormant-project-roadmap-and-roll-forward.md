### Finding 1 — `Getawayinsured2023` needs only the stamp, and that is now *verified*, not assumed

The milestone spec guessed "likely no corpus bump." Confirmed: the submodule is already at the
v7.0.0 commit, and **the installed agent's sha256 is `66404389f29fa1ff8e829015b70ab8b33373dc3ac3eca3f2faea121d3da3441e`
— byte-identical to canonical v7.0.0.** E33.1 Failure Mode 3 (stale out-of-band agent copy) **does
not bite here**, which is unusual and worth recording: it is the only fleet project where it did not.

Its lift is a one-line `framework_version: v7.0.0` addition. **This is the DoD's guaranteed minimum
— secure it first**, before spending effort on the harder two.

**Do not clobber its `models:` block.** `Getawayinsured2023` carries project-specific per-level model
routing from its own **SN-2 decision 2 (2026-07-23)**, including a remote Kimi K3 and local Ollama
entries, with human-confirmed `epic_manual`. That is the project's own governance, not drift. E33.1
Failure Mode 7 applies with force: **edit field-by-field; never template-replace.**

### Finding 2 — `courtis` has TWO submodule declarations, and Step 0 will halt on it

`.gitmodules` contains:

```
[submodule "governance"]      path = governance     branch = v2.0.0
[submodule ".governance"]     path = .governance
```

Only `.governance` is live (`git submodule status` lists it alone, at v4.0.1). The `governance`
entry is an orphaned declaration carrying **`branch = v2.0.0`** — the same FM9 defect E34.1 found in
`ai-project-system-mcp`, at an even older version, in a submodule that no longer exists.

**Consequence for the amended procedure:** E34.1's new **Step 0** resolves `$SUB` with
`git config -f .gitmodules --get-regexp '^submodule\..*\.path$' | awk '{print $2}'`. On `courtis`
that returns **two paths**, `$SUB` becomes a two-line string, and the `[ -d "$SUB" ]` guard fires:
*"submodule path not found — STOP."*

**Step 0 behaves correctly — it halts rather than guessing.** But it is single-submodule-assuming,
and `courtis` is the case that proves it. Resolving this is part of this Epic's work (see
Deliverable 4), not a reason to hand-edit around the guard.

### Finding 3 — two projects are mid-governance-work on non-default branches

`Getawayinsured2023` is on `phase/P1`; `footboard` is on `milestone/M1` with modified tracked files
and three untracked artifact directories. E33.1 says to bump on a `chore/framework-v7.0.0-bump`
branch **but never says what to branch it from.** Branching off an in-progress milestone branch
bundles that project's unmerged governance work into the bump branch — which the CFO then has to
publish or untangle.

This is an unrecorded gap in the lever and a decision this Epic must make and document per project.

### Finding 4 — `courtis` is schema-invalid in a way that is *inverted*, not merely absent

```yaml
version: "v4.0.1"      # rule 5 violation — must match \d+\.\d+\.\d+ ; the `v` belongs on ref
ref: 4.0.1             # the v-prefix is missing here, where it belongs
# project.description  — absent; rule 3 violation
```

The two fields are **swapped** relative to fleet convention (`version: "7.0.0"` / `ref: v7.0.0`).
The bump legitimately rewrites both, so correcting the swap is in scope. **`project.description` is
not** — it is unrelated to the bump (E34.1 set that precedent by leaving the same field alone in
`ai-project-system-mcp`). Record it; do not fix it. Fixing it here would also let the epic appear to
close **P10-GH-5**, which it must not: GH-5 is the *absence of enforcement*, not these instances.

   branches. **Recommendation: branch from the project's default branch** (`main`/`master`), not from

   tree. A recorded roadmap plus a **partial** move with an honest stopping point is a *success*

   completion.

   don't** — none of the three is an obvious candidate, E34.3's routing fix is proven only by
   E33.2/E33.4's runs, and M34's remaining value is in the roadmap. If you do, the Hard Constraint
   binds in full (real work, run-first, exit-code untrust, transcript-and-repo verification).

## Hard Constraint (carried from the Milestone spec)

**Honesty of state binds fully.** Every "rolling"/"bumped" claim is confirmable from committed
evidence against the actual target repo. **A project that cannot be moved is a recorded blocker with
a named cause — never silently counted as rolling, and never a guessed stamp.** `courtis` is the
likely candidate; a documented partial with an honest stopping point is a good outcome.

**Exit-code untrust:** `git`/`cp` exiting 0 proves nothing about what landed. The **checksum** and the
confirmation method are the evidence.

**If a first governed epic is run anywhere**, run-first ordering applies exactly as in M33: real work
advancing the target, judged from the transcript and the target repo, never the exit code (E33.2
exit-0/zero-work; E33.4 exit-2/complete-work).
