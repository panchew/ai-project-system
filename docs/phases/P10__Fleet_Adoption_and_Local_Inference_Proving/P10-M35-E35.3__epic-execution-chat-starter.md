### Summary

The framework can dispatch work to run unattended. It has no recorded way for that work to say *"I am
blocked."* An instance that hits something requiring human judgment has two exits today: finish
wrongly, or stop silently. You are writing the rule that closes that: a blocked autonomous instance
**must** hand back, to its **immediate parent**, via the **existing** escalation-notice artifact, and
the intervention that follows **carries authority**.

### Problem Statement

Four facts, all from committed records:
- **Autonomy has no call for help.** `bin/run-dev-agent` has run unattended since P7, exercised
  through M33 and M34. Nothing says what a blocked run owes anyone.
- **"Hand back to a human" is a rule no instance can execute.** An instance cannot identify or select
  a human. HQ corrected the destination to the **immediate parent**; the human is reached because the
  chain terminates at a manual level **by construction** (SN-22), in a bounded number of hops.
- **The rule it needs already exists.** One-level escalation is normative in three surfaces. SN-25
  called this "a restoration of the framework's existing design" — and it is, literally.
- **Detection is measured broken in both directions.** E33.2 Run A: **exit 0, zero work**. E33.4:
  **exit 2, complete and green work**. Two projects, corroborated; and `epic_qa` has **zero captured
  runs** (G11). That is **P10-GH-7**, and your job is to state it, not fix it.
