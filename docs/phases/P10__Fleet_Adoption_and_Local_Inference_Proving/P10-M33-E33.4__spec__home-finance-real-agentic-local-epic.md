# Epic E33.4 — home_finance real Agentic/Local epic (proving-pair completion)

## Context

E33.4 is a **decomposition addition** to M33, authored by the Milestone Chat on 2026-07-20 under
the decomposition authority the Milestone spec grants (§Planned Epics: "the Milestone Chat may
adjust epic boundaries within this milestone's scope"), following an explicit **Phase Chat/CFO
disposition** taken at milestone-closure review.

**Why it exists — a completion gap found at closure.** M33's completion bar requires **each**
proving-pair project to have a committed run record for at least one real Agentic/Local epic
(Milestone DoD; Milestone Acceptance Criterion 1; Phase Success Criterion 1; Phase Acceptance
Criteria — all say *each*). E33.2 delivered a real run on **`local-agent-runner`** only; the
Milestone spec's E33.2 epic detail was written in the singular ("running **a** genuine epic of
**a** target project's own work"), so the original three-epic decomposition (bump both / one run /
measure) never gave the **`home_finance`** run a home. `home_finance` is bumped and confirmed at
`framework_version: v7.0.0` (E33.1) but has carried no real epic. E33.4 closes that gap: it gives
`home_finance` its real Agentic/Local run so the *pair* is proven, not just one of it.

**What E33.4 is NOT.** It is **not** a second runtime experiment. The Ollama-vs-llama.cpp question
is already settled by E33.2 and the Phase Chat/CFO disposition recorded at
`P10-M33-E33.2__runtime-decision.md` (§Phase Chat / CFO disposition): **"Ollama stands; raise the
model tier"** (the configured `qwen2.5-coder:14b` was proven unusable for agentic epic work; a
30B-class coder is the lever). E33.4 **applies** that settled choice; it does not re-open it and
records no new runtime decision.

## Problem Statement

The proving pair is meant to demonstrate adoption end-to-end (SN-23: "adoption demonstrated, not
asserted"). Only `local-agent-runner` has actually carried a real governed epic; `home_finance` is
bumped but un-run. Until `home_finance` carries at least one real Agentic/Local epic under the
fixed posture with a committed run record, the milestone's and the phase's "each proving-pair
project" bar is unmet and the pair is only half-proven. E33.4 delivers that missing run.

---

## Goals

By the end of this Epic:

1. **`home_finance` has carried at least one real Agentic/Local epic end-to-end** under the fixed
   posture, with a committed **run record** in the governance record on `phase/P10`.
2. **The run advanced `home_finance`** — real work, evidenced by the target-repo commit(s) the run
   record cites (not a demo).
3. **If the run cannot complete**, an explicit **blocker record + escalation** stands in place of a
   substituted claim (Hard Constraint).
4. **The framework-repo suite stays green** for any change touching this repo (366 baseline, no new
   skips).

Together with E33.2's `local-agent-runner` run, this satisfies the "each proving-pair project has a
committed run record" bar (Milestone DoD/AC 1; Phase Success Criterion 1 / Phase AC).

---

## Non-Goals

This Epic explicitly does **not**:

- **Re-decide or re-open the runtime question.** Settled by E33.2 + the Phase disposition (Ollama;
  raise model tier). E33.4 records **no** runtime decision and runs no comparative model trial for
  decision purposes.
- **Edit `.ai-project.yml` `models:` routing.** The raised-tier selection is a dispatch choice
  documented as a deviation; the routing change stays a separate authorized act (carried to M34).
- **Run a synthetic demo.** The run must be genuine `home_finance` work that advances the project
  (Hard Constraint).
- **Redo E33.2's or E33.3's work**, or capture new burn/measurement data (that leg closed with
  E33.3). If the run record is per-model-layout compatible, that is a convenience, not a
  deliverable.
- **Rebuild the dual-mode switch / guardrail** (P9/M31 — applied, not edited).
- **Merge target-repo code onto `phase/P10`.** The run's code lands in `home_finance`; this branch
  carries the run record only (Cross-Repo split).

dispatched through the M31 dual-mode switch to `bin/run-dev-agent` + the P7 orchestrator path on
the local substrate, using the **raised model tier** (30B-class per the E33.2 disposition, since
`qwen2.5-coder:14b` was proven unusable). This Epic's Execution Chat Starter declares

rule apply — confirm the substrate is up before relying on it; a substrate that won't come up is a
blocker to escalate. Any dispatch deviation (e.g. direct-on-host, or selecting a model other than
the configured `epic_dev`/`epic_qa` pending the routing edit) is **documented in the run record**,
exactly as E33.2 did.
