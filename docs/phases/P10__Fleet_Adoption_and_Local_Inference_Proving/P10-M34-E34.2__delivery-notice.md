## How the `courtis` two-submodule case was resolved, and where FM10/FM11 were recorded

**Step 0 halted first, exactly as the spec predicted**, and that was correct behavior:

```
$ SUB="$(git config -f .gitmodules --get-regexp '^submodule\..*\.path$' | awk '{print $2}')"
raw $SUB value:
    |governance
    |.governance
line count: 2
guard: >>> submodule path not found — STOP <<<   (correct halt)
```

Resolved by **disambiguating against `git submodule status`**, which lists live submodules only, plus
on-disk existence:

```
  governance     exists=NO   in-submodule-status=NO     <- orphan declaration (branch = v2.0.0)
  .governance    exists=yes  in-submodule-status=yes    <- the live submodule, at v4.0.1
```

`$SUB` = `.governance`. **The guard was not hand-edited around.** The **whole orphan stanza** was then
removed from `.gitmodules` — not just its `branch` line, because the path does not exist and FM9's
narrower remedy would have left Step 0 still resolving two declarations. Step 0 now returns a single
path on that repo.

**Recorded in** `.ai-project/artifacts/reference/v7-bump-procedure/README.md`:

| Finding | Recorded as |
|---|---|
| Multiple / orphaned submodule declarations halt Step 0 | **New Failure Mode 10** + **Step 0 rewritten** to intersect declared paths with `git submodule status` and on-disk existence, requiring exactly one survivor. Verified against the six bumped projects, including the FM8 `governance` path. A genuine multi-submodule project still stops — correctly, since a human must say which submodule carries governance. |
| The branch base was never specified, and can be unreachable | **New Failure Mode 11** — preferred base is the default branch, with the dirty-tree exception, the git error that surfaces it, the requirement to record the choice per project, and the publishing consequence. |

Plus an amendment note: FM10 was **predicted** before execution and reproduced exactly; FM11 was
**not** predicted and surfaced only when `git checkout main` refused. Two lessons carried forward — *a
guard that halts is doing its job, but a halt the operator must resolve by hand is unfinished work*,
and *the steps a procedure omits cost as much as the ones it gets wrong.*
