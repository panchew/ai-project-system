## The Open Decision on `ref:`

**Chose (a) — add `ref: v7.0.0` alongside `version: "7.0.0"`.**

The spec recommended (a) and permitted (b) only if adding the key conflicted with something in the
file. Nothing conflicted, and reading `governance/ai-project-yml-spec.md` at v7.0.0 promoted the
recommendation to a requirement: **`governance.ref` is marked REQUIRED** (validation rule 3), and
`governance.version` is specified as a **quoted semver**, with non-semver values listed as *Invalid*.

So the target was not merely shaped differently — it was **schema-invalid on two fields**. Option (b)
would have knowingly left a required field missing. (a) also makes the standard confirmation method
work unmodified, which matters because M34's bar is *confirmable*.

**Second decision, not anticipated by the spec:** `.gitmodules` carried `branch = <raw SHA>`, and the
spec said the SHA must go but not what replaces it. **Chose to delete the line** — both proving-pair
projects carry no `branch` key at all, and a tag in that field is equally unresolvable to
`git submodule update --remote` (which reads `refs/remotes/origin/<branch>`), so `branch = v7.0.0`
would only *look* correct. Full reasoning in the confirmation evidence.
