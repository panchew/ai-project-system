# Epic E35.4 — Execution matrix ratification + mode-is-not-authority

## Context

`governance/systems/chat-hierarchy.md`'s **Execution Mode** section (P9-M31-E31.1, 2026-07-19) made
manual-vs-agentic normative at Phase, Milestone, and Epic. SN-23 then fixed P10's opening posture
narrower than the mechanism required — **Manual/Paid from Creation through Milestone, Agentic/Local at
the Epic** — which was the right call for a phase whose whole job was proving adoption.

The CFO's 2026-07-30 precision (SN-25) is that the underlying question was never *"should this be
possible"* but *"should P10 build the dispatcher"* — and those have different answers. The HQ Ruling
on SN-25 (Decision 4) ratified the execution matrix, restoring the E31.1 baseline at Phase and
Milestone, and bound the restoration with the constraint that makes it safe: **mode is not
authority.**

This Epic records the ratified matrix and that constraint. It records **only** the matrix; it does not
wire dispatch, does not decide `model-routing-policy.md` row P4, and does not widen anything.

## The one thing this Epic must get right

**Three ways this table can silently contradict the document it lands in.** All three are live, and
each produces a corpus that disagrees with itself rather than an obviously broken delivery.

**1. The Creation and HQ rows.** The matrix says *"Manual only (permanent, SN-22)"* in the Execution
Mode column for both. The section it lands in says those levels **never take an Execution Mode
declaration at all**. Those are not the same claim, and a table read literally would suggest Creation
and HQ carry a manual *declaration* — which is exactly the drift SN-22 forecloses.

**The reconciliation, which the record must state:** the matrix's Creation/HQ cells describe **how
those levels run** — manually, always, with no per-instance override possible — **not a declaration
they accept.** No Creation or HQ opener gains an Execution Mode field, then or now. Write the
reconciliation; do not leave a reader to perform it.

**2. The locality column is not this document's decision to make.** Inference locality is decided by
`model-routing-policy.md` rows P1–P7, under its own §Change discipline (*"Policy rows change only with
new cited evidence … never by assumption"*). If the matrix's locality column is recorded as a
freestanding claim, the corpus gains a **second statement of routing policy that nothing keeps in
sync** — and the framework already expects mapping refreshes to recur.

**The rule: the locality column is a pointer, not an authority.** Record it with an explicit
statement that `model-routing-policy.md` is authoritative on locality and wins on any divergence —
the same relationship `chat-hierarchy.md` already has with that file in its Manual Chat Model
Verification section.

**3. Restoring the mode is not building the dispatcher.** E31.1's gap statement — no dispatch
mechanism consumes a Phase/Milestone agentic declaration — **remains true after this Epic**, and the
Milestone spec's Non-Goals say so explicitly. A matrix that reads as though Phase/Milestone agentic
runs are now available would be false on the day it merged. Record the restoration as a
**permission**, and keep E31.1's gap statement intact and visible next to it.

   | Epic | Agentic or manual | Local or remote (in force, E34.3) |

   Delivered with all three reconciliations: the Creation/HQ *describes-not-declares* reading; the
   locality column marked as a **pointer** to `model-routing-policy.md`, which wins on divergence; and
   E31.1's dispatch gap intact and visible so restoration is not read as availability.

2. **Mode-is-not-authority, stated explicitly and unambiguously.** Restoring agentic mode at Phase and
   Milestone says an instance **may run unattended**; it does **not** widen what that instance may
   **authorize**. Name the acts: **Stage-2 acceptance and merge authorization still require the
   human's key, whatever Execution Mode the instance is running in.** Include the framing that makes
   it memorable and hard to erode — *mode is what may run; gates are what may be decided without a
   key* — and the reason it matters at Milestone specifically: that is where Stage-2 accept authority
   lives, and errors there propagate into merges.

   **This is the normative home of that rule.** E35.3's handback subsection already states it in
   context; make the relationship explicit — one home, the other citing it — so the corpus does not
   acquire two independent statements that can drift apart. Adjusting E35.3's sentence into a citation
   is in scope for this Epic.

3. **The SN-23 Ratified Decision #2 supersession, recorded.** Decision 2's **Execution Mode axis is
   superseded** (Phase and Milestone may run agentically or manually, restoring the E31.1 baseline);
   its **locality axis stands**, with Milestone × local inference under a directed evidence evaluation
   (E35.5) rather than settled either way. The supersession is recorded explicitly **so it is a
   decision, not drift.** This Epic's record and the phase spec's Note-on-Decision-2 footnote must
   **agree with each other** — read that footnote and match its substance rather than paraphrasing
   from memory.

## Notes

- **This is the smallest epic in M35 and the easiest to get subtly wrong.** A five-row table looks
  like transcription work; the delivery is really the three reconciliations around it, without which
  the table contradicts the section it sits in.
- **"Under evaluation" is a real state, not a hedge.** The Milestone × local cell is neither opened
  nor closed; it opens or closes on E35.5's evidence, and a further HQ call moves row P4 if warranted.
  Write the cell so a reader understands the question is live and directed, not unanswered by neglect.
- **Why the constraint is the point.** A mode restoration that quietly widened authority would be the
  most expensive kind of governance error — invisible, well-intentioned, and load-bearing at exactly
  the level where Stage-2 errors propagate into merges. Recording the permission without the
  constraint would have been worse than recording neither.
