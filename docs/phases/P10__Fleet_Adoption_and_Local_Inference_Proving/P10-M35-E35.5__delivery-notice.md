### An observed flaky test — recorded, not fixed (new gap: P10-GH-10)

**One of ten full-suite runs failed**, and it is reported rather than dropped:

```
FAILED tests/test_artifact_router.py::test_daemon_extensions_error_branches
1 failed, 365 passed
```

Evidence gathered immediately afterwards: the test **passes in isolation** (`1 passed in 0.11s`) and
**nine consecutive full-suite runs were clean** at 366/0/0 — the two before it and the six after, plus
the isolated run. Approximate rate: **1 in 10**. The failing run was the one executed right after
`docker start comfyui` and an Ollama model unload, i.e. under transient system load.

The test patches `time.sleep` and `Path.exists` **globally** and drives a daemon loop that it exits by
raising from the patched `sleep`, with assertions against filesystem state in `tmp_path`. That is a
plausible shape for a load-sensitive intermittent failure, but this Epic did **not** root-cause it and
did **not** change the test — `tests/test_artifact_router.py` is untouched, and fixing a framework test
is a capability change, out of scope for this Epic (the same reasoning by which E34.2 recorded
P10-GH-6 rather than fixing it).

**Why it is worth a gap rather than a shrug.** Every epic's Definition of Done in this phase asserts
"full suite green" as evidence. If the suite is intermittently red for reasons unrelated to the change
under review, then a green suite is weaker evidence than it appears — and an epic that measures once
may either report a green it did not really have, or attribute a pre-existing flake to its own work.
That is the same class of problem as exit-code untrust (M33) and the two-sided block-detection failure
recorded as **P10-GH-7**: a signal trusted as authoritative that does not always mean what it says.

Filed as **P10-GH-10**; see `P10-M35__carry-forward-note__P10-GH-10-flaky-artifact-router-test.md`.
**The Milestone Chat should confirm the identifier** — gap numbering is its to assign, and P10-GH-9 is
the highest previously recorded.
