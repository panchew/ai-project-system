# Bugfix B2.1 — `run_in_sandbox()` severs the container from the Ollama endpoint it must reach

## Problem

`run_in_sandbox()` (`bin/ai-project-orchestrator`) forwards exactly one environment variable —
`AI_PROJECT_ACTIVE_MODEL` — plus the project mount. It forwards **no network configuration**, no
`AI_PROJECT_OLLAMA_ENDPOINT`, and no `LOCAL_AGENT_RUNNER`. Inside the container, `localhost:11434`
is the container's own loopback, not the host's Ollama.

Measured 2026-08-06 against `ai-project-sandbox:latest`:

| From inside the sandbox | Result |
|---|---|
| `http://localhost:11434/api/tags` | **HTTP 000** |
| `http://172.17.0.1:11434/api/tags` | **HTTP 200** |

`bin/run-dev-agent` calls `check_local_availability` (line 221) **before** `discover_runner`
(line 252), so a sandboxed agentic/local dispatch exits **class 5 — local unavailable** having done
no work.

**This was documented on 2026-07-12** in P7-M26-E26.3's spec, verbatim: *"cannot reach the real
Ollama endpoint or the runner binary — `run_in_sandbox()` forwards no network config or
`LOCAL_AGENT_RUNNER`/`AI_PROJECT_OLLAMA_ENDPOINT` into the container."* It was worked around
per-epic and never filed.

## Impact

- **Severity: High.** Every agentic/local Epic dispatched through the sandbox is blocked. It blocks
  **P11-M37/E37.1** today and is a prerequisite for M38 and M39's dispatch work.
- **Affected component:** `bin/ai-project-orchestrator` → `run_in_sandbox()`; consumed by
  `bin/run-dev-agent`.
- **The documented workaround is not equivalent.** E26.3's fallback (curate `PATH` to omit `docker`
  so the local-execution route fires) obtains the capability **by discarding sandbox isolation** —
  it trades away a safety property rather than restoring the feature. A workaround that removes a
  guarantee does not reduce severity.

## Root Cause

Known. `run_in_sandbox()` was written to inject the active-model metadata and nothing else. Local
inference over HTTP to a host-side endpoint was not a use case at the time; when it became one
(P7-M26-E26.3), the gap was routed around per-epic instead of being fixed at the seam.

## Fix

**Route B.1 only — engine-agnostic.** Forward what the container needs to reach the host:

- Pass an Ollama endpoint into the sandbox that resolves from inside it. `172.17.0.1` is the
  measured-working Docker bridge gateway on this host; **do not hard-code it** — derive it, or make
  it configurable with a documented default, so the fix survives a different Docker network setup.
- Forward `AI_PROJECT_OLLAMA_ENDPOINT` and `LOCAL_AGENT_RUNNER` when set in the invoking
  environment. `bin/run-dev-agent` already consumes both; only the forwarding is missing.
- Add a test that fails when `run_in_sandbox()` stops forwarding the endpoint. **The durable part is
  the test** — this defect survived three weeks precisely because nothing asserted the seam.

**Explicitly out of scope — Route B.2, declined by HQ Ruling 2026-08-06 Decision 5.** Do **not**
install `local-agent-runner` (or any engine) into the sandbox image. It is under directed retirement
assessment (SN-27 A1.2, at M38/E38.4), and M38/E38.2's adapter surface should make it unnecessary.

**This fix does not by itself make E37.1 dispatchable, and is not expected to.** Measured: with the
endpoint reachable, `local-agent-runner` is **still absent** from the image, so `discover_runner()`
still fails. That is Route B.2's territory and is declined. B2.1 removes the *first* blocker, which
is the one that blocks everything downstream too.

## Definition of Done

- [ ] `run_in_sandbox()` forwards a host-reachable Ollama endpoint into the container
- [ ] `AI_PROJECT_OLLAMA_ENDPOINT` and `LOCAL_AGENT_RUNNER` are forwarded when set
- [ ] The gateway address is derived or configurable — **not hard-coded**
- [ ] A test asserts the forwarding and fails if it regresses
- [ ] Demonstrated from inside the sandbox: the endpoint returns **HTTP 200**
- [ ] No engine is installed into the sandbox image (Route B.2 stays out)
- [ ] No regressions — full suite green against the branch's measured baseline, no route-around skips
- [ ] Delivery Notice committed
- [ ] Merged with explicit human merge authorization

## Acceptance Criteria

- A sandboxed dispatch reaches the host's Ollama and **no longer exits class 5 for endpoint
  unreachability**. (It may still fail on runner discovery — that is expected and out of scope.)
- Removing the forwarding fails the suite.
- `Dockerfile.sandbox` contains no engine install step.
