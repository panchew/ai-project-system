# Post-Mortem: B2.1 — A known defect that was routed around for three weeks instead of filed

## Incident Summary

From 2026-07-12 to 2026-08-06, every agentic/local Epic dispatched through the
orchestrator's Docker sandbox was blocked: `run_in_sandbox()` forwarded no inference
endpoint, so `bin/run-dev-agent`'s local-availability preflight met the container's own
loopback and exited class 5 before doing any work. The defect was **identified and written
down on the first day**, in P7-M26-E26.3's spec, in the same words the bugfix spec later
used. It was not filed as a defect. It was worked around, per epic, for three weeks, and
the workaround was cited as precedent by the epics that followed.

The user-visible impact was zero, which is the point of interest: nothing broke, because
every affected run took the fallback. The cost was paid in P11 instead — E37.1's posture
had to be reverted, the local/paid comparison moved to M38, and an escalation ran Epic →
Milestone → Phase → HQ to re-derive a conclusion that was already in the repository.

**The finding is not the missing `-e` flag.** It is the three weeks.

## Timeline

1. **2026-07-12** — P7-M26-E26.3 confirms on this host that the sandboxed route cannot
   reach Ollama or the runner, and records the cause exactly:
   *"`run_in_sandbox()` forwards no network config or `LOCAL_AGENT_RUNNER`/
   `AI_PROJECT_OLLAMA_ENDPOINT` into the container."* The spec **authorizes a fallback** —
   a curated `PATH` omitting `docker`, so `run_in_sandbox()`'s own `FileNotFoundError`
   handler fires and execution happens on the host. No `GH-` record, no bugfix, no
   follow-up epic.
2. **P10-M33-E33.2** — dispatches on the host, *"not wrapped in the orchestrator's Docker
   sandbox,"* citing **the E26.3 precedent** as its rationale.
3. **P10-M33-E33.4** — dispatches on the host, *"the same path E33.2 took (and
   P7-M26-E26.3-PROVE before it)."* Rationale recorded as *"unchanged from E33.2."*
4. **2026-08-05** — P11-M37 finds E37.1's agentic/local posture non-executable and
   escalates. The escalation's own dispatch preconditions had been checked at the **host**
   layer for code that runs **inside the sandbox**.
5. **2026-08-06** — HQ re-measures at the sandbox layer (000 vs 200 vs runner absent),
   authorizes **B2.1** (High), declines Route B.2, and files `P11-GH-2`.
6. **2026-08-07** — Fix delivered: endpoint and runner override forwarded, gateway derived
   by the daemon, 16 new tests, HTTP 200 measured from inside the sandbox.

## Root Cause

**Process, not code.** The code cause is trivial and was known on day one: one `-e` was
never added.

What allowed it to persist is that **the workaround was authorized at the layer that
suffered it.** E26.3 was an Epic; an Epic can authorize its own execution route, and it did
so correctly — the run had to happen. What an Epic cannot do is open a defect record
against shared infrastructure, and nothing in the flow required it to hand the finding
upward. So the finding stayed in the artifact where it was made.

Two mechanisms then converted a one-off into a standing practice:

- **The workaround was cheap and total.** It restored the capability completely, so no
  later run felt friction. A defect that hurts gets filed; this one did not hurt.
- **A documented workaround reads as a design decision to whoever inherits it.** E33.2 and
  E33.4 did not re-discover a gap and choose to tolerate it — they cited a precedent. By
  the third run, *"not wrapped in the sandbox"* was the house style, with a rationale
  recorded as *"unchanged."*

**And the workaround was not equivalent to the feature.** It obtains local execution by
omitting `docker` from `PATH` — that is, by discarding sandbox isolation. Three weeks of
agentic runs executed with a safety property silently traded away, recorded in each run
record as a routine dispatch-path note.

## Resolution

`run_in_sandbox()` forwards `AI_PROJECT_OLLAMA_ENDPOINT`, loopback-rewritten to a gateway
Docker itself resolves (`--add-host <alias>:host-gateway`, overridable via
`AI_PROJECT_SANDBOX_GATEWAY`), and `LOCAL_AGENT_RUNNER` when set. Verified from **inside**
the sandbox through the real function: **HTTP 200**, against **000** for the same probe on
the container's loopback. Deleting the forwarding line fails 7 tests. Suite 391 passed /
1 xfailed, from a 375 / 1 baseline. Details in `docs/bugfixes/B2.1__delivery-notice.md`.

This does not make E37.1 dispatchable — `local-agent-runner` is still absent from the
image, which is Route B.2 and declined. It removes the blocker that fired first.

## Prevention

- **The seam is now asserted.** `tests/test_sandbox_endpoint_forwarding.py` fails if the
  forwarding is removed. This defect survived three weeks precisely because nothing
  asserted the seam; the test is the durable deliverable, not the flag.
- **The measurement is taken where the code runs.** The live test starts a real container
  and asks the real endpoint, rather than checking the host and inferring. This is the
  practice the 2026-08-06 ruling ratified in the interim (`P11-GH-2`): a verification
  states the layer it was performed at, and where that differs from the layer the verified
  thing executes at, it is not evidence.
- **The negative control is kept.** Asserting only that something answers would also pass
  if an engine were installed into the image — the outcome Decision 5 declines. The paired
  000 keeps the guard honest about *what* fixed it.

## Action Items

1. **Route-around findings get a record, not just a run note.** When an Epic authorizes a
   workaround against shared infrastructure, it hands the finding to its parent for a
   `GH-` record or a bugfix — the workaround unblocks the run, the record is a separate,
   non-optional obligation. — Owner: P11 Phase Chat (to route to HQ as a governance
   amendment) — Due: P11-M38 planning
2. **A workaround that removes a guarantee is escalated, not absorbed.** E26.3's fallback
   traded away sandbox isolation; that class of workaround should reach the layer that owns
   the guarantee before it is used a second time. — Owner: HQ Chat — Due: P11-M38 planning
3. **Audit the remaining `run_in_sandbox()` forwarding surface.** This fix covers the two
   variables `bin/run-dev-agent` consumes. Whether any other host-side resource is severed
   the same way was not audited here and should be, before M38/E38.2's adapter surface is
   designed against it. — Owner: P11-M38 — Due: M38 execution
4. **Reconsider the `FileNotFoundError` fallback.** Silently executing on the host when
   `docker` is missing is what made the workaround a one-liner. Whether an isolation
   downgrade should be silent belongs with M38's adapter-surface work. — Owner: P11-M38 —
   Due: M38 execution
