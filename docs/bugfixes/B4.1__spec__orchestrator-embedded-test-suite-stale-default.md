# Bugfix B4.1 — Orchestrator's embedded `--test` suite asserts the pre-E27.1 default

## Problem

`bin/ai-project-orchestrator`'s own embedded unittest suite (invoked via
`python3 bin/ai-project-orchestrator --test`, separate from `pytest tests/`) has 2 failing tests:
`test_visual_artifacts_absent_is_disabled` and `test_visual_artifacts_absent_block_is_disabled`
(defined inline in `bin/ai-project-orchestrator`, ~lines 530-540). Both assert
`resolve_visual_artifacts(...)["enabled"] is False` for an absent/empty block — the pre-E27.1
opt-in default. E27.1 (P7-M27, merged `dcfc9b6`) flipped `DEFAULT_VISUAL_ARTIFACTS["enabled"]` to
`True` and rewrote the equivalent tests in `tests/test_visual_artifacts_config.py`
(`test_absent_resolves_enabled` etc.), but missed this second, embedded suite — a genuine gap in
that Epic's "rewrite tests asserting the old default" DoD item, and in the Milestone Chat's own
merge verification (which ran `pytest` only, never `--test`).

## Impact

**Low.** The embedded `--test` suite is invoked manually (`bin/ai-project-orchestrator --test`),
not by `pytest` or any CI workflow (this repo has none) — it is not part of the suite result
routinely reported as "full suite passes" in Epic/Milestone Delivery Notices, so this predates
E27.1 without having blocked any prior acceptance. It was surfaced during E27.3 (P7-M27) execution
when the Coding Agent ran `--test` as part of its own due diligence — confirmed via `git stash`
against `milestone/M27` (pre-E27.3) to predate that Epic. No user-facing or production behavior is
affected: `resolve_visual_artifacts()` itself is correct and covered by the passing `pytest` suite
(306/1); only these 2 embedded self-test assertions are stale.

## Root Cause

`bin/ai-project-orchestrator` carries its own inline `unittest.TestCase` suite (`class
TestOrchestrator`, reachable via `--test`) that duplicates coverage already present in
`tests/test_visual_artifacts_config.py`. E27.1 rewrote the `tests/` copy but did not know the
embedded duplicate existed (not discoverable via a `tests/`-scoped grep) and did not run
`--test` as part of its own verification.

## Fix

Rewrite the 2 embedded test methods to assert the new default-on behavior, mirroring exactly what
E27.1 already correctly did in `tests/test_visual_artifacts_config.py`
(`test_absent_resolves_enabled` / `test_present_block_without_enabled_defaults_enabled`, merged
`dcfc9b6`) — an absent/empty block resolves `enabled: True`; add or retain a case confirming
explicit `enabled: false` still resolves `False`. Do not delete the tests; rewrite them. Run both
`pytest tests/` and `python3 bin/ai-project-orchestrator --test` before closing, since this defect
was invisible to the former.
